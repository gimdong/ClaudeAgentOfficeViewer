- **대상:** developer (T2). 절 번호(§1–§5)를 T2가 인용합니다.
- **입력:** 지시서 `.superpowers/sdd/2026-10-16-reopen/brief.md`(사용자 승인), progress.md B201–B204. 재사용: Phase 4a 디자인 §1(층 머리 버튼)·§3(종료 확인 창 `.dlg .td`, `.td-kv`, `.td-warn`, `.dlg-err` keep-all)·§1.5(칩 `종료 중`), Phase 4b 화면(`web/floors/ChannelDialogs.tsx`: 일하는 방식 라디오 `.ch-mode`, "붙어서 확인하기" 단계 `attach*`·`.cmd`·복사 단추).

## §1 버튼

### 1.1 자리와 대상 (B203)

층 머리 컨트롤의 **"작업 지시" 자리**에 둡니다(Phase 4a §1.4의 순서: 스위치 · 작업 지시 자리 · 종료). 한 자리에 버튼은 하나입니다.

| 층 | 그 자리의 버튼 |
|---|---|
| 실험 기능 켜짐 + 살아 있음 + 대시보드가 띄우지 않음(channel 없음) + 합치지 않은 층 | **`작업 지시 켜기`** (이 문서) |
| 위 조건이지만 **두 기록을 합쳐 보이는 층**(parkedJobId, B205 ③) | `작업 지시 켜기`를 `aria-disabled`로, `title` 문구표 "합친 층" |
| 위 조건이지만 **이 대시보드를 켠 조상 세션**(서버 409 `ancestor`, B205 ③) | `작업 지시 켜기`를 `aria-disabled`로, `title` 문구표 "조상 세션". ★ 현재 세션 경고는 조상이 아닐 때만 창에 나옵니다 |
| 대시보드가 띄운 층(launched) | 지금처럼 `작업 지시` |
| 실험 기능 꺼짐 | 지금처럼 `작업 지시`(`aria-disabled`, 실험 기능 제목) |
| 끝난 층 | 지금처럼 `삭제`만 |

### 1.2 모양

- `.pbtn`(28px, 12px), 아이콘 `send`(지금 작업 지시와 같음), 글자 「지시서」 `작업 지시 켜기`. 위험 색은 쓰지 않습니다(누르면 확인 창이 위험을 알림 — 4a "종료"만 위험 색).
- `aria-haspopup="dialog"`, `aria-label` 문구표, `title` 문구표(무엇을 하는지 한 줄).

### 1.3 상태

| 상태 | 모양 |
|---|---|
| 누를 수 있음 | 보통 `.pbtn` |
| **멈춘 층**(B202) | `aria-disabled="true"`, 투명도 .4(4a의 작업 지시 흐림과 같음), `title` 문구표 "멈춘 층". 누르면 아무것도 하지 않습니다 |
| 이 층을 옮겨 여는 중(창을 닫았을 때) | `aria-disabled="true"` + `aria-busy="true"`, `title` 문구표 "옮기는 중". 층 칩은 `종료 중`(§4) |

**기다리는 동안 다른 버튼도 막습니다(B205 ②):** 옮겨 여는 동안 서버는 그 층의 멈춤·재개·종료·숨김을 409 `busy`로 거절합니다. 화면은 그 층의 **스위치·`종료`·`삭제`**(잠깐 끝난 층으로 보일 때)를 `aria-disabled`로 두고 `title`을 문구표 "옮기는 중"으로 답니다. 스위치에는 `aria-busy`를 주지 않습니다(그 요청을 보낸 것이 아니므로). 그래도 요청이 나가 409 `busy`를 받으면 4a §1.3 실패 한 줄(`.fc-err`)에 문구표 "busy"를 씁니다.

`disabled`는 쓰지 않습니다(포커스가 body로 떨어짐, Phase 3 B105).

## §3 성공 뒤 — "붙어서 확인하기" (4b 재사용)

- 200 `{ tmux }`를 받으면 **같은 창**이 4b `LaunchDialog`의 붙는 단계로 바뀝니다: 제목 `터미널에서 붙어 확인해 주세요`, 붙는 명령 `tmux attach -t {tmux}`(`.cmd` 상자 + [복사]), [닫기]. 테두리는 4b 창과 같게 바뀝니다(위험 동작이 끝났으므로).
- **본문만 다릅니다**(문구표 "붙기 본문"): 옮겨 연 세션은 같은 폴더라 "폴더 신뢰" 확인 창이 다시 뜨지 않을 수 있고, 개발용 channel 경고는 뜹니다. 4b 본문의 "확인 창 두 개"를 그대로 쓰면 하나만 뜰 때 사용자가 기다립니다.
- 포커스: 4b 붙는 단계와 같게(창이 바뀌면 [복사]).
- live region(App의 하나뿐인 `role="status"`): 문구표 "성공 알림".

## §4 기다리는 동안의 층

- 층 칩: 4a §1.5의 **`종료 중`**(`.chip--terminating`, 분홍 점선). reopen 진행 표에서 와서 sweep에 지워지지 않습니다(B204).
- 옛 프로세스가 끝나고 새 세션이 같은 id로 레코드에 오기까지 스냅샷 주기(3초)만큼 그 층이 `종료됨`으로 보이거나 잠깐 목록에서 빠질 수 있습니다(4a B117과 같은 늦음). 화면은 이를 따로 감추지 않습니다. 새 세션이 오면 층은 같은 자리·같은 이름으로 돌아오고, 머리에 4b 칩 `대시보드가 띄움` · `연결 전`(붙어서 경고를 확인하면 `연결됨`)이 붙고, 그 자리 버튼은 `작업 지시`가 됩니다.
- 그 층의 다른 컨트롤(스위치·종료)은 기다리는 동안에도 4a 그대로입니다. 단, 스위치를 누르면 서버가 `ended`로 답할 수 있습니다(4a §6.2 문구).

## director 확인용 (지시서에 없는 것)

| # | 이 문서 | 이유 |
|---|---|---|
| 1 | 요청 중 [취소] → `닫기`, 닫아도 서버는 이어 가고 끝나면 붙는 창이 저절로 열림(§2.1) | 기다림은 되돌릴 수 없고(이미 SIGTERM), 붙는 명령을 잃으면 사용자가 새 tmux 세션을 찾을 수 없습니다 |
| 2 | 붙기 본문을 옮겨 열기용으로 따로(§3) | 같은 폴더라 폴더 신뢰 창이 안 뜰 수 있어 4b 본문("두 개")이 틀릴 수 있습니다 |
| 3 | launch 실패에 `claude --resume {대화 id}` 명령 상자(§2.2) | B201 "터미널에서 열 수 있다는 안내"를 그대로 쓸 수 있는 명령으로 |
| 4 | (B207 W4로 바뀜) 작업 중 구성원 수 줄은 두지 않음 — `.td-kv`의 `작업 중 {M}명`이 수를 보임 | 같은 수를 두 번 쓰지 않습니다 |
