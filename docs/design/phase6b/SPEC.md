# Phase 6b 화면 — 팀리더 일(보고서·결재, 대화 질문, 퇴근·퇴사)

근거: 스펙 `docs/superpowers/specs/2026-10-21-v2-phase6b-design.md`(이하 「스펙」), 계획 Task 4. 문구 중 「스펙」 표시는 스펙 글자 그대로, 「안」은 이 문서의 제안(qa 검토 대상, §9 목록).

**원칙:** 새 모양을 만들기 전에 있는 것을 씁니다.

| 필요한 것 | 다시 쓰는 것 |
|---|---|
| 지시 버튼 자리 | 에이전트 패널(phase3 §1, 책상을 누르면 열리는 보라 서랍)의 새 절 |
| 서류철 패널 | 같은 자리의 서랍(`.rp` 틀, phase2 §1.1) — 한 번에 하나(phase3 §7.1) |
| ask_user 질문 | 결정 표시(손들기 + 노란 ?, phase1 6장)와 결정 보고서 서랍. kind `chat` |
| 답을 기다립니다 | 책상 말머리(`StatusBubble`) 자리, 하늘색 |
| 답 칸 | 결정 보고서의 질문 답(`QuestionForm`, phase2 §2.2) 모양 |
| 퇴근 빈 의자 | 퇴근(offline)·휴업 책상의 빈 의자 + 휴업 셔터 팻말 색(phase4a §2.1) |
| 퇴사 확인 창 | 종료 확인 창 `.dlg.td`(phase4a §3, 분홍 테두리, 포커스는 [취소]) |
| 전임자 서랍 | `<details>` 접힘(층 안, 책상 줄 아래) |

**글은 글자로만:** 보고서 본문·인수인계 메모·질문 글·마지막 assistant 글은 모두 React 텍스트 노드로만 넣습니다(`dangerouslySetInnerHTML` 금지, 마크다운 해석 없음). 줄바꿈은 CSS `white-space: pre-wrap`으로만 살립니다. `#`·`**`·`<b>`는 그 글자 그대로 보입니다(Review Focus 3).

## §0 새 토큰과 아이콘

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `--folder` | `var(--green)` | 서류철 서랍 왼쪽 테두리, 서류철 버튼 아이콘, 승인됨 도장 |
| `--paper` | `#f4f0dc` | 보고서 종이 배경(글자는 `--wall`) |
| `--await` | `var(--cyan)` | "답을 기다립니다" 말머리·이름표 밑줄 |

- 결재 대기는 사용자의 결정이므로 **노랑**(결정 색), 승인은 **초록**, 수정 요청은 **분홍**입니다. 서랍 테두리는 초록(노랑 결정 보고서·하늘 진단·보라 에이전트 패널과 구별).
- 새 아이콘(7×7, `ICONS`, 아이콘 수 +2):

```ts
folder: ["xxx....", "x..xxxx", "x.....x", "xxxxxxx", "x.....x", "x.....x", "xxxxxxx"],   // 서류철
door:   ["xxxxxxx", "x.....x", "x.....x", "x...a.x", "x.....x", "x.....x", "xxxxxxx"],   // 퇴근(a = 손잡이, accent는 글자색 그대로)
```

- 책상에 그리는 작은 서류철 `FOLDER_DESK`(4×4, 책상 SVG 도트 1칸 = 4px. 자리는 §2.2):

```ts
export const FOLDER_DESK = ["xx..", "xxxx", "xaax", "xxxx"];   // x 표지, a 종이
```

  색: `x` = `--yellow`(대기 있음) / `--muted`(대기 없음, 보고서만 있음), `a` = `--paper`.

- 퇴근 팻말 `OFFDUTY_SIGN`: 책상 SVG 안 사각 + 글자(§2.4).

## §1 에이전트 패널의 "지시" 절

에이전트 패널(phase3 §1)의 스크롤 영역 **맨 위**에 절 하나를 더합니다. 이 층이 지금 보이는 층이고, 대상이 그 층의 **리드 또는 팀원**일 때만 둡니다(서브에이전트·그 밖의 모든·목록에서 연 화면에 없는 이름에는 없음).

```
┌ 4px --policy ─────────────────────────────────────┐
│ [아바타] [리드]                         [×]        │
│          team-lead                                │
├───────────────────────────────────────────────────┤
│ 지시                                               │  ← 새 절 .ap-cmd (h3 11px --muted)
│ [▤ 보고 요청]  [▤ 서류철 · 대기 2]                  │  리드
│ 옮겨 열기로 연결하면 쓸 수 있습니다                   │  비활성 이유 (있을 때만)
│ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ │
│ 모델·토큰 …  (기존 절)                              │
```

### 1.1 버튼

| 대상 | 버튼(순서대로) | 모양 |
|---|---|---|
| 리드 | `[보고 요청]` `[서류철 · 대기 {n}]` | `.pbtn` 높이 32px, 아이콘 14px(`send`, `folder`) |
| 팀원 · 일하는 중/쉬는 중 | `[퇴근]` `[퇴사]` | `[퇴근]` `.pbtn`(아이콘 `door`), `[퇴사]` `.pbtn pbtn--danger`(분홍 글자, 아이콘 없음) |
| 팀원 · 퇴근함 | `[출근]` `[퇴사]` | `[출근]` `.pbtn`(아이콘 `play`) |
| 팀원 · 퇴근 요청함(아직 안 끝남) | `[퇴근 요청함]`(누를 수 없음) `[퇴사]` | `aria-disabled="true"`, 이유 줄 없음(상태 자체가 이유) |
| 팀원 · 퇴사 진행 중 | `[퇴사 진행 중]`(누를 수 없음) | 다른 버튼 없음 |

- `[서류철 · 대기 {n}]`: 대기 0이면 `[서류철]`(보고서가 하나도 없어도 둡니다 — 빈 서류철 안내 §3.5). 서류철은 channel이 없어도 **열 수 있습니다**(읽기). 결재 버튼만 비활성(§3.3).
- 버튼 줄: `display:flex; flex-wrap:wrap; gap:8px`. 360폭에서 두 버튼이 한 줄에 들어갑니다(렌더 확인).
- 리드 패널에는 `[퇴근]`·`[퇴사]`가 없습니다(리드는 필수 소통 창구, 「스펙」 1장).

### 1.2 비활성과 이유 줄

| 층 상태 | 지시 버튼 | 이유 줄 |
|---|---|---|
| 대시보드가 띄운 층이 아님(터미널에서 연 층) | 비활성 | 「스펙」 `옮겨 열기로 연결하면 쓸 수 있습니다` |
| 띄웠지만 channel 연결 없음 | 비활성 | 기존 `CH_TEXT.notConnected` 그대로 |
| 휴업(멈춤) | **활성** — 누르면 보관(held)에 들어감 | 「안」 `휴업 중이라 재개할 때 전합니다` (`--muted`) |
| 연결됨 | 활성 | 없음 |

- 비활성은 `disabled`가 아니라 `aria-disabled="true"` + `aria-describedby`(이유 줄 id). 포커스가 머물고 이유가 읽힙니다(phase4a §1.4와 같은 이유).
- 이유 줄: `--font-text` 12px `--muted`, 위 여백 6px, `word-break: keep-all; overflow-wrap: anywhere`.

### 1.3 누른 뒤

- `[보고 요청]`·`[퇴근]`·`[출근]`: 확인 창 없이 바로 보냅니다(되돌릴 수 있는 일). 보내는 동안 그 버튼 `aria-busy="true"` + 글자 `보내는 중…`(phase4a 1.2와 같은 규칙).
- 성공: 버튼 아래 한 줄(이유 줄 자리) 「안」 `팀리더에게 전했습니다` 초록, 5초 뒤 사라짐 + `announce`. 휴업이면 「안」 `보관했습니다 — 재개할 때 전합니다`.
- 실패: 같은 자리 `--red` `role="alert"`. 409 not-connected → `CH_TEXT.notConnected`, 그 밖 → 「안」 `보내지 못했습니다. 잠시 뒤 다시 해 보세요`.
- `[보고 요청]`을 보낸 뒤 10분 동안 보고서가 오지 않으면(「스펙」 10장) 리드 패널 지시 절에 「안」 `보고 요청 뒤 10분째 답이 없습니다` (`--yellow`, 다음 보고서가 오면 사라짐). 책상에는 표시하지 않습니다(책상 표시 과잉 방지).
- `[퇴사]` → §5 확인 창.

## §2 책상 표시

책상 SVG(viewBox `0 0 24 30`)와 이름표 아래 줄에 더합니다. 기존 자리: 말머리·? x 1–12 y 0–8, 자물쇠 (18, 3)/(16, 3), 캐릭터 x 2–9 y 9–20, 모니터 x 12–19 y 11–16, 받침 x 15–16 y 17–18, 책상판 y 19–20.

### 2.1 우선순위 (말머리 자리)

결정 대기(? · ask_user 포함) → 답을 기다립니다(§2.3) → 정책으로 막힘 말풍선 줄(phase3 §6.3) → 기존 상태 말머리.

**누르면(책상 버튼):** 결정 대기 → 결정 보고서(ask_user면 §4 답 칸) · 답을 기다립니다 → 같은 서랍의 §4 답 칸 · 그 밖 → 에이전트 패널(§1).

### 2.2 서류철 (리드 책상)

- 보고서·인수인계가 하나라도 있으면 `FOLDER_DESK`(§0의 4×4 맵)를 **(20, 15)**에 그립니다. x 20–23 y 15–18 — 모니터(x ≤ 19)의 오른쪽, 책상판(y 19) 바로 위에 놓인 모양입니다.

- 이름표 아래 한 줄 자리(`.desk-extra`, §2.6)에 대기가 있을 때만 「안」 `결재 {n}` 칩 `.desk-folder` — 10px, `--wall` 글자에 `--yellow` 배경, 여백 `0 4px`, `line-height:14px`. 대기 0이면 비어 있습니다(서류철 그림만).
- 책상 aria-label 덧붙임: 「안」 `, 결재 대기 {n}건`.

### 2.3 답을 기다립니다 (Stop 대체 경로)

`member.awaitingReply`가 있으면:

- 말머리를 `--await` 바탕의 말머리로 바꿉니다: 기존 `StatusBubble` 틀(12×7 + 꼬리 2×1)에 바탕 `--cyan`, 글자 `· · ·`(점 셋 = 「스펙」의 "파란 점"), 글자색 `--wall`. **손은 들지 않고 ?도 없습니다**(「스펙」 4장).
- 이름표에 2px `--await` 밑줄(노란 이름표는 결정 대기 전용).
- 말풍선(호버·포커스) 첫 줄: 「스펙」 `답을 기다립니다`, 둘째 줄: 마지막 글의 첫 줄(60자, phase1 말풍선 자르기 규칙).
- 책상 aria-label: `{이름}, 답을 기다립니다. 답하기 열기`.
- 깜빡이지 않습니다.

### 2.4 퇴근 팻말 빈 의자

퇴근함(퇴근 요청 뒤 끝남 — `offDuty`)이면:

- 기존 빈 의자(`data-testid="empty-chair"`)를 그리고, 의자 위에 팻말: `rect` (2, 10) 9×5 `--shutter-bar` + 테두리 대신 아래 줄 (2, 15) 9×1 `--shutter-gap`, 글자 `퇴근` `fontSize 3.5` 가운데 `--ink`(휴업 셔터 팻말과 같은 색).
- 모니터는 꺼짐(`screenOff`), 말머리 없음.
- 이름표 `--muted`.
- aria-label: `{이름}, 퇴근함. 출근시키기`.
- 퇴근 요청함(아직 끝나지 않음): 캐릭터는 그대로, 이름표 아래 줄 `.desk-status` 「안」 `퇴근 요청함`.

**구별:** 그냥 offline(세션 기록상 꺼짐)은 팻말 없는 빈 의자 그대로입니다. 팻말은 "사용자가 퇴근시킨 자리"만.

### 2.5 오래 쉬는 중

마지막 활동이 1시간 넘은 팀원(자동 퇴근 없음): 말머리 `z z` 그대로, 이름표 아래 `.desk-status` 「스펙」 `오래 쉬는 중` 10px `--muted`. 퇴근함·퇴근 요청함·퇴사 진행 중이면 그 줄이 대신합니다(한 줄만).

### 2.6 이름표 아래 한 줄 자리 `.desk-extra`

**모든 책상에 늘 둡니다(비어 있어도).** 줄이 있는 책상만 그 높이만큼 위로 밀려(`.desks`는 `align-items:flex-end`) 책상 바닥선이 어긋났습니다(정적 렌더에서 확인). `display:block; height:14px; line-height:14px; overflow:hidden; font-size:10px`. 서브에이전트 임시 책상에는 두지 않습니다.

이 자리에 들어가는 것은 하나뿐입니다: 리드는 `결재 {n}` 칩(§2.2), 팀원은 아래 `.desk-status`.


| 우선 | 글자 | 색 |
|---|---|---|
| 1 | 「안」 `인수인계 쓰는 중` (퇴사 진행 중, 메모 도착 전) | `--pink` |
| 2 | 「안」 `퇴근 요청함` | `--muted` |
| 3 | 「스펙」 `오래 쉬는 중` | `--muted` |

`.desk-status`: `font-size:10px; line-height:14px; max-width:92px; white-space:nowrap; overflow:hidden; text-overflow:ellipsis`(이름표·메타 줄과 같은 폭 규칙).

### 2.7 ask_user (kind `chat`)

기존 결정 표시 그대로(손들기 + 노란 ?, 노란 이름표, 60초 이하 급함은 없음 — `chat`은 시간 제한이 없으므로 `deadline` 없음). 결정 칩 수에 들어갑니다(HUD `결정 대기 {n}`). 누르면 결정 보고서 서랍이 §4 답 칸으로 열립니다.

## §3 서류철 서랍 (`ReportFolder`)

결정 보고서와 같은 서랍(`.rp`), 왼쪽 테두리 4px `--folder`. `aria-labelledby="rf-title"`. 한 번에 하나(phase3 §7.1).

### 3.1 머리

| 요소 | 값 |
|---|---|
| 종류 칩 | 「안」 `서류철` (`.rp-chip` 모양, 색 `--folder`) |
| 제목 | `{층 이름}` 17px 700 (`#rf-title`, `tabindex=-1`) |
| 보조 줄 | 「안」 `대기 {n} · 모두 {m}` 11px `--muted` |
| ‹ | 본문(§3.3)을 보고 있을 때만 — 목록으로. aria-label 「안」 `목록으로` |
| × | 닫기 |

### 3.2 목록

최신 먼저. 행 하나(`.rf-row`, 버튼 — 누르면 §3.3):

```
┌─────────────────────────────────────────────┐
│ [대기]  이번 주 진행 보고                     │  도장 칩 + 제목(14px --font-text, 2줄까지)
│         보고서 · 10-21 14:05                  │  종류 · 받은 시각 (11px --muted)
└─────────────────────────────────────────────┘
```

- 격자: `grid-template-columns: 64px minmax(0,1fr); grid-template-rows: auto auto`(FB-6 행·열 명시). 도장 열을 `max-content`로 두면 행마다 도장 폭이 달라 제목 시작점이 들쭉날쭉했습니다(렌더 확인) — 가장 긴 `수정 요청`이 들어가는 64px로 고정. 도장 `grid-column:1; grid-row:1 / 3; align-self:start; justify-self:start`, 제목 `2 / 1`, 보조 `2 / 2`.
- 행 사이 1px 점선 `--desk`. 호버 테두리 없음, 배경 `--pick`.
- 제목 2줄 넘으면 말줄임(`-webkit-line-clamp: 2`). 본문에서는 전부 보입니다.
- 인수인계 행: 종류 「안」 `인수인계 · {팀원 이름}`.

**도장 칩** `.rf-stamp`(11px, 2px 테두리, 여백 `0 6px`, 글자·테두리 같은 색):

| 상태 | 글자 「안」 | 색 |
|---|---|---|
| 대기 | `대기` | `--yellow` |
| 승인됨 | `승인됨` | `--green` |
| 수정 요청 | `수정 요청` | `--pink` |
| 인수인계 · 아직 시작 안 함 | `대기` | `--yellow` |
| 인수인계 · 새 팀원 시작함 | `시작함` | `--green` |

### 3.3 본문 (종이)

```
│ [‹] [×]                                       │
│ [대기]  이번 주 진행 보고                       │  제목 17px 700, overflow-wrap:anywhere
│ team-lead · 10-21 14:05                        │
│ ┌ 종이 --paper ───────────────────────────┐   │
│ │ ## 한 일                                 │   │  본문: pre-wrap, --font-text 13px/1.7, --wall
│ │ - 로그인 화면 고침                        │   │  마크다운 기호 그대로
│ │ …                                        │   │
│ └──────────────────────────────────────────┘   │
├────────────────────────────────────────────────┤
│ [수정 사항 적기]                     [승인]      │  아래 고정(.ap-foot 틀)
```

- 종이 `.rf-paper`: 배경 `--paper`, 글자 `--wall`, 여백 14px 16px, 아래 그림자 `0 4px 0 var(--slab)`, `white-space: pre-wrap; word-break: break-word; overflow-wrap: anywhere`. 높이 제한 없음(서랍 스크롤). 64KB 본문도 그대로(자르지 않음).
- 종이 오른쪽 위 도장(결재 뒤): 승인됨이면 `승인` 글자를 2px `--green` 테두리 사각 안에 `rotate(-8deg)`, 수정 요청이면 `--pink` `수정 요청`. 대기면 없음. `aria-hidden`(상태는 칩이 말함).
- **아래 고정 영역** `.rf-foot`(`.ap-foot` 값):
  - 대기: `[수정 사항 적기]`(`.pbtn`) 왼쪽, `[승인]`(`.pbtn pbtn--primary`) 오른쪽(`margin-left:auto`).
  - 승인됨·수정 요청: 버튼 없이 한 줄 「안」 `{시각}에 승인했습니다` / `{시각}에 수정을 요청했습니다` `--muted`.
  - channel 없음: 버튼 둘 `aria-disabled` + 위 줄 §1.2 이유(`옮겨 열기로 연결하면 쓸 수 있습니다` 등).
- `[승인]`: 확인 없이 보냄 → 성공하면 칩·도장이 바뀌고 `announce` 「안」 `승인을 팀리더에게 전했습니다`.

### 3.4 수정 사항 적기

`[수정 사항 적기]`를 누르면 아래 고정 영역이 펼쳐집니다(서랍 안, 모달 아님):

```
│ 수정 사항                                (0/4,000) │
│ ┌───────────────────────────────────────────────┐ │  textarea 4줄, --slab, 2px --desk, 포커스 --cyan
│ └───────────────────────────────────────────────┘ │
│ [취소]                              [수정 요청 보내기] │
```

- 라벨 「안」 `수정 사항`, 글자 수 `({n}/4,000)`(4,000 = 「스펙」 상한, 넘으면 `--red` + 보내기 비활성).
- 빈 글이면 보내기 비활성(`aria-disabled`).
- `[수정 요청 보내기]` `.pbtn pbtn--deny`(분홍). 성공 → 칩 `수정 요청`, 영역 닫힘, `announce` 「안」 `수정 사항을 팀리더에게 전했습니다`.
- Esc: 영역만 닫고 포커스 `[수정 사항 적기]`.

### 3.5 인수인계 본문

종류가 인수인계면 제목 「안」 `{팀원 이름} 인수인계`, 종이에 메모 그대로. 아래 고정:

- 아직 시작 안 함: `[새 팀원 시작]`(`.pbtn pbtn--primary`, 아이콘 `plus`) 하나 + 위 줄 「안」 `같은 이름으로 새 팀원을 띄우고 이 메모를 첫 지시로 줍니다` 12px `--muted`.
- 시작함: 「안」 `{시각}에 새 팀원을 시작했습니다`.

### 3.6 빈 서류철

목록 자리에 「안」 `아직 받은 보고서가 없습니다. 팀리더에게 [보고 요청]을 보내 보세요.` (`.rp-empty`).

### 3.7 보관 한도

목록 맨 아래 10px `--muted` 「안」 `층마다 최근 50개까지 보관합니다` (「스펙」 5장 숫자 — Global Constraints "숫자는 스펙에만": 이 줄을 넣을지 director 판정, §10).

## §4 답 칸 (`ReplyDialog`) — 결정 보고서 서랍 안

ask_user(kind `chat`)와 답을 기다립니다(Stop 대체)는 **같은 서랍 같은 모양**이고 머리만 다릅니다.

| | ask_user | 답을 기다립니다 |
|---|---|---|
| 서랍 테두리 | `--yellow`(결정) | `--await` |
| 종류 칩 | 「안」 `대화 질문` (노랑) | 「스펙」 `답을 기다립니다` (하늘) |
| 위쪽 시간 막대 | 없음(제한 시간 없음) | 없음 |
| 질문 글 | 도구 인자 `question` | 마지막 assistant 글(4,000자로 자름, 잘렸으면 끝에 「안」 `… (앞부분만 보입니다)` `--muted`) |
| 선택지 | `options`(최대 6) | 번호 목록에서 뽑은 것(최대 6, 없으면 선택지 줄 없음) |

### 4.1 본문

```
│ [대화 질문]                              [×]      │
│ team-lead                                        │
├──────────────────────────────────────────────────┤
│ ┌ --slab, 왼쪽 2px 노랑 ──────────────────────┐   │  .rp-quote 모양, pre-wrap
│ │ 배포를 오늘 할까요, 내일 할까요?              │   │
│ └─────────────────────────────────────────────┘   │
│ 고르기                                            │
│ [오늘 배포]  [내일 배포]  [보류]                    │  선택지 버튼 .pbtn, flex-wrap, 높이 32px
│ 직접 답하기                              (0/4,000) │
│ ┌──────────────────────────────────────────────┐  │  textarea 3줄
│ └──────────────────────────────────────────────┘  │
├──────────────────────────────────────────────────┤
│                                     [보내기]       │  아래 고정, pbtn--primary
```

- 선택지 버튼은 **누르면 바로 보내지 않습니다.** 고른 버튼은 `aria-pressed="true"` + 배경 `--pick` + 테두리 `--yellow`(답을 기다립니다는 `--await`). 다시 누르면 해제. 자유 답 칸에 글이 있으면 선택지와 함께 보냅니다(틀: 고른 것 + 덧붙인 말 — 서버 틀이 정함).
- 선택지 글이 길면(200자) 버튼 안에서 줄바꿈(`white-space: normal; text-align:left; height:auto; min-height:32px; padding:6px 10px`).
- `[보내기]`: 고른 것도 글도 없으면 `aria-disabled`. Enter = 줄바꿈(textarea), Ctrl/⌘+Enter = 보내기(InstructDialog와 같게 — 확인 필요 §10).
- 성공: 서랍을 닫고 포커스는 그 책상, `announce` 「안」 `답을 팀리더에게 전했습니다`. 책상 표시는 서버가 다음 이벤트에서 지웁니다(「스펙」 4장).
- 실패: 아래 고정 영역 위 `--red` `role="alert"`, 서랍은 그대로(쓴 글 보존).

### 4.2 channel 없는 층

질문 글은 그대로 보여 주고, 선택지·답 칸·[보내기]를 `aria-disabled`(흐리게 `opacity:.4`). 아래 고정 영역에 「스펙」 `터미널에서 답하거나, 옮겨 열기로 연결하세요` (`--font-text` 13px `--ink`, 왼쪽 2px `--await` 막대).

### 4.3 터미널에서 먼저 답했을 때

서랍이 열려 있는 동안 표시가 사라지면(다음 UserPromptSubmit/PreToolUse) 결정 보고서의 "이미 답함" 띠(phase2 `.rp-banner.green`)를 다시 씁니다: 「안」 `터미널에서 답했습니다`, 입력은 잠김(`locked`).

## §5 퇴사 확인 창 (`RetireDialog`)

종료 확인 창 `.dlg.td`(phase4a §3.1) 그대로: `<dialog>.showModal`, 분홍 테두리, Esc = 취소, 열릴 때 포커스 `[취소]`.

```
┌ 4px --pink ─────────────────────────────────┐
│ designer 퇴사                                │  .dlg-title 「안」 `{이름} 퇴사`
│                                             │
│ designer의 기억은 새 팀원에게 이어지지 않고,     │  .td-body 「스펙」 7장 1번
│ 인수인계 메모만 넘어갑니다. 대화 기록은           │
│ 지우지 않습니다.                               │
│                                             │
│ 팀리더가 메모를 받아 서류철에 올리면, 거기서       │  .dlg-help 「안」
│ [새 팀원 시작]을 누를 수 있습니다.              │
│                                  [취소] [퇴사 진행] │  [퇴사 진행] .pbtn pbtn--deny
└─────────────────────────────────────────────┘
```

- 본문 이름 자리 `{이름}`은 그대로 넣습니다(따옴표 없음). 「스펙」 문장: `X의 기억은 새 팀원에게 이어지지 않고, 인수인계 메모만 넘어갑니다. 대화 기록은 지우지 않습니다.` — 한국어 조사 `의`는 이름 뒤에 붙입니다(영문 이름도 같음).
- 보내는 중: `[퇴사 진행]` → 「안」 `보내는 중…` + `aria-busy`. 성공 → 창 닫힘, 포커스 그 책상, 책상 줄 §2.6 `인수인계 쓰는 중`, `announce` 「안」 `퇴사를 팀리더에게 전했습니다`.
- 실패: `.dlg-err` `role="alert"`(종료 창과 같음).
- channel 없으면 `[퇴사]` 버튼 자체가 비활성(§1.2)이라 이 창은 열리지 않습니다.

## §6 전임자 서랍

층 방(`.room`) 안, 책상 줄(`.desks`) 아래가 아니라 **층 머리 바로 아래 한 줄**에 두면 방 높이를 바꾸므로, **방 오른쪽 아래 모서리**에 `<details class="predecessors">`를 둡니다(방은 `align-items:flex-end`인 flex — `margin-left:auto`로 오른쪽 끝, 책상 줄과 같은 바닥선).

```
                                         ▸ 전임자 2
펼치면:
                                         ▾ 전임자 2
                                           designer · 퇴사 10-21 14:05
                                           qa · 퇴사 10-20 09:12
```

- `summary`: 아이콘 `fold`(접힘이면 오른쪽 향함 — 기존 층 접기와 같은 아이콘을 90° 돌림) + 「안」 `전임자 {n}` 11px `--muted`. 포커스 링 기존 규칙.
- 펼친 목록: `--panel` 바탕, 2px `--desk` 테두리, 여백 6px 8px, 줄마다 11px `--ink` `{이름} · 퇴사 {MM-DD HH:mm}`, 최대 높이 8줄 후 스크롤. 펼친 목록은 방 위로 겹치게 `position:absolute; right:0; bottom:100%`(방 높이를 바꾸지 않음).
- 이름·시각만(「스펙」 7장 4번). 누를 것 없음.
- 전임자가 없으면 그리지 않습니다.
- 휴업 셔터가 내려와도 셔터 아래(z-index 셔터보다 낮음) — 휴업 중엔 보이지 않습니다.

## §7 좁은 화면·키보드·움직임

### 7.0 한글 문장 줄바꿈

서류철 제목·종이·안내 줄, 답 칸 질문·선택지, 퇴사 창 보조 줄은 `word-break: keep-all; overflow-wrap: anywhere`(phase3 B105와 같은 규칙). 렌더에서 `결제 테스|트`, `쿠폰 경우까|지`, `[새 팀원 시|작]`처럼 낱말 가운데서 꺾였습니다. 띄어쓰기 없는 긴 값은 그래도 꺾입니다(종이 안 긴 낱말 렌더 확인).

### 7.1 360폭

- 서랍들은 기존 규칙(≤720px 아래 시트, `top:8vh; width:100vw`).
- 지시 절 버튼: 두 개가 한 줄(가장 긴 `[서류철 · 대기 12]` + `[보고 요청]` ≈ 250px < 328px).
- 서류철 목록 행: 격자 그대로(도장 열 max-content).
- 답 칸 선택지: 줄바꿈되며 한 줄에 2–3개.
- 퇴사 창: `.dlg` `min(420px, 100vw - 32px)` 그대로.
- 책상: 96px 그대로, `.desk-folder`·`.desk-status`는 92px 안에서 말줄임.
- 전임자 서랍: 방 오른쪽 아래, 펼친 목록 폭 `min(240px, 100vw - 48px)`.

### 7.2 키보드

| 곳 | Tab 순서 / 키 |
|---|---|
| 지시 절 | 버튼 순서대로(비활성도 포커스됨), 이유 줄은 `aria-describedby` |
| 서류철 목록 | ‹(없음) → × → 행들 → (빈 안내엔 컨트롤 없음). 행은 `button` |
| 서류철 본문 | ‹ → × → (종이는 `tabindex=0`, 긴 글 키보드 스크롤) → [수정 사항 적기] → [승인] |
| 수정 사항 영역 | textarea → [취소] → [수정 요청 보내기]. Esc = 영역 닫기 |
| 답 칸 | × → 질문 글(`tabindex=0`) → 선택지들 → textarea → [보내기] |
| 퇴사 창 | [취소](처음) ↔ [퇴사 진행], Esc = 취소 |
| 전임자 | `summary` Enter/Space |

- 포커스: 서랍 열 때 제목(`#rf-title`, 답 칸은 질문 글), 닫을 때 연 요소(책상 또는 지시 절 버튼). 서류철에서 행을 누르면 본문 제목, ‹로 돌아오면 그 행.
- **Esc 순서:** 말풍선 → 수정 사항 영역 → 서랍.

### 7.3 움직임

새 애니메이션 없음. 도장도 정적(회전만). `prefers-reduced-motion` 전역 규칙 그대로.

## §10 director 확인용 (지시서·스펙과 다르게 정한 것)

1. **버튼 자리:** 「스펙」은 "팀리더 책상에 [보고 요청]", "팀원 책상에 [퇴근]"이라 했지만, 책상은 이미 하나의 버튼(누르면 에이전트 패널·결정 보고서)이라 그 안에 버튼을 더 넣을 수 없습니다(버튼 안 버튼 금지). 책상을 누르면 열리는 에이전트 패널의 맨 위 "지시" 절에 둡니다. 책상에는 표시(서류철·상태 줄·팻말·말머리)만.
2. **서류철 여는 길:** 리드 패널의 `[서류철 · 대기 n]` 하나. HUD에 따로 버튼을 두지 않습니다. 결재 대기를 HUD `결정 대기` 수에 넣을지는 정하지 않았습니다(지금 안: 넣지 않음 — 결정 칩은 시간 제한 있는 결정용).
3. **ask_user는 결정 칩 수에 들어갑니다**(kind `chat` 결정이라). "답을 기다립니다"는 결정이 아니라 칩 수에 넣지 않습니다.
4. **선택지 버튼은 바로 보내지 않음**(고른 뒤 [보내기]) — 실수 방지. 바로 보내기가 필요하면 판정.
5. **§3.7 보관 한도 줄**은 숫자를 화면에 적습니다(Global Constraints "판정 메시지에 숫자를 따로 쓰지 않는다"는 서버 판정 문구 이야기로 읽었지만, 넣지 않는 쪽이 더 안전하면 뺍니다).
6. **퇴근 팻말**은 사용자가 퇴근시킨 자리만. 그냥 꺼진(offline) 책상과 구별.
7. **전임자 서랍**은 방 오른쪽 아래(방 높이를 바꾸지 않으려고). 층이 접히면 함께 숨습니다.
