| 필요한 것 | 다시 쓰는 것 |
|---|---|
| 지시 버튼 자리 | 에이전트 패널(phase3 §1, 책상을 누르면 열리는 보라 서랍)의 새 절 |

## §0 새 토큰과 아이콘

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `--folder` | `var(--green)` | 서류철 서랍 왼쪽 테두리, 서류철 버튼 아이콘, 승인됨 도장 |
| `--paper` | `#f4f0dc` | 보고서 종이 배경(글자는 `--wall`) |
| `--await` | `var(--cyan)` | "답을 기다립니다" 말머리·이름표 밑줄 |

- 결재 대기는 사용자의 결정이므로 **노랑**(결정 색), 승인은 **초록**, 수정 요청은 **분홍**입니다. 서랍 테두리는 초록(노랑 결정 보고서·하늘 진단·보라 에이전트 패널과 구별).
- 새 아이콘(7×7, `ICONS`, 아이콘 수 +2):

```ts
folder: ["xxx....", "x..xxxx", "x.....x", "xxxxxxx", "x.....x", "x.....x", "xxxxxxx"],   // 서류철
door:   ["xxxxxxx", "x.....x", "x.....x", "x...a.x", "x.....x", "x.....x", "xxxxxxx"],   // 퇴근(a = 손잡이, accent는 글자색 그대로)
```

- 책상에 그리는 작은 서류철 `FOLDER_DESK`(4×4, 책상 SVG 도트 1칸 = 4px. 자리는 §2.2):

```ts
export const FOLDER_DESK = ["xx..", "xxxx", "xaax", "xxxx"];   // x 표지, a 종이
```

  색: `x` = `--yellow`(대기 있음) / `--muted`(대기 없음, 보고서만 있음), `a` = `--paper`.

- 퇴근 팻말 `OFFDUTY_SIGN`: 책상 SVG 안 사각 + 글자(§2.4).

## §1 에이전트 패널의 "지시" 절

에이전트 패널(phase3 §1)의 스크롤 영역 **맨 위**에 절 하나를 더합니다. 이 층이 지금 보이는 층이고, 대상이 그 층의 **리드 또는 팀원**일 때만 둡니다(서브에이전트·그 밖의 모든·목록에서 연 화면에 없는 이름에는 없음).

```
┌ 4px --policy ─────────────────────────────────────┐
│ [아바타] [리드]                         [×]        │
│          team-lead                                │
├───────────────────────────────────────────────────┤
│ 지시                                               │  ← 새 절 .ap-cmd (h3 11px --muted)
│ [▤ 보고 요청]  [▤ 서류철 · 대기 2]                  │  리드
│ 작업 지시 켜기(옮겨 열기)로 연결하면 쓸 수 있습니다   │  비활성 이유 (있을 때만)
│ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ │
│ 모델·토큰 …  (기존 절)                              │
```

### 1.1 버튼

| 대상 | 버튼(순서대로) | 모양 |
|---|---|---|
| 리드 | `[보고 요청]` `[서류철 · 대기 {n}]` | `.pbtn` 높이 32px, 아이콘 14px(`send`, `folder`) |
| 팀원 · 일하는 중/쉬는 중 | `[퇴근]` `[퇴사]` | `[퇴근]` `.pbtn`(아이콘 `door`), `[퇴사]` `.pbtn pbtn--danger`(분홍 글자, 아이콘 없음) |
| 팀원 · 퇴근함 | `[출근]` `[퇴사]` | `[출근]` `.pbtn`(아이콘 `play`) |
| 팀원 · 퇴근 요청함(아직 안 끝남) | `[퇴근 요청함]`(누를 수 없음) `[퇴사]` | `aria-disabled="true"`, 이유 줄 없음(상태 자체가 이유) |
| 팀원 · 퇴사 진행 중 | `[퇴사 진행 중]`(누를 수 없음) | 다른 버튼 없음. 대시보드를 다시 켠 뒤 그 층이 아직 연결되지 않았으면 버튼 아래 이유 줄 「스펙」 `연결되면 이어 갑니다`(12장 m, `--muted`) |

- `[서류철 · 대기 {n}]`: 대기 0이면 `[서류철]`(보고서가 하나도 없어도 둡니다 — 빈 서류철 안내 §3.5). 서류철은 channel이 없어도 **열 수 있습니다**(읽기). 결재 버튼만 비활성(§3.3).
- 버튼 줄: `display:flex; flex-wrap:wrap; gap:8px`. 360폭에서 두 버튼이 한 줄에 들어갑니다(렌더 확인).
- 리드 패널에는 `[퇴근]`·`[퇴사]`가 없습니다(리드는 필수 소통 창구, 「스펙」 1장).

### 1.2 비활성과 이유 줄

| 층 상태 | 지시 버튼 | 이유 줄 |
|---|---|---|
| 대시보드가 띄운 층이 아님(터미널에서 연 층) | 비활성 | B312 `작업 지시 켜기(옮겨 열기)로 연결하면 쓸 수 있습니다` (「스펙」 8장 대표 글에 실제 버튼 이름 `작업 지시 켜기`를 앞에 붙임) |
| 띄웠지만 channel 연결 없음 | 비활성 | 기존 `CH_TEXT.notConnected` 그대로 |
| 휴업(멈춤) | **활성** — 누르면 보관(held)에 들어감. **종류와 대상마다 하나**만 보관합니다(「스펙」 12장 l): 결재는 보고서마다 하나(같은 보고서의 승인·수정 요청은 서로 대신함), 퇴근·출근·퇴사·새 팀원은 팀원마다 하나(퇴근·출근은 서로 대신함), 답은 질문마다 하나, 보고 요청은 층마다 하나 | 기존 `CH_TEXT.instructPaused` 그대로 `휴업 중이라 보관했다가, 재개할 때 확인하고 보냅니다.` (B319 ①, `--muted`) |
| 연결됨 | 활성 | 없음 |

- 비활성은 `disabled`가 아니라 `aria-disabled="true"` + `aria-describedby`(이유 줄 id). 포커스가 머물고 이유가 읽힙니다(phase4a §1.4와 같은 이유).
- 이유 줄: `--font-text` 12px `--muted`, 위 여백 6px, `word-break: keep-all; overflow-wrap: anywhere`.

### 1.3 누른 뒤

- `[보고 요청]`·`[퇴근]`·`[출근]`: 확인 창 없이 바로 보냅니다(되돌릴 수 있는 일). 보내는 동안 그 버튼 `aria-busy="true"` + 글자 `보내는 중…`(phase4a 1.2와 같은 규칙).
- 성공: 버튼 아래 한 줄(이유 줄 자리) 「안」 `리드에게 보냈습니다` 초록, 5초 뒤 사라짐 + `announce`. 휴업이면 「안」 `보관했습니다 — 재개할 때 확인하고 보냅니다`. 기존 지시 알림(`{name} 층에 지시를 보냈습니다`)과 같은 동사 "보냈습니다"·같은 호칭 "리드"를 씁니다(화면 어디에도 "팀리더"는 없음).
- "퇴근 요청함"(책상 줄·버튼)은 보관할 때가 아니라 **실제로 보냈을 때** 생깁니다(「스펙」 11장 a). 휴업 중 [퇴근]을 눌러도 재개 전까지 버튼은 `[퇴근]` 그대로입니다.
- 실패: 같은 자리 `--red` `role="alert"`. 409 not-connected → `CH_TEXT.notConnected`, 그 밖 → 기존 `CH_TEXT.failed` 그대로 `처리하지 못했습니다. 서버 연결을 확인하고 다시 시도해 주세요.`(새 글자를 만들지 않음).
- `[보고 요청]`을 보낸 뒤 10분 동안 보고서가 오지 않으면(「스펙」 10장) 리드 패널 지시 절에 「안」 `보고 요청 뒤 10분 넘게 답이 없습니다` (`--yellow`, 다음 보고서가 오면 사라짐). 책상에는 표시하지 않습니다(책상 표시 과잉 방지).
- `[퇴사]` → §5 확인 창.

### 1.4 재개 브리핑에 보이는 lead 지시 (개선안, 판정은 리뷰 뒤)

휴업 중 보관된 lead 지시는 재개 브리핑(Phase 4b) 목록에 일반 작업 지시처럼 보이는데, 지금은 틀 머리말 `[대시보드 지시 r-…]`까지 든 **틀 전체 글**이 보입니다. 사용자가 쓴 글이 아니라 서버 틀이라 무엇을 보내는지 알아보기 어렵고, 고칠 수 있는 칸처럼 보입니다.

- 안: 목록에서는 kind별 짧은 이름표만 보입니다 — 「안」 `리드: 보고 요청` / `리드: 승인 — {보고서 제목}` / `리드: 수정 요청 — {보고서 제목}` / `리드: {질문자 이름}의 질문에 답`(qa: "답 — 이름"은 누가 답했는지 헷갈림, W21a와 같은 말) / `리드: 퇴근 — {팀원}` / `리드: 출근 — {팀원}` / `리드: 퇴사 — {팀원}` / `리드: 새 팀원 — {팀원}`. 사용자가 쓴 글(수정 사항·답)이 있으면 둘째 줄에 그 글만(2줄 말줄임). 틀 글은 보이지 않습니다.
- lead 지시 행은 고치기(편집)를 두지 않고 지우기만 둡니다(틀이라 고칠 것이 없음, 사용자 글은 원래 창에서 다시 쓰면 됨).
- 제목·이름은 글자로만 그립니다.
- **보관된 답(reply)을 지우면** 그 질문 표시는 "보관됨"(§2.3a)에서 다시 **열림**(답할 수 있음)으로 돌아갑니다. 보내지 않았는데 "보관됨"이 남으면 사실과 다릅니다(qa, developer 몫).
- 기존 브리핑 글자 `CH_TEXT.briefMemory` `보관한 지시는 대시보드가 켜져 있는 동안만 남습니다.`는 lead 지시·보관한 답에도 그대로 맞습니다(developer 확인, 4c8e70d): 모두 메모리라 서버를 다시 켜면 사라지고, 그때 질문 표시도 "열림"이 아니라 **표시 자체가 없어집니다**. 보관한 답을 지우면 "열림"으로 돌아가는 것은 4c8e70d에 들어감.

## §2 책상 표시

책상 SVG(viewBox `0 0 24 30`)와 이름표 아래 줄에 더합니다. 기존 자리: 말머리·? x 1–12 y 0–8, 자물쇠 (18, 3)/(16, 3), 캐릭터 x 2–9 y 9–20, 모니터 x 12–19 y 11–16, 받침 x 15–16 y 17–18, 책상판 y 19–20.

### 2.1 우선순위 (말머리 자리)

결정 대기(? · ask_user 포함) → 답을 기다립니다(§2.3) → 정책으로 막힘 말풍선 줄(phase3 §6.3) → 기존 상태 말머리.

**질문이 붙는 책상(「스펙」 11장 b, 12장 e):** ask_user는 그 도구를 부른 에이전트의 책상에 붙습니다 — 팀원이 불렀으면 그 팀원 책상, 서브에이전트가 불렀으면 그 서브에이전트를 띄운 책상(리드 또는 팀원, 기존 결정 표시와 같은 규칙), hook 없이 제출만 왔으면 리드 책상. "답을 기다립니다"(Stop 대체)는 리드 책상에만 붙습니다(팀원·서브에이전트의 Stop은 판정하지 않음).

**한 책상에 질문 하나:** 새 질문이 오면 옛 질문은 지나간 것으로 처리하고 책상에는 새 질문만 보입니다. 지나간 질문이 열려 있던 답 칸은 §4.3처럼 잠깁니다.

**지우는 때(「스펙」 12장 k — 11장 c·12장 e를 고침):** 둘이 다릅니다. **ask_user 질문**(손들기 + ?)은 대시보드에서 답을 보냈을 때, 또는 리드 본인이 터미널에 글을 쳤을 때(UserPromptSubmit)만 지웁니다 — 리드가 다른 도구를 써도 남습니다. **답을 기다립니다**(Stop 대체)는 리드 본인이 다시 움직이면(UserPromptSubmit·PreToolUse) 지웁니다. 둘 다 대시보드 답은 **바로** 지우고, 팀원·서브에이전트의 이벤트로는 지우지 않습니다.

**누르면(책상 버튼):** 결정 대기 → 결정 보고서(ask_user면 §4 답 칸) · 답을 기다립니다 → 같은 서랍의 §4 답 칸 · 그 밖 → 에이전트 패널(§1).

### 2.2 서류철 (리드 책상)

- 보고서·인수인계가 하나라도 있으면 `FOLDER_DESK`(§0의 4×4 맵)를 **(20, 15)**에 그립니다. x 20–23 y 15–18 — 모니터(x ≤ 19)의 오른쪽, 책상판(y 19) 바로 위에 놓인 모양입니다.

- 이름표 아래 한 줄 자리(`.desk-extra`, §2.6)에 대기가 있을 때만 「안」 `결재 {n}` 칩 `.desk-folder` — 10px, `--wall` 글자에 `--yellow` 배경, 여백 `0 4px`, `line-height:14px`. 대기 0이면 비어 있습니다(서류철 그림만).
- 책상 aria-label 덧붙임: 「안」 `, 결재 대기 {n}건`.

### 2.3 답을 기다립니다 (Stop 대체 경로)

`member.awaitingReply`가 있으면:

- 말머리를 `--await` 바탕의 말머리로 바꿉니다: 기존 `StatusBubble` 틀(12×7 + 꼬리 2×1)에 바탕 `--cyan`, 글자 `· · ·`(점 셋 = 「스펙」의 "파란 점"), 글자색 `--wall`. **손은 들지 않고 ?도 없습니다**(「스펙」 4장).
- 이름표에 2px `--await` 밑줄(노란 이름표는 결정 대기 전용).
- 말풍선(호버·포커스) 첫 줄: 「스펙」 `답을 기다립니다`, 둘째 줄: 마지막 글의 첫 줄(60자, phase1 말풍선 자르기 규칙).
- 책상 aria-label: `{이름}, 답을 기다립니다. 답하기 열기`.
- 깜빡이지 않습니다.

### 2.3a 보관됨 (휴업 중에 보낸 답, B309·「스펙」 12장 e)

휴업 중 대시보드에서 답하면 답은 보관(held)되고, 질문 표시는 **"보관됨"** 상태로 남았다가 재개 때 실제로 보내지면 사라집니다.


- **선택지 글은 모델이 쓴 것입니다**(「스펙」 12장 a): 답에는 고른 글이 아니라 `선택지 N번`만 실립니다. 그래서 절 제목을 「안」 `제안된 선택지`로, 바로 아래 「안」 `질문한 쪽이 쓴 선택지입니다. 고르면 번호만 보냅니다`를 두고, 버튼 글 앞에 번호 `{N}. `을 붙여 무엇이 전해지는지 보이게 합니다. 사용자가 자기 말을 전하려면 아래 "직접 답하기"에 씁니다.
- 선택지 버튼은 **누르면 바로 보내지 않습니다.** 고른 버튼은 `aria-pressed="true"` + 배경 `--pick` + 테두리 `--yellow`(답을 기다립니다는 `--await`). 다시 누르면 해제. 자유 답 칸에 글이 있으면 선택지 번호와 함께 보냅니다(틀: `선택지 N번` + 사용자가 친 글 — 서버 틀이 정함).
- 선택지 글이 길면(200자) 버튼 안에서 줄바꿈(`white-space: normal; text-align:left; height:auto; min-height:32px; padding:6px 10px`).
- `[보내기]`: 고른 것도 글도 없으면 `aria-disabled`. Enter = 줄바꿈(textarea), Ctrl/⌘+Enter = 보내기(InstructDialog와 같게 — 확인 필요 §10).
- 성공: 서랍을 닫고 포커스는 그 책상, `announce` 「안」 `답을 리드에게 보냈습니다`. 책상 표시는 **보내는 즉시** 사라집니다(「스펙」 11장 c — 대시보드에서 답을 보냈을 때 지움). 휴업 중이면 표시는 §2.3a "보관됨"으로 바뀌고 `announce` 「안」 `답을 보관했습니다 — 재개할 때 확인하고 보냅니다`.
- 실패: 아래 고정 영역 위 `--red` `role="alert"`, 서랍은 그대로(쓴 글 보존).

### 4.2 channel 없는 층

질문 글은 그대로 보여 주고, 선택지·답 칸·[보내기]를 `aria-disabled`(흐리게 `opacity:.4`). 아래 고정 영역에 「스펙」 4장 글에 버튼 이름을 붙인 「안」 `터미널에서 답하거나, 작업 지시 켜기(옮겨 열기)로 연결하세요`(B312와 같은 방식) (`--font-text` 13px `--ink`, 왼쪽 2px `--await` 막대).

### 4.3 터미널에서 먼저 답했을 때 · 새 질문이 왔을 때

서랍이 열려 있는 동안 표시가 사라지면(리드 본인의 다음 UserPromptSubmit/PreToolUse) 결정 보고서의 "이미 답함" 띠(phase2 `.rp-banner.green`)를 다시 씁니다: 기존 글자 그대로 `이미 터미널에서 답했습니다`(`web/report/text.ts` `conflictLine`), 입력은 잠김(`locked`).

같은 책상에 새 질문이 와서 열린 질문이 닫히면 띠 `.rp-banner.yellow` 「안」 `새 질문이 와서 이 질문은 닫혔습니다` + [새 질문 보기](`.pbtn`, 같은 서랍에서 새 질문으로 바뀜, 포커스는 질문 글). 입력은 잠김.

## §6 전임자 서랍

층 방(`.room`) 안, 책상 줄(`.desks`) 아래가 아니라 **층 머리 바로 아래 한 줄**에 두면 방 높이를 바꾸므로, **방 오른쪽 아래 모서리**에 `<details class="predecessors">`를 둡니다(방은 `align-items:flex-end`인 flex — `margin-left:auto`로 오른쪽 끝, 책상 줄과 같은 바닥선).

```
                                         ▸ 전임자 2
펼치면:
                                         ▾ 전임자 2
                                           일한 기간
                                           designer · 10-18 09:00 ~ 10-21 14:05
                                           qa · 10-19 10:30 ~ 10-20 09:12
```

- `summary`: 아이콘 `fold`(접힘이면 오른쪽 향함 — 기존 층 접기와 같은 아이콘을 90° 돌림) + 「안」 `전임자 {n}` 11px `--muted`. 포커스 링 기존 규칙.
- 펼친 목록: `--panel` 바탕, 2px `--desk` 테두리, 여백 6px 8px, 맨 위 10px `--muted` 「안」 `일한 기간`, 줄마다 11px `{이름}`(`--ink`, 길면 이름만 말줄임) + 8px + `{시작 MM-DD HH:mm} ~ {퇴사 MM-DD HH:mm}`(`--muted`, 줄지 않음). 목록은 2열 격자(`grid-template-columns: minmax(0,max-content) max-content`, 줄 `li`는 `display:contents`, 머리 `일한 기간`은 `grid-column:1 / 3`)라 시각이 세로로 맞습니다. 최대 높이 8줄 후 스크롤. 폭 `min(320px, 100vw - 48px)`. 첫 렌더에서 240px로 두었더니 퇴사 시각이 말줄임으로 잘렸습니다 — 시각은 자르지 않고 이름만 자릅니다.
- **B323 — 시작 시각이 없을 때:** `SessionView.predecessors`에 `startedAt`이 없는 항목은 시각 열에 「안」 `퇴사 {MM-DD HH:mm}`만 보입니다(같은 이름 구별은 퇴사 시각만으로도 됨). 목록의 모든 항목에 `startedAt`이 없으면 머리 줄도 `일한 기간` 대신 그리지 않습니다. 둘이 섞이면 머리 줄 `일한 기간`을 두고, 없는 항목만 `퇴사 {시각}`. 데이터는 `{ name, retiredAt, startedAt? }`(developer 7fd1f52 + startedAt는 구할 수 있을 때만).
- **새 팀원은 같은 이름**이라(「스펙」 11장 f) 이름만으로는 구별되지 않습니다. 그래서 퇴사 시각만이 아니라 **시작 시각부터** 적습니다(지금 책상의 같은 이름 팀원과 다른 사람임이 보이게). 같은 이름이 여러 번이면 줄이 여러 개입니다. 펼친 목록은 방 위로 겹치게 `position:absolute; right:0; bottom:100%`(방 높이를 바꾸지 않음).
- 이름·시각만(「스펙」 7장 4번, 시작 시각은 11장 f에 따라 더함). 누를 것 없음.
- 전임자가 없으면 그리지 않습니다.
- 휴업 셔터가 내려와도 셔터 아래(z-index 셔터보다 낮음) — 휴업 중엔 보이지 않습니다.

## §7 좁은 화면·키보드·움직임

### 7.0 한글 문장 줄바꿈

서류철 제목·종이·안내 줄, 답 칸 질문·선택지, 퇴사 창 보조 줄은 `word-break: keep-all; overflow-wrap: anywhere`(phase3 B105와 같은 규칙). 렌더에서 `결제 테스|트`, `쿠폰 경우까|지`, `[새 팀원 시|작]`처럼 낱말 가운데서 꺾였습니다. 띄어쓰기 없는 긴 값은 그래도 꺾입니다(종이 안 긴 낱말 렌더 확인).

### 7.1 360폭

- 서랍들은 기존 규칙(≤720px 아래 시트, `top:8vh; width:100vw`).
- 지시 절 버튼: 두 개가 한 줄(가장 긴 `[서류철 · 대기 12]` + `[보고 요청]` ≈ 250px < 328px).
- 서류철 목록 행: 격자 그대로(도장 열 max-content).
- 답 칸 선택지: 줄바꿈되며 한 줄에 2–3개.
- 퇴사 창: `.dlg` `min(420px, 100vw - 32px)` 그대로.
- 책상: 96px 그대로, `.desk-folder`·`.desk-status`는 92px 안에서 말줄임.
- 전임자 서랍: 방 오른쪽 아래, 펼친 목록 폭 `min(320px, 100vw - 48px)`.

### 7.2 키보드

## §10 director 확인용 (지시서·스펙과 다르게 정한 것)

1. **버튼 자리:** 「스펙」은 "팀리더 책상에 [보고 요청]", "팀원 책상에 [퇴근]"이라 했지만, 책상은 이미 하나의 버튼(누르면 에이전트 패널·결정 보고서)이라 그 안에 버튼을 더 넣을 수 없습니다(버튼 안 버튼 금지). 책상을 누르면 열리는 에이전트 패널의 맨 위 "지시" 절에 둡니다. 책상에는 표시(서류철·상태 줄·팻말·말머리)만.
2. **서류철 여는 길:** 리드 패널의 `[서류철 · 대기 n]` 하나. HUD에 따로 버튼을 두지 않습니다. 결재 대기를 HUD `결정 대기` 수에 넣을지는 정하지 않았습니다(지금 안: 넣지 않음 — 결정 칩은 시간 제한 있는 결정용).
3. **ask_user는 결정 칩 수에 들어갑니다**(kind `chat` 결정이라). "답을 기다립니다"는 결정이 아니라 칩 수에 넣지 않습니다.
4. **선택지 버튼은 바로 보내지 않음**(고른 뒤 [보내기]) — 실수 방지. 바로 보내기가 필요하면 판정.
5. ~~보관 한도 줄~~ — 뺌(B317 ④: 화면에 숫자를 적지 않음). 보관함 안내 문장으로 대신(§3.7, W14a).

**B317 판정:** ①②③⑤ 수용, ④ 숫자 줄 대신 보관함 안내 문장.
6. **퇴근 팻말**은 사용자가 퇴근시킨 자리만. 그냥 꺼진(offline) 책상과 구별.
7. **전임자 서랍**은 방 오른쪽 아래(방 높이를 바꾸지 않으려고). 층이 접히면 함께 숨습니다. 같은 이름이라 시작~퇴사 기간을 적습니다(「스펙」 11장 f).
8. **보관됨(휴업 중 답):** 휴업 층은 셔터로 책상이 가려지므로 책상 그림은 바꾸지 않고, 셔터의 `결정 {n}건` 수에서 빼고 답 칸 띠로 알립니다(§2.3a).
9. **선택지 번호:** 버튼 글 앞에 `{N}. `을 붙입니다. 답에 실리는 것이 번호뿐이라(「스펙」 12장 a) 무엇이 전해지는지 보이게 하려는 것입니다.
10. ~~W4~~ — B319 ① 확정: 기존 CH_TEXT.instructPaused. "보내다"가 든 휴업 글자(W5·W11a·W26)는 B320으로 모두 "재개할 때 확인하고 보냅니다"(그냥 재개하면 보관된 채 남음).
11. **§11 PLAN 이유 줄:** 「스펙」 12장 f는 "Pro·Max나 지출 한도 gateway에서만 온다"를 이유로 들지만, 배포판은 아직 상태줄 연결(statusline tap)을 설치하지 않아(admin.md) 지금은 모든 계정에서 비어 있습니다. 이유 줄에 이 사실도 넣을지 판정 바랍니다(지금 안은 두 문장 모두 넣음).
