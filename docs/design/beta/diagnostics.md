# 베타 디자인: 진단 칩과 진단 패널, 사용설명서 그림 목록

- **기준 문서**
  - 동작의 기준은 이 문서이고, 값(px, 색, 문구)의 기준은 `diagnostics-mock.html`입니다. Phase 1과 같은 규칙입니다.
  - mock은 브라우저로 바로 열 수 있고, 위쪽 점선 상자에서 오류 유무, 패널 내용, 진단 파일 상태를 바꿔 볼 수 있습니다. 이 상자는 제품에 넣지 않습니다.
  - mock은 폰트를 CDN으로 불러오지만, 제품은 Phase 1 SPEC 3.1대로 번들에 포함된 Galmuri를 씁니다.
- **입력**
  - 데이터: `DiagnosticsSummary`(PLAN Task 5)
  - 따를 규칙: Phase 1 HUD와 결정 칩, 결정 보고서 서랍의 규칙(`docs/design/phase1/SPEC.md` 3장, 6장, 8장)
- **구현:** Task 10(developer). 구조와 클래스 이름은 결정 칩(`web/hud/DecisionChip.tsx`)을 따릅니다.

## 2. 진단 칩

| 항목 | 값 |
|---|---|
| 위치 | HUD 안, **결정 칩 바로 뒤, `● LIVE` 앞**입니다. 결정 칩이 없을 때도 같은 자리에 있습니다. **칩은 항상 보입니다.** |
| 요소 | `<button type="button" class="diag-chip" aria-haspopup="dialog" aria-expanded aria-controls="diag-panel">` |
| 크기 | 높이 26px(결정 칩과 같음), 여백 `0 10px 0 6px`, 아이콘과 글자 사이 6px, 글자 12px `--font-pixel` |
| 모양 | 배경 `--panel`, 글자 `--ink`, 테두리 `2px solid var(--desk)`, 그림자 `0 2px 0 var(--slab)`. 결정 칩과 달리 **채우지 않은 칩**이라, 노란 칩("지금 답해야 함")보다 덜 튀게 둡니다 |
| 아이콘 | `diag`(7×7, 14×14px, 9장), `currentColor` |
| 문구 | `진단` |
| 호버 / 열림 | 테두리 `--cyan`. 패널이 열려 있는 동안(`aria-expanded="true"`)도 `--cyan`을 유지합니다 |
| 누를 때 | `translateY(2px)`, 그림자 없음(Phase 1 도트 버튼과 같음) |
| **빨간 점** | 조건은 `errorsLastHour > 0`입니다. 8×8px 정사각형, `--red`, 칩 오른쪽 위 모서리에서 `top:-5px; right:-5px`에 둡니다. `box-shadow: 0 0 0 2px var(--panel), 0 0 6px var(--red)`로 칩 테두리와 분리하고 빛을 줍니다. **깜빡이지 않습니다.** 결정 LED의 깜빡임과 겹치지 않게 하려는 것입니다. `aria-hidden="true"` |
| aria-label | 오류가 없으면 `진단 열기`, 있으면 `진단 열기, 최근 1시간 오류 {N}건` |
| 갱신 | 패널이 닫혀 있어도 60초마다 `/api/diagnostics`를 가져옵니다(PLAN Task 10). 가져오기에 실패하면 점을 바꾸지 않고 마지막 값을 유지합니다 |
| 누르면 | 패널이 닫혀 있으면 열고, 열려 있으면 닫습니다(토글) |

## 3. 진단 패널

### 3.1 서랍

- `<aside id="diag-panel" class="diag-panel" role="dialog" aria-modal="false" aria-labelledby="dp-title">`
- `position: fixed; top:0; right:0; bottom:0; width: 440px; z-index: 50`, 배경 `--panel`, **왼쪽 테두리 4px `--cyan`**, 그림자 `-8px 0 0 rgba(11,10,23,.6)`
- 열리는 애니메이션은 `slide-in`(0.16초, steps(4))입니다. 결정 보고서와 같은 keyframes를 쓰고, 닫힐 때는 바로 닫습니다.
- 열 때 `GET /api/diagnostics`를 다시 가져옵니다(`useDiagnostics(open)`).

### 3.2 구조 (위에서 아래로)

```
┌ [diag 20px] 진단(17px 굵게)          14:32 확인  [↻][×] ┐  머리 (아래 테두리 2px --desk)
├──────────────────────────────────────────────────────────┤
│ [fail] 문제 1개를 찾았습니다              (15px 굵게, 색) │  판정
│ 최근 오류                                     (11px 흐림) │
│ 최근 1시간 오류 3건                   (13px, 숫자 --red)  │
│ 로그 폴더 ~/.claude-office/logs             (11px 흐림)  │
│ hook 수신                                                │
│ 최근 10분 5건, 마지막 수신 2분 전, 거부 0건              │
│ 점검 결과                                                │
│ ┌[fail] 회사 관리자 설정 ───────────── (2px --red) ┐     │
│ │       관리자 설정이 플러그인 hook을 막고 있습니다 │     │
│ │       고치는 법 사용설명서 부록 A를 …             │     │
│ └───────────────────────────────────────────────────┘     │
│ ┌[warn] 프록시 ─────────────────── (2px 점선 --yellow)┐   │
│ [ok] Node 버전                               v24.1.0     │  ok는 한 줄
│ 진단 파일                                                │
│ 문제가 생기면 이 파일을 만들어 담당자에게 보내 주세요. … │
│ [ 진단 파일 만들기 ]                                     │
└──────────────────────────────────────────────────────────┘
```

- **머리**: 여백 `12px 14px 10px`, 요소 사이 10px입니다.
  - 아이콘 `diag`는 20×20px, `--cyan`입니다.
  - 제목 `진단`은 `--font-text` 17px 700이고, `id="dp-title"`, `tabindex="-1"`입니다.
  - "`HH:MM` 확인"은 11px `--muted`, `margin-left:auto`이고, 마지막으로 가져온 시각입니다.
  - 버튼 두 개는 28×28이고 Phase 1의 `.icon-btn`과 같습니다. `다시 확인`(reload 아이콘)과 `닫기`(close 아이콘)입니다.
- **스크롤 영역**: 여백 `0 14px 16px`입니다. 각 절은 여백 12px 0이고, 절 사이에 1px 점선 `--desk`를 둡니다. 절 제목은 11px `--muted`이고 `<h3>`입니다. 절은 `aria-labelledby`로 제목과 연결합니다.
- **판정 줄**(맨 위): `--font-text` 15px 700에 16px 상태 아이콘을 붙입니다. `role="status"`입니다.
  - fail이 있으면 `문제 {f}개를 찾았습니다`(`--red`)
  - 없고 warn이 있으면 `확인할 항목이 {w}개 있습니다`(`--yellow`)
  - 둘 다 없으면 `모두 정상입니다`(`--green`)

### 3.3 패널 상태

| 상태 | 모습 |
|---|---|
| 불러오는 중(`data === null`, 오류 없음) | 머리 아래에 가운데 정렬로 `진단 정보를 불러오는 중…`(13px `--muted`, `role="status"`). "확인" 시각은 비웁니다 |
| 불러오기 실패(`error`) | `진단 정보를 가져오지 못했습니다. 서버가 켜져 있는지 확인해 주세요.`(`--red`, `role="alert"`)와 그 아래 `[다시 시도]` 버튼(`reload()`) |
| 정상 | 3.2의 구조 |
| 다시 확인 중 | 내용을 그대로 두고 `다시 확인` 버튼에 `aria-busy="true"`를 줍니다. 끝나면 "확인" 시각만 바뀝니다. mock은 단순하게 "불러오는 중"으로 바꾸지만, 제품은 깜빡임을 피하려고 내용을 유지합니다 |

## 4. 점검 결과 행

| 상태 | 아이콘(7×7 → 14px) | 행 테두리 | 여백 | 보이는 것 |
|---|---|---|---|---|
| fail | `fail` `--red` | `2px solid var(--red)` | `8px 10px` | 제목 / detail / 고치는 법 |
| warn | `warn` `--yellow` | `2px dashed var(--yellow)` | `8px 10px` | 제목 / detail / 고치는 법 |
| ok | `ok` `--green` | 없음(투명), 배경 `#15132a` | `4px 10px` | **한 줄**: 제목(`--muted`) … detail(오른쪽 정렬) |

- 행은 `<ul class="dp-rows">` 안의 `<li class="dp-row dp-row--{status}">`입니다. 행 사이 간격은 4px입니다.
- 격자: fail/warn은 `16px 1fr`, ok는 `16px 1fr auto`이고 열 간격은 8px입니다.
- **제목**: 12px `--font-pixel`입니다. 앞에 스크린 리더용 `<span class="sr-only">{문제|확인 필요|정상}: </span>`을 둡니다. 모양(X, !, ✓)과 테두리 모양(실선, 점선, 없음)이 달라서 색을 구분하지 못해도 상태를 알 수 있습니다.
- **detail**: `--font-text` 12px `--muted`입니다. doctor가 주는 문자열을 그대로 씁니다(값이 아닌 있음/없음과 숫자뿐입니다).
- **고치는 법**: warn/fail에서 `fix`가 비어 있지 않을 때만 보여 줍니다. `--font-text` 13px `--ink`, 위 여백 2px이고, 앞에 11px `--muted` 라벨 `고치는 법 `를 붙입니다(`::before`로 넣어도 되고 span으로 넣어도 됩니다).
- CLI의 ✅⚠️❌ 이모지는 화면에서 쓰지 않고, 도트 아이콘으로 대신합니다. 이모지는 폰트마다 모양이 달라 도트 화면과 어울리지 않습니다.

## 5. 오류 수와 hook 요약

| 줄 | 규칙 |
|---|---|
| 오류 수 | `errorsLastHour > 0`이면 `최근 1시간 오류 {N}건`이고, `{N}건`만 굵게 `--red`로 씁니다. 0이면 `최근 1시간 오류 없음`(`--ink`)입니다. `--font-text` 13px |
| 로그 폴더 | 그 아래에 `로그 폴더 {logDir}`(11px `--muted`, 줄바꿈 허용)를 둡니다. `logDir`은 이미 "~"로 치환되어 옵니다 |
| hook 요약 | `최근 10분 {last10min}건, 마지막 수신 {ago}, 거부 {rejected 합}건`. `--font-text` 13px |
| `{ago}` | `lastAt`이 null이면 `마지막 수신 없음`(이때 "마지막 수신" 뒤에 `{ago}`를 붙이지 않습니다). 60초 미만은 `방금`, 60분 미만은 `{m}분 전`, 그 이상은 `{h}시간 전`이고 모두 내림입니다. Phase 1 경과 시간과 같은 규칙입니다 |

예: `최근 10분 5건, 마지막 수신 2분 전, 거부 0건` / `최근 10분 0건, 마지막 수신 없음, 거부 0건`

## 6. "진단 파일 만들기" 버튼

절 제목은 `진단 파일`이고, 안내 문장(`--font-text` 13px `--muted`)은 다음과 같습니다.
`문제가 생기면 이 파일을 만들어 담당자에게 보내 주세요. 대화 내용, 이름, 비밀값은 들어가지 않습니다.`

버튼: 높이 36px, 여백 `0 16px`, 13px, 초록 채움(`--green` 배경, `--wall` 글자, Phase 1 `.pbtn--primary`)입니다.

| 상태 | 버튼 | 아래 영역 | 포커스 / 알림 |
|---|---|---|---|
| 기본 | `진단 파일 만들기` | 없음 | — |
| 만드는 중 | `만드는 중…`, `disabled`, `aria-busy="true"`, 투명도 .5, `cursor: progress` | 없음 | 포커스는 버튼에 그대로 둡니다 |
| 완료 | `다시 만들기`(활성) | 초록 결과 상자(아래) | 결과 상자는 `role="status"`입니다. 포커스를 **받기 링크로 옮깁니다** |
| 실패 | `진단 파일 만들기`(활성, 다시 누를 수 있음) | 빨간 알림 상자(아래) | `role="alert"`. 포커스는 버튼에 둡니다 |

- **요청**: `POST /api/diagnostics/bundle`, 헤더 `Content-Type: application/json`, `body: "{}"`입니다.
- **완료 상자**: 위 여백 10px, 여백 `8px 10px`, `2px solid var(--green)`, 격자 `1fr auto`입니다.
  - 1행: `진단 파일을 만들었습니다`(`--font-text` 13px `--green`)
  - 2행: 경로. monospace 12px `--ink`, `word-break: break-all`입니다. `diagDir`이 있으면 `{diagDir}/{file}`, 없으면 `{file}`만 씁니다(가정 D4).
  - 오른쪽(1–2행에 걸침): **받기 링크** `<a class="pbtn" href="/api/diagnostics/files/{file}" download>`입니다. 높이 32px, `down` 아이콘을 붙이고, 문구는 `받기`입니다.
- **실패 상자**: 위 여백 10px, 여백 `8px 10px`, `2px solid var(--red)`, 글자 `--red` 13px입니다.
  - 문구: `진단 파일을 만들지 못했습니다. 잠시 뒤 다시 눌러 주세요. 계속 안 되면 터미널에서 claude-office diag를 실행해 주세요.`
  - `claude-office diag`는 `<code>`로 감싸고 `--ink`로 씁니다.
- 패널을 닫았다가 다시 열면 기본 상태로 돌아갑니다.

## 7. 키보드와 포커스

| 동작 | 결과 |
|---|---|
| 칩에서 Enter / Space | 패널을 열고 **제목(`#dp-title`)에 포커스**를 줍니다 |
| 패널 안 Tab 순서 | 다시 확인 → 닫기 → (실패 상태면 다시 시도) → 진단 파일 만들기 → 받기. 점검 행은 포커스를 받지 않습니다 |
| Esc | 패널을 닫고 **칩으로 포커스를 돌려줍니다.** 패널 밖에 포커스가 있어도 패널이 열려 있으면 Esc로 닫힙니다. 단, 말풍선이 떠 있으면 Esc는 말풍선을 먼저 닫습니다(Phase 1 규칙) |
| 닫기 버튼, 칩 다시 누르기 | Esc와 같습니다 |
| 패널 밖 클릭 | 닫지 않습니다(비모달). 결정 보고서와 같습니다 |

포커스 가두기는 하지 않습니다. 패널이 비모달이라 빌딩을 계속 조작할 수 있어야 합니다.

## 8. 좁은 화면, 테마, 움직임

- **≤ 720px**: 패널은 아래 시트로 바뀝니다. `width: 100vw; top: 8vh`, 왼쪽 테두리를 없애고 **위 테두리 4px `--cyan`**을 둡니다. 결정 보고서와 같습니다. 칩은 HUD가 줄을 바꿀 때 같이 내려갑니다. 결과 상자의 경로는 줄바꿈되고, 받기 링크는 오른쪽에 남습니다.
- **테마**: 다크 전용입니다(가정 D1).
- **움직임 줄이기**: `slide-in`을 끕니다(Phase 1 전역 규칙). 빨간 점은 원래 움직이지 않습니다. "만드는 중…"도 글자만 쓰고 애니메이션은 넣지 않습니다.

## 12. 사용설명서(Task 12) 그림 목록

### 12.1 공통 규칙

- **형식**: 인라인 `<svg>`입니다. 외부 파일, 외부 폰트, `<image>`를 쓰지 않습니다.
- **도트 그리기**
  - `viewBox`에서 1단위가 도트 1칸이고, `shape-rendering="crispEdges"`를 줍니다.
  - 도트 그림은 Phase 1 스프라이트 맵(`BODY_A`, `BODY_UP`, `QMARK`, 아이콘)을 그대로 `<rect>`로 옮깁니다.
  - 표시 크기는 도트 1칸 = 3–4px입니다. 너비는 100%, 최대 640px입니다.
- **글자**: SVG 안 글자는 **시스템 폰트**(`font-family: -apple-system, "Apple SD Gothic Neo", "Noto Sans KR", sans-serif`)로 씁니다. 사용설명서에 Galmuri를 넣으면 단일 파일이 수백 KB 커지기 때문입니다. 글자는 12–14px 상당으로 쓰고 짧게 둡니다.
- **색**: Phase 1 토큰과 `--red`만 씁니다. 그림 배경은 `--bg` 또는 `--wall`입니다. 사용설명서 본문이 밝은 배경이어도 그림은 제품처럼 어둡게 그리고, 2px `--desk` 테두리로 감쌉니다.
- **접근성**
  - `role="img"`와 `<title>`(짧은 이름), `<desc>`(무엇을 보여 주는지 한두 문장)를 넣습니다.
  - 번호 표시는 본문 목록과 짝을 이룰 때만 씁니다. 원 안에 숫자를 넣은 `--yellow` 표시로 그립니다.
- **스크린샷 자리**
  - 실제 스크린샷을 나중에 넣을 곳에는 점선 상자(2px dashed `--muted`, 비율 16:10)를 둡니다.
  - 상자 가운데에 `스크린샷 자리: {무엇}`을 적고, `data-screenshot="{id}"`를 붙입니다.
- **가짜 값만 씁니다.** 사용자 이름, 실제 경로, 비밀값은 넣지 않습니다. 경로는 `~/…`로 씁니다.
