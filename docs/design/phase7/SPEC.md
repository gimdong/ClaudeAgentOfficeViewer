## 0. 한 줄 원칙

테마가 바꾸는 것은 **그림 시트, `--th-*` 토큰, 장소 낱말 문구표** 셋뿐입니다. 칸 배치(140px 칸, 남는 폭에서 줄바꿈), DOM 구조, `aria-label`, 공통 UI 토큰, 상태 색의 뜻은 모든 테마가 같습니다.

## 1. 테마 묶음(theme bundle)

```
themes/<id>/
  theme.json        매니페스트(아래)
  tokens.css        :root[data-theme="<id>"] { --th-*: … }  — --th-* 말고는 쓰지 않음
  scene.png         장면 칸 시트(§2)
  character/*.png   층 시트(§3), 빌드 때 팔레트 판 생성
  aura.png          선택. 없으면 오피스 오라를 테마 색으로
  LICENSE.md        출처·라이선스(§8)
```

```json
{
  "id": "fantasy",
  "name": { "ko": "종탑 성채", "en": "Bellspire Keep" },
  "contract": 1,
  "px": 3,
  "words": {
    "floor": { "ko": "{n}번 홀", "en": "Hall {n}" },
    "lobby": { "ko": "성문 홀", "en": "Gate Hall" },
    "rest": { "ko": "선술집", "en": "Tavern" },
    "pantry": { "ko": "물동이 구석", "en": "Water corner" },
    "elevator": { "ko": "승강 우리", "en": "Lift cage" },
    "guard": { "ko": "성문지기", "en": "Gatekeeper" },
    "team": { "ko": "길드 탁자 · {team}", "en": "Guild table · {team}" },
    "report": { "ko": "두루마리", "en": "Scroll" }
  },
  "frames": { "walk_left": 6, "walk_right": 6 },
  "palette": { "C1": "#…", "C2": "#…", "C3": "#…" }
}
```

- `contract`가 앱이 아는 값보다 크면 그 테마를 끄고 오피스로 그립니다.
- `words`가 빠진 칸은 오피스 낱말을 씁니다. 낱말은 **이름만** 바꿉니다. 버튼·안내·오류 문장은 테마가 바꾸지 않습니다(§5).
- `frames`는 §3 표의 프레임 수를 늘릴 때만 적습니다. CSS 변수 `--frames`로 받습니다.

### 2a. 엘리베이터·쉬는 곳(4446d1a §5에서)

- 엘리베이터: HUD 층 바로가기를 누르면 장면의 엘리베이터 칸이 그 층까지 칸 단위로 움직이고(0.12초/층, `steps`), 문 열림 2프레임 뒤 그 층으로 스크롤합니다. 움직임 줄이기면 바로 그 층.
- 쉬는 곳(`pantry`·`rest`·옥상): 어느 곳으로 갈지는 화면이 고르고 서버 데이터는 상태만 씁니다.
- 로비 경비·행인·차는 장식이고 데이터와 무관합니다.

바뀌지 않는 칸(모든 테마 공통): 손들기 "!" 풍선, 결재 배지, 이름표·말풍선 판, 포커스 링, 버튼, 대화상자.

## 3. 캐릭터 시트 계약 (MOTION.md 788217f 그대로)

- 칸 **26×30**(1배율), 기준점 **발 가운데 (13, 28)**. 시트 **104×270**(4열 × 9행). 행 순서가 계약입니다.

| 행 | 이름 | 프레임 | 한 프레임 | 반복 | 움직임 줄이기 멈춤 |
|---|---|---|---|---|---|
| 0 | `walk_left` | 4 | 120ms | 무한 | 걷지 않고 목적지에 놓음 |
| 1 | `walk_right` | 4 | 120ms | 무한 | 같음 |
| 2 | `sit_down` | 3 | 100ms | 한 번. `stand_up` = 거꾸로 | 2(앉음) / `stand_up`은 0 |
| 3 | `type` | 2 | 200ms | 무한 | 0 |
| 4 | `think` | 2 | 600ms | 무한 | 0 |
| 5 | `idle` | 4 | 200ms | 무한 | 0 |
| 6 | `hand_up` | 2 | 450ms | 무한 | 0 |
| 7 | `coffee` | 4 | 1600·200·800·200ms | 무한 | 0 |
| 8 | `hand_up_stand` | 2 | 450ms | 무한 | 0 |

- 테마는 프레임 수만 늘릴 수 있습니다. **이름·행 순서·칸 크기·기준점은 바꾸지 않습니다.** 새 동작은 행 9부터 덧붙입니다.
- 층 여섯(아래 → 위): `body` → `outfit` → `hands` → `hair-*` → `glasses` → `prop`. 모든 층 시트가 같은 크기·칸 배치라 요소 하나에 `background-image` 여러 장으로 겹칩니다.
- 테마가 다시 그려도 되는 층: `outfit`(실루엣 칸 안: 앞 x 5–20 / y 14–28, 옆 x 5–19 / y 13–28), `glasses`(같은 칸), `prop`. 나머지는 팔레트만.
- 외곽선: 자기 둘레에만, 아래 층이 칠한 칸에는 두지 않음(`make-sheet.mjs`의 `Fr.finish`). 머그만 예외.
- 팔레트 슬롯: 피부 `S1–S3`, 머리 `H1–H3`, 옷 `C1–C3`, 바지 `P1 P2`, 신발 `K`, 외곽선 `O`. 테마·팀원 변형은 **빌드 때 슬롯 색만 바꾼 PNG**를 만듭니다. 런타임 `filter`·`hue-rotate` 금지.
- themes SPEC의 `--costume-1~5`는 CSS 토큰이 아니라 `theme.json`의 `palette` 판 목록(팀원 순서로 돌려 씀)으로 옮깁니다.
- 겹침 순서(뒤 → 앞): 의자 등받이 → 오라 → 캐릭터 → 모니터·책상 윗면 → 책상 앞면 → DOM(이름표·말풍선·"!").
- 오라: `aura.png` 칸 38×50, 행 = `effort.level` 1–4(low 1 · medium 2 · high 3 · xhigh/max 4, 값 없으면 1), 2프레임 400ms. 캐릭터를 오라 칸 (6,20)에 놓음. **working(`type`)일 때만**. 테마는 색만 바꿀 수 있음.
### 3a. 테마별 추가 캐릭터 시트(선택 칸) — 미룸

**다음 테마 Phase로 미룹니다**(Phase 7 오피스는 쓰지 않음). 아래는 그때 쓸 안입니다. 사람 몸이 아닌 캐릭터(우주선 경비 드로이드 등)는 사람 시트로 그릴 수 없습니다.
- `theme.json`의 `extraActors: { "<칸 이름>": "actors/<이름>.png" }`. 지금 받는 칸은 `guard`, `passerby` 둘뿐(장식 자리). **팀원 자리에는 쓰지 않습니다** — 팀원은 언제나 §3 사람 시트.
- 시트 규칙: 칸 26×30·기준점 (13,28)은 같게, 행은 `idle` 하나만 필수(2–4프레임, `steps`, 깜빡임 없음). 움직임 줄이기면 프레임 0.
- 층 여섯·팔레트 슬롯은 따르지 않아도 됩니다(한 장 그림). 외곽선 1칸·3단 음영은 같게.
- 없으면 그 자리는 사람 시트 + 옷 겹(투구·선글라스 등)으로 그립니다.
- 4방향 테마용 앞·뒤 걷기(`walk_down`·`walk_up`)는 motion에 행 9·10으로 제안했습니다. 받아들여지면 이 표에 더합니다(선택 행, 없으면 좌우 걷기로 대신).

- 상태 → 움직임 순서와 스토리보드 타이밍은 MOTION.md §2·§3을 따릅니다.
- **탕비실 걷기(team-lead 판정):**
  - 쉼 상태가 **30초** 이어지면 `stand_up` → 걷기 → `coffee`. `longIdle`(1시간) 표시와는 따로입니다.
  - 한 층에서 동시에 걷는 사람은 **최대 2명**, 나머지는 차례를 기다립니다(앉은 채 `idle`).
  - 쉬는 중 일이 다시 시작되면(PreToolUse 등) 곧바로 자리로 걸어 돌아가 `sit_down` → `type`.
  - 손들기는 걸어 돌아오지 않고 그 자리에서 `hand_up_stand`(P7-3).
  - 움직임 줄이기: 걷지 않고 바로 탕비실 자리의 `coffee` 0 정지 그림.

## 4. 팔레트 토큰

두 안이 있었습니다: (가) 테마 전용 `--th-*` 이름공간, (나) themes SPEC의 "기존 토큰(`--wall`·`--panel`·`--ink`…)을 테마가 다시 정의 + `--plate`". **(가)로 정합니다.** (나)는 테마가 `--ink`·`--panel`을 바꿔 대화상자·HUD·포커스 링 대비를 테마마다 다시 검사해야 하고, 테마 하나가 공통 UI를 깨뜨릴 수 있습니다.

## 5. 공통 UI와 테마의 경계

| 테마가 바꿈 | 테마가 못 바꿈 |
|---|---|
| 장면 그림(§2), 캐릭터 옷·소품·팔레트(§3) | 글꼴·글자 크기·줄 높이 |
| `--th-*` 토큰 | 공통 UI 토큰, 포커스 링(`--focus`, 2px 이상) |
| 장소 낱말(`words`) | 버튼·대화상자·HUD·서류철 창의 모양과 문장 |
| 이름표·층 이름 판의 색(`--th-label-*`) | 이름표·말풍선·"!"·배지의 위치·크기·DOM |
| | `aria-label`·읽는 순서·키보드 동작 |
| | 움직임 줄이기 규칙(§3, MOTION.md §4) |

- 글자는 그림에 넣지 않습니다. 광고판·간판도 글자 없는 도형입니다.
- 스크린 리더 이름은 테마 낱말을 따르되 뜻을 덧붙입니다: 예 `3번 홀(3층)`. 테마를 바꿔도 같은 뜻으로 읽혀야 합니다.

## 6. 대비 규칙

- 글자는 **언제나 불투명 판 위**(`--th-label-bg` 또는 공통 `--panel`). 하늘·별밭·창 불빛·반투명 홀로 판 위에 바로 쓰지 않습니다.
- 글자/판 **4.5:1 이상**(WCAG AA), 큰 제목(18.66px 굵게 이상)만 3:1. 판 테두리는 글자색으로 쓰지 않습니다(판타지 `#b07a46` 4.6:1, 사이버 분홍 6.2:1은 테두리·큰 제목 전용).
- 확인된 값(themes bb5d0dc): 판타지 글자/판 14.2:1 · 양피지 글 12.6:1, 우주선 글자/판 16.4:1, 사이버펑크 글자/판 17.9:1.
- 주의 예: 우주선 글자 `#e6f4ff`를 선체 `#8a93a8` 위에 바로 쓰면 2.7:1 — 판 필수.
- 반투명(0.22–0.35) 홀로 판에 보고서 본문을 올릴 때는 안쪽에 불투명 판을 하나 더 깝니다.
- 상태는 색만으로 나타내지 않습니다: "!"·배지·말풍선 글자·모니터 그림 모양이 함께 바뀝니다.
- 빌드 검사: `tokens.css`의 `--th-label-ink`/`--th-label-bg`, `--th-paper-ink`/`--th-paper`가 4.5:1 미만이면 실패.

## 7. 성능 예산

- 테마 묶음 PNG 합계 **200KB 이하**(gzip 전). 캐릭터 층 시트 합계 약 7KB, 팔레트 판 각 ~2KB(MOTION.md §5).
- 캐릭터 하나 = `div` 하나, 층은 `background-image` 여러 장. JS 타이머 없음, `steps()`로 `background-position`만.
- 이동은 `transform`만(`left`·`top` 금지), `image-rendering: pixelated`, 정수 배율(`--px` 3 또는 4).
- 접힌 층·화면 밖 층은 `content-visibility: auto` + `.floor--offscreen`으로 `animation-play-state: paused`.
- 장면에서 동시에 움직이는 것: 캐릭터·오라·엘리베이터, 그리고 테마 장식 **2프레임 이하 3곳까지**(화로 불꽃·김 등). 비·네온 반사·창 불빛은 정지 그림. 무작위 패턴 금지(다시 그릴 때 깜빡여 보임).
- 30명 층에서 메인 스레드 프레임 시간 16ms 안(qa가 성능 패널로 확인).

## 9. 렌더 도구 역할

도구 셋을 역할로 나눕니다.

| 역할 | 도구 | 결과 |
|---|---|---|
| **시트 생성**(실제 자산) | motion `make-sheet.mjs`(Node 표준 `zlib`만) | 캐릭터 층·팔레트 판·오라 PNG + 파일별 바이트 |
| **장면 확인 렌더**(목업) | HTML(+`web/styles.css`, `<meta charset="utf-8">`) → `qlmanage -t -s 1400` | 900·360폭 PNG. 360은 `.narrow` 래퍼 |
| 장면 HTML 만들기 | 각자 생성기(themes `render.mjs`, office `mock/building.html` 등) 자유 | 단, 캐릭터는 `make-sheet.mjs` 시트를 `<img style="image-rendering:pixelated">` 정수배로 넣음(직접 그리지 않음) |

- qlmanage는 자기 시간 제한을 겁니다: `perl -e 'alarm 150; exec @ARGV' qlmanage -t -s 1400 -o <out> <file>.html`. 생성 → `ls`로 HTML 확인 → 한 장씩 렌더 → PNG 확인.
- 디더·체크 무늬처럼 사각형이 아주 많으면 qlmanage가 멈춥니다. 같은 색 가로 줄을 합치거나 PNG 타일로 넣습니다.
- 멈춘 프로세스는 자기 PID만 끕니다(B113).
