## 0. 한 줄 원칙

테마가 바꾸는 것은 **그림 시트, `--th-*` 토큰, 장소 낱말 문구표** 셋뿐입니다. 칸 배치(140px 칸, 남는 폭에서 줄바꿈), DOM 구조, `aria-label`, 공통 UI 토큰, 상태 색의 뜻은 모든 테마가 같습니다.

## 1. 테마 묶음(theme bundle)

```
themes/<id>/
  theme.json        매니페스트(아래)
  tokens.css        :root[data-theme="<id>"][data-variant="<v>"] { --th-*: … }  — --th-* 말고는 쓰지 않음
  scene-<v>.png     장면 칸 시트(§2), 변형(낮·밤)마다
  character/*.png   층 시트(§3), 빌드 때 팔레트 판 생성
  aura.png          선택. 없으면 오피스 오라를 테마 색으로
  LICENSE.md        출처·라이선스(§8)
```

```json
{
  "id": "fantasy",
  "name": { "ko": "종탑 성채", "en": "Bellspire Keep" },
  "contract": 1,
  "px": 2,
  "variants": { "day": { "ui": "light" }, "night": { "ui": "dark" } },
  "pantrySpot": 64,
  "words": {
    "floor": { "ko": "{n}번 홀", "en": "Hall {n}" },
    "lobby": { "ko": "성문 홀", "en": "Gate Hall" },
    "rest": { "ko": "선술집", "en": "Tavern" },
    "pantry": { "ko": "물동이 구석", "en": "Water corner" },
    "elevator": { "ko": "승강 우리", "en": "Lift cage" },
    "guard": { "ko": "성문지기", "en": "Gatekeeper" },
    "team": { "ko": "길드 탁자 · {team}", "en": "Guild table · {team}" },
    "report": { "ko": "두루마리", "en": "Scroll" }
  },
  "frames": { "walk_left": 6, "walk_right": 6 },
  "palette": { "C1": "#…", "C2": "#…", "C3": "#…" }
}
```

- `contract`가 앱이 아는 값보다 크면 그 테마를 끄고 오피스로 그립니다.
- `words`가 빠진 칸은 오피스 낱말을 씁니다. 낱말은 **이름만** 바꿉니다. 버튼·안내·오류 문장은 테마가 바꾸지 않습니다(§5).
- `variants`는 하나 이상. 변형마다 `ui`(공통 UI 벌, §4.1)와 장면 시트가 따로입니다. 오피스는 `day`·`night`. 다른 테마는 변형 하나여도 됩니다.
- **변형 고르기(team-lead 판정):** 빌딩 정보 창에 `낮 / 밤 / 시스템 따라`(「안」) 설정. **기본은 `시스템 따라`**(`prefers-color-scheme`: 밝음 = 낮, 어둠 = 밤, 시스템이 바뀌면 바로 따라감). `낮`·`밤`을 고르면 그 변형으로 고정됩니다. 시각에 따른 자동 전환은 없습니다. 값은 서버 `building.json`에 저장합니다(기기마다 같게). 변형이 하나인 테마는 이 설정을 흐리게 둡니다.
- `frames`는 §3 표의 프레임 수를 늘릴 때만 적습니다. CSS 변수 `--frames`로 받습니다.

### 2a. 칸 경계 — office와 themes (P7-6 원문)

> 로비는 office가 건물 칸(바닥·데스크·입구 문·표지)을, themes가 그 안팎을 지나는 엑스트라(경비·행인)를 그린다. 카페도 office는 카운터·테이블·머신, themes는 손님 엑스트라다. 엑스트라 사람은 motion 시트 형식(26×30·층 6)을 따르고, themes는 옷 변형만 만든다(사람 프레임은 motion 계약을 재사용). 차처럼 사람이 아닌 것은 themes 시트다. 하늘·스카이라인(낮·밤)과 도로·인도 타일은 themes 몫이다.

- 그래서 §2 표의 `guard`는 사람 엑스트라(motion 형식 + 옷 변형)이고, 카페 손님·행인도 같습니다. 차 같은 탈것은 themes 시트(§3a의 사람이 아닌 캐릭터와 달리 이번 Phase에 그림, 장식 전용).

### 2b. 엘리베이터·쉬는 곳(4446d1a §5에서)

- **오래 쉬면 카페로(사용자 결정, 보충 2의 "탑승자 없음"을 대체):**
  - 짧은 쉼(30초~): 자기 층 `pantry`(§3 탕비실 걷기).
  - `longIdle`(1시간): 탕비실에서 통로로 걸어 → 문 열림 → `ride` → 출발 `ride_lurch` → 상자가 카페 층으로 → 도착 `ride_lurch` → 걸어 나가 카페 오래 쉬는 자리(러그 위 테이블 x153·x228, §2 `rest`)에서 앉아 `idle`(또는 `coffee`). 실제 팀원이므로 **이름표가 따라갑니다**(엑스트라와 구별).
  - **일이 다시 시작되거나 손들기가 생기면** 엘리베이터로 자기 층에 돌아가 `walk_*` → `sit_down` → `type`(손들기면 앉은 `hand_up`). 카페에서는 그 자리에서 손을 들지 않습니다(team-lead 최종, P7-9 대체). **돌아오는 동안에도 책상의 결정 표시는 바로 보입니다.** 같은 층 탕비실에서는 P7-3대로 그 자리에서 `hand_up_stand`.
  - 카페에 간 동안 빈 책상에는 점선 이름표 「안」`카페 ↑`(DOM, qa 검토)를 둡니다. 탕비실은 지금처럼 `탕비실 →`.
  - 타이밍은 motion 67ba302 §3.2·§3.3(카페 왕복, 층 하나 이동 2.64초)을 따릅니다.
  - 엘리베이터는 **한 번에 1명**. 기다리는 사람은 지금 자리(탕비실·카페)에서 그대로 기다립니다. **돌아가는 사람(일 시작)이 가는 사람보다 먼저**입니다.
  - 사용자가 HUD 층 버튼으로 옮기는 이동과 겹치면 **HUD 이동이 먼저**입니다. 타려던 사람은 그 자리에서 기다리고, HUD 이동이 끝난 뒤 탑니다.
  - 움직임 줄이기: 타지 않고 바로 목적지 정지 그림(카페 자리 `idle` 0, 돌아오면 자기 책상).
  - 카페 층의 팀원 자리 수가 모자라면(테이블 수 < 오래 쉬는 사람) 나머지는 자기 층 탕비실에 남습니다.

- **받지 않음: `--th-light-glow`**(형광등 빛 원뿔, `rgba(…, .35)`). §7 "반투명 빛 금지"와 부딪힙니다. 빛 원뿔은 불투명 도트 두 단(`--th-light` + `--th-wall-shade` 사이 색)으로 그림에 굽거나 뺍니다.
- 다른 세 테마 값은 그 테마 구현 때 themes 렌더 값에서 옮깁니다(이번 Phase 구현 밖).
- 옷 색 `--costume-*`은 토큰이 아니라 `theme.json` `palette` 목록입니다(§3).
- "!"·결재 배지 = 공통 `--yellow` + `--yellow-ink`. 모니터 상태는 그림 속 색이라 테마가 정하되 **밝기 순서 ask > work > think > rest**로 색 없이도 구별되어야 합니다(office 규칙 채택).

## 6. 대비 규칙

- 글자는 **언제나 불투명 판 위**(`--th-label-bg` 또는 공통 UI 판). 하늘·벽지·타일·차양·별밭·창 불빛·반투명 홀로 판 위에 바로 쓰지 않습니다. 이 규칙 하나로 테마마다 검사할 쌍이 아래 표로 줄어듭니다(office 1ac7d29 §3).
- 글자/판 **4.5:1 이상**(WCAG AA). 판 테두리(`--th-label-border`)는 장식이라 글자색으로 쓰지 않습니다(office 낮 `#c9c0b0`/흰 1.8:1, 판타지 `#b07a46` 4.6:1).
- 비텍스트(포커스 링 등) 3:1 이상. **포커스 링은 공통 두 겹**(office 제안, 사용자 확정): `outline: 2px solid var(--focus); box-shadow: 0 0 0 6px var(--ink)`. 바깥 겹은 **`--ink`**입니다(P7-11). `--panel`은 light 벌에서 흰색이라 낮 장면 위에서 두 겹 모두 1.22–1.64:1로 모자랐습니다. `--ink`는 두 벌 모두 판과 반대 밝기라 바깥 겹이 낮 10.7–14.3:1, 밤 10.1–13.5:1(office 7334726 `contrast.cjs` `RING_OUTER`). 검사는 "두 겹 중 하나가 장면 색 모두에 ≥ 3:1".
- 상태는 색만으로 나타내지 않습니다: "!"·배지·말풍선 글자·모니터 그림 모양이 함께 바뀝니다.
- 반투명 판 위에 실제 글(보고서 본문)을 올릴 때는 안쪽에 불투명 판을 하나 더 깝니다.

**테마가 통과해야 할 쌍**(벌·변형마다):

| 글 / 바탕 | 쓰는 곳 | office 낮 | office 밤 |
|---|---|---|---|
| `--th-label-ink` / `--th-label-bg` | 이름표·층 이름표·말풍선·팀 팻말·통로 층 번호(판 위로 옮김, b2bfdd4) | 15.73 | 15.58 |
| `--th-label-muted` / `--th-label-bg` | 보조 글(· 일하는 중), 점선 이름표 | 6.71 | 7.05 |
| `--th-label-accent` / `--th-label-bg` | 로비 `2F ▲` | 5.36 | 14.83 |
| `--th-paper-ink` / `--th-paper` | 보고서 1인칭 창 | 지금 값 | 지금 값 |

**앱(공통 UI 두 벌)이 통과해야 할 쌍:** 포커스 두 겹 링 / 장면 색(벽·바닥·러그·겉벽, 둘 중 하나 ≥ 3:1, 낮·밤 모두), `--ink`/`--panel`(HUD), `--muted`/`--panel`, `--yellow-ink`/`--yellow`(결재 칩·`!`, office 낮 11.37 · 밤 16.99), `--wall`/`--green`(`.pbtn--primary` 글자, light 5.36), `--pink`/`--panel`(오류), `--cyan`/`--panel`(링크).

**검사 원형:** office `docs/design/phase7/office/mock/contrast.cjs`(1ac7d29). 쌍 목록 `PAIRS`와 WCAG 휘도 계산 `ratio()`, AA 미만이면 exit 1. 구현 때 이것을 테스트로 옮깁니다: 각 테마 `tokens.css`에서 `--th-*` 값을 읽어 위 테마 쌍을, 공통 UI 두 벌에서 앱 쌍을 검사합니다. 목업의 참고 쌍 `muted`/`tile`(4.56, 아슬아슬)은 "판 없이 바닥 위 글"이라 이 계약에서는 금지이므로 검사에서 뺍니다.

## 7. 성능 예산

- **장면 그림 합계 64KB 이하**(테마·변형 하나, gzip 전 PNG). office 낮 실측 약 37KB(목업 canvas, 최적화 전, 바깥 포함). 바깥을 themes 3a0b0bc 시트(낮·밤 합계 **3,816B**)로 바꾸면 office 몫(약 19KB) + 바깥 약 2–3KB → **약 22KB** 예상. 캐릭터 층 시트·오라는 따로 합계 8,162B(a4b45bc), 팔레트 판 각 ~2KB.
- 층 안 무늬(벽지·타일·차양)는 CSS 그라데이션이라 그림 예산에 들지 않습니다.
- 캐릭터 하나 = `div` 하나, 층은 `background-image` 여러 장. JS 타이머 없음, `steps()`로 `background-position`만.
- 이동은 `transform`만(`left`·`top` 금지), `image-rendering: pixelated`, 정수 배율.
- 접힌 층·화면 밖 층·길은 `content-visibility: auto` + `.floor--offscreen`으로 `animation-play-state: paused`.
- 장식 움직임(데이터와 무관): 행인 `walk_*` + `translateX`(약 25칸/초, 화면 밖에서 반대편으로 다시 들어옴), 차 `translateX`만(가까운 차로 오른쪽, 먼 차로 왼쪽), 카페 손님 `coffee`·`idle`, 경비 `idle`. 구름은 정지. **행인 최대 2명 + 차 최대 2대를 한 곳으로 셉니다**(themes 제안 채택), 그 밖의 테마 장식은 **2프레임 이하 3곳까지**(화로 불꽃·김 등). 움직임 줄이기면 모두 멈춤. 깜빡임·밝기 변화 없음(안테나 등은 늘 켜짐). 비·네온 반사·창 불빛은 정지 그림, 무작위 패턴 금지.
- **반투명 빛 금지:** 전조등·가로등 빛줄기 같은 반투명 덧칠은 쓰지 않습니다(어두운 바탕에서 회색 얼룩처럼 보임, 3a0b0bc). 빛은 밝은 점·불투명 도트로만.
- 30명 층에서 메인 스레드 프레임 시간 16ms 안(qa가 성능 패널로 확인).

## 9. 렌더 도구 역할

도구 셋을 역할로 나눕니다.

| 역할 | 도구 | 결과 |
|---|---|---|
| **시트 생성**(실제 자산) | motion `make-sheet.mjs`(Node 표준 `zlib`만) | 캐릭터 층·팔레트 판·오라 PNG + 파일별 바이트 |
| **장면 확인 렌더**(목업) | HTML(+`web/styles.css`, `<meta charset="utf-8">`) → `qlmanage -t -s 1400`, **또는 job tmp에 둔 Playwright(headless Chromium)** | 900·360폭 PNG. qlmanage는 뷰포트 약 1020px 고정이라 360은 `.narrow` 래퍼. Playwright는 실제 `@media`·`prefers-reduced-motion`·`prefers-color-scheme`을 적용할 수 있어 낮·밤·360 확인에 낫습니다(office b2bfdd4). **job tmp에만 설치**, 저장소 의존성에 넣지 않음. office 장면은 Playwright로 찍습니다 |
| 장면 HTML 만들기 | 각자 생성기(themes `render.mjs`, office `mock/building.html` 등) 자유 | 단, 캐릭터는 `make-sheet.mjs` 시트를 `<img style="image-rendering:pixelated">` 정수배로 넣음(직접 그리지 않음) |

- qlmanage는 자기 시간 제한을 겁니다: `perl -e 'alarm 150; exec @ARGV' qlmanage -t -s 1400 -o <out> <file>.html`. 생성 → `ls`로 HTML 확인 → 한 장씩 렌더 → PNG 확인.
- 디더·체크 무늬처럼 사각형이 아주 많으면 qlmanage가 멈춥니다. 같은 색 가로 줄을 합치거나 PNG 타일로 넣습니다.
- 멈춘 프로세스는 자기 PID만 끕니다(B113).
