## 1. 프레임 세트 계약 (모든 테마가 채울 것)

칸 크기는 테마마다 같게 **26×30**(1배율), 기준점은 **발 가운데 = (13, 28)**. 앉은 프레임은 같은 기준점에서 그리고 책상 앞면이 아랫몸을 가립니다. 시트 행 순서가 곧 계약입니다(CSS가 `행 × 30px`로 찾아감).

| 행 | 이름 | 프레임 | 한 프레임 | 반복 | 용도 | 움직임 줄이기 때 멈출 프레임 |
|---|---|---|---|---|---|---|
| 0 | `walk_left` | 4 | 120ms | 무한 | 왼쪽으로 걷기(0 = 가까운 다리 앞, 1 = 모음+몸 1칸 위, 2 = 가까운 다리 뒤, 3 = 모음) | 걷지 않음 — 목적지에 바로 놓고 그 상태의 프레임 |

| 11 | `ride` *(선택)* | 2 | 600ms | 무한 | 엘리베이터 상자 안에서 앞모습으로 서 있기(0: 층수 표시를 올려다봄, 1: 앞을 봄) | 0 |

- **퇴근**은 세트가 없습니다(빈 의자, phase6b 그대로 — 사람이 자리에 없음).
- **의자는 캐릭터 시트에 없습니다**(P7-3 판정). 의자·책상은 테마마다 다른 장면 칸(designer-office 몫)입니다. 겹침 순서(뒤 → 앞): **의자 등받이 → 오라 → 캐릭터(층 여섯) → 모니터·책상 윗면 → 책상 앞면(아랫몸 y 24 이하를 가림) → DOM(이름표·말풍선·"!")**. 앉은 프레임(`sit_down` 2, `type`, `think`, `idle`, `hand_up`)은 같은 기준점 (13, 28)에서 의자 등받이 위에 놓입니다. `sit_down` 0·1(선 모습)은 의자 앞에 서 있는 그림이라 순서가 같습니다.
- 테마가 더할 수 있는 것(선택): 같은 이름에 프레임 수만 늘리기(예: 판타지 `walk_left` 6프레임). 프레임 수는 테마 매니페스트에 적고 CSS 변수(`--frames`)로 받습니다. **이름·행 순서·칸 크기·기준점은 바꾸지 않습니다.**
- 쉬는 곳(탕비실·카페·옥상)은 **장소 소품 쪽 계약**이고 캐릭터 세트는 `coffee` 하나를 함께 씁니다. 행 9·10은 **4방향 테마만** 채웁니다(리드 SPEC §3a). 없으면 좌우 걷기로 대신합니다. 행 11·12는 **엘리베이터가 있는 건물 장면만** 씁니다(§3.2). 옥상·카페 전용 동작(기지개 등)이 필요하면 행 13부터 덧붙입니다.

## 1a. 층 계약 — 테마는 옷과 팔레트만 바꾼다

한 프레임 = 아래부터 **`body` → `outfit` → `hands` → `hair` → `glasses` → `prop`** 여섯 층. 모든 층 시트는 `office-character.png`와 **같은 크기·같은 칸 배치**(104×390, 행 = 세트)라서, 한 요소에 `background-image`를 여러 장 겹치고 `background-position` 하나로 함께 움직입니다(요소는 캐릭터당 하나).

| 층 | 담는 것 | 테마가 바꾸는 법 |
|---|---|---|
| `body` | 얼굴·표정(눈·입·홍조)·목·귀 | 보통 그대로. 피부 3단(`S1~S3`)만 팔레트로 바꿀 수 있음(예: 우주선 테마의 외계인) |
| `outfit` | 셔츠·팔(소매)·바지·신발 | **다시 그려도 됨**(로브·우주복·재킷). 단 실루엣 칸 안에서: 앞모습 몸통 x 5–20 / y 14–28, 옆모습 x 5–19 / y 13–28. 팔 위치는 이 시트를 따름 |
| `hands` | 손(셔츠 위에 와야 해서 따로) | 팔레트만(장갑 색) |
| `hair-*` | 머리 모양 셋 + 눈썹(고민 표정) | 팔레트만(머리색). 모양은 머리 칸 x 5–20 / y 0–12 안 |
| `glasses` | 안경테(선 없음) | 팔레트만, 또는 고글 등으로 다시 그림(같은 칸) |
| `prop` | 머그·김·땀방울 | 테마 소품으로 다시 그림(판타지: 물약 잔, 우주선: 파우치) |

- **외곽선 규칙:** 각 층은 자기 둘레에만 `--panel` 선을 두되, **아래 층이 이미 칠한 칸에는 선을 두지 않습니다**. 그래서 머리 모양·안경을 바꿔도 얼굴·옷 층의 선이 그대로 맞습니다(`scripts/theme-assets/make-sheet.mjs`의 `Fr.finish`). 머그만 예외로 늘 둘레 전체에 선.
- **색 역할 이름**(팔레트 슬롯): 피부 `S1 S2 S3`, 머리 `H1 H2 H3`, 옷 `C1 C2 C3`(밝음·중간·그늘), 바지 `P1 P2`, 신발 `K`, 외곽선 `O`. 팀원 변형(beta15 §8: 머리 셋 × 머리색 × 셔츠 × 안경)과 테마는 모두 **이 슬롯 색만 바꾼 PNG를 빌드 때 만들어** 씁니다. 런타임 `filter`·`hue-rotate`는 쓰지 않습니다(팔레트가 어긋나고 매 프레임 비쌈).
- `renders/layers-variants-4x.png` 아래 줄이 같은 실루엣에 테마 팔레트 넷(office·fantasy·space·cyber)만 바꾼 모습입니다.

## 1b. 노력 정도 오라 겹치는 자리

- 별도 시트 `web/themes/office/aura.png`, 칸 **38×50**, 행 = `effort.level` 1~4, 열 = 프레임 0·1. 캐릭터 칸(26×30)을 오라 칸의 **(6, 20)**에 놓으면 맞습니다 → 기준점은 캐릭터 (13, 28) = 오라 (19, 48).
- **캐릭터 뒤**에 그림(별도 요소, `z-index`가 캐릭터보다 아래, 책상·모니터보다도 아래 — beta15 §7a). 말풍선·이름표는 DOM이라 오라 위.
- **`type`(working)일 때만** 보입니다. 걷기·커피 중에는 숨김. 단계 기준은 beta15 §7a(low 1 · medium 2 · high 3 · xhigh/max 4, 값 없으면 1).
- 움직임: 2프레임 400ms `steps(2)` — 불꽃 끝이 한 칸 엇갈리고 입자가 한 칸 위로. 밝기·투명도 변화 없음. 움직임 줄이기면 프레임 0.
- 4단계 머리색: `web/themes/office/layers/hair-<모양>-gold.png`로 바꿔 끼움(`H1 #fff7a8 · H2 #ffd84a · H3 #a87a10`, 생성기가 만듦).
- 오라 모양은 실루엣(type 프레임 0)에서 자동으로 만들므로, 테마가 실루엣을 크게 바꾸면 같은 스크립트로 다시 뽑습니다. 색(`--yellow-deep` → `--yellow` → 흰 심)은 테마가 바꿀 수 있음(사이버펑크: 분홍 불꽃 등).

### 3.1 탕비실 규칙(team-lead 판정)

| 규칙 | 값 |
|---|---|
| 걷기 시작 | 쉼이 **30초** 이어지면(`longIdle` 1시간과 별개) |
| 동시에 걷는 사람 | 층마다 **최대 2명**. 3번째부터는 앞 사람이 도착할 때까지 자리에서 `idle`로 기다렸다가 출발 |
| 일이 다시 시작됨 | **곧바로** 그 자리에서 돌아서 자리로(걷는 중이면 방향만 바꿈, 커피는 끝까지 마시지 않음). 돌아가는 걷기는 최대 2명 제한에 걸리지 않음(일이 우선) |
| 손들기 | 그 자리에서 `hand_up_stand` + "!" 풍선. 책상에도 결정 표시가 남음 |
| 움직임 줄이기 | 걷지 않음. 쉼 30초가 되면 바로 탕비실 자리에 `coffee` 프레임 0(정지), 일이 시작되면 바로 자리에 `type` 프레임 0 |

### 3.2 엘리베이터 타기(선택, 사용자 참고작의 분위기만 따름)

> **사용 — longIdle 카페 이동, 1명씩.** 사용자 결정(앞의 "이번 Phase 미사용" 판정을 대체): 짧게 쉬면 탕비실(§3.1), **longIdle(1시간)이면 엘리베이터로 카페 층**에 가고, 일이 다시 시작되면 엘리베이터로 돌아옵니다. 순서는 §3.3.

상자 칸은 designer-office 몫이고, 크기·기준점은 아래 값으로 **확정**했습니다(designer-office 합의). 상자 그림은 뒷벽(뒤)과 문짝·테두리(앞) 두 장이고, 문 프레임은 닫힘·반·열림 셋입니다. 통로 폭은 900폭에서 34칸(×2 = 68px)입니다.

| 항목 | 값 |
|---|---|
| 상자 안쪽 | 1배율 **30×34** |
| 기준점 | 상자 바닥 가운데 **(15, 32)** = 캐릭터 (13, 28). 캐릭터 칸은 상자 **(2, 4)**에 놓임 |
| 겹침(뒤 → 앞) | 상자 뒷벽 → 캐릭터 → 문짝·상자 테두리 → 층수 표시(DOM) |
| 문 | 타기 전·내리기 전에 문을 닫힘 → 반 → 열림(프레임마다 100ms, `steps(3)`), 사람이 상자 안(또는 통로)에 다 들어간 뒤 거꾸로 닫힘. 움직임 줄이기면 문은 늘 닫힘으로 둠 |
| 타기 | 문이 열림이 된 뒤, 층 통로에서 `walk_left`/`walk_right`로 문 가운데까지(마지막 4프레임, 프레임마다 3칸) → 바로 `ride` |
| 출발·도착 | `ride_lurch` 한 번(0.2초) → `ride` |
| 이동 | 상자만 `transform: translateY`를 `steps()`로 **프레임마다 2칸**(층 높이 44칸이면 `steps(22)`, 120ms/프레임 = 2.64초). 캐릭터는 상자 안에서 `ride` 반복 |
| 내리기 | `ride_lurch` → 문 가운데에서 `walk_*`로 통로로 |
| 움직임 줄이기 | 상자·캐릭터 모두 이동하지 않음. 상자는 도착 층에 바로 놓이고, 캐릭터는 그 층 목적지에 바로 놓임(정지 프레임은 목적지 상태의 것). 타는 중 모습이 필요하면 `ride` 0 |

- 상자 안에서도 이름표는 캐릭터를 따라갑니다(DOM, 상자 바깥으로 넘치면 상자 위에 붙음).
- **한 번에 1명만 탑니다.** 다음 사람은 상자가 돌아올 때까지 자기 자리(또는 카페 자리)에서 그대로 기다렸다가 출발합니다. 일이 다시 시작되어 돌아가는 사람이 카페로 가는 사람보다 먼저 탑니다(일이 우선, §3.1과 같음).

아래층 = 자기 층(자리), 위층 = 카페 층. 그림은 두 층을 한 장에 줄여 그렸습니다(실제 층 사이 거리는 건물 장면이 정함).

- **움직임 줄이기:** 걷기·엘리베이터 모두 하지 않습니다. longIdle이 되면 바로 **카페 자리에 `idle` 프레임 0(앉은 정지 그림)**, 일이 시작되면 바로 자리에 `type` 프레임 0.
- 카페에 가 있는 동안 빈 자리에는 「안」 `카페 ↑`(DOM, 탕비실의 `탕비실 →`와 같은 방식).
- **카페에서 손들기(team-lead 최종):** 그 자리에서 손들지 않고, **일이 다시 시작될 때와 같은 길**(6 → 7 → 8)로 엘리베이터를 타고 자기 자리에 돌아온 뒤 `sit_down` → `hand_up` + "!" 풍선. 엘리베이터 순서는 일하러 돌아가는 사람과 같은 우선. **돌아오는 동안에도 책상의 결정 표시는 바로 보입니다**(사람이 도착하기 전부터 — 결정을 놓치지 않게). 움직임 줄이기면 바로 자리에 `hand_up` 프레임 0. 탕비실(같은 층)은 지금처럼 그 자리에서 `hand_up_stand`(§3.1).
- 사용자가 HUD로 층을 옮기는 이동과 겹치면 **HUD 이동이 먼저**입니다(캐릭터의 엘리베이터 이동은 그 뒤에).

### 3.1a 계획기 세부

탕비실 걷기 규칙은 SPEC.md 탕비실 목록을 따름.

- 걷는 동안 이름표·말풍선은 캐릭터 감싸개(`.agent`) 안에 있어 같이 움직입니다(누르면 그 팀원 패널).
- 위치 이동도 계단식: `transform: translateX()`를 `steps(26)`로(픽셀 사이 번짐 없음). 거리가 다르면 `steps(ceil(거리/3))`.

## 4. 깜빡임·움직임 줄이기 규칙

- 모든 프레임 전환은 **`steps(n)`**, 밝기·투명도·`filter`를 애니메이션하지 않습니다. 바뀌는 것은 그림의 위치(프레임 칸)뿐입니다. (지금 `styles.css`의 `blink`·`frameA/B`는 투명도를 바꾸므로 새 캐릭터에는 쓰지 않습니다.)
- `@media (prefers-reduced-motion: reduce)`: `animation: none` + 위 표의 멈춤 프레임을 `background-position`으로 고정. 걷기는 하지 않고 캐릭터를 목적지에 바로 놓습니다(beta15 §6과 같음). `sit_down`/`stand_up`도 건너뛰고 끝 모습만.

## 5. 30명이어도 가볍게

1. **시트 한 장 공유**: 모든 캐릭터가 같은 층 시트들(합계 약 9KB)을 `background-image` 여러 장으로 — 한 번 내려받고 한 번 디코드. 층 수만큼 요소를 늘리지 않음. 색 변형(머리·셔츠·안경, beta15 §8)은 빌드 때 팔레트만 바꾼 시트 몇 장(각 ~2KB)으로, 런타임 `filter`는 쓰지 않습니다.
2. **CSS 스프라이트 오프셋**: 캐릭터 하나 = `div` 하나. 세트는 행(`--row`), 프레임은 `steps()`로 `background-position-x`만 움직임. JS 타이머 없음.
3. **정수 배율**: `background-size`를 시트 크기 × `--px`(3 또는 4), `image-rendering: pixelated`.
4. **화면 밖은 멈춤**: 접힌 층·스크롤 밖 층은 `content-visibility: auto`로 그리지 않고, IntersectionObserver가 `.floor--offscreen`을 붙여 `animation-play-state: paused`. 탭이 숨으면 브라우저가 알아서 멈춤.
5. **걷기 중에만 레이아웃 이동**: 위치는 `transform`(합성 단계)만 바꾸고 `left`·`top`은 건드리지 않습니다.

```css
/* 목업 예시 — 제품 코드 아님 */
.char {
  --px: 3; --row: 5; --frames: 4; --dur: .8s;
  width: calc(26px * var(--px)); height: calc(30px * var(--px));
  background: url(web/themes/office/office-character.png) 0 calc(var(--row) * -30px * var(--px)) / calc(104px * var(--px)) auto no-repeat;
  image-rendering: pixelated;
  animation: char-play var(--dur) steps(var(--frames)) infinite;
}
@keyframes char-play { to { background-position-x: calc(var(--frames) * -26px * var(--px)); } }
.char--walk-right { --row: 1; --dur: .48s; }
.char--sit-down   { --row: 2; --frames: 3; --dur: .3s; animation-iteration-count: 1; animation-fill-mode: forwards; }
.char--stand-up   { --row: 2; --frames: 3; --dur: .3s; animation-iteration-count: 1; animation-direction: reverse; animation-fill-mode: forwards; }
/* coffee는 프레임 길이가 달라 % 키프레임 4개를 steps(1)로 */
.floor--offscreen .char { animation-play-state: paused; }
@media (prefers-reduced-motion: reduce) {
  .char { animation: none; background-position-x: calc(var(--freeze, 0) * -26px * var(--px)); }
  .char--sit-down { --freeze: 2; }
}
```
