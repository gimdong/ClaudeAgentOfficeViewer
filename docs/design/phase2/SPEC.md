- **대상:** developer (Task 8, 9, 10). Task들이 이 문서의 절 번호(§1–§9)를 인용합니다.

## §1 결정 보고서 (줄인 모양, Ruling B27)

### 1.1 구조

```
┌ 6px 남은 시간 막대 ─────────────────────────────────────┐   ← 답할 수 있을 때만(1.3)
│ [아바타 48]  3F claude_project · developer   [‹][›][×] │   머리
│              이 명령을 실행해도 될까요?  (17px 굵게)     │
│              [권한 요청] 1 / 3   9:32 남음 · 지나면 터미널에서 묻습니다 │
├─────────────────────────────────────────────────────────┤
│ (상태 배너 §3)                                          │
│ 하려는 일   도구 Bash                                   │   스크롤 영역
│             ┌ npm run test -- --run web/ ┐  코드 상자   │
│             설명  웹 테스트 실행                         │
│ 이유        이 명령을 실행해도 될지 묻고 있습니다         │
│ 답하기      (종류별 §2)                                  │
└─────────────────────────────────────────────────────────┘
```

**Phase 1 8장에서 뺀 것:** 채팅 입력과 보낸 메시지 기록(아래 고정 영역 전체), "지금까지의 흐름", 추천 딱지와 추천 이유, "이 세션에서 같은 명령은 다시 묻지 않기", "{n}k 늘리고 계속", 팀원 요청 선택지. 서랍 아래쪽 고정 영역이 없어지므로 스크롤 영역이 서랍 끝까지 갑니다.

**그대로 쓰는 것(Phase 1 8.1):**
- 서랍: 폭 440px, 배경 `--panel`, 왼쪽 테두리 4px `--yellow`, 그림자, 열기 애니메이션 `slide-in` 0.16초 steps(4)
- 아바타: 48×48, `BODY_UP` 0–6행
- 섹션 제목: 11px `--muted`, 섹션 사이 1px 점선
- 코드 상자와 버튼(높이 36px, 여백 `0 16px`, 13px)
- 720px 이하에서는 아래 시트(`top: 8vh`, 위 테두리 4px `--yellow`)로 바뀝니다.

### 1.2 머리

| 요소 | 값 |
|---|---|
| 누가 | `{층 번호}F {층 이름} · {에이전트 이름}`(11px `--muted`) |
| 제목 | §2의 종류별 제목. `--font-text` 17px 700, `id="rp-title"`, `tabindex="-1"` |
| 종류 칩 | `권한 요청` / `질문` / `계획 승인` / `예산 도달` / `팀원 요청`. 11px, 2px `--yellow` 테두리, 글자 `--yellow` |
| 순번 | `{i} / {N}`. N은 **모든 층의 대기 중 결정 수**이고, 오래 기다린 것부터 셉니다. 보고서만 있는 결정(팀원 요청, 보고서만인 계획)도 셉니다 |
| ‹ › | 28×28 `.icon-btn`. 처음과 끝에서는 `disabled`. aria-label `이전 결정` / `다음 결정` |
| × | 28×28, aria-label `닫기` |
| 남은 시간 | 1.3 |

### 1.3 남은 시간

- **답할 수 있는 결정(`answerable: true`이고 `deadline`이 있는 결정)에만** 막대와 남은 시간을 보여 줍니다. 팀원 요청, 보고서만인 계획, 예산 대체 방식(B39가 "대체"일 때)에는 막대가 없습니다. 그 자리에는 §2의 안내 문장을 씁니다.
- 기준은 `deadline`(= `createdAt + 590초`, Ruling B29)입니다. 막대 폭은 `남은 초 / 590 × 100%`입니다. 그래서 처음 열면 `9:50 남음`부터 시작합니다.
- 문구: `{m:ss} 남음 · 지나면 터미널에서 묻습니다`(11px `--muted`). 남은 시간이 0이 되면 §3의 "시간이 지나 터미널로 넘어감"으로 바뀝니다.
- **60초 이하**: 막대와 문구를 `--pink`로 바꾸고, 막대는 1초 주기로 깜빡입니다(steps(1)). 손든 캐릭터의 ?도 급함 팔레트로 바뀝니다(Phase 1 6장).
- 매초 바뀌는 숫자는 `aria-live="off"`입니다. 60초와 10초가 남았을 때만 live region에 알립니다(§9).

### 1.4 본문

| 절 | 내용 |
|---|---|
| 하려는 일 | 첫 줄 `도구 {toolName}`(12px `--font-pixel`). 그 아래 **요약 코드 상자** 하나와 키/값 목록 |
| 이유 | `whyLine`의 한 줄(§2 표). `--font-text` 14px |
| 답하기 | §2 |

**요약 코드 상자의 값** (`DecisionDetail`에서 처음 있는 것 하나):
`command` → `filePath` → `pattern` → `query` → `domain` → `to`

- 상자는 Phase 1 8.1 그대로입니다(monospace 12px, 최대 7.5em, 넘치면 `전체 보기` / `접기` 버튼).
- 값은 서버가 이미 가리고 200자로 자른 것이라 화면에서 다시 자르지 않습니다.
- 위의 값이 하나도 없으면 상자 대신 `입력 요약이 없습니다`(13px `--muted`)를 씁니다.

키/값 목록(11px, 값이 있는 것만):
- `설명`은 `detail.description`입니다.
- 질문·계획·예산·팀원 요청은 §2에서 정한 행을 씁니다.

## §2 종류별 답하기

### 2.1 권한 요청 (`permission`)

| 항목 | 값 |
|---|---|
| 제목 | `Bash` → `이 명령을 실행해도 될까요?` / `Edit`·`MultiEdit`·`NotebookEdit` → `이 파일을 고쳐도 될까요?` / `Write` → `이 파일을 만들어도 될까요?` / `WebFetch` → `이 페이지를 열어도 될까요?` / 그 밖 → `이 도구를 써도 될까요?` |
| 이유 | `Bash` → `이 명령을 실행해도 될지 묻고 있습니다` / 파일 도구 → `이 파일을 바꿔도 될지 묻고 있습니다` / 그 밖 → `이 도구를 써도 될지 묻고 있습니다` |
| 이유 입력 | 라벨 `거부 이유 (선택, Claude에게 전달됩니다)`. 한 줄 `<input type="text" maxlength="200">`, 폭 100%, 배경 `--slab`, 2px `--desk`, 포커스하면 `--cyan`. 오른쪽 아래에 `{n}/200`(10px `--muted`). 비워 두면 서버가 기본 문구를 씁니다 |
| 버튼 | `[허용]`(초록 채움) `[거부]`(분홍 테두리). 순서는 이 순서, 사이 8px |
| 키보드 | 이유 입력에서 Enter(한글 조합 중 제외)는 **거부**를 보냅니다 |
| 보내는 값 | `{action:"allow"}` / `{action:"deny", reason?}` |

DOM 순서는 이유 입력 → 허용 → 거부입니다. 열릴 때 포커스는 **거부**입니다(§4). Shift+Tab으로 허용과 이유 입력에 갑니다.

### 2.2 질문 (`question`, Ruling B30)

| 항목 | 값 |
|---|---|
| 제목 | `질문에 답해 주세요` |
| 이유 | `작업을 이어 가려면 답이 필요합니다` |
| 하려는 일 | 코드 상자 없이 키/값 한 행 `질문 {n}개` |
| 질문 하나 | `<fieldset>` + `<legend>`. `header`가 있으면 legend 위에 11px `--muted`로 쓰고, legend는 질문 원문(`--font-text` 14px 700)입니다 |
| 선택지 | 단일 선택은 라디오, 다중 선택은 체크박스입니다. 상자는 Phase 1 8.2 선택지 상자 그대로입니다(여백 8px 10px, 2px `--desk`, 호버 `--cyan`, 선택 `--yellow` + 배경 `#1c1a2c`). 라벨 14px, 설명 12px `--muted`. **같은 label이 둘이어도 따로 고를 수 있게** 값은 인덱스입니다 |
| 기타 | 각 질문의 마지막 선택지 `기타 (직접 입력)`. 고르면 그 아래에 입력란(`<textarea>` 2줄, `maxlength="500"`, 카운터 `{n}/500`)이 나타납니다. 입력란 라벨 `기타 답` |
| 다중 선택의 기타 | 기타는 다른 선택지와 함께 고를 수 없습니다. 기타를 고르면 다른 선택이 풀리고, 다른 선택지를 고르면 기타가 풀립니다 |
| 보내기 | `[이 답 보내기]`(초록 채움). 모든 질문에 답하기 전에는 `aria-disabled="true"`이고, 버튼 바로 위에 `모든 질문에 답하면 보낼 수 있습니다`(12px `--muted`, 버튼의 `aria-describedby`)를 씁니다. 기타를 골랐는데 입력이 비어 있으면 답하지 않은 것으로 봅니다 |
| 키보드 | 라디오는 화살표 키로 움직입니다(브라우저 기본). 기타 입력에서 Enter(한글 조합 중 제외)는 답이 다 찼을 때만 보내고, Shift+Enter는 줄바꿈입니다 |
| 보내는 값 | `{action:"answer", answers:[{labels:[i,…]} 또는 {other:"…"}]}`(질문 순서) |

질문에는 거부 버튼이 없습니다. 답하지 않으려면 닫고 터미널에서 답합니다.

### 2.4 예산 도달 (`budget`, Ruling B34·B35·B39)

| 항목 | 값 |
|---|---|
| 제목 | `예산에 도달했습니다. 계속할까요?` |
| 이유 | `예산 {예산 표기}에 도달했습니다` (예: `예산 50만 토큰에 도달했습니다`) |
| 하려는 일 | 코드 상자에 멈춘 도구 호출의 요약(1.4 규칙). 키/값: `예산` `{예산 표기}`, `지금까지 쓴 양` `{사용량 표기}` |
| 안내 | 버튼 위에 13px `--muted`로 두 줄을 씁니다. 기본 방식(B39 "기본"): `계속을 누르면 이 도구 실행도 함께 허용됩니다` / `예산만큼 더 쓰면 다시 묻습니다`. 대체 방식(B39 "대체"): `계속을 누르면 다음 도구 실행부터 통과합니다` / `예산만큼 더 쓰면 다시 묻습니다` |
| 버튼 | `[계속]`(초록 채움) `[중단]`(분홍 테두리) |
| 보내는 값 | `{action:"continue"}` / `{action:"stop"}` |

**숫자 표기:**
- **예산 표기**: 1억으로 나누어떨어지면 `{n}억 토큰`, 1만으로 나누어떨어지면 `{n}만 토큰`, 그 밖은 `{쉼표} 토큰`입니다. 예: 500,000 → `50만 토큰`, 100,000,000 → `1억 토큰`, 123,456 → `123,456 토큰`.
- **사용량 표기**: 항상 `{쉼표} 토큰`입니다(정확한 값). 예: `512,340 토큰`.

## §3 상태 배너와 다음 결정으로 넘어가기

배너는 머리 바로 아래, 스크롤 영역 위에 있습니다. 여백 `10px 14px 0`, 안쪽 `8px 10px`, 2px 테두리, `--font-text` 13px입니다. `role="status"`이고, 보내기 실패만 `role="alert"`입니다.

| 상태 | 언제 | 색 | 문구 (`resultLine`) | 컨트롤 |
|---|---|---|---|---|
| 보내는 중 | POST 중 | `--cyan` | `보내는 중…` | 답하기 잠금(투명도 .4) |
| 대시보드에서 답함 | POST 성공, 또는 다른 탭이 답함(`answered-dashboard`) | `--green` | `outcome`별: allow `대시보드에서 허용함`(계획은 `대시보드에서 승인함`) / deny `대시보드에서 거부함` / answer `대시보드에서 답함` / continue `대시보드에서 계속함` / stop `대시보드에서 중단함` | 잠금 |
| 터미널에서 이미 답함 | `closed-terminal` | `--yellow` | `터미널에서 이미 답함` | 잠금 |
| 이미 답한 요청 | POST가 409 | `--yellow` | `이미 터미널에서 답했습니다` | 잠금 |
| 시간이 지남 | `expired`, 또는 남은 시간 0 | `--yellow` | `시간이 지나 터미널로 넘어감` | 잠금 |
| 요청이 사라짐 | 열어 둔 결정이 목록에서 없어짐(서버 재시작 등) | `--yellow` | `이 요청은 끝났습니다. 터미널을 확인해 주세요` | 잠금 |
| 보내기 실패 | 네트워크 오류, 5xx | `--red` | `보내지 못했습니다. 서버 연결을 확인하고 다시 시도해 주세요.` + `[다시 시도]` | 활성. 입력한 이유와 선택은 그대로 |

- 대체 방식 예산에서 `중단`을 보냈을 때만 초록 배너 뒤에 한 줄을 덧붙입니다: `대시보드에서 중단함. 이 층의 도구 실행은 계속 막힙니다. 다시 하려면 예산 설정을 바꿔 주세요.`
- POST가 401이면 배너 대신 앱 전체가 §8 화면으로 바뀝니다.

**다음 결정으로 넘어가기 (스펙 4장, Phase 1 8.3의 1.5초와 5초를 대체):**
- 잠금 배너(실패를 뺀 위 표의 모든 상태)가 뜬 뒤 **3초** 뒤에 동작합니다.
  - 대기 중 결정이 남아 있으면 가장 오래 기다린 결정으로 넘어갑니다.
  - 남은 결정이 없으면 서랍을 닫습니다.
- 3초 동안 배너 오른쪽에 `[닫기]` 버튼을 둡니다(높이 26px). 누르면 바로 닫습니다.
- **예외:** 입력란(거부 이유, 고칠 점, 기타 답)에 포커스가 있으면 자동으로 넘기지 않고 `[닫기]`만 둡니다. 입력 중인 글을 잃지 않게 하려는 것입니다. 버튼을 눌러 보낸 경우에는 포커스가 버튼에 있으므로 자동으로 넘어갑니다.
- 3초를 세는 숫자는 화면에 보이지 않습니다.
- 넘어가면 §4의 포커스 규칙을 다시 적용하고, live region에 §9의 "다음 결정" 문장을 알립니다.

## §6 예산 막대와 설정 창

### 6.1 층 머리의 예산 자리

Phase 1의 `예산 없음` 미니 바 자리(`.bars`의 두 번째)를 바꿉니다. 종료 층에는 Phase 1처럼 바를 두지 않습니다.

| 상태 | 모양 |
|---|---|
| 예산 없음 | `예산 없음`(Phase 1 미니 바 none) + 설정 버튼 |
| 예산 있음 | Phase 1 미니 바(라벨 `예산`, 트랙 80×10, `{n}%`) + 설정 버튼 |
| 예산 도달 | 미니 바 `0%`(분홍 깜빡임, Phase 1 A3 danger) + 설정 버튼 + §7 |

- **남은 양 %** = `(nextGateAt − usedTokens) / budgetTokens × 100`을 0–100으로 자르고 반올림한 값입니다. 색은 Phase 1 A3을 따릅니다(50 이상 초록, 20 이상 노랑, 그 아래 분홍).
- 미니 바에 `title="{사용량 표기} / {nextGateAt 쉼표} 토큰"`을 붙입니다. 예: `512,340 / 1,000,000 토큰`.
- `role="meter"`, aria-label `예산 남은 양`, `aria-valuetext="남은 양 {n}%, {사용량 표기} 사용"`.
- **설정 버튼:** 미니 바 바로 오른쪽(간격 6px)에 둡니다.
  - 크기 24×24, 2px `--desk` 테두리, 배경 없음, 아이콘 `settings` 14px. 호버하면 `--cyan`입니다.
  - aria-label `{층 이름} 예산 설정`, `aria-haspopup="dialog"`.
  - 층이 접혀 있어도 머리에 있으므로 보입니다.

### 6.2 설정 창

Phase 1 9장 대화상자 모양(`<dialog>.showModal()`, 폭 `min(420px, 100vw − 32px)`, 4px `--desk` 테두리)을 씁니다.

```
┌ {층 이름} 예산 ─────────────────────────────┐
│ 이 층의 예산                                 │
│ [ 500,000                     ] 토큰         │
│ 지금까지 쓴 양 512,340 토큰                   │
│ 비워 두면 예산 없음. 1,000 ~ 1,000,000,000   │
│                                              │
│ 새 층의 기본값                               │
│ [                             ] 토큰         │
│ 앞으로 새로 생기는 층에 적용됩니다.           │
│ 지금 있는 층은 바뀌지 않습니다.               │
│                                              │
│ (알림 안내 한 줄)                            │
│                          [취소] [저장]       │
└──────────────────────────────────────────────┘
```

| 항목 | 값 |
|---|---|
| 제목 | `{층 이름} 예산` (`--font-text` 17px 700) |
| 입력 | `<input type="text" inputmode="numeric" autocomplete="off">`, 폭은 남은 폭 전부, 오른쪽에 `토큰`(12px `--muted`). 처음 값은 현재 값을 쉼표로 씁니다(없으면 빈칸) |
| 입력 규칙 | 쉼표와 공백은 지우고 읽습니다. 그 뒤 빈 값이면 "예산 없음"(`null`)입니다. 정수가 아니거나 1,000–1,000,000,000 밖이면 저장하지 않고 그 칸 아래에 `1,000에서 1,000,000,000 사이의 정수를 입력해 주세요`(12px `--red`)를 씁니다. 칸에 `aria-invalid="true"`를 주고 `aria-describedby`로 연결합니다 |
| 보조 줄 | 이 층 칸 아래: `지금까지 쓴 양 {사용량 표기}` / `비워 두면 예산 없음. 1,000 ~ 1,000,000,000`. 기본값 칸 아래: `앞으로 새로 생기는 층에 적용됩니다. 지금 있는 층은 바뀌지 않습니다.` (모두 12px `--muted`) |
| 알림 안내 | `Notification.permission`에 따라 한 줄을 씁니다(12px `--muted`). `default`: `처음 저장할 때 브라우저가 알림을 허용할지 묻습니다. 거절해도 층 경광등은 켜집니다.` / `granted`: `예산에 닿으면 브라우저 알림과 층 경광등으로 알려 드립니다.` / `denied`: `브라우저 알림이 꺼져 있어 층 경광등만 켜집니다.` / 지원하지 않음: `이 브라우저는 알림을 지원하지 않아 층 경광등만 켜집니다.` |
| 버튼 | `[취소]` `[저장]`(초록 채움). 바뀐 칸만 `PUT /api/budget`으로 보냅니다 |
| 저장 중 | `[저장]`을 `disabled`로 바꾸고 글자를 `저장하는 중…`으로 바꿉니다 |
| 저장 실패 | 창을 닫지 않고 버튼 위에 `저장하지 못했습니다. 다시 시도해 주세요.`(`--red`, `role="alert"`)를 씁니다 |
| 처음 저장 | 예산을 처음 저장할 때(이 브라우저에서 한 번) `Notification.requestPermission()`을 부릅니다. 저장은 권한 결과를 기다리지 않습니다 |
| 포커스 | 열면 이 층의 예산 칸에 둡니다. Esc, 취소, 저장 성공이면 창을 닫고 **설정 버튼**으로 돌아갑니다 |

- 층 바로가기(엘리베이터)의 LED도 `led--budget`으로 바꿉니다. 결정 대기가 함께 있으면 Phase 1처럼 결정(노랑)이 우선입니다.

| 위치 | 문구 |

| 층 머리 | 예산 · 예산 없음 · 예산 도달 · `{n}%` |
| 미니 바 title | `{사용량} / {nextGateAt} 토큰` |

| 브라우저 알림 | 제목 `예산에 도달했습니다`, 본문 `{층 이름} — 계속할지 정해 주세요` (계획 Task 10) |

### 9.4 401

§8 표의 제목, 본문 두 문단, `$ claude-office`, 문서 제목 `접속 열쇠 필요 · Claude Office`.

### 9.5 live region 문장

모두 App의 하나뿐인 `role="status"`에 넣습니다. 같은 문장을 다시 넣을 때는 끝에 NBSP를 번갈아 붙입니다(Phase 1 Ruling P16, 테스트는 `endsWith`).

| 때 | 문장 |
|---|---|
| 남은 시간 60초 | `1분 남았습니다` |
| 남은 시간 10초 | `10초 남았습니다` |
| 답을 보냄, 또는 보고서를 연 채 결정이 끝남 | §3의 `resultLine` 그대로 |
| 보내기 실패 | `보내지 못했습니다` (배너가 `role="alert"`이므로 live region에는 넣지 않습니다) |
| 다음 결정으로 넘어감 | `다음 결정: {층 이름} {에이전트 이름}, {종류 칩 문구}` |
| 예산 도달(층마다, `nextGateAt`마다 한 번) | `{층 이름} 층이 예산에 도달했습니다` |
| 예산 저장 성공 | `예산을 저장했습니다` |

새 결정이 생겼을 때의 알림은 Phase 1 문장(`{층} {이름}이(가) 결정을 기다립니다`)을 그대로 씁니다.
