## §1 보고서를 내 책상 위에서 1인칭으로 (보고 3, 보고 1과 이어짐)

`renders/desk-report-900.png`, `desk-report-360.png`

### 1.1 장면

서류철에서 보고서 하나를 열면, 지금의 "서랍 안 종이"(phase6b §3.3) 대신 **책상을 위에서 내려다보는 창**이 열립니다.

| 자리 | 놓인 것 | 하는 일 |
|---|---|---|
| 가운데 | 보고서 종이(`--paper`, -1° 기울임, 클립) | 제목·`{리드} · {시각}`·본문(스크롤). 오른쪽 위 점선 도장 칸 `대기` |
| 종이 아래(겹쳐 붙음) | 노란 쪽지(+1° 기울임, 테이프) | **리드에게 쓰기** 칸(늘 펼침) + 왼쪽 `[답장 보내기]`(하늘, **제안** — 결재 없이 말만 전함) + 오른쪽 `[수정 요청 보내기]`(분홍) |
| 오른쪽 | 인주 + 도장 둘 | `[승인 도장]`(초록) 누르면 바로 승인 / `[수정 요청]`(분홍) 누르면 쪽지 칸으로 포커스 |
| 왼쪽 위 | 커피 잔(김이 남) | 장식(`aria-hidden`) |
| 왼쪽 아래 | 펜 | 장식 |
| 바닥 | 안내 한 줄 | `승인: 도장을 누르면 바로 보냅니다 · 답장·수정 요청: 노란 쪽지에 써서 보냅니다` |

- 책상판: `--desk`/`--desk-dark` 세로 판자 무늬(CSS 반복 그라데이션), 바깥 테두리 4px `--desk`. 창 크기 `min(640px, 100vw - 16px)`, `<dialog>.showModal`(Esc = 닫기, 열릴 때 포커스는 종이).
- 결재가 끝나면 종이에 도장이 찍히고(phase6b §3.3 도장 그대로) 쪽지·도장 자리는 `{시각}에 승인했습니다` 한 줄로 바뀝니다. 보관됨(휴업)은 점선 도장 그대로.

### 1.2 "보고서에서 직접 답하기가 안 된다"(보고 1)에 대한 디자인 쪽 답

원인은 developer·reviewer가 보지만, 화면만 봐도 걸리는 점이 있습니다: 지금은 답하는 칸이 `[수정 사항 적기]`를 눌러야 열리고(phase6b §3.4), 이름도 "수정 사항"이라 **"답"을 쓰는 자리로 보이지 않습니다**.

- 쪽지 칸을 **늘 펼쳐 둡니다**(누르지 않아도 보임). 머리 「안」 `리드에게 쓰기`, 빈 칸 안내 「안」 `답이나 고칠 점을 여기에 쓰세요`.
- 버튼 셋의 자리: **승인 = 도장**(오른쪽, 바로 보냄) / **수정 요청 = 쪽지 오른쪽 분홍 버튼**(지금의 `revise` 지시 그대로 — 틀·4,000자·글자로만) / **답장 = 쪽지 왼쪽 하늘 버튼**(제안). 쪽지 아래 한 줄 「안」 `답장은 결재 없이 말만 전합니다(새 기능 — 제안). 수정 요청은 이 보고서를 "수정 요청"으로 표시합니다.`
- `[답장 보내기]`는 **새 지시 종류**가 필요합니다(보고서 id + 사용자 글, 결재 상태를 바꾸지 않음 — 서버 틀·security 검토 필요). 사용자가 "그냥 답하기"를 원하면 넣고, 아니면 쪽지에는 `[수정 요청 보내기]` 하나만 둡니다.
- 서류철로 가는 길·답 칸의 "대기 보고서 N건 — 서류철 열기"·말풍선 글자는 B335로 developer가 지금 화면에서 먼저 고칩니다(§3). 이 장면은 그 서류철이 열린 뒤의 모습입니다.
- channel이 없는 층: 쪽지와 도장을 흐리게(`aria-disabled`) + 쪽지 위에 기존 이유 줄(`작업 지시 켜기(옮겨 열기)로 연결하면 쓸 수 있습니다`).

### 1.3 360폭

도장 둘은 쪽지 아래 가로 한 줄, 커피 잔은 오른쪽 위로 작게(0.6배), 펜·인주는 숨깁니다. 종이 제목은 도장 칸과 겹치지 않게 오른쪽 여백 56px(렌더에서 겹쳐 보여 고침).

### 1.4 키보드

종이(`tabindex=0`, 긴 글 스크롤) → 쪽지 칸 → `[수정 요청 보내기]` → `[승인 도장]` → `[수정 요청]` → 닫기. 소품은 Tab에 걸리지 않습니다. 도장 aria-label 「안」 `승인 도장 찍기` / `수정 요청 도장(쪽지 칸으로)`.

## §3 "· · ·"만 보이는 문제(보고 2) — 표시 개선안

`renders/await-900.png`, `await-360.png`(실제 Desk 컴포넌트에 표시만 바꿔 그림)

지금(beta.15): 리드 책상에 하늘 말머리 `· · ·`만 있고, `답을 기다립니다`는 마우스를 올려야 보입니다. 보고서가 와서 서류철과 `결재 2`가 함께 있으면, 사용자는 "보고서가 왔는데 · · ·만 보인다"로 읽습니다. 또 렌더에서 `· · ·`의 점이 말머리 양 끝에 붙어 글자로 읽히지 않았습니다.

| 안 | 말머리 | 이름표 아래 한 줄(`.desk-extra`) |
|---|---|---|
| 지금 | `· · ·` | `결재 2`(있으면) |
| **제안** | 「안」 `답?` (하늘 바탕, 글자 `--wall`) | 「안」 `답을 기다립니다`(하늘 바탕 칩) |

- **겹칠 때 우선순위:** 이름표 아래 한 줄은 `답을 기다립니다` > `결재 {n}`. 결재 대기는 책상 위 노란 서류철 그림이 계속 보여 주고, 수는 aria-label(`, 결재 대기 {n}건`)과 리드 패널 `[서류철 · 대기 n]`에 남습니다. 렌더 셋째 칸이 겹침 모습입니다.
- `답?`은 결정의 노란 ?(손들기, 머리 위 떠 있음)과 색(하늘)·자리(말머리 안)·모양(글자 + 물음표)이 달라 헷갈리지 않습니다.
- 칩 `답을 기다립니다`는 92px 안에 들어갑니다(10px 8자, 렌더 확인).
- **원인 확정·B335(developer가 지금 화면에서 먼저 고침):** 보고서를 낸 턴의 Stop은 "답을 기다립니다"를 만들지 않고, 말풍선에 `답을 기다립니다` 글자를 보이며, 결재 칩·서류철 그림을 서류철을 여는 버튼으로 만들고, 답 칸에 「안」 `대기 보고서 {n}건 — 서류철 열기`를 둡니다. 위 표의 제안(`답?` 말머리 + 칩)은 B335 커밋을 보고 SPEC·렌더를 맞춥니다(말풍선 안 긴 글자가 360폭에서 넘치면 이 칩 방식을 권함).

## §5 꺼진 버튼의 이유를 바로 보이게 (사용자 요청 4)

`renders/disabled-reason-900.png`, `-360.png`

"퇴근·퇴사가 그냥 비활성 버튼처럼 보인다." 지금은 버튼이 흐리고, 이유는 버튼 아래 작은 회색 줄(phase6b §1.2)이라 눈에 잘 띄지 않습니다.

- 작업 지시가 꺼진 층이면 **버튼 묶음 위**에 이유 상자: 하늘 점선 테두리, 세모 표시, 「안」 `이 층은 작업 지시가 꺼져 있어 아래 버튼을 쓸 수 없습니다.` + `[작업 지시 켜기]`(하늘 바탕 버튼 — 지금의 옮겨 열기 창을 엶).
- 꺼진 버튼에는 작은 자물쇠 도트를 앞에 붙여 "잠김"이 모양으로도 보이게 합니다(`aria-disabled` + `aria-describedby`는 지금처럼).
- 보고 요청·결재(서류철)·답 칸도 같은 상자 하나를 그 묶음 위에 둡니다. 연결되면 상자는 사라집니다.
- 360폭: 상자 안 글이 두 줄, 버튼은 그 아래 줄.

## §6 쉬는 팀원은 탕비실로 (사용자 요청 5)

`renders/pantry-900.png`, `-360.png`

- 층 방 오른쪽 끝에 칸막이 하나로 나눈 **탕비실**(커피 머신·소파). 이름표 `탕비실`(10px `--muted`).
- 오래 쉬는 팀원·퇴근 전 쉬는 팀원은 자기 책상에서 탕비실까지 **걸어가**(걷기 2프레임, steps) 커피 앞이나 소파에 머뭅니다. 빈 책상에는 「안」 `탕비실 →`.
- 다시 일하면 책상으로 걸어 돌아옵니다. 걷는 동안 이름표·말풍선은 캐릭터를 따라갑니다(누르면 그 팀원 패널).
- **`prefers-reduced-motion`:** 걷지 않고 바로 그 자리에 놓인 멈춘 그림(렌더가 그 모습).
- 360폭: 방이 좁아 탕비실은 맨 아래 줄 오른쪽 한 칸.
- 퇴근 팻말 빈 의자(phase6b)는 탕비실로 가지 않습니다(퇴근은 자리에 없음).

## §7 "일하는 중" 표시 — 불꽃과 오라 (사용자 요청 6)

`renders/aura-900.png`

키보드 이모지(`⌨`) 대신 캐릭터 주변 도트 효과. 노력 정도(developer #646 조사 결과로 기준을 정함)에 따라 4단계:

| 단계 | 모양 |
|---|---|
| 1 평소 | 효과 없음(모니터 켜짐만) |
| 2 불꽃 | 노란 도트 불꽃 2개가 번갈아 튐 |
| 3 오라 | 노란 점선 오라 한 겹 + 불꽃 4개 |
| 4 큰 오라 | 오라 두 겹(바깥 `--yellow-deep`) + 불꽃 7개 |

- 그림 속 오라는 둥근 점선으로 대략 그렸습니다. 확정 때는 도트 불꽃 모양(위로 솟는 3~4단 계단)으로 다시 그립니다.
- 움직임: 불꽃 반짝임만(0.4초 steps), 깜빡임 금지(번쩍임 없음). `prefers-reduced-motion`이면 정지한 오라.
- 말풍선 자리와 겹치지 않게 오라는 캐릭터·모니터 뒤에 그립니다.
