## 1. 목적

Phase 1의 대시보드는 보기만 했다. Phase 2부터는 **사용자가 대시보드에서 Claude Code의 결정 요청에 답할 수 있다.**

- 캐릭터가 손을 들면 클릭한다. 결정 보고서가 열리고, 거기서 허용·거부·선택을 하면 그 답이 Claude Code로 돌아간다.
- 층(세션)마다 토큰 예산을 둔다. 예산에 닿으면 알람을 울리고 "계속 진행?"을 묻는다.

## 2. 전제 (Phase 0에서 확인한 것)

- **결정은 모두 `PermissionRequest` hook에서 기다린다.**
  - 터미널 창과 hook은 동시에 진행되고, 먼저 답한 쪽이 적용된다.
  - 터미널이 먼저 답하거나 timeout이 지나면 hook HTTP 연결이 끊긴다. 서버는 이를 `res.on('close')`와 `!res.writableEnded`로 감지한다.
- **응답 형식**
  - 권한 요청: `{"hookSpecificOutput":{"hookEventName":"PermissionRequest","decision":{"behavior":"allow"|"deny"}}}`
  - 질문: `behavior:"allow"`에 `updatedInput`을 함께 보낸다. `updatedInput`은 **원래 `tool_input` 전체**에 `answers`(`{질문: 선택지 label 또는 자유 문자열}`)를 더한 것이다. 다중 선택은 `"a, b"`처럼 쓴다.
- **`PreToolUse`에서는 오래 기다리지 않는다.** 기다리는 동안 터미널이 멈추기 때문이다. 즉시 `ask` 또는 `deny`만 돌려준다.
- **설정 파일은 고치지 않는다.** 상태는 서버 쪽 저장소에만 둔다.

### 확인 스파이크 (Task 0, 구현 전에 한다)

Phase 0이 확인하지 못한 두 가지를 먼저 확인한다. 결과에 따라 아래 대체 방식을 쓴다.

1. **`PreToolUse`가 `ask`를 돌려주면 `PermissionRequest`가 이어서 오는가?**
   - 안 온다면 예산 관문은 대체 방식(5.3)을 쓴다.
2. **`ExitPlanMode`가 `PermissionRequest`를 거치고, allow·deny가 계획 승인·거부로 동작하는가?**
   - 안 된다면 계획 승인은 "보고서만"(팀원 결정과 같은 방식)으로 줄인다.

스파이크는 베타 때 정한 안전 규칙을 그대로 따른다.
- 실험 폴더와 임시 설정만 쓰고, 실제 `claude`는 절대 경로 바이너리를 쓴다.
- 실행 전후로 안전 값을 비교한다.
- 분류기가 막으면 멈춘다.

## 3. 구조

```
Claude Code ── PreToolUse (timeout 5s) ───────▶ 서버: 즉시 응답(평소엔 빈 200, 예산 관문이면 ask)
           ── PermissionRequest (timeout 600s) ▶ 서버: DecisionQueue에 보관하고 응답을 붙잡음
           ◀────────── decision JSON ────────── 대시보드에서 답하면 응답
브라우저 ── POST /api/decisions/:id (쿠키 인증) ▶ 서버 ── SSE로 상태 갱신 ──▶ 브라우저
```

### 3.1 플러그인
- `hooks.json`에서 `PermissionRequest`의 `timeout`을 5에서 **600**으로 올린다. 다른 hook은 5 그대로 둔다.
- 플러그인 버전을 올린다. 번호는 Q7 결정 때 정한다. 그 전까지는 `2.1.0-dev`를 쓴다.
- hook 요청에는 비밀값을 붙이지 않는다(5.5).

### 3.2 서버 `DecisionQueue` (`server/decisions/queue.ts`)
- **보관 단위**는 `{id, sessionId, agent, kind, toolName, summary(가림 적용), createdAt, state, res}`이다.
  - 원래 `tool_input`은 **서버 메모리에만** 둔다. 질문 응답의 `updatedInput`을 만들 때만 쓰고, 화면·로그·진단 파일에는 내보내지 않는다. 화면에는 Phase 1의 `redact()`와 요약 함수를 거친 값만 보낸다.
- **상태 변화**: `pending`은 다음 셋 중 하나로 바뀐다.
  - `answered-dashboard`: 대시보드에서 답했다.
  - `closed-terminal`: 연결이 끊겼다. 터미널이 먼저 답했거나 Claude Code의 timeout이 지난 경우다.
  - `expired`: 서버가 590초에 빈 200으로 놓아준 경우다. 이러면 터미널 창이 결정한다.
- **답은 한 번만 받는다.** `pending`이 아닌 결정에 대시보드가 답하면 409를 돌려주고, 화면에는 "이미 터미널에서 답했습니다"를 보여 준다.
- **서버를 다시 시작하면** 대기 중이던 결정은 사라진다. Claude Code 쪽 연결도 끊기므로 터미널 창이 남는다.
- **같은 세션에 결정이 여럿 있을 수 있다.** 화면에는 오래된 것부터 보여 준다.
- Phase 1의 결정 감지(`derive.ts`의 손들기)는 이 큐가 알려 주는 상태와 합친다. 손을 드는 기준은 큐에 `pending`이 있는지다.

### 3.3 결정 종류별 응답

| kind | 대시보드 선택 | hook 응답 |
|---|---|---|
| permission | 허용 / 거부 (+이유, 선택, 200자) | `allow` / `deny`. 거부 이유는 `message`로 보내고, 없으면 "대시보드에서 사용자가 거부했습니다"를 쓴다 |
| question | 질문마다 선택지 하나(다중 선택은 여럿) 또는 "기타" 자유 입력 | `allow` + `updatedInput` = 원래 입력 + `answers` |
| plan | 승인 / 거부 (+이유) | `allow` / `deny` (Task 0 결과를 따른다) |
| budget | 계속 / 중단 | 5장 |
| team | (답 없음) 보고서만 | — |

- 거부 이유는 Claude에게 전달되는 짧은 메모다. 자유 채팅을 대신하지 않는다(Q1). 이유 문자열은 서버 로그에 남기지 않는다.

## 4. 결정 보고서 화면 (designer → developer)

- **여는 방법**: 손을 든 캐릭터를 클릭하거나, HUD의 "결정 대기 N" 칩을 누른다. 칩을 누르면 가장 오래 기다린 결정이 열린다. Phase 1에 있던 칩을 쓴다.
- **패널**: 진단 패널과 같은 오른쪽 서랍을 쓴다. 담는 내용은 다음과 같다.
  - **누가**: 층 이름, 에이전트 이름
  - **무엇을**: 도구 이름, 그리고 가림을 거친 입력 요약. 예를 들어 Bash 명령, 파일 경로, 질문 문구
  - **왜**: 종류별 한 줄 설명. 예: "이 명령을 실행해도 될지 묻고 있습니다", "예산 50만 토큰에 도달했습니다"
  - **남은 시간**: 10분에서 거꾸로 셈
  - **선택지**: 3.3의 표를 따른다
- **답한 뒤**: 결과를 한 줄로 보여 준다. "대시보드에서 허용함", "터미널에서 이미 답함", "시간이 지나 터미널로 넘어감" 중 하나다. 3초 뒤 다음 결정으로 넘어가거나 패널을 닫는다.
- **접근성**: Phase 1의 규칙을 그대로 따른다. 포커스 이동과 복귀, 하나뿐인 live region에 문구를 바꿔 넣고 반복 시 NBSP를 번갈아 붙이며 `endsWith`로 테스트한다. 키보드만으로 모든 선택을 할 수 있어야 한다.
- **추천은 넣지 않는다**(Q5).

## 5. 예산 (R3)

### 5.1 저장
- 상태 파일은 설치본이면 `~/.claude-office/state.json`, 개발 중이면 `.logs/state.json`이다. 경로는 `resolvePaths`를 따른다.
- 형식은 `{ defaultBudgetTokens?, sessions: { [sessionId]: { budgetTokens, nextGateAt } } }`이다.
- 쓸 때는 원자적으로 쓴다(임시 파일에 쓴 뒤 rename). 읽기에 실패하면 빈 상태로 시작하고 warn 로그를 남긴다.
- 끝난 세션의 항목은 30일 뒤 정리한다.

### 5.2 사용량과 판정
- 사용량은 Phase 1 스냅샷의 세션 `TokenSum.total`(input + output + cacheWrite, cacheRead 제외)이다. 대화 기록에서 세므로 요금제와 관계없이 동작한다.
- `nextGateAt`의 처음 값은 `budgetTokens`이다. **"계속"을 고르면 `nextGateAt += budgetTokens`**가 된다(Q4-3).
- **알람**: 사용량이 `nextGateAt`에 닿는 순간 다음을 한다.
  - 해당 층에 경광등을 켠다. 움직임 줄이기 설정을 따른다.
  - 브라우저 알림을 한 번 보낸다. 알림 권한은 사용자가 처음 예산을 정할 때 묻는다. 거절하면 경광등만 쓴다.
  - 소리는 없다.

### 5.3 관문
- **기본 방식** (Task 0에서 1번이 확인되면 쓴다)
  - 사용량이 `nextGateAt` 이상이고 그 세션에 아직 처리되지 않은 관문이 있으면, 다음 `PreToolUse`에 **즉시** 아래를 돌려준다.
    `{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"ask","permissionDecisionReason":"예산(…토큰)에 도달했습니다. 대시보드나 이 창에서 계속할지 정해 주세요"}}`
  - 이어 오는 같은 도구 호출의 `PermissionRequest`는 `kind: budget`으로 큐에 넣는다.
  - "계속"을 고르면 `allow`를 보내고 `nextGateAt`을 올린다. "중단"을 고르면 `deny`와 함께 "예산에 도달해 사용자가 중단했습니다"를 보낸다.
- **대체 방식** (1번이 확인되지 않으면 쓴다)
  - `PreToolUse`가 즉시 `deny`와 "예산에 도달했습니다 — 대시보드에서 '계속'을 눌러 주세요"를 돌려준다.
  - 대시보드에서 "계속"을 누르면 `nextGateAt`을 올리고, 다음 도구 호출부터 통과시킨다.
  - 이 방식에서는 대시보드가 꺼져 있으면 작업이 막힌다. 그래서 **대시보드에 예산을 설정한 층에만** 적용한다. 대시보드가 꺼져 있으면 서버도 꺼져 있으므로 hook 연결이 실패하고 통과된다.
- **대시보드가 응답하지 않을 때**: 기본 방식에서는 터미널에 평범한 권한 창이 뜬다(Q4-5).
- **PreToolUse 응답 시간**: 판정은 메모리의 스냅샷 값만으로 하고, 5초 timeout 안에 끝낸다. 파일 읽기나 대화 기록 다시 읽기를 기다리지 않는다.

### 5.4 화면
- 층 머리에 있는 Phase 1의 "예산 없음" 자리를 바꾼다. 예산 막대(사용량 / `nextGateAt`)와 설정 버튼을 둔다.
- 설정 창에서 이 층의 예산(토큰)을 정하고, 새 층의 기본값도 정한다. 빈 값은 "예산 없음"이다.

## 6. 팀원 `[결정 필요]` (보고서만)
- 리드 세션 대화 기록에서 팀원이 team-lead에게 보낸 메시지를 찾는다. 요약이나 본문 첫 줄이 `[결정 필요]`로 시작하면 감지한다.
- 그 팀원 책상이 손을 들고, 보고서에 메시지 요약을 보여 준다(가림 적용, 200자).
- 버튼은 없다. 안내 문구는 "터미널(리드 세션)에서 답해 주세요"이다.
- **해제 조건**: 리드가 그 팀원에게 메시지를 보낸 뒤이거나, 30분이 지난 뒤다.

## 7. 보안

### 7.1 토큰
- **설치**: 설치 스크립트가 무작위 32바이트(hex)를 만들어 `~/.claude-office/token`에 저장한다.
  - 권한은 0600이다. Windows는 사용자 프로필 아래에 둔다.
  - 이미 있으면 그대로 둔다.
  - 개발 중에는 서버가 처음 켜질 때 `.logs/token`을 만든다.
- **접속**: `claude-office`가 `http://127.0.0.1:4317/?k=<토큰>`으로 브라우저를 연다. 서버는 토큰이 맞으면 다음을 한다.
  - `Set-Cookie: co=<토큰>`을 보낸다. 속성은 `HttpOnly; SameSite=Strict; Path=/; Max-Age=31536000`이다.
  - `/`로 리다이렉트한다. 그래서 주소창과 방문 기록에 토큰이 남지 않는다.
- **인증 범위**: `/hooks/event`와 화면 정적 파일을 뺀 모든 `/api/*`는 쿠키가 있어야 한다. 기존 진단 API와 스냅샷도 포함한다.
  - 쿠키가 없으면 401을 돌려주고, 화면은 "터미널에서 `claude-office`로 열어 주세요"를 보여 준다.
- **쓰기 API**는 쿠키에 더해 다음 조건을 모두 만족해야 한다.
  - 기존 Host 검사를 통과한다.
  - 같은 출처의 Origin이다.
  - `Content-Type: application/json`이다.
- **CLI**: `doctor`와 `diag`는 토큰 파일을 읽어 헤더로 보낸다.
- **로그와 진단**: 토큰 값은 어디에도 쓰지 않는다. doctor는 토큰 파일이 "있음/없음"만 본다.

### 7.2 hook 요청은 인증하지 않는다 (판정)
- hook 요청은 **결정을 요청**할 뿐이다. 허용을 **만들어 내는** 길은 쿠키 인증된 대시보드 API 하나뿐이다.
- 그래서 같은 PC의 다른 프로세스가 가짜 hook을 보내도, 할 수 있는 일은 화면에 가짜 요청을 띄우는 것뿐이다. 그 요청에 답해도 실제 Claude Code에는 아무 영향이 없다.
- hook에 비밀값을 붙이려면 Claude Code가 실행되는 환경변수(`allowedEnvVars`)가 필요하다. 이렇게 하면 설치(특히 Windows와 회사 정책)가 복잡해진다. 그래서 Phase 2에서는 넣지 않는다.
- 기존 검사(Host, Origin이 있으면 거부, 1MB, JSON)는 그대로 둔다.
- 남은 위험: 가짜 요청이 화면을 어지럽히는 정도이고, 6장의 남은 위험에 적는다.

## 8. 로그와 진단
- 결정마다 로그를 한 줄 남긴다. 기록하는 것은 `kind`, 결과(state), 걸린 시간(ms), 세션 순번이다. **도구 입력, 이유 문자열, 답 내용은 남기지 않는다.**
- doctor에 두 항목을 추가한다.
  - 토큰 파일이 있는지
  - 플러그인의 PermissionRequest timeout이 600인지. 플러그인 캐시를 읽어 확인한다.
- 진단 파일에 결정 통계를 넣는다. 종류별 건수와 결과별 건수다.

## 10. 완료 기준

1. **결정 큐 단위 테스트**
   - 대시보드 답이 정확한 JSON으로 돌아간다.
   - 연결이 끊기면 `closed-terminal`이 된다.
   - 590초가 지나면 `expired`가 된다.
   - 답한 뒤 다시 답하면 409를 돌려준다.
   - 질문의 `updatedInput`이 원래 입력과 `answers`로 이루어진다.
   - 화면과 로그에 원래 입력이 없다.
2. **예산**
   - 판정, `nextGateAt` 증가, 상태 파일의 원자적 쓰기와 손상 시 복구를 테스트한다.
   - PreToolUse가 1초 안에 응답한다(측정 테스트).
3. **보안**
   - 쿠키가 없으면 401이다.
   - 토큰 주소로 접속하면 쿠키가 생기고 리다이렉트된다.
   - 쓰기 API가 Origin, Content-Type, 쿠키를 모두 검사한다.
   - 토큰 값이 로그, 진단 파일, 스냅샷 어디에도 없다.
4. **끝에서 끝까지(이 Mac)**
   - 실험 세션(Phase 1과 같은 `--plugin-dir` 사본, 포트 4319)에서 권한이 필요한 명령을 실행하면 손들기가 뜬다. 대시보드에서 허용하면 명령이 실행된다. 같은 방식으로 거부가 동작하는지, 터미널에서 먼저 답하면 대시보드가 "이미 답함"이 되는지, 질문에 대시보드로 답할 수 있는지, 예산을 낮게 잡으면 알람과 관문이 뜨고 "중단"이 거부되는지 확인한다.
   - 대화형 세션이 필요하면 tmux를 쓴다. 분류기가 막으면 해당 항목은 사용자가 직접 확인하는 것으로 넘긴다.
   - **사용자 확인**: 실제 세션에서 대시보드로 허용과 거부를 한 번씩 해 본다(Q7).
5. **전체 확인**
   - 단독 실행으로, 새 worktree에서 npm ci 뒤 전체 테스트 3회, typecheck, build, package를 돌린다.
   - 안전 값이 바뀌지 않아야 한다. 사용자 설치본(4317과 `~/.claude-office`)은 건드리지 않는다.
6. **Windows**: 사용자 PC에서 한 번 확인한다(Q8).

## 12. 위험
- **Task 0 결과에 따라 범위가 바뀐다.** PreToolUse의 `ask`가 PermissionRequest로 이어지지 않으면 예산 관문은 대체 방식을 쓴다. ExitPlanMode가 PermissionRequest를 거치지 않으면 계획 승인은 "보고서만"으로 줄인다.
- **대시보드는 이제 Claude Code의 행동을 바꾼다.** 잘못 허용하면 되돌릴 수 없다. 그래서 다음 두 가지를 둔다.
  - 버튼은 두 번 누를 필요는 없지만, 기본 포커스는 "거부"에 둔다.
  - 보고서에는 무엇을 허용하는지 가림 처리된 요약을 반드시 보여 준다.
- **회사 정책**: `allowManagedHooksOnly`인 회사는 PermissionRequest hook도 막힌다. 부록 A에 적는다(검증은 하지 않는다).
- **연구 프리뷰와 버전 변화**: hook 응답 형식이 Claude Code 버전에 따라 바뀔 수 있다. 응답 형식은 상수 한 곳에 두고, 테스트로 고정한다.

## 13. 실행 뒤 확인된 것과 남은 위험 (2026-10-02, 구현 `feat/v2-phase2`)

스펙 1–12장은 승인 당시 그대로 둔다. 구현하며 확인된 사실과 남은 위험을 여기에 적는다. 판정 원문은 계획 문서의 "계획서 판정"·"실행 중 바뀐 것"과 진행 기록에 있다.

### 확인 스파이크 결과 (2장)
- `PreToolUse`가 `ask`를 돌려주면 권한 창과 `PermissionRequest`가 이어서 온다(자동 허용 도구와 auto·acceptEdits 모드 포함). 예산 관문은 5.3의 **기본 방식**을 쓴다.
- `ExitPlanMode`는 `PermissionRequest`를 거치고 deny는 동작하지만 **allow가 적용되지 않는다.** 계획 승인은 **"보고서만"**이다.
- 330초(실제 서버로는 376초) 붙잡은 연결에 답해도 적용된다.

### 2장 전제의 정정
- "터미널이 먼저 답하면 hook HTTP 연결이 끊긴다"는 **거부·Esc·timeout에서만** 성립한다. 터미널에서 **허용**하면 연결이 닫히지 않는다(Claude Code 2.1.287). 그래서 `closed-terminal`은 연결 종료에 더해 그 도구의 `PostToolUse` 계열 이벤트와 그 에이전트의 턴 종료 이벤트로도 판정한다.
- `PermissionRequest` 입력에는 `tool_use_id`가 없다. 짝 찾기는 `tool_input`의 해시로 한다(Read·Write·Bash·Edit에서 요청과 종료의 해시가 같음을 확인).

### 남은 위험
- **터미널에서 허용한 뒤의 틈:** 대시보드의 요청은 그 도구가 끝날 때 닫힌다. 그 사이 대시보드에서 누른 답은 화면에 "대시보드에서 허용함/거부함"으로 보여도 적용되지 않는다. 요청과 종료의 입력 해시가 다른 도구(MultiEdit, NotebookEdit, WebFetch, MCP 도구는 확인 전)가 있으면 그 에이전트의 턴이 끝나거나 590초가 지날 때까지 남는다.
- **가짜 hook(7.2 보충):** hook 요청은 인증하지 않는다. 같은 PC의 다른 프로세스(127.0.0.1에 닿는 다른 OS 사용자 포함)는 도구 허용을 만들어 내지는 못하고 터미널 권한 창도 그대로 뜨지만, 다음은 할 수 있다. (a) 가짜 요청으로 대기 상한 50건을 채워 진짜 요청이 대시보드를 거치지 않게 한다. (b) 세션 id를 알면 가짜 종료 이벤트로 대시보드의 진짜 요청을 닫는다(터미널 창은 그대로 남는다). (c) 도구 호출 id를 알면 예산 관문의 "계속"을 흉내 낸다. 막으려면 hook 요청에 플러그인 전용 비밀값 인증이 필요하다(7.2에서 Phase 2 범위 밖으로 둔 것 — 넣을 시점은 사용자 결정 항목).
- **토큰:** 브라우저를 여는 순간 토큰이 붙은 주소가 잠깐 프로세스 목록에 보인다. 브라우저가 302의 출발 주소를 내부 방문 기록에 남길 수 있다(미실측). 이전 버전(베타) 서버가 켜진 채 새 런처를 실행하면 브라우저가 그 서버에 토큰 주소로 열려 주소창에 토큰이 남는다. 4317을 먼저 차지한 프로세스는 "이 프로그램" 표시(401 + app)를 흉내 낼 수 있어, `doctor`·`diag` 실행 때 토큰을 받을 수 있다.
- **auto 모드:** 권한 모드가 auto인 세션은 Claude Code가 스스로 허용하는 일이 많아 일반 권한 요청이 대시보드에 드물게 온다. 예산 관문은 모드와 관계없이 온다.
- **팀원 요청:** 대화 압축 요약이나 붙여 넣은 글에 팀원 메시지 태그가 원문 그대로 들어 있으면 `[결정 필요]`가 30분 다시 표시될 수 있다(답 버튼 없는 보고서).
- **Windows:** PowerShell 스크립트는 정적 검증만 했다. 실기 확인 항목: PowerShell 5.1 창에서 설치 질문이 뜨고 y가 읽히는지, ISE에서 `Read-Host` 창으로 묻는지, 런처가 브라우저를 여는지, 브라우저 열기 실패 안내가 보이는지.
- **회사 정책:** `allowManagedHooksOnly`가 켜진 환경은 검증하지 못했다.
