# v2 Phase 6b — 팀리더 전용 기능 (보고서·결재, 대화 질문 답하기, 퇴근·퇴사)

사용자 결정(2026-10-21): 지시는 **channel이 연결된 층만**(터미널에서 연 층은 버튼 비활성 + "작업 지시 켜기(옮겨 열기)로 연결하면 쓸 수 있습니다"), 보고서는 **channel MCP 도구로 제출**, 퇴근은 **버튼으로만**(오래 쉬면 표시만), 퇴사 인수인계는 **떠나는 팀원이 쓰고 못 쓰면 팀리더가**. 추가 요구: 팀리더가 도구가 아닌 **대화 글로 사용자에게 묻고 멈출 때**도 대시보드에서 보고 답할 수 있어야 한다(터미널을 보지 않고).

## 1. 원칙
- 모든 층에는 사용자와 세션을 잇는 **팀리더**가 하나 있다(필수 소통 창구). 보고·결재·퇴근·퇴사·대화 답은 모두 팀리더를 거친다.
- 대시보드는 `~/.claude`에 쓰지 않는다. 새 상태는 `<PREFIX>/reports.json`(0600)에만.
- 세션으로 가는 모든 지시는 기존 channel(Phase 5 B257·B268 서명)로, 세션에서 오는 모든 제출은 channel MCP 도구 → channel 연결 인증으로.

## 2. 팀리더 지시 통로
- `POST /api/floors/:id/lead` 본문 `{kind, ...}`. kind: `report`(보고 요청), `approve`·`revise`(결재), `reply`(대화 질문 답), `offduty`·`onduty`(퇴근·출근), `retire`(퇴사 시작), `rehire`(인수인계 확인 후 새 팀원 시작).
- 서버가 kind별 **정해진 틀**로 지시문을 만든다(`server/floors/leadText.ts`의 상수). 사용자 글(수정 사항·답)은 틀의 정해진 칸에만, 4,000자 상한, 따옴표 블록으로 감싸 넣는다.
- channel 연결이 없으면 409 `{error:"not-connected"}`. 휴업 중이면 기존 보관(held)으로 들어가 재개 때 전달.
- 지시 id(`r-<8hex>`)를 만들어 틀에 넣고, 팀리더가 도구를 부를 때 그 id를 쓰게 한다.

## 3. channel MCP 도구 (plugins/claude-office/channel/server.mjs)
- `tools/list`가 열쇠가 있을 때만 세 도구를 낸다(열쇠가 없으면 지금처럼 빈 목록).
  - `submit_report {request_id, title(≤200), body(≤64KB)}`
  - `submit_handover {request_id, member, body(≤64KB)}`
  - `ask_user {question(≤4,000), options?: string[≤6, 각 ≤200]}` — 4장
- 도구 호출 → channel 서버가 대시보드 `POST /channel/submit`으로 보낸다. 인증은 channel 연결의 세션 키로 만든 MAC(Phase 6a B268과 같은 `JSON.stringify([...])` 입력). 대시보드는 연결이 살아 있는 층의 것만 받는다.
- 도구 결과는 "대시보드에 전달했습니다" 한 줄. 대시보드가 받지 못하면 오류 결과("대시보드에 연결되지 않았습니다 — 사용자에게 터미널에서 물어 주세요").
- MCP `instructions`에 한 문단을 더한다: 사용자의 결정이나 답이 필요하면 대화 글 대신 `ask_user`를 부르고, 보고 요청에는 `submit_report`로 답하라.

## 4. 대화로 묻고 멈출 때 (추가 요구)
- **ask_user 도구**(주 경로): 팀리더가 `ask_user`를 부르면 그 층 팀리더 책상에 손들기 + 노란 물음표(기존 결정 표시 재사용, kind `chat`). 클릭하면 질문 글과 선택지 버튼 + 자유 답 칸. 답하면 `reply`로 channel 지시가 간다. 도구 자체는 바로 돌아오고(기다리지 않음), 답은 다음 사용자 지시로 들어간다.
- **Stop 대체 경로**(도구를 안 부른 경우): 팀리더의 Stop 이벤트 때 마지막 assistant 글이 물음으로 끝나거나(`?`, `까요`, `습니까`, `할지`, `원하시` 등 끝말 목록) 번호 목록으로 선택지를 내놓으면, 팀리더 책상에 "답을 기다립니다" 말풍선 표시(파란 점, 손들기 아님). 클릭하면 마지막 글 전문(4,000자로 자름) + 자동으로 뽑은 선택지(번호 목록 항목, 최대 6) + 자유 답 칸. 답하면 `reply`.
  - 다음 UserPromptSubmit이나 PreToolUse가 오면 표시를 지운다(터미널에서 답한 것).
- channel이 없는 층은 글을 보여 주되 답 칸은 비활성 + "터미널에서 답하거나, 작업 지시 켜기(옮겨 열기)로 연결하세요".

## 5. 보고서와 결재
- 팀리더 책상에 [보고 요청]. 보고서가 오면 책상 위 서류철 아이콘 + 개수(대기 중인 것).
- 서류철 패널: 보고서 목록(최신 먼저) → 종이 모양 본문(마크다운은 글자로만, HTML로 그리지 않음) → [승인] / [수정 사항 적기]. 상태 도장: 대기·승인됨·수정 요청.
- 보관: `reports.json` 층마다 50개, 넘으면 오래된 승인된 것부터 지움. 층이 사라져도 7일 보관 후 정리.

## 6. 퇴근·출근·오래 쉼
- 팀원 책상에 [퇴근]. 지시: "팀원 X에게 shutdown_request를 보내 종료하라". 대시보드는 "퇴근 요청함"을 기억하고, 그 팀원의 프로세스가 끝나거나(팀 설정에서 isActive false) 10분 동안 활동이 없으면 "퇴근" 팻말 빈 의자.
- 퇴근 의자에 [출근]. 지시: "팀원 X에게 메시지를 보내 다시 일을 시작하게 하라"(같은 이름 → 대화 기록에서 재개).
- 마지막 활동이 1시간 넘은 팀원은 책상에 "오래 쉬는 중" 표시(자동 퇴근 없음).

## 7. 퇴사·새 팀원
1. [퇴사] → 확인 창: "X의 기억은 새 팀원에게 이어지지 않고, 인수인계 메모만 넘어갑니다. 대화 기록은 지우지 않습니다." [퇴사 진행]/[취소].
2. 지시: 팀리더가 X에게 인수인계를 `submit_handover`로 쓰게 하고, X가 5분 안에 제출하지 않거나 멈춰 있으면 팀리더가 X의 대화 기록을 보고 대신 `submit_handover`.
3. 메모가 서류철에 "인수인계" 종류로 도착 → [새 팀원 시작] → `rehire` 지시: 같은 이름으로 새 팀원을 띄우고 메모를 첫 지시로.
4. 화면: 새 팀원이 앉고 옛 팀원은 "전임자" 서랍(접힘)에 이름·퇴사 시각만.

## 8. 화면 문구(대표, designer·qa가 확정)
- 비활성 이유: `작업 지시 켜기(옮겨 열기)로 연결하면 쓸 수 있습니다`
- 퇴사 확인: 7장 1번 문장
- 대화 질문 말풍선: `답을 기다립니다`

## 9. 테스트
- 지시 틀: 사용자 글이 정해진 칸 밖으로 새지 않음(따옴표·줄바꿈·`</channel>` 같은 글자), 4,000자 상한, not-connected 409, 휴업 중 보관.
- MCP 도구: 열쇠 없으면 도구 0개, 크기 상한, 잘못된 형식 오류 결과, `/channel/submit` MAC 틀림·연결 없음 거절, 평문 열쇠 미전송.
- 대화 질문: 끝말 목록 판정(참·거짓 예시 각 10개), 번호 목록 선택지 뽑기, 다음 UserPromptSubmit에 해제.
- 보고서 저장 상한·정리·0600.
- 퇴근 표시 전이, 오래 쉼 1시간 경계, 퇴사 순서(확인 → 메모 → 새 팀원).
- 화면: 비활성 이유, 서류철, 도장, 퇴근 의자, 전임자 서랍.

## 10. 위험
- 팀리더가 틀을 따르지 않을 수 있다(모델 동작). 도구 미사용 시 4장 Stop 대체 경로와 "보고 요청 후 10분 무응답" 표시로 드러낸다.
- 대화 질문 판정은 휴리스틱이다 — 틀려도 "답을 기다립니다" 말풍선이 더 뜨거나 덜 뜰 뿐 동작을 막지 않는다.
- 모든 기능은 channel 층에서만 동작한다 — 실험 기능(channels) 의존.

## 11. 사전 검토 반영 (reviewer #604 — 이 장이 앞 장과 다르면 이 장을 따른다)
- **(a) 휴업 중 보관:** lead 지시는 층마다 `kind`별로 하나만 보관한다(새것이 옛것을 대체). 같은 팀원의 `offduty`·`onduty`는 서로 지운다. `reply`는 질문 id(아래 b)마다 하나. "퇴근 요청함" 기록은 보관할 때가 아니라 **실제로 channel로 보냈을 때** 남긴다.
- **(b) ask_user 질문 id:** `ask_user` 도구 결과로 `q-<8hex>`를 돌려주고, 대시보드는 그 id로 질문을 저장한다. `reply` 틀에 그 id를 넣는다. 질문의 주인은 그 도구 호출의 **PreToolUse hook의 agent 정보**로 가린다(기존 `agentOf` 규칙). 팀원·서브에이전트가 부른 `ask_user`는 그 팀원 책상에 붙고, 답(reply)은 팀리더에게 "팀원 X의 질문 q-… 에 대한 답"으로 전달한다.
- **(c) 해제 조건:** "답을 기다립니다"·`ask_user` 표시는 **팀리더 본인**(team-lead, 서브에이전트 아님)의 UserPromptSubmit·PreToolUse 이벤트, 또는 대시보드에서 답을 보냈을 때만 지운다(결정 대기열 `queue.ts`의 규칙과 같게). 팀원·서브에이전트 이벤트로는 지우지 않는다.
- **(d) 퇴근 판정 제외:** 휴업 중인 층, 대기 중 결정(손들기)이 있는 팀원은 "10분 무활동 → 퇴근" 판정과 "1시간 오래 쉼" 표시에서 뺀다.
- **(e) 퇴사 5분은 서버가 잰다:** 시작 시각을 `reports.json`에 남겨 서버를 다시 켜도 이어 간다. 5분이 지나도 `submit_handover`가 없으면 서버가 팀리더에게 "대신 써 달라" 지시를 한 번 보낸다.
- **(f) 퇴사 이름:** 새 팀원은 **같은 이름**으로 띄운다(사용자 요구: 다음에 부르면 기억 없는 새 팀원). 순서: ① 옛 팀원에게 shutdown_request(퇴근과 같은 지시) ② 종료 확인 ③ 같은 이름으로 새 팀원 생성(SendMessage 문서: 같은 이름이면 최신 에이전트가 이름을 가짐). 이 동작은 실제 세션 확인 항목에 넣는다(설명서 부록): 새 팀원이 옛 기억을 모르는지. 틀리면 이름에 `-2`를 붙이는 쪽으로 바꾼다.
- **(g) reports.json 정리:** 층마다 `lastSeenAt`을 남긴다. 서버 시작 직후 첫 스냅샷 전에는 정리하지 않는다. 50개 상한이 대기 중 보고서로만 차면 새 보고서를 받되 가장 오래된 대기 보고서를 "보관함"(화면에서 접힘)으로 옮기고, 파일 상한은 층마다 100개로 둔다.
- **휴업 중 도구:** 휴업(Phase 4a) 중에도 이 플러그인의 MCP 도구(`mcp__plugin_claude-office_office-channel__*`의 `ask_user`·`submit_report`·`submit_handover`)는 막지 않는다 — 제출만 하고 세션 작업을 진행시키지 않기 때문.

## 12. 설계 보안 검토 반영 (security #602) · 판정 · 빌딩 디자인 (이 장이 앞 장과 다르면 이 장을 따른다)
- **(a) 모델 글은 사용자 지시가 되지 않는다:** `reply` 틀에는 질문 id, 고른 "선택지 N번", 사용자가 직접 친 글만 넣는다. 질문 글과 선택지 글(ask_user·Stop 경로 모두)은 다시 싣지 않는다.
- **(b) 틀의 사용자 아닌 값:** 팀원 이름은 그 층 팀 설정에 있는 이름과 같고 launch NAME 글자 규칙에 맞을 때만 받는다(아니면 400). `submit_handover.member`는 서버가 retire 때 정한 이름과 같아야 한다.
- **(c) 따옴표 방식:** 사용자 글은 모든 줄 앞에 `> `를 붙이고 `<`·`>`를 전각 `＜`·`＞`로 바꾼다. 코드 펜스는 쓰지 않는다.
- **(d) 출처:** Stop 대체 경로 판정, ask_user·submit_*의 주인 짝짓기(11장 b), 표시 해제(11장 c)는 `/hooks/v2` 이벤트만 쓴다. 마지막 글은 서버가 이미 아는 그 세션의 대화 기록 파일 뒤쪽에서만 읽는다(이벤트의 `transcript_path`·글은 쓰지 않는다).
- **(e) 해제 판정(qa):** 팀원이 부른 질문 표시도 팀리더 본인 이벤트나 대시보드 답으로만 지운다. 휴업 중 보낸 답은 표시를 "보관됨"으로 바꾸고 실제로 channel로 보냈을 때 지운다. hook 없이 제출만 온 질문은 팀리더 책상에 붙인다. 팀원·서브에이전트의 Stop은 대체 경로 판정을 하지 않는다.
- **(f) 빌딩 이름과 속성(사용자 요청 2026-10-21):**
  - 지붕 간판 기본값을 `CLAUDE 야근 빌딩` 대신 `<사용자 이름>의 회사`로 한다. 사용자 이름은 OS 계정 표시 이름이 아니라 대시보드 설정 값이며, 처음에는 `User`(→ `User의 회사`).
  - 간판을 누르면 "빌딩 정보" 창이 열린다. ① 이름 고치기(1~40자, 글자로만 그림) ② 정보 보기: 지금 HUD의 TODAY·5H·WEEK 토큰 수와 캐시 읽기, 5H·WEEK·PLAN 잔여 %, 층 수·팀원 수, 서버·화면 버전. 이름은 `<PREFIX>/building.json`(0600)에 저장한다.
  - HUD의 토큰 칸(TODAY·5H·WEEK)은 숫자 오른쪽 정렬, 같은 폭(`tabular-nums`), 이름표·값·보조 줄의 세로 기준선을 맞춘다.
  - "사용 가능한 토큰 %"는 지금 PLAN 바(statusline `rate_limits`의 잔여 %)를 쓴다. 이 값은 Pro·Max나 지출 한도 gateway에서만 오므로, 없을 때 문구를 `-- 데이터 없음`에서 `-- 요금제가 알려 주지 않음`으로 바꾸고 빌딩 정보 창에 그 이유를 한 줄 적는다.
- **(g) 팀원 프로세스의 channel 연결:** channel 서버는 팀리더 프로세스에서만 대시보드에 연결한다. 팀원·서브에이전트 프로세스(tmux 환경의 층 열쇠를 물려받았어도)에서는 연결하지 않고 도구 목록도 비운다 — 새 연결이 리드 연결을 끊거나 지시가 팀원에게 가지 않게. 판별 방법(env·인자)은 developer가 찾아 근거와 함께 커밋 메시지에 적는다. **두 겹으로 둔다**(대시보드 재시작 때 팀원이 먼저 붙을 수 있어 대시보드 규칙만으로는 부족하다 — security Important-8): ① 팀원 판별이 1순위(env·인자, 안 되면 launch 때 기억한 리드 pid와 channel 서버의 부모 pid 대조를 검토) ② 그 위에 대시보드 규칙: 같은 층에 첫 연결이 살아 있는 동안 새 연결은 **지시 스트림 단계에서 409**로 거절하고(첫 인사 401·403은 쓰지 않는다 — 클라이언트가 멈춰 옮겨 열기·재시작 뒤 새 리드가 영구히 끊긴다, Important-7), channel 서버는 409를 받으면 잠시 뒤 다시 시도한다. 첫 연결이 끊긴 뒤의 다시 연결은 받는다. Ctrl-Z로 멈춘 리드가 연결을 붙잡는 경우(Minor-7)는 받아들인다. 실제 세션 확인 항목(설명서 부록)에 넣는다.
