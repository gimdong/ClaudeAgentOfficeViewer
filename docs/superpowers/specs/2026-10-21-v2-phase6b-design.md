# v2 Phase 6b — 팀리더 전용 기능 (보고서·결재, 대화 질문 답하기, 퇴근·퇴사)

사용자 결정(2026-10-21): 지시는 **channel이 연결된 층만**(터미널에서 연 층은 버튼 비활성 + "옮겨 열기로 연결하면 쓸 수 있습니다"), 보고서는 **channel MCP 도구로 제출**, 퇴근은 **버튼으로만**(오래 쉬면 표시만), 퇴사 인수인계는 **떠나는 팀원이 쓰고 못 쓰면 팀리더가**. 추가 요구: 팀리더가 도구가 아닌 **대화 글로 사용자에게 묻고 멈출 때**도 대시보드에서 보고 답할 수 있어야 한다(터미널을 보지 않고).

## 1. 원칙
- 모든 층에는 사용자와 세션을 잇는 **팀리더**가 하나 있다(필수 소통 창구). 보고·결재·퇴근·퇴사·대화 답은 모두 팀리더를 거친다.
- 대시보드는 `~/.claude`에 쓰지 않는다. 새 상태는 `<PREFIX>/reports.json`(0600)에만.
- 세션으로 가는 모든 지시는 기존 channel(Phase 5 B257·B268 서명)로, 세션에서 오는 모든 제출은 channel MCP 도구 → channel 연결 인증으로.

## 2. 팀리더 지시 통로
- `POST /api/floors/:id/lead` 본문 `{kind, ...}`. kind: `report`(보고 요청), `approve`·`revise`(결재), `reply`(대화 질문 답), `offduty`·`onduty`(퇴근·출근), `retire`(퇴사 시작), `rehire`(인수인계 확인 후 새 팀원 시작).
- 서버가 kind별 **정해진 틀**로 지시문을 만든다(`server/floors/leadText.ts`의 상수). 사용자 글(수정 사항·답)은 틀의 정해진 칸에만, 4,000자 상한, 따옴표 블록으로 감싸 넣는다.
- channel 연결이 없으면 409 `{error:"not-connected"}`. 휴업 중이면 기존 보관(held)으로 들어가 재개 때 전달.
- 지시 id(`r-<8hex>`)를 만들어 틀에 넣고, 팀리더가 도구를 부를 때 그 id를 쓰게 한다.

## 3. channel MCP 도구 (plugins/claude-office/channel/server.mjs)
- `tools/list`가 열쇠가 있을 때만 세 도구를 낸다(열쇠가 없으면 지금처럼 빈 목록).
  - `submit_report {request_id, title(≤200), body(≤64KB)}`
  - `submit_handover {request_id, member, body(≤64KB)}`
  - `ask_user {question(≤4,000), options?: string[≤6, 각 ≤200]}` — 4장
- 도구 호출 → channel 서버가 대시보드 `POST /channel/submit`으로 보낸다. 인증은 channel 연결의 세션 키로 만든 MAC(Phase 6a B268과 같은 `JSON.stringify([...])` 입력). 대시보드는 연결이 살아 있는 층의 것만 받는다.
- 도구 결과는 "대시보드에 전달했습니다" 한 줄. 대시보드가 받지 못하면 오류 결과("대시보드에 연결되지 않았습니다 — 사용자에게 터미널에서 물어 주세요").
- MCP `instructions`에 한 문단을 더한다: 사용자의 결정이나 답이 필요하면 대화 글 대신 `ask_user`를 부르고, 보고 요청에는 `submit_report`로 답하라.

## 4. 대화로 묻고 멈출 때 (추가 요구)
- **ask_user 도구**(주 경로): 팀리더가 `ask_user`를 부르면 그 층 팀리더 책상에 손들기 + 노란 물음표(기존 결정 표시 재사용, kind `chat`). 클릭하면 질문 글과 선택지 버튼 + 자유 답 칸. 답하면 `reply`로 channel 지시가 간다. 도구 자체는 바로 돌아오고(기다리지 않음), 답은 다음 사용자 지시로 들어간다.
- **Stop 대체 경로**(도구를 안 부른 경우): 팀리더의 Stop 이벤트 때 마지막 assistant 글이 물음으로 끝나거나(`?`, `까요`, `습니까`, `할지`, `원하시` 등 끝말 목록) 번호 목록으로 선택지를 내놓으면, 팀리더 책상에 "답을 기다립니다" 말풍선 표시(파란 점, 손들기 아님). 클릭하면 마지막 글 전문(4,000자로 자름) + 자동으로 뽑은 선택지(번호 목록 항목, 최대 6) + 자유 답 칸. 답하면 `reply`.
  - 다음 UserPromptSubmit이나 PreToolUse가 오면 표시를 지운다(터미널에서 답한 것).
- channel이 없는 층은 글을 보여 주되 답 칸은 비활성 + "터미널에서 답하거나, 옮겨 열기로 연결하세요".

## 5. 보고서와 결재
- 팀리더 책상에 [보고 요청]. 보고서가 오면 책상 위 서류철 아이콘 + 개수(대기 중인 것).
- 서류철 패널: 보고서 목록(최신 먼저) → 종이 모양 본문(마크다운은 글자로만, HTML로 그리지 않음) → [승인] / [수정 사항 적기]. 상태 도장: 대기·승인됨·수정 요청.
- 보관: `reports.json` 층마다 50개, 넘으면 오래된 승인된 것부터 지움. 층이 사라져도 7일 보관 후 정리.

## 6. 퇴근·출근·오래 쉼
- 팀원 책상에 [퇴근]. 지시: "팀원 X에게 shutdown_request를 보내 종료하라". 대시보드는 "퇴근 요청함"을 기억하고, 그 팀원의 프로세스가 끝나거나(팀 설정에서 isActive false) 10분 동안 활동이 없으면 "퇴근" 팻말 빈 의자.
- 퇴근 의자에 [출근]. 지시: "팀원 X에게 메시지를 보내 다시 일을 시작하게 하라"(같은 이름 → 대화 기록에서 재개).
- 마지막 활동이 1시간 넘은 팀원은 책상에 "오래 쉬는 중" 표시(자동 퇴근 없음).

## 7. 퇴사·새 팀원
1. [퇴사] → 확인 창: "X의 기억은 새 팀원에게 이어지지 않고, 인수인계 메모만 넘어갑니다. 대화 기록은 지우지 않습니다." [퇴사 진행]/[취소].
2. 지시: 팀리더가 X에게 인수인계를 `submit_handover`로 쓰게 하고, X가 5분 안에 제출하지 않거나 멈춰 있으면 팀리더가 X의 대화 기록을 보고 대신 `submit_handover`.
3. 메모가 서류철에 "인수인계" 종류로 도착 → [새 팀원 시작] → `rehire` 지시: 같은 이름으로 새 팀원을 띄우고 메모를 첫 지시로.
4. 화면: 새 팀원이 앉고 옛 팀원은 "전임자" 서랍(접힘)에 이름·퇴사 시각만.

## 8. 화면 문구(대표, designer·qa가 확정)
- 비활성 이유: `옮겨 열기로 연결하면 쓸 수 있습니다`
- 퇴사 확인: 7장 1번 문장
- 대화 질문 말풍선: `답을 기다립니다`

## 9. 테스트
- 지시 틀: 사용자 글이 정해진 칸 밖으로 새지 않음(따옴표·줄바꿈·`</channel>` 같은 글자), 4,000자 상한, not-connected 409, 휴업 중 보관.
- MCP 도구: 열쇠 없으면 도구 0개, 크기 상한, 잘못된 형식 오류 결과, `/channel/submit` MAC 틀림·연결 없음 거절, 평문 열쇠 미전송.
- 대화 질문: 끝말 목록 판정(참·거짓 예시 각 10개), 번호 목록 선택지 뽑기, 다음 UserPromptSubmit에 해제.
- 보고서 저장 상한·정리·0600.
- 퇴근 표시 전이, 오래 쉼 1시간 경계, 퇴사 순서(확인 → 메모 → 새 팀원).
- 화면: 비활성 이유, 서류철, 도장, 퇴근 의자, 전임자 서랍.

## 10. 위험
- 팀리더가 틀을 따르지 않을 수 있다(모델 동작). 도구 미사용 시 4장 Stop 대체 경로와 "보고 요청 후 10분 무응답" 표시로 드러낸다.
- 대화 질문 판정은 휴리스틱이다 — 틀려도 "답을 기다립니다" 말풍선이 더 뜨거나 덜 뜰 뿐 동작을 막지 않는다.
- 모든 기능은 channel 층에서만 동작한다 — 실험 기능(channels) 의존.
