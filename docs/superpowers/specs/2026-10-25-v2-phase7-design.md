# v2 Phase 7 — 테마(스킨) 구조와 오피스 테마

사용자 결정(2026-10-25):
- 디자인을 스킨처럼 바꿔 끼우는 **테마**로 만든다. 이번 Phase는 **오피스 테마부터 완성**한다(테마 교체 구조 + 오피스 낮·밤). 판타지·우주선·사이버펑크는 다음 Phase.
- 오피스는 밝은 진짜 사무실, 캐릭터가 걷고 앉고 쉬며, 건물 바깥(하늘·도시, 로비 경비·행인·도로·차, 엘리베이터, 카페, 옥상)이 있다.
- 낮·밤 기본은 **시스템 다크 모드 따름**, 빌딩 정보 창에서 고정 가능.
- 층 안 **하위 팀 구역**(예: 디자인 팀)을 보인다.
- 참고 분위기: 타이니 타워(Tiny Tower). 이름·그림은 베끼지 않는다.

**디자인 계약:** `docs/design/phase7/SPEC.md`(판 3, 19a4904 + 보충 079ee7a·afe7c12·9d42e54). 칸·시트·토큰·대비·예산·지식재산권은 그 문서가 기준이다. 이 스펙은 "무엇을 어떤 순서로 구현하는가"만 정한다. 둘이 다르면 계약을 따르고 이 스펙을 고친다.

**그림 자산(디자이너 브랜치):** motion `design/p7-motion`(캐릭터 층 시트·오라·`make-sheet.mjs`), office `design/p7-office`(장면 칸·`tokens.js`·`contrast.cjs`), themes `design/p7-themes` `office-exterior/`(하늘·스카이라인·거리·차·엑스트라·`make-exterior.mjs`). 구현 브랜치로 합칠 때 생성기와 최종 PNG만 가져오고 목업 HTML·렌더는 `docs/design/phase7/`에 둔다.

## 1. 원칙
- 테마가 바꾸는 것은 그림 시트, `--th-*` 토큰, 장소 낱말(`words`) 셋뿐이다(계약 §0). 배치·DOM·`aria-label`·공통 UI·상태 색의 뜻은 모든 테마가 같다.
- 서버 데이터(스냅샷)는 바뀌지 않는다. 걷기·탕비실·엘리베이터 연출은 화면이 스냅샷 상태로 정한다. 예외는 §5의 세 가지(변형 설정, 노력 정도, 하위 팀).
- 글자는 언제나 DOM이고 불투명 판 위에 있다(계약 §6). 키보드 포커스 링은 두 겹(안쪽 `--focus` + 바깥 `--panel`)으로 바꾼다(계약 §6, 낮·밤 모두 3:1). 보고서·이름 같은 바깥 글은 텍스트 노드로만 그린다.
- `~/.claude`에 쓰지 않는다. 새 상태는 `<PREFIX>/building.json`(변형)과 `<PREFIX>/groups.json`(하위 팀)에만.

## 2. 테마 구조(화면)
- `web/themes/<id>/`: `theme.json`, `tokens.css`, 시트 PNG. 이번에는 `office` 하나. 빌드 때 `import`로 묶는다(동적 다운로드 없음, 새 의존성 없음).
- `web/themes/registry.ts`: 테마 목록과 `contract` 검사. 알 수 없는 `contract`는 오피스로 대신.
- 루트에 `data-theme`·`data-variant`·`data-ui`를 단다. `data-ui`는 변형의 `ui`(`light`|`dark`)이고 공통 UI 토큰 두 벌 중 하나를 고른다(계약 §4.1).
- 변형 고르기: `building.json`의 `variant`가 `day`|`night`|`system`(기본 `system`). `system`은 `prefers-color-scheme`을 따르고 시스템이 바뀌면 바로 따라간다. 시각 자동 전환 없음.
- 공통 UI 토큰을 `light`·`dark` 두 벌로 나눈다. 지금 값이 `dark`, office 낮 값이 `light` 출발점. `.q-chip` 등 노란 바탕 글은 `--yellow-ink`.

## 3. 장면
- 빌딩 세로 순서(위 → 아래): 하늘·스카이라인(가로 반복) → 옥상 → 세션 층들(지금 순서 그대로) → 빈 층 → 카페(장식, 층 번호 없음) → 로비 → 거리. 처음 화면은 지금처럼 일하는 층.
- 엘리베이터 통로는 건물 왼쪽. HUD 엘리베이터(세션 층만)를 누르면 칸이 그 층까지 칸 단위로 움직인 뒤 스크롤(계약 §2b). 상자 30×34, 문 3프레임(motion c7f5d02).
- **오래 쉬면 카페로(사용자 결정 2026-10-25):** 짧게 쉬면 자기 층 탕비실, `longIdle`(1시간)이 되면 엘리베이터를 타고 카페 층으로 가 앉는다(`ride`·`ride_lurch`). 일이 다시 시작되면 엘리베이터로 자기 층에 돌아온다. 손들기는 카페 자리에서 앉은 채 그 자리에서 한다(돌아오지 않음, motion 67ba302). 카페에 간 동안 빈 자리에는 「안」 `카페 ↑` 표시. 한 번에 엘리베이터에 타는 사람은 1명, 나머지는 차례. 누가 타고 있을 때 HUD 층 버튼을 누르면 그 층으로 스크롤만 한다. 카페 자리가 모자라면 나머지는 탕비실에 남는다. 카페에서도 이름표가 따라간다(장식 손님과 구별). 탑승 행이 없는 테마는 카페로 가지 않는다(계약 보충 3, 9d42e54). 움직임 줄이기에서는 바로 카페 자리 정지 그림.
- 층 안: 벽·바닥 CSS 무늬(`--th-*`), 창, 책상 세트(의자 등받이·책상 윗면·앞면 세 장), 모니터 상태 4장, 층마다 탕비실(소파·커피 머신).
- 층마다 벽지 변형 2~4종을 층 id로 돌려 쓸 수 있다(타이니 타워 참고, 디자이너 결정).
- 장식(행인·차·카페 손님·경비)은 `aria-hidden`, 누를 수 없음. 한 번에 행인 2 + 차 2 이하.
- 360폭: 책상 한 줄에 둘, 장식 일부 숨김(계약 §2 표).

## 4. 캐릭터와 동작
- 캐릭터 = `div` 하나에 층 시트 여러 장(`background-image`), `steps()`로 `background-position`만 움직인다(계약 §3, §7).
- 상태 → 동작: 일함 `type`, 고민 `think`, 손듦 `hand_up`(탕비실이면 `hand_up_stand`), 쉼 `idle`, 퇴근은 빈 의자.
- 탕비실 걷기(계약 §3 판정): 쉼 30초 → 일어서기 → 걷기 → 커피. 한 층 동시 걷기 최대 2명, 돌아가는 걷기는 제한 밖, 걷는 중 일이 시작되면 방향만 바꿈. 일이 다시 시작되면 자리로 돌아와 앉음.
- 움직임 줄이기: 걷지 않고 목적지 정지 그림. 깜빡임·밝기 변화 없음.
- 팀원 변형(머리·안경·옷 색)은 빌드 때 팔레트만 바꾼 PNG. 팀원 이름으로 정해진 순서로 돌려 써서 다시 그려도 같다.
- 오라: 일하는 중일 때만, `effort.level` 1~4(§5.2).

## 5. 서버가 새로 주는 것
### 5.1 변형 설정
- `building.json`에 `variant: "day"|"night"|"system"`. `PUT /api/building`이 받는다(기존 이름 저장과 같은 검사, 남는 키 거절, 0600). 스냅샷 `building.variant`.
### 5.2 노력 정도
- hook 입력의 `effort.level`(`low`|`medium`|`high`|`xhigh`|`max`)을 멤버별로 마지막 값으로 남긴다. 스냅샷 `Member.effort?`. 알 수 없는 값은 버린다. `/hooks/v2` 이벤트만 쓴다.
### 5.3 하위 팀
- 기본: 팀원 이름의 첫 하이픈 앞으로 묶는다. team-lead는 빼고, 2명 이상일 때만 묶는다.
- 고치기: `<PREFIX>/groups.json`(0600)에 팀 이름 키로 `{member: group}`과 묶음 표시 이름을 둔다. `PUT /api/teams/:name/groups`(토큰·Host·같은 계정·Origin 검사, 이름 규칙은 팀원 이름과 같음, 남는 키 거절, 크기 상한). 층 id가 아니라 팀 이름 키라 옮겨 열기 뒤에도 이어진다.
- 스냅샷 `Member.group?`, `Floor.groups?: {id, label}[]`. 화면은 팀 구역(칸막이·러그·팻말)으로 묶고, 리드 자리는 표시를 다르게 한다.
- 묶음 편집 화면: 에이전트 패널에 "팀 구역" 고르기(기존 묶음 + 새 이름 + 묶지 않음). 문구는 qa.

## 6. 보고서 1인칭 창
- 서류철을 열면 입체 책상 장면(desk4)에 보고서 종이가 놓인다. 커피 잔·펜·도장·소매. 종이 본문은 텍스트 노드, 기울임은 CSS만.
- 승인은 도장을 찍으면 보내고, 종이에 도장 자국이 남는다. 수정 요청은 노란 쪽지 칸.
- **[답장 보내기](결재 없이 말만 전함, 사용자 결정 2026-10-25: 넣음):** 새 지시 종류 `note {reportId, text≤4000}`를 lead 틀에 더한다. 틀 규칙은 B306·12장 (c)와 같다(인용 칸, 모든 줄 `> `, 전각 `＜＞`, 코드 펜스 없음). 보고서 상태는 바꾸지 않고, 서류철에 "답장 보냄" 기록만 남긴다. 휴업 중 보관 키는 보고서 id별 하나(12장 l). security가 실패 테스트를 먼저 넣는다.

## 7. 검사(새 테스트)
- 빌드 검사 셋(계약 §10): `tokens.css`에 공통 UI 토큰이 있으면 실패, 대비 쌍(테마 쌍 + 앱 두 벌 쌍) AA 미만이면 실패, 장면 그림 합계 64KB 초과면 실패.
- 테마 로더: 알 수 없는 `contract` → 오피스, 빠진 필수 칸 → 오피스 그림, 빠진 `words` → 오피스 낱말.
- 변형: `system`이 `prefers-color-scheme` 변화를 따름, `day`·`night` 고정, 잘못된 값 400.
- 동작: 쉼 30초 전후, 동시 걷기 2명, 걷는 중 일 시작, 탕비실 손들기, 움직임 줄이기 정지 그림. 가짜 타이머로.
- 하위 팀: 이름 앞부분 묶기 규칙(리드 제외, 1명 묶음 없음), `groups.json` 저장·재시작·0600·권한 검사, API 거절(Origin·남는 키·잘못된 이름·상한).
- 노력 정도: v2 이벤트만, 알 수 없는 값 버림, 일하는 중일 때만 오라.
- 접근성: 장식은 `aria-hidden`, 이름표·버튼 읽는 순서와 이름이 테마와 무관, 포커스 링 대비.
- 성능: 층 30개·팀원 30명 화면에서 화면 밖 층의 애니메이션이 멈추는지(클래스 확인). 실측은 qa 수동.

## 8. 하지 않는 것
- 판타지·우주선·사이버펑크 구현, 사람이 아닌 캐릭터 시트(계약 §3a), 시각에 따른 낮·밤 자동 전환, 외부 에셋.

## 9. 위험
- 화면 회귀: 지금 화면 테스트는 DOM만 보므로 그림이 틀려도 통과한다. qa가 900·360 렌더를 계약 렌더와 나란히 보고, 사용자 실사용 확인을 받는다.
- 성능: 층·팀원이 많을 때. 화면 밖 정지와 스프라이트 시트로 막고, 실측 결과에 따라 장식 수를 줄인다.
- 그림 자산 출처: 모두 저장소 생성기로 만든 것만 넣는다(계약 §8). 생성기는 Node 표준만 쓴다.
- 렌더 도구: 디자이너가 job 임시 폴더에 설치한 Playwright는 저장소 의존성이 아니다. 저장소에는 넣지 않는다.
