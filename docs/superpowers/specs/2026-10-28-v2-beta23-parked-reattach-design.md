# beta.23 설계안: 백그라운드로 옮겨진 층 다시 조종하기 (개정 2)

2026-10-28 · 상태: **사용자 승인 대기** · 앞선 일: beta.21(옮겨진 층에 지시를 막고 이유 표시, 0f1799d), beta.22(안 A)
개정 2: security 재검토(H1·M1~M5·L1·L2) 반영 — **7장이 구현 규칙이고, 2·3장과 다르면 7장이 이긴다.**
개정 1: security 검토(같은 날) 반영 — 처음 안(세션 기록을 따라 앞면 열쇠를 찾고 bg 연결이 앞면을 자동으로 대신)을 버리고 **대안 A(버튼 + 대화별 1회용 열쇠)**로 바꿈.

**결론:** 사용자가 옮겨진 층에서 **[백그라운드로 연결 옮기기]**를 누르면, 대시보드가 그 대화 전용 **새 열쇠**를 만든다.
bg 쪽 channel 서버는 **자기 대화 id와 이름이 같은 열쇠 파일**만 찾아 붙는다. 앞면 연결은 건드리지 않는다(12장 g ② 그대로).
함께, 지금 코드에 있는 위험(데몬이 물려준 열쇠 경로로 **엉뚱한 대화가 다른 층에 붙는 것**)을 막는다.

## 1. 문제

대시보드가 tmux로 띄운 층의 대화가 Claude Code 백그라운드 job으로 옮겨 가면(세션 기록: 앞면 `parkedJobId` ↔ bg `kind:"bg"`·`jobId`, B192로 이미 짝지음):

```
                 대시보드(4317)
                 ▲ channel 연결됨            ✕ 연결 못 함
                 │                           │
 tmux 층 ── 앞면 claude ── channel 서버    ← 열쇠 파일 경로(CLAUDE_OFFICE_FLOOR_KEY_FILE) 있음
            대화 없음(지시를 대기열에만 쌓음)
 bg-pty-host ── bg claude ── channel 서버  ← 열쇠 파일 경로 없음
            대화 있음(사용자가 지금 쓰는 쪽)
```

- beta.21은 이 층에 지시를 **막고** "백그라운드로 옮겨짐"을 보인다(이 Mac에서 실확인). 지시가 **닿게** 하지는 않았다.
- bg 프로세스는 Claude Code가 미리 띄워 둔 예비 프로세스(`claude bg-spare`)가 대화를 넘겨받은 것이다. 환경은 **데몬이 처음 뜬 세션의 것**을 물려받는다(이 Mac의 bg에 옛 이름 `CLAUDE_OFFICE_FLOOR_KEY`가 남아 있음 — 이 층의 것이라는 보장이 없음).

## 2. 지금 코드에 있는 위험 (security 1번, 이번에 함께 고침)

데몬이 층 A에서 뜨면 모든 bg 대화가 A의 `CLAUDE_OFFICE_FLOOR_KEY_FILE`을 물려받는다. 무관한 대화 X의 channel 서버가 A의 열쇠로 붙을 준비를 하고 있다가, A의 앞면 연결이 끊기는 순간(`/mcp` 재연결·재시작) 먼저 붙는다. 그러면 A로 보낸 지시가 **X의 폴더에서 실행**되고, X가 낸 보고서·질문은 A의 것으로 들어간다(층은 연결로만 정해짐 — `server/floors/channels.ts:358-366`).

**고침:**
- 모든 연결의 hello·증명(proof)에 **주장하는 대화 id**(`CLAUDE_CODE_SESSION_ID`)를 넣고 MAC에 묶는다.
- 대시보드는 그 id가 {그 층의 id, 그 층의 지금 대화 id(convId)} 중 하나일 때만 연결을 받는다.
- 지시·보관 지시 보내기(`flushHeld`)·제출(`/channel/submit`)마다 "연결의 대화 id = 그 층이 지금 받아야 할 대화 id"를 다시 확인한다.
- 확인할 것: 앞면의 `CLAUDE_CODE_SESSION_ID`가 등록 파일의 층 id와 같은지, 옮겨 열기(`--resume`)로 연 층에서도 같은지 — 실측.

## 3. 설계 (대안 A)

### 3.1 대시보드: 버튼과 대화별 열쇠
- 옮겨진 층(beta.21의 `parked`) 칩 옆에 **[백그라운드로 연결 옮기기]**. 누르면 확인 창에 붙을 대화의 이름·폴더를 보여 사람이 확인한다.
- 확인하면 `<floors>/conv-<convId>.key`(0600, 무작위 64자 hex)를 새로 쓴다. 층 열쇠와 따로다.
- 그 열쇠로 붙은 연결은 **별도 연결**이다(앞면 연결을 대신하지 않음 → 12장 g ② 그대로). 옮겨진 층의 지시·제출은 이 연결로만 오간다.
- 끊기: 층이 끝나거나, 대화가 앞면으로 돌아오거나(parked 해제), 사용자가 [연결 끊기]를 누르면 열쇠 파일을 지우고 연결을 닫는다.
- 짝이 모호하면(같은 jobId·parkedJobId 짝이 둘 이상) 버튼을 끄고 이유를 보인다(security 3번).
- 함께 고침: bg 기록이 남아 있어도 **bg pid가 죽었으면** 옮겨진 것으로 보지 않는다(beta.21 리뷰 메모).

### 3.2 channel 서버: 자기 이름의 열쇠만 찾기 (`plugins/claude-office/channel/server.mjs`)
- 자기 세션 기록이 `kind:"bg"`이면 **환경의 열쇠 경로를 무시**한다(2장).
- `<floors>/conv-<CLAUDE_CODE_SESSION_ID>.key`가 있으면 그것으로 붙는다. 세션 기록·등록 파일을 따라가는 코드는 없다 — 짝 계산은 대시보드 한 곳에만 둔다.
- `<floors>` 위치는 환경(`CLAUDE_OFFICE_PREFIX`)이 아니라 **고정 기본값 또는 플러그인 설치 위치**에서 정한다(security 4번).
- 열쇠 읽기는 대시보드의 `readKeyFile`과 같은 수준: `O_NOFOLLOW`로 열고 `fstat`으로 소유자·0600/0400 확인, 폴더도 소유자·쓰기 권한 검사. 대화 id는 세션 id 정규식, 열쇠는 64자 hex만.
- 열쇠가 없거나 검사에 실패하면 지금처럼 조용히 연결하지 않는다. 팀원 프로세스 판별(12장 g ①)은 그대로 먼저.
- 파일을 1~2초마다 다시 볼 것인가(버튼을 누른 뒤 붙으려면 필요) — 구현 때 간격과 상한을 정한다.

### 3.3 독립 확인 (security 2번, 선택)
연결한 소켓의 프로세스를 운영체제에 물어(macOS `lsof`, Linux `/proc`) 그 부모가 bg 기록의 pid인지 확인하면, "가짜 세션 기록 JSON 하나"로는 붙지 못한다. 대안 A에서는 대화별 열쇠가 사람 확인 뒤에만 생기므로 **이번에는 넣지 않고** 보안 검토에서 다시 판단한다.

### 3.4 하지 않는 것
| 항목 | 이유 |
|---|---|
| 자동으로 bg가 앞면을 대신하기(처음 안) | security: 불변식(12장 g ②)이 검사 안 된 파일과 문서에 없는 필드에 맡겨짐 |
| 웹 터미널(Phase 8) | 별개 기능 |
| 별도 창(tmux) 팀원 손 내리기 | 회사 진단 파일 뒤 |
| 회사 PC 에이전트 안 보임 | beta.22 진단 결과 뒤 |

## 4. 보안 검토 반영표

| security 지적 | 심각도 | 반영 |

| 1. 데몬이 물려준 열쇠 경로로 엉뚱한 대화가 붙음(지금 코드) | 높음 | 2장 — 모든 연결에 대화 id 확인, bg는 환경 열쇠 경로 무시 |
| 2. 자동 대신하기의 근거가 검사 안 된 파일·스스로의 주장 | 중간 | 자동 대신하기 버림(대안 A). 독립 확인은 3.3 |
| 3. 맞는 연결 둘이 서로 빼앗기 / 짝이 모호 | 중간 | 별도 연결이라 빼앗기 없음. 모호한 짝은 버튼 끔 |

| 5. 문서에 없는 필드의 뜻이 바뀜 | 중간 | 짝 계산은 대시보드 한 곳 + 사람 확인 + 모호하면 끔 |

## 5. 검증
1. **단위:** 대화 id 확인(맞음·틀림·없음 → 거절), bg의 환경 열쇠 경로 무시, 환경에만 열쇠가 있을 때 연결 안 됨, 대화별 열쇠 만들기·지우기, 모호한 짝, 열쇠 파일 권한·링크.

## 7. 구현 규칙 (개정 2, security 재검토 반영 — 2·3장보다 우선)

**위협 모델:** 같은 계정의 프로세스는 원래 열쇠 파일을 모두 읽을 수 있다. 이 기능의 장치(사람 확인·1회용 열쇠·대화 id 확인)는 **잘못 배달**(엉뚱한 대화가 지시를 받거나 보고서를 냄)을 막는 장치이며, 같은 계정 공격을 막는 경계가 아니다.

### 7.1 허용 집합 (H1·M1·M5)
| 연결에 쓴 열쇠 | 받는 대화 id | 비고 |
|---|---|---|
| 층 열쇠 `<tmux>.key` | **expectConv 하나** = 층을 띄울 때 정한 id(`resume ?? sessionId`) | 지금 대화 id(bg)는 받지 않는다 — 자동 대신하기가 되살아나지 않게(H1) |
| 대화 열쇠 `conv-<convId>.key` | **convId 하나** = 버튼을 누른 순간 대시보드가 계산한 bg 대화 id | 층 id는 받지 않는다 |
- `register(sessionId, tmux, expectConv)`. 등록 파일에 `conv` 필드를 더하고 복원 때 같이 되살린다(옮겨 열기 층, M1). 지시·flushHeld·submit 때 다시 확인하는 기준도 builder 값이 아니라 **저장된 값**.
- 주장하는 대화 id는 client proof와 세션 키 계산에 모두 넣는다. 대화 열쇠는 **별도 Map**, 용도 접두사도 따로(`conv-kid`, `conv-client|…`). 대화 연결의 submit·ack는 그 층 id로 매핑한다(M5).
- channel 서버는 **세션 기록을 읽지 않는다**(3.2의 "kind:bg면 환경 열쇠 무시"는 뺀다). 물려받은 층 열쇠로 붙으려 해도 대화 id가 expectConv와 달라 거절된다 — 판단은 대시보드 한 곳.

### 7.2 대화 id가 없거나 다를 때, 옛 channel 서버 (M1·M4, 호환)
- 실측(이 Mac, 2026-10-28): `--session-id`로 띄운 층 2개의 channel 서버 `CLAUDE_CODE_SESSION_ID` = 층 id. bg 대화의 channel 서버도 이 값을 가짐. 옮겨 열기 층·`/clear` 뒤 `/mcp` 재연결은 **구현 중 실측**.
- 거절은 401이 아닌 **403 + reason**(`conv-mismatch`·`conv-missing`·`old-channel`). channel 서버는 403이면 그 열쇠로 다시 시도하지 않는다. 거절 로그는 연결마다 한 번.
- 층에는 조용히 끊기는 대신 **"다시 띄우기 필요"**(옛 channel 서버·대화 id 바뀜)를 표시한다. 옛 형식(대화 id 없음)은 받지 않는다 — 허용하면 그 동안 위험 ①이 열려 있다. 업그레이드 뒤 기존 층은 `/mcp`에서 다시 연결하거나 다시 띄워야 하며, 설명서·화면에 적는다.
- security 답(질문 7): 옛 형식을 한 릴리스 허용하는 안은 위험 ①을 막는 효과가 **0** — 대시보드는 kid로만 구분하고, 물려받은 열쇠도 같은 층 열쇠라서. 업그레이드(대시보드 재시작) 직후가 오히려 가장 위험한 때. 그래서 거절(a)로 확정하되 두 조건:
  1. **`/mcp` 재연결이 새 코드를 띄우는지 실측.** 이 Mac의 channel 서버는 모두 버전 없는 경로(`~/.claude-office/plugin/plugins/claude-office/channel/server.mjs`)에서 뜬다 → 설치가 같은 경로를 덮으면 `/mcp`로 충분할 가능성이 큼. 아니라면 안내를 "층 다시 띄우기(옮겨 열기)"로.
  2. 옛 서버는 거절을 받아도 열쇠 파일이 있는 한 계속 다시 시도한다(server.mjs:197·221) — hello에 대화 id 필드가 없으면 옛 형식으로 알아보고, kid가 가리키는 층에 **"이 층 열쇠로 옛 버전 channel이 붙으려 함"**(중립 문구 — bg X가 시도해도 A에 뜨므로)을 표시, 로그는 kid마다 한 번.
- 구현 시험에 옮겨 열기 층을 하나 띄워 `CLAUDE_CODE_SESSION_ID` = resume id인지 잰다(다르면 그 층이 영구히 끊기는 회귀).

### 7.3 대화 열쇠 수명 (M2·M4)
| 시점 | 동작 |
|---|---|
| 버튼 확인 | tmp에 쓰고 rename(0600). 옛 대화 열쇠·kid 무효 |
| **첫 연결 성공** | 파일 지우고 kid 무효(1회용). 끊기면 버튼을 다시 눌러야 함 |
| 연결 끊기 버튼·parked 해제·bg pid 죽음(빌드마다)·층 종료 | 파일과 대화 연결 함께 정리 |
| 대시보드 시작 | 등록 파일을 믿든 못 믿든 **자기 소유 `conv-*.key` 모두 지움**. 되살리지 않음 |
- 대화 연결은 층마다 하나, 첫 연결이 이긴다.

### 7.4 channel 서버 (M2·L2)
- **구현 중 바꿈(폴링 없음):** channel 능력(`claude/channel`)은 MCP initialize 때만 알릴 수 있어(server.mjs), 열쇠 없이 떠 있던 서버가 나중에 열쇠를 찾아도 Claude Code가 지시를 channel로 받지 않는다. 그래서 **시작할 때 한 번만** 찾고, 사용자는 버튼을 확인한 뒤 그 bg 터미널에서 `/mcp`로 다시 연결한다(확인 창·칩 안내). 폴링이 없어 공격면도 줄었다.
- 찾기는 **부모 프로세스가 claude일 때만**(이미 있는 `procOf` 재사용 — Bash 자식이 대화 id를 물려받아 붙는 것을 막음).
- **남은 실측:** bg job으로 옮겨진 세션이 channel 알림을 받는지(`--dangerously-load-development-channels`가 bg 쪽에도 이어지는지) — 이 Mac의 이 세션으로 확인.
- 열쇠 읽기: `O_NOFOLLOW` + `fstat`(소유자·0600/0400) + 64자 hex, 폴더 소유자·쓰기 권한 검사. convId는 **UUID 정규식**을 통과한 뒤에만 경로에 쓴다(지금 SESSION_ID 정규식은 `..`을 허용 — M3).
- `<floors>`는 고정 기본값(`~/.claude-office/floors`). 대시보드 위치가 이와 다르면 버튼을 끈다. 테스트는 환경으로 물려받지 않는 진입점으로 폴더·포트를 주입.
- stdout 오류(EPIPE)면 종료(재연결 뒤 옛 서버가 연결을 쥐고 있지 않게).

### 7.5 버튼 API (M3·L1)
- 쿠키 + same-origin만. **bearer(CLI 토큰) 거절**.
- 요청 본문에 화면이 보여 준 convId를 넣고, 서버가 그 순간의 짝과 다르면 409.
- 확인 창: 층 이름·폴더와 bg 쪽 이름·폴더·pid·시작 시각을 나란히, 제어·bidi 문자 제거. "같은 대화가 여러 곳에 열려 있으면 먼저 붙는 쪽이 받습니다" 문구, 또는 같은 sessionId의 살아 있는 기록이 둘 이상이면 버튼 끔.
- 짝이 모호하면(같은 jobId의 bg 둘 이상, 같은 parkedJobId의 앞면 둘 이상) 버튼 끔. `pairLaunched`가 표시를 남긴다(지금은 마지막 bg가 조용히 이김 — 주석과 다름).
