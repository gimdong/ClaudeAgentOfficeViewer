# v2 Phase 6b Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 팀리더 전용 기능 — 지시 통로, channel MCP 제출 도구, 대화 질문 답하기, 보고서·결재, 퇴근·출근, 퇴사·새 팀원.

**Architecture:** 서버가 정해진 틀로 지시문을 만들어 기존 channel로 보내고(`/api/floors/:id/lead`), 세션은 channel MCP 도구(`submit_report`·`submit_handover`·`ask_user`)로 결과를 `/channel/submit`에 MAC 인증으로 보낸다. 대화로 묻고 멈춘 경우는 Stop 이벤트의 마지막 글로 판정해 보여 준다. 상태는 `<PREFIX>/reports.json`.

**Tech Stack:** Node, Express 5, React, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-21-v2-phase6b-design.md`

## Global Constraints
- 새 의존성 없음. `~/.claude` 쓰기 없음. 숫자(상한)는 스펙에만 — 판정 메시지에 숫자를 따로 쓰지 않는다(Phase 6a 교훈).
- 사용자 글은 틀의 칸 안에서만, 4,000자. 보고서 본문 64KB, 층마다 50개.
- channel 연결 없는 층은 409 + 화면 비활성 문구 `작업 지시 켜기(옮겨 열기)로 연결하면 쓸 수 있습니다`.
- 보고서·질문 글은 화면에 글자로만 그린다(HTML·마크다운 렌더 금지).
- 사용자 4317·설치본·`~/.claude` 접근 금지, 시험 포트 4320+, install.sh 시험은 `--port`.
- 커밋 전 `git diff --cached --stat`. 보충·판정이 커밋 뒤에 닿을 수 있으니 director는 커밋마다 스펙·판정과 대조.

## Review Focus
1. 지시 틀 주입: 사용자 글에 `</channel>`·줄바꿈·"이전 지시 무시" 같은 글이 있어도 틀 밖 지시가 되지 않아야 한다.
2. `/channel/submit`은 연결이 살아 있고 MAC이 맞는 층의 것만 받아야 한다(다른 층 이름으로 제출 불가).
3. 보고서·질문 글이 화면에서 HTML로 해석되지 않아야 한다(XSS).
4. 대화 질문 표시가 터미널에서 답한 뒤 남아 있지 않아야 한다(다음 UserPromptSubmit/PreToolUse에 해제).
5. reports.json 상한·정리·0600, 서버 재시작 후 보존.
