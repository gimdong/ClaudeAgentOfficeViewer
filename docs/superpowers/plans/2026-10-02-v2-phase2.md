# v2 Phase 2 — 결정 루프와 예산 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 대시보드에서 Claude Code의 결정 요청(권한, 질문, 계획 승인, 예산 관문)에 답할 수 있게 하고, 층마다 토큰 예산과 알람을 둔다.

**Architecture:**
- **플러그인:** `PermissionRequest` hook의 timeout만 600초로 올린다. 나머지 hook은 5초 그대로다.
- **서버:** `/hooks/event`가 `PermissionRequest`의 응답을 `DecisionQueue`에 붙잡아 두고, 대시보드의 답(`POST /api/decisions/:id`)이 오면 hook 응답 JSON을 돌려준다. 연결이 끊기면 `closed-terminal`, 590초가 지나면 빈 200으로 놓아준다(`expired`). `PreToolUse`는 메모리 값만으로 즉시 응답한다(평소 빈 200, 예산 관문이면 `ask`).
- **예산:** `BudgetStore`가 상태 파일(`state.json`)을 원자적으로 쓰고, `BudgetGate`가 스냅샷이 넣어 준 세션 사용량으로 관문을 판정한다.
- **보안:** 설치 때 만든 토큰을 `/?k=<토큰>`으로 한 번 받아 쿠키로 바꾼다. `/hooks/event`와 정적 파일을 뺀 모든 `/api/*`는 쿠키(또는 CLI의 Bearer 헤더)가 있어야 한다.
- **화면:** 손 든 캐릭터와 HUD 칩이 결정 보고서(오른쪽 서랍)를 연다. 층 머리에 예산 막대와 설정 창을 둔다.

**Tech Stack:** Node 24 (ESM), TypeScript, Express 5, React 19, Vite, Vitest, jsdom, POSIX sh, PowerShell 5+

**Spec:** `docs/superpowers/specs/2026-10-02-v2-phase2-design.md` (커밋 67a41f0, 사용자 승인)
**선행:** Phase 1 계획 `docs/superpowers/plans/2026-10-01-v2-phase1.md`, 베타 계획 `docs/superpowers/plans/2026-10-01-beta-release.md`, Phase 0 보고서 `docs/superpowers/spikes/2026-09-30-phase0-report.md`, 디자인 `docs/design/phase1/SPEC.md`(6·8·11장) + `docs/design/phase2/SPEC.md`(Task 1)

## Global Constraints

- 기준 브랜치 `feat/v2-phase2`(main `2827b1a` + 스펙 `67a41f0`). push·merge·태그 push는 하지 않는다.
- Phase 1·베타의 제약은 그대로다: Node ≥ 24, `127.0.0.1`에만 바인딩, Host 검사, 서버는 claude home 아래에 아무것도 쓰지 않는다, UI 문구는 한국어, 이미지 파일을 쓰지 않는다.
- hook: `PermissionRequest`만 `"timeout": 600`, 나머지 12개는 `"timeout": 5`. hook 요청에는 비밀값을 붙이지 않는다(스펙 7.2). `/hooks/event`의 기존 검사(Host, Origin이 있으면 403, 1MB, JSON, 400)는 그대로다.
- `/hooks/event`는 어떤 경우에도 hook을 막지 않는다. 처리 중 예외가 나면 **빈 200**을 돌려준다. `PreToolUse` 응답은 메모리 값만으로 만들고 파일·대화 기록 읽기를 기다리지 않는다(1초 안, 측정 테스트).
- 결정 상태: `pending` → `answered-dashboard` | `closed-terminal` | `expired`. 서버는 **590초**에 빈 200으로 놓아준다. 답은 한 번만 받고, `pending`이 아니면 **409**.
- hook 응답 형식은 `server/decisions/protocol.ts` 한 곳에만 둔다.
  - 권한·계획: `{"hookSpecificOutput":{"hookEventName":"PermissionRequest","decision":{"behavior":"allow"|"deny","message"?}}}`
  - 질문: `behavior:"allow"` + `updatedInput` = **원래 `tool_input` 전체** + `answers`(`{질문 원문: label 또는 자유 문자열}`, 다중 선택은 `"a, b"`)
  - 예산 관문: `{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"ask","permissionDecisionReason":"예산(…토큰)에 도달했습니다. 대시보드나 이 창에서 계속할지 정해 주세요"}}`
- 문구(스펙 그대로): 거부 이유 기본값 `대시보드에서 사용자가 거부했습니다`, 예산 중단 `예산에 도달해 사용자가 중단했습니다`, 401 화면 `터미널에서 claude-office로 열어 주세요`, 409 화면 `이미 터미널에서 답했습니다`, 팀원 요청 안내 `터미널(리드 세션)에서 답해 주세요`.
- 원래 `tool_input`은 **서버 메모리에만** 둔다. 화면·SSE·로그·진단 파일에는 `redact()`와 200자 자르기를 거친 값만 나간다. 거부 이유·답 내용·토큰 값은 로그·진단 파일·스냅샷 어디에도 쓰지 않는다. 결정 로그는 `kind`, `state`, 걸린 시간(ms), 세션 순번만.
- 토큰: 무작위 32바이트 hex. 설치본 `<prefix>/token`, 개발 `.logs/token`, 권한 0600. 이미 있으면 그대로 둔다. 쿠키 `co=<토큰>; HttpOnly; SameSite=Strict; Path=/; Max-Age=31536000`. 비교는 `timingSafeEqual`.
- 예산 상태 파일: 설치본 `<prefix>/state.json`, 개발 `.logs/state.json`. 임시 파일에 쓴 뒤 rename. 읽기에 실패하면 빈 상태로 시작하고 warn 로그.
- 사용량은 세션 구성원 `tokens.total`의 합이다(input + output + cacheWrite, cacheRead 제외).
- 추천·자동 응답·자유 채팅·소리·금액 단위 예산·hook 요청 인증은 범위 밖이다(스펙 11장).
- 버전은 `2.1.0-dev`. `package.json`, `plugin.json`, `marketplace.json`, 패키지 `VERSION`, 사용설명서가 모두 같다(기존 일치 테스트 유지).
- **안전 규칙(전원):**
  - 실제 `~/.claude`, `~/.zshrc`를 고치지 않는다. 사용자 실제 설치본(`~/.claude-office`, 4317 서버)은 쓰지도 끄지도 고치지도 않는다. 실험·개발 포트는 **4319 이상** 또는 테스트의 `listen(0)`.
  - 시작 기준값(2026-10-02 director 측정): `~/.claude/settings.json` sha1 `8aad40373b0e9a196d0c8e5e6250aab5468476a6`, `known_marketplaces.json`의 `claude-office` 3건, `~/.claude-office/VERSION` `2.0.0-beta.1`(sha1 `56f848cf…`, mtime Oct 1 22:31:40), `~/.zshrc` mtime Oct 1 22:31:40, 4317 리슨 PID 32825. 실험·설치 테스트 전후로 비교하고 하나라도 다르면 정리 없이 멈춰 보고한다.
  - 설치 스크립트와 실제 `claude`는 node `spawnSync`에 `env`를 명시해 실행한다(`process.env`를 펼치지 않는다). 설치 스크립트는 `HOME`·`CLAUDE_CONFIG_DIR`가 임시 폴더, `--no-open`. 실제 `claude`는 shim이 아니라 `readlink ~/.local/bin/claude`의 절대 경로를 쓴다.
  - 권한 분류기가 막으면 멈추고 보고한다. 다른 방법으로 우회하지 않고, 다른 팀원에게 대신 시키지 않는다.
  - 자격 증명 파일은 읽지 않는다. 비밀값을 옮기지 않는다. 테스트 값은 가짜만 쓴다.
  - 커밋은 `git add <경로>`로 자기 파일만. `git add -A`, `git add .`, `commit -a`, `checkout`, `restore`, `stash`는 금지다.
  - 메모리 파일(`~/.claude/projects/…`)은 고치지 않는다.
- 원인을 모르는 간헐 실패가 하나라도 있으면 완료로 적지 않는다(B14). 최종 확인은 한 사람 단독 실행(B23).

## Review Focus

1. **가짜 hook이나 폭주로 결정이 수백 건 쌓이는 경우:** 같은 PC의 다른 프로세스가 `PermissionRequest`를 계속 보내도 서버 메모리와 화면이 버텨야 한다. `pending`은 50건까지만 붙잡고, 넘으면 즉시 빈 200으로 돌려보낸다. → Task 3 테스트 `pending이 50건이면 새 요청은 붙잡지 않고 빈 200`
2. **같은 결정에 거의 동시에 두 번 답하는 경우(더블클릭, 두 탭, 터미널과 동시):** 응답은 한 번만 쓰고 두 번째는 409여야 한다. 이미 끊긴 연결에 쓰다가 서버가 죽으면 안 된다. → Task 3 테스트 `연결이 끊긴 뒤의 답은 409이고 응답에 쓰지 않는다`, `같은 답을 두 번 보내면 두 번째는 409`
3. **질문 문구나 선택지에 가림 대상·200자 초과·같은 label이 있는 경우:** 화면 문자열로 `answers`를 만들면 원문과 어긋난다. 화면은 인덱스로 답하고 서버가 원문으로 키를 만든다. → Task 3 테스트 `가려진 질문도 원문 그대로 answers의 키가 된다`
4. **상태 파일이 깨졌거나 쓸 수 없는 경우:** 서버는 빈 상태로 켜지고, `PreToolUse`는 계속 빈 200을 돌려줘야 한다(작업을 막지 않는다). → Task 6 테스트 `손상된 state.json이면 빈 상태로 시작하고 warn`, `저장에 실패해도 preToolUse는 던지지 않는다`
5. **쿠키가 없거나 서버가 다시 켜진 뒤의 화면:** 401이면 빈 화면이 아니라 안내를 보여 주고, 보고서를 연 채 결정이 사라지면 "터미널에서 이미 답함"으로 닫혀야 한다. → Task 8 테스트 `401이면 안내 화면을 보여 준다`, `열어 둔 결정이 목록에서 사라지면 닫힘 배너를 보여 준다`

## 계획서 판정 (계획을 쓰며 정한 것, B27부터)

- **Ruling B27 (범위와 디자인의 충돌):** Phase 1 디자인 8장의 결정 보고서에는 채팅 입력, "이 세션에서 같은 명령은 다시 묻지 않기", 추천 딱지, "지금까지의 흐름", "{n}k 늘리고 계속", 팀원 요청 선택지가 있다. Phase 2 스펙(Q1·Q5·Q6, 3.3, 6장)은 이들을 범위 밖으로 둔다. **기능 범위는 스펙, 크기·색·문구는 디자인**이 정한다. designer가 Task 1에서 `docs/design/phase2/SPEC.md`에 줄인 모양을 적고, 그 문서가 Phase 1 8장보다 먼저다. — 틀리면 비용: Phase 4에서 채팅을 넣을 때 서랍 아래쪽을 다시 그린다.
- **Ruling B28 (손들기 기준):** 스펙 3.2대로 손을 드는 기준은 큐의 `pending`이다. `SnapshotBuilder`에 큐가 연결되면 `derive.ts`의 `decision`은 쓰지 않는다. 예외는 큐가 다루지 않는 종류다: 팀원 요청(6장)과, Task 0에서 계획 승인이 "보고서만"으로 판정될 때의 `plan`(`derive`의 `PreToolUse(ExitPlanMode)` 감지를 쓴다). `expired`·`closed-terminal`이 되면 손을 내린다. — 틀리면 비용: 시간이 지난 요청은 터미널에서만 보인다(Q2가 정한 동작).
- **Ruling B29 (남은 시간 기준):** 화면의 남은 시간은 서버가 놓아주는 시각(`createdAt + 590초`)까지 센다. 0이 되는 순간과 `expired`가 같다. — 틀리면 비용: 처음 표시가 "9:50"이다.
- **Ruling B30 (질문 답은 인덱스):** `POST /api/decisions/:id`의 질문 답은 `answers: Array<{ labels: number[] } | { other: string }>`(질문 순서)이다. 서버가 메모리의 원문에서 `answers` 객체를 만든다. 자유 입력은 500자까지. — 틀리면 비용: 없음.
- **Ruling B31 (계획 미리보기):** `ExitPlanMode`의 `plan`은 `redact()` 뒤 4000자까지 화면에 보낸다. 무엇을 승인하는지 보여 줘야 하기 때문이다(스펙 12장). 로그·진단 파일에는 넣지 않는다. — 틀리면 비용: 계획 본문이 SSE로 브라우저에 간다(같은 PC, 쿠키 인증 뒤).
- **Ruling B32 (쓰기 인증):** 쓰기 API는 `(쿠키 일치 + 같은 출처 Origin 있음)` 또는 `(Authorization: Bearer <토큰> + Origin 없음)`일 때만 통과한다. 뒤쪽은 CLI(`diag`)용이다. 둘 다 `Content-Type: application/json`과 Host 검사가 필요하다. 읽기 API는 쿠키 또는 Bearer. — 틀리면 비용: CLI 경로를 막으면 `claude-office diag`가 서버 통계를 못 넣는다.
- **Ruling B33 (토큰 파일이 없을 때):** 서버는 시작할 때 토큰 파일이 없으면 만든다(설치본·개발 모두). beta.2에서 올라온 설치본에는 토큰 파일이 없기 때문이다. 런처는 파일을 읽기만 한다. 개발 모드에서만 콘솔(로그 파일 아님)에 토큰 주소를 출력한다. 설치본은 출력하지 않는다. — 틀리면 비용: 개발 터미널 기록에 토큰이 남는다.
- **Ruling B34 (예산 "계속"의 계산):** `nextGateAt += budgetTokens`를 `nextGateAt > 사용량`이 될 때까지 되풀이한다. 평소에는 스펙 식과 같고, 사용량이 예산을 크게 넘었을 때 곧바로 다시 묻지 않는다(Q4-3 "예산만큼 더 쓰면 다시 묻는다"). 예산을 새로 정할 때도 같은 식으로 처음 값을 잡는다. — 틀리면 비용: 한 줄.
- **Ruling B35 (예산 관문의 범위):** 관문은 `AskUserQuestion`·`ExitPlanMode`에는 걸지 않는다(사용자와의 대화이지 실행이 아니다). 관문 중에 "계속"을 누르면 그 도구 호출 하나를 허용하고 `nextGateAt`을 올린다. 같은 세션의 다른 예산 결정은 자동으로 허용하지 않고 `permission` 종류로 바꿔 남긴다(Q6). 터미널에서 허용한 것으로 확인되면(`PostToolUse`가 그 `tool_use_id`로 옴) "계속"으로 본다 — 스펙의 안내 문구가 "대시보드나 이 창에서"이기 때문이다. — 틀리면 비용: 터미널 허용을 계속으로 보지 않으면 도구 호출마다 창이 뜬다.
