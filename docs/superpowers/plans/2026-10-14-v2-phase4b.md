# v2 Phase 4b — 작업 지시·새 층(실험 기능) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 대시보드가 channel을 붙인 새 층을 tmux로 띄우고, 그 층에 작업을 지시하며, 휴업 중 지시는 보관했다가 재개 브리핑에서 고쳐 보낸다.

**Architecture:** 플러그인에 의존성 없는 stdio MCP channel 서버(`plugins/claude-office/channel/server.mjs`)를 넣는다. 이 서버는 포트를 열지 않고, 층 열쇠가 env에 있을 때만 4317 `/channel/stream`(SSE)에 나가는 연결을 건다. 서버 쪽 `server/floors/channels.ts`가 launched·연결·보관함·실험 스위치를 들고, `server/floors/launch.ts`가 `tmux`를 인자 배열로 실행한다. 화면은 스냅샷의 `SessionView.channel`만 보고 그린다.

**Tech Stack:** Node 24 ESM, TypeScript, Express 5, React 19, Vitest, jsdom.

**Spec:** `docs/superpowers/specs/2026-10-14-v2-phase4b-design.md` (1d2c8ce)

## Global Constraints
- 브랜치 `feat/v2-phase4b`(main f7d04db 위). push·merge·태그는 사용자 지시 후에만.
- 실행 파일은 `tmux`와 서버 시작 때 확인한 claude 절대 경로뿐, 셸 없음. 첫 지시는 channel 옵션 **앞**.
- channel 서버는 포트를 열지 않는다. `process.env`에서 `CLAUDE_OFFICE_FLOOR_KEY`, `CLAUDE_OFFICE_PORT`만 읽는다. 열쇠 없으면 무연결·무출력.
- 층 열쇠·지시 글·폴더 경로는 로그·진단·스냅샷에 넣지 않는다.
- 상한: 띄운 층 8, 층당 보관 20, 지시 8,000자.
- 실험 스위치는 `~/.claude-office/experimental.json`(0600, 원자적 쓰기)에 저장한다 — 스펙 §3의 "state.json과 같은 파일"을 B160으로 바꿈: 예산 저장소의 형식을 건드리지 않으려고 따로 둔다.
- 실제 세션 확인은 job tmp·4319 이상·`tmux -L p4bt`, 프롬프트 4개 이하, 사용자 4317과 그 세션은 대상 아님.

## Review Focus
1. 열쇠 없는 평범한 세션에서 channel 서버가 연결·출력을 하면 모든 세션이 영향을 받는다 → 무연결 테스트.
2. 지시 글에 따옴표·`$()`·줄바꿈이 있어도 그대로 한 인자 → 인자 배열 테스트.
3. 휴업 중 보낸 지시가 바로 나가면 도구 거부만 쌓인다 → held 상태 테스트.
4. 재개 브리핑에서 [취소]하면 휴업 유지·보관 유지.
5. channel 연결이 끊긴 층에 지시를 보내면 조용히 사라지면 안 된다 → 409 `not-connected`.

## 실행 중 바뀐 것
- **B160** 실험 스위치는 `experimental.json`에 따로 저장(예산 저장소 형식을 건드리지 않음).
- **B161** 재개 브리핑은 **보관 지시가 있는 층**에서만 연다. 결정만 기다리는 층은 4a 흐름 그대로(재개 뒤 가장 오래된 결정 보고서). 스펙 §7의 "휴업 중 답한 질문 N건" 줄은 넣지 않았다 — 결정 큐에 "휴업 중 대시보드가 답한 질문"을 세는 기록이 없어 새로 만들어야 하고, 답 고치기와 함께 다음 단계에서 다룬다.
- **B162** 진단 묶음의 launched/connected/held 수와 doctor 한 줄은 넣지 않았다(다음 정리 후보). 로그 `floors` 줄(launch·channel-connect·instruct·held·resume-send·channel-drop)은 들어갔다.
- **B163** Task 0을 Task 5와 합쳤다(모델 호출 없이 따로 할 이유가 없었음). 결과는 아래.
- channel 서버는 열쇠가 없으면 channel 능력·안내 문구(instructions)도 내지 않는다 — 플러그인은 모든 세션에 깔리므로, 안내 문구가 모든 세션의 맥락에 들어가지 않게.
- `/channel/stream`은 `flushHeaders()`로 바로 연결됨을 알린다(처음엔 심장박동 15초를 기다렸다).
- claude 실행 파일은 `~/.local/bin/claude`를 PATH보다 먼저 본다 — PATH 앞쪽의 터미널 shim(cmux)은 자기 `--session-id`를 끼워 넣는다. `CLAUDE_OFFICE_CLAUDE_BIN`·`CLAUDE_OFFICE_CHANNEL_SPEC`·`CLAUDE_OFFICE_TMUX_SOCKET` 환경변수로 바꿀 수 있다(실험·시험용).

## 브랜치 리뷰(#410, reviewer Opus) 반영
- 판정: 수정 후 승인(Critical 0, Important 3, Minor 6). 결과 `.superpowers/sdd/2026-10-13-v2-phase4b-spike/branch-review.md`.
- **I1 고침:** 첫 지시·이름이 `-`로 시작하면 claude가 옵션(`--dangerously-skip-permissions`, `--mcp-config=` 등)으로 읽는다 → 400 `prompt-dash`/`name`, 폴더 이름에서 만든 기본 이름은 앞 `-`를 뗀다. 화면·설명서에 안내.
- **I2 고침:** tmux 3.0 미만은 명령을 `sh -c`로 넘긴다 → 시작 때 `tmux -V`를 읽어 3.0 미만이면 실험 기능을 켤 수 없다.
- **I3 고침:** 정상 종료(레코드 삭제)·확인 창 미확인·tmux 삭제 층이 `launched`에 남아 8개 뒤 429가 됐다 → 빌드마다 `sweep`: 나타났다 사라진 층은 바로, 10분 넘게 안 나타나고 연결도 없는 층은 정리.
- **M2 고침:** 연결 전인 층의 [보내고 재개]는 재개하지 않고 409 `not-connected`(보관 지시와 휴업이 함께 남음).
- **M5 고침:** `PUT /api/experimental`에도 floors의 guard.
- **M6 반영:** 설명서에 "모든 세션에 작은 channel 서버가 뜬다, 대시보드가 띄운 층에서만 연결" 한 줄.
- **M3:** B161로 이미 적음(브리핑은 보관 지시가 있을 때만). **M4:** 이 커밋 전에 결과를 계획에 적어 두었음.
- **남은 위험(M1):** 층 열쇠가 `tmux -e`의 argv와 tmux 세션 환경에 실려 같은 PC의 다른 OS 사용자가 `ps`로 볼 수 있다. 같은 사용자 위협 모델에서는 받아들인다. 줄이려면 0600 파일로 넘기는 방식(스펙 9장 (나))으로 바꾼다.
- **M2의 나머지:** SSE에 쓴 즉시 `sent`로 보고 보관함에서 뺀다. 반쯤 죽은 연결에서는 지시가 사라질 수 있다(ack는 마지막 지시만 추적). 다음 정리 후보.
