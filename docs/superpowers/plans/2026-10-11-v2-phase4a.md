# v2 Phase 4a — 층 관리(일시정지·종료·숨김) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 사용자가 대시보드에서 층(세션)을 멈추고(일시정지), 다시 돌리고(재개), 끄고(종료 2단계), 목록에서 치울(숨김) 수 있게 한다. 모두 서버 메모리만 쓴다.

**Architecture:**
- **서버 상태:** `server/floors/control.ts`의 `FloorControl` 하나가 `paused`·`pausedDenied`·`hidden`·`terminating`을 메모리에 들고, 스냅샷 빌드마다 끝난 세션을 정리한다.
- **hook 관문:** `/hooks/event`의 `PreToolUse`가 **일시정지 deny → 정책 deny → 예산 관문 → 정책 ask** 순서로 답한다. 일시정지 deny는 정책 deny처럼 이벤트 저장소·큐·예산 관문을 거치지 않는다. 예외 도구 아홉 개(`EXEMPT_TOOLS`)는 통과한다.
- **종료:** `POST /api/floors/:id/terminate`가 세션 레코드의 `pid`·`procStart`를 `ProcStartMatcher`로 확인한 뒤에만 주입된 `signal(pid, sig)`를 부른다. 실제 `process.kill`은 `server/index.ts`에서만 묶는다.
- **숨김:** 끝난 세션만 숨기고, 스냅샷은 숨긴 세션을 뺀 뒤 층 번호를 다시 매기며 `hiddenFloors`를 싣는다.
- **화면:** Phase 1이 비워 둔 `FloorControls`에 동작을 붙이고, 일시정지 층은 Phase 1 5.3의 셔터·팻말로, 종료는 `BudgetDialog` 패턴의 확인 창 두 단계로, 숨김은 빌딩 맨 아래 "모두 보이기" 버튼으로 그린다.

**Tech Stack:** Node 24 (ESM), TypeScript, Express 5, React 19, Vite, Vitest, jsdom

**Spec:** `docs/superpowers/specs/2026-10-11-v2-phase4a-design.md` (커밋 8591cb9, 사용자 승인 2026-10-11)
**선행:** Phase 3 계획 `docs/superpowers/plans/2026-10-07-v2-phase3.md`(관문 순서 B78·B79, 응답 형식), Phase 3 스펙 14장, 디자인 `docs/design/phase1/SPEC.md`(A8·A9, 5.2·5.3 휴업 셔터·팻말, 스위치) + `docs/design/phase2/SPEC.md`(§6.2 설정 창 패턴) + `docs/design/phase4a/SPEC.md`(Task 1), 팀 규칙 `.superpowers/sdd/2026-10-11-v2-phase4a/team-protocol.md`

## Global Constraints

- 기준 브랜치 `feat/v2-phase4a`(MERGE_BASE `72fa75b`, 스펙 `8591cb9`). push·merge·태그 push는 하지 않는다.
- Phase 1~3의 제약은 그대로다: Node ≥ 24, `127.0.0.1`에만 바인딩, Host 검사, 서버는 claude home 아래에 아무것도 쓰지 않는다, UI 문구는 한국어, 이미지 파일을 쓰지 않는다, `role="status"`는 화면에 하나.
- **사용자 결정 네 가지는 바꾸지 않는다:** 종료는 확인 창 → SIGTERM → 10초 뒤에도 살아 있으면 한 번 더 확인 → SIGKILL. 삭제는 세션 기록 파일을 건드리지 않고 대시보드에서만 숨긴다. 일시정지는 층 전체(리드·팀원·서브에이전트)이고 예외는 Phase 3의 예외 도구 아홉 개와 같다. 저장은 서버 메모리만(껐다 켜면 모두 영업 중, 숨긴 층도 다시 보인다).
- **관문 순서(스펙 4.2):** 일시정지 deny → 정책 deny → 예산 관문 → 정책 ask → 빈 200. 일시정지 deny는 관문 기록·큐 항목·이벤트 저장을 만들지 않는다. `PreToolUse`가 아닌 이벤트는 일시정지와 무관하게 그대로 처리한다. 판정에서 예외가 나면 로그만 남기고 일시정지가 없는 것처럼 이어 간다.
- **예외 도구:** `server/policy/tools.ts`의 `EXEMPT_TOOLS` 하나만 쓴다(아홉 개: `AskUserQuestion`, `ExitPlanMode`, `SendMessage`, `TaskCreate`, `TaskUpdate`, `TaskList`, `TaskGet`, `SubagentHandback`, `TaskStop`). 목록을 복사하지 않는다.
- hook 응답 형식은 `server/decisions/protocol.ts`의 `preToolDeny(reason)`을 그대로 쓴다. 이유 문구(고정, 설명서·테스트가 글자까지 대조): `대시보드 일시정지: 사용자가 대시보드에서 이 세션을 일시정지해 지금은 이 도구를 쓸 수 없습니다. 사용자가 대시보드에서 스위치를 "영업 중"으로 돌리면 다시 쓸 수 있습니다. 기다리거나 사용자에게 알려 주세요.`
- **종료 검사(스펙 5.1, 모두 통과해야 신호):** 레코드가 있고 `alive`(아니면 409 `ended`) → `pid !== process.pid`(아니면 400 `self`) → `ProcStartMatcher(pid, procStart)`가 `true`(false면 409 `pid-reused`, `undefined`면 409 `unverified` — **확인 불가면 보내지 않는다**) → `force`가 아닌데 이미 `terminating`이면 200(멱등). 신호는 `force ? "SIGKILL" : "SIGTERM"`. **신호 보내기는 주입**(`signal: (pid, sig) => void`)이고 실제 `process.kill`은 `server/index.ts`에서만 쓴다. 테스트는 가짜 함수만 쓴다.
- **API 보호:** `/api/policy`와 같은 미들웨어(토큰 쿠키 + 같은 출처 + JSON `Content-Type`). 쓰기 메서드는 기존 `/api` 미들웨어가 JSON `Content-Type`을 요구하므로 화면은 본문 없는 요청에도 `Content-Type: application/json`과 본문 `{}`를 보낸다(Phase 3 B99와 같음).
- **문구(스펙 그대로):**
  - 종료 확인 창: `이 세션을 끕니다. 대화 기록은 남지만, 하던 작업은 끊깁니다.` 현재 세션(`isCurrent`)이면 `지금 이 대시보드를 켠 세션입니다. 끄면 이 터미널의 Claude Code도 끝납니다.`
  - 두 번째 확인 창: `아직 켜져 있습니다. 강제로 끌까요? 저장되지 않은 작업이 사라질 수 있습니다.` 버튼 `강제로 끄기`.
  - 409 안내: `ended` → `이미 끝난 층입니다.` / `pid-reused`·`unverified` → `이 세션의 프로세스를 확인하지 못해 끄지 않았습니다. 터미널에서 직접 끝내 주세요.`
  - 스위치 라벨 `영업 중` ↔ `멈춤`, 칩 `멈춤`·`종료 중`, 머리 요약 `· 막힌 호출 N`, 빌딩 아래 `숨긴 층 N개 · 모두 보이기`, 작업 지시 버튼 제목 `아직 사용할 수 없습니다`.
  - 스펙에 없는 나머지 문구는 `docs/design/phase4a/SPEC.md`의 문구표가 기준이고, 코드에 넣기 전에 qa가 앞뒤 출력과 나란히 읽어 검토한다(팀 규칙 9).

## Review Focus

1. **종료를 누른 뒤 10초가 지나기 전에 세션이 저절로 끝나거나 사용자가 창을 닫은 경우:** 두 번째 확인 창이 끝난 층 위에 뜨거나, 닫은 뒤에 뜨면 안 된다. 타이머는 스냅샷의 `alive`·`terminating`과 창의 열림 상태를 함께 봐야 한다. → Task 6 테스트 `10초 전에 층이 끝나면 두 번째 창이 뜨지 않는다`, `첫 창을 닫으면 타이머가 사라진다`
2. **일시정지 중에 큐에 남아 있던 결정에 대시보드가 답하는 경우:** 일시정지 전 `PermissionRequest`는 그대로 붙잡혀 있어야 하고(스펙 4.3), 답하면 그 도구 하나는 실행된다. 일시정지 deny가 큐의 `onEvent`를 건너뛰어 기존 결정이 잘못 닫히지 않아야 한다. → Task 3 테스트 `일시정지 전의 결정은 그대로이고 답할 수 있다`
3. **숨긴 세션의 id로 hook이 오거나(같은 id가 `--resume`으로 살아남), 숨긴 세션에 정책·예산 상태가 남아 있는 경우:** 살아 있으면 숨김이 풀리고 다시 보여야 하고, 숨겨도 `BudgetStore`·정책 횟수는 건드리지 않는다. → Task 4 테스트 `숨긴 세션이 다시 살아나면 숨김이 풀리고 보인다`, `숨겨도 예산·정책 상태는 그대로다`
4. **세션 레코드에 `procStart`가 없거나(옛 Claude Code, Windows) `ps`가 없는 경우:** 생존 판정은 살아 있는 쪽, 종료 신호는 보내지 않는 쪽이어야 한다. `unverified`가 화면에 "터미널에서 직접 끝내 주세요"로 보여야 한다. → Task 3 테스트 `procStart가 없으면 unverified로 거부한다`, Task 7 테스트 `unverified 안내`
5. **가짜 hook이 숨긴·일시정지한 id로 쏟아지는 경우:** `pausedDenied`는 세션 수만큼만 커지고(일시정지한 id에만 센다), 모르는 id는 세지 않는다. → Task 3 테스트 `일시정지하지 않은 세션의 호출은 세지 않는다`

## 계획서 판정 (계획을 쓰며 정한 것, B114부터)

- **Ruling B114 (세션 레코드의 `procStart`):** `readSessions`는 `procStart`를 읽기만 하고 버린다. `SessionRecord.procStart?: string`으로 남기고(파일에 없으면 없음), `SnapshotBuilder.record(sessionId)`로 마지막 빌드의 레코드를 꺼낼 수 있게 한다. 종료 API는 스냅샷(`SessionView`에는 pid가 없다)이 아니라 이 레코드로 검사한다. `SessionView`에 pid·procStart를 싣지 않는다. — 틀리면 비용: 필드 하나, 메서드 하나.
- **Ruling B115 (문구와 모양의 출처):** 칩·스위치 라벨은 스펙 7장(`멈춤`, `종료 중`), 셔터·팻말의 모양과 팻말 글자(`휴업` / `잠시 쉬는 중`)는 Phase 1 디자인 5.3을 그대로 쓴다. 두 말이 함께 보이는 것(칩 "멈춤", 팻말 "휴업")은 designer가 명세에서 정리하고 qa가 검토한다. — 틀리면 비용: 문구.
- **Ruling B116 (일시정지 판정은 한 단계):** 정책 관문의 판정·적용 분리(B78)는 뒤 관문이 먼저 답할 수 있어서였다. 일시정지는 맨 앞이라 분리할 필요가 없다. `FloorControl.preToolUse(input)`은 deny 응답 JSON을 돌려주며 횟수·로그를 바로 남긴다(또는 null). 던지지 않는다. — 틀리면 비용: 없음.
- **Ruling B117 (살아 있음의 기준):** pause·resume·terminate·hide의 "살아 있는가"는 **마지막 스냅샷 빌드의 세션 레코드**(`record(id).alive`)다. 레코드가 없으면 pause·resume·terminate는 409 `ended`, hide는 409 `alive`가 아니라 **404**(없는 층). 스냅샷 주기(3초)만큼 늦을 수 있다는 것을 받아들인다(종료 뒤 "종료됨"이 뜨는 것도 같은 주기). — 틀리면 비용: 없음.
- **Ruling B118 (숨김과 층 번호):** 층 번호는 숨긴 세션을 뺀 나머지로 다시 매긴다(스펙 6). `isCurrent`도 남은 세션에서 고른다. `hidden`은 레코드가 목록에서 사라질 때(1일 뒤) 지운다. 살아 있는 세션은 `hide`가 409 `alive`이고, 숨긴 뒤 같은 id가 살아나면 스냅샷 빌드에서 `hidden`에서 빼고 보인다. — 틀리면 비용: 없음.
- **Ruling B119 (실제 세션 확인의 구성):** 스펙 11.4는 "job tmp `CLAUDE_CONFIG_DIR`"이지만 실제 `claude`의 로그인(자격 증명)이 그 폴더에 없으면 로그인 화면이 뜬다. Task 11은 먼저 프롬프트 없이 `CLAUDE_CONFIG_DIR`을 job tmp로 두고 세션을 띄워 **로그인·온보딩 화면이 뜨는지만** 본다(모델 호출 없음). 뜨면 그 세션을 내리고 Phase 3과 같은 구성(실제 `HOME`, `--plugin-dir` 사본, 서버는 기본 claude home을 읽음)으로 한다 — 이때 실험 대시보드에 사용자 세션이 함께 보이므로 pause·terminate는 **cwd가 job tmp 작업 폴더인 세션 id**에만 보내고, 호출 전에 id ↔ cwd를 결과 파일에 적는다. 신호가 필요 없는 항목(pid-reused·unverified 거부, 숨김·모두 보이기, SIGTERM이 프로세스를 끝내는 것)은 **모델 없이** job tmp claude home에 가짜 세션 레코드와 우리가 띄운 `sleep` 프로세스로 확인한다(Task 11 Part A). — 틀리면 비용: 프롬프트 0개(Part A) + 2~3개(Part B).
