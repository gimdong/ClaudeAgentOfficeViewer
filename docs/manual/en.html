Install, start and troubleshoot. For everything else (reading the screen, decision reports, budgets, permission policies, floor controls) see the Korean manual. The dashboard and the installer show messages in Korean; this guide quotes them and gives the meaning in English.

1. Install

Before you start

  1. Claude Code is installed and you have run it at least once. Check in a terminal: 
    claude --version

    One line with a version number appears (for example 2.1.0 (Claude Code)).

  2. Node.js 24 or later. Check: 
    node --version

    It should start with v24 or higher. If not, install the LTS release from nodejs.org, then close and reopen the terminal.

Download the installer from the project's Releases page: claude-office-<version>.tar.gz for macOS and Linux, claude-office-<version>.zip for Windows. Do not use the "Source code (zip / tar.gz)" archives; GitHub attaches them to every release and they are not installers. No internet connection is needed to install. Program files go into ~/.claude-office only (Windows: C:\Users\<user name>\.claude-office).

macOS

  1. Put the file in your Downloads folder and open the Terminal app.
  2. Extract it and run the installer: 
    cd ~/Downloads && tar -xzf claude-office-<version>.tar.gz && cd claude-office-<version> && sh install.sh
  3. Answer the two questions (below).
The beta is not signed by Apple. If macOS warns about an unidentified developer, open System Settings → Privacy & Security, click Open Anyway, and run the same command again.

Linux

  1. Put the file in your Downloads folder and open a terminal.
  2. Extract it and run the installer: 
    cd ~/Downloads && tar -xzf claude-office-<version>.tar.gz && cd claude-office-<version> && sh install.sh
  3. Answer the two questions (below).

Windows (not yet verified in the beta)

  1. Put the file in your Downloads folder. Open PowerShell (or Windows Terminal) from the Start menu — not PowerShell ISE.
  2. Extract it and run the installer. -ExecutionPolicy Bypass allows this one script to run; it does not change your computer's settings. 
    cd $HOME\Downloads; Expand-Archive claude-office-<version>.zip -DestinationPath . -Force; cd claude-office-<version>; powershell -ExecutionPolicy Bypass -File .\install.ps1
  3. If Windows says the file is not digitally signed, unblock the extracted folder and try again: 
    Get-ChildItem -Recurse $HOME\Downloads\claude-office-<version> | Unblock-File

    If it is still blocked, your company's policy blocks it; ask your IT administrator.

  4. Answer the two questions (below).

The questions

~/.zshrc에 claude-office 명령 경로를 추가할까요? [y/N]
"Add the claude-office command to PATH in ~/.zshrc?" Press y so you can type claude-office from any folder. The file name may be ~/.bash_profile or ~/.bashrc depending on your shell; on Windows it asks about the user PATH. If you press n, the last line tells you the full path to run instead.
Claude Code 플러그인(claude-office)을 설치할까요? … [y/N]
"Install the Claude Code plugin?" y is recommended. The plugin sends Claude Code's tool events to the dashboard and returns the answers you click there. Without it you still see floors and token counts, but no speech bubbles, raised hands or answering. It never allows or denies anything on its own; it passes on only the answer from this computer's dashboard that uses the same key file (see Another account on port 4317).
Claude Code 상태줄(statusline)에 연결할까요? PLAN 바(남은 사용량 %)를 채우려면 필요합니다. Claude Code 설정(~/.claude/settings.json)의 statusLine을 바꾸고, 원래 설정은 백업하며, 쓰던 상태줄은 그대로 보입니다. [y/N] (macOS / Linux)
"Connect to the Claude Code status line? It is needed to fill the PLAN bar (remaining usage %). It changes statusLine in the Claude Code settings (~/.claude/settings.json), backs up the original, and the status line you used keeps showing." Optional. Apart from the plugin list, this is the only Claude Code setting the installer changes, and only if you press y here or run the installer with --statusline; --yes alone does not turn it on. If it was not asked (for example with --yes), the installer prints statusline 연결은 묻지 않고 건너뛰었습니다. 켜려면 설치 스크립트를 --statusline을 붙여 다시 실행하세요. ("Skipped the statusline connection without asking. To turn it on, run the installer again with --statusline."). Windows does not support it: -StatusLine only prints PLAN 바(statusline 연결)는 Windows에서 지원하지 않습니다. ("The PLAN bar (statusline connection) is not supported on Windows.").

The installer finishes with a setup check (doctor) and this last line:

설치 완료. 새 터미널에서 claude-office 를 실행하세요.

"Installed. Run claude-office in a new terminal." Two yellow lines right after installing are normal, because the dashboard is not running yet: ⚠️ 포트: 서버가 꺼져 있습니다(4317) (port: server is off) and ⚠️ 실시간 이벤트: 서버가 꺼져 있어 확인하지 못했습니다 (live events: not checked because the server is off).

2. Start and stop

Start

  1. Open a new terminal (PowerShell on Windows) and run: 
    claude-office

    If you answered n to the PATH question, run the full path instead: ~/.claude-office/bin/claude-office (Windows: $HOME\.claude-office\bin\claude-office.cmd).

  2. Your browser opens the dashboard. The address carries an access key at first; it disappears from the address bar once the page opens, and the browser remembers it for a year. After that you can bookmark http://127.0.0.1:4317 (127.0.0.1 means "this computer").
이 창을 닫으면 대시보드가 꺼집니다.
Claude Agent Office: http://127.0.0.1:4317  (data: /Users/<user name>/.claude)

"Closing this window stops the dashboard." The browser shows a building with floors, and ● LIVE at the right of the top bar.

  • claude-office open opens the running dashboard again in your default browser (with the key); claude-office open Safari opens it in a named browser (macOS). It does not start a second server.
  • Running claude-office while the dashboard is already running reopens it in the browser and exits: 이미 켜져 있습니다. 브라우저에서 대시보드를 다시 열었습니다. … ("Already running. Reopened the dashboard in the browser.")
Keep the terminal window open while you use the dashboard (you can minimize it). Do not start it from inside Claude Code with ! claude-office: it keeps running with no window to stop it.

Stop

Press Ctrl+C in the terminal that runs the dashboard, or close that window. Claude Code keeps working. While the dashboard is off, Claude Code asks in the terminal as usual. (A plugin from beta.13 or earlier may show PreToolUse:Bash hook error with connect ECONNREFUSED 127.0.0.1:4317; that only means it could not reach the dashboard.) Permission policies and floor pausing do not apply while it is off.

View from another computer (SSH tunnel)

When you use Claude Code on another computer (for example, a Linux server at work), you can view that computer's dashboard in your own browser. The dashboard listens only inside that computer (127.0.0.1), so an SSH tunnel connects a port on your computer to its 4317.

  1. Install this program on the remote computer (chapter 1) and start the dashboard there with claude-office. A message that the browser could not be opened is fine. Closing that window stops the dashboard, so start it in its own SSH session or inside tmux, and do step 3 in another window.
  2. On your own computer, open a new terminal and open the tunnel. <host> is the address you normally use with ssh. Keep this window open while you view the dashboard. 
    ssh -L 14317:127.0.0.1:4317 <host>
  3. In that SSH window (on the remote computer), get the address with the key: 
    claude-office url

    It prints one address line and one notice line, and does not open a browser:

    http://127.0.0.1:4317/?k=…
이 주소는 열쇠입니다. 남에게 보내지 마세요.

    "This address is a key. Do not send it to anyone."

  4. Copy the address, change only the port to 14317 (http://127.0.0.1:14317/?k=…), and open it in the browser on your own computer. The dashboard remembers a separate key for each port, so this does not interfere with a dashboard on your own computer.
  • Connect with SSH as the same account that runs the dashboard (on Linux the dashboard accepts only that account).
  • Closing the tunnel does not stop the remote dashboard or Claude Code.

3. Troubleshooting

Run the setup check first

claude-office doctor

Each line is marked ✅ (fine), ⚠️ (check) or ❌ (problem), and ⚠️/❌ lines are followed by → and how to fix it. Follow that line.

Send a diagnostics file

If it is not fixed, make a diagnostics file and send it to whoever supports you. It contains only what is needed to find the problem — no conversation content, names or secrets; folder names are replaced with numbers like <project-1>. Either click 진단 (Diagnostics) in the top bar and then 진단 파일 만들기 (Make diagnostics file) and 받기 (Download), or run:

claude-office diag

It prints the file location, for example ~/.claude-office/diagnostics/claude-office-diag-20261001-093000.json.

The dashboard says "터미널에서 claude-office로 열어 주세요"

"Open it with claude-office from the terminal." The dashboard opens only in a browser that has the access key, so that other web pages cannot click "allow" for you. This appears when you typed http://127.0.0.1:4317 in a browser that was never opened through claude-office, after clearing cookies, in a private window, or in another browser. Run claude-office (or claude-office open) once more.

The browser did not open and the terminal printed an address

브라우저를 열지 못했습니다. 이 주소를 브라우저에 붙여 넣어 주세요: http://127.0.0.1:4317/?k=…
이 주소는 열쇠입니다. 남에게 보내지 마세요.

"Could not open the browser. Paste this address into your browser." Copy the whole line including everything after ?k=. This address is a key; do not share it, and keep it out of screen shares and pasted logs.

I want to stop the dashboard but there is no window

This happens if you started it with ! inside Claude Code or closed the window. In a new terminal (macOS / Linux):

lsof -ti :4317 | xargs kill

On Windows (PowerShell): Get-NetTCPConnection -LocalPort 4317 | ForEach-Object { Stop-Process -Id $_.OwningProcess }. Then start it again from a normal terminal.

I installed a new version but the screen did not change

An older dashboard is still running. claude-office then prints 이전 버전 대시보드가 켜져 있습니다. … ("An older dashboard is running…"). Stop it in its terminal with Ctrl+C (or as in the previous item), then run claude-office again. Close any old browser tab whose address showed ?k=.

"포트 4317번이 이미 사용 중입니다"

"Port 4317 is already in use." Another program (or the old v1 viewer) is using port 4317. claude-office doctor tells you whether it is the old viewer or another program. Stopping that program is best; starting on another port with --port works, but then the plugin cannot reach the dashboard (no speech bubbles or answering). If you do not know the program, do not use another port: see the next section.

Another account on port 4317

Hook events are encrypted (from beta.14). The plugin passes each hook event to a small relay program, which encrypts it with a key file only your account can read (~/.claude-office/hook.key), and accepts only an answer encrypted with the same key. Another account that takes port 4317 while the dashboard is off cannot read your prompts, tool inputs or results, and cannot answer for you; Claude Code simply asks in the terminal as usual.

If you installed an earlier version, its plugin still sends plain HTTP hooks, and the dashboard shows 옛 플러그인(http hook)이 남아 있습니다 — 같은 압축 파일로 다시 설치하세요 ("An old plugin (http hook) is still installed — install again from the same archive"). Install again from the archive you downloaded; Claude Code windows that were already open keep the old hooks until you run /reload-plugins or restart them. Until then, the old risk remains: while the dashboard is off, another account on the same computer that takes port 4317 can receive your prompts, tool inputs and tool results, answer permission requests in your place, and add text to the conversation. beta.14 still accepts these old HTTP hooks, so this applies to anyone who has not installed again. If you still use beta.13 or earlier, or the old plugin: until you install again, turn the plugin off when you are not using the dashboard (claude plugin disable claude-office@claude-office --scope user), or keep the dashboard running.

If an unknown program holds port 4317, do not start the dashboard on another port; find out what it is and turn the plugin off until the port is free. claude-office doctor reports a program holding the port as:

❌ 포트: 다른 프로그램이 4317을 쓰고 있습니다

"Another program is using 4317."

"Node.js 24 이상이 필요합니다"

"Node.js 24 or later is required." Install Node.js 24 (see Before you start), close and reopen the terminal, and try again.

Characters appear but no speech bubbles or raised hands

Claude Code is not reaching the dashboard. doctor shows ⚠️ 실시간 이벤트: 받은 이벤트 0건 (live events: 0 received).

  1. Do anything in a Claude Code session once.
  2. If doctor's 플러그인 (plugin) line is ⚠️, install the plugin as it says, then close and reopen Claude Code.
  3. If doctor shows ❌ 회사 관리자 설정: 있음: 관리자 hook만 허용 (company managed settings: only managed hooks allowed), or everything is ✅ and it still does not work, your company's managed settings are blocking the plugin. Send your administrator the administrator guide.

Linux: "같은 사용자 계정의 프로그램만 접속할 수 있습니다"

"Only programs of the same user account can connect." On Linux the dashboard accepts connections only from processes of the user account that started it. Another account on a shared machine, or a container with its own network (even under the same account), gets this reply (HTTP 403). This is intended, and there is no setting to turn it off. Run the dashboard as the same account, and in the same network, as Claude Code. doctor counts these refusals at the end of its 실시간 이벤트 (live events) line:

⚠️ 실시간 이벤트: 최근 10분 4건. 다른 계정의 접속 3건을 막았습니다. 여러 사람이 쓰는 컴퓨터라면 정상입니다.

"Blocked 3 connections from other accounts. Normal on a computer shared by several people." The part before it depends on the current event check.

doctor: "hook 실행" (running hooks)

❌ hook 실행: hook을 실행할 node가 없습니다(nvm 등으로 바뀜) — 다시 설치하세요
  → 설치 스크립트로 다시 설치한 뒤, 열려 있는 Claude Code 창에서 /reload-plugins를 실행하거나 창을 다시 열어 주세요.

"There is no node to run the hooks (changed by nvm or similar) — install again." The installer writes the full path of the Node.js it ran with into the plugin's hooks. If that Node.js was removed or moved (for example, you switched versions with nvm), hooks stop reaching the dashboard and Claude Code asks in the terminal. Install again from the archive with the Node.js you use now, then run /reload-plugins in open Claude Code windows or restart them, as the second line says.

The same fix applies to ❌ hook 실행: hook 설정에 Node.js·열쇠 경로가 적혀 있지 않습니다 — 다시 설치하세요 ("the hook settings do not contain the Node.js and key paths") and to ⚠️ hook 실행: 옛 플러그인(http hook)입니다 ("old plugin (http hook)"; install again from the same archive).

doctor: "hook 열쇠" (hook key)

❌ hook 열쇠: 다른 계정의 파일입니다(hook을 받지 않음)
  → 설치 폴더의 hook.key를 지운 뒤 claude-office를 다시 켜 주세요. 지울 수 없으면 컴퓨터 관리자에게 문의해 주세요.

"The file belongs to another account (hooks are not accepted)." Delete hook.key in the install folder (~/.claude-office) and start claude-office again; it makes a new one. If you cannot delete it, ask the computer's administrator. If the key file is missing or others can read it, doctor shows ⚠️ and starting claude-office again fixes it.

doctor: another install's dashboard is running

⚠️ 실시간 이벤트: 다른 설치본의 대시보드가 켜져 있어 확인하지 못했습니다(열쇠가 다름)
  → 켜져 있는 대시보드를 끄고 이 설치본의 claude-office로 다시 켜 주세요.

"A dashboard from another install is running, so this could not be checked (different key)." Hooks from this install cannot reach it either. Stop that dashboard and start this install's claude-office. doctor also counts recent relay failures as ⚠️ hook 전달: 최근 24시간 실패 {n}건 ("{n} failures in the last 24 hours"); a dashboard from another install is the usual cause.

The installer stops: "플러그인 hook 설정(node·열쇠 경로)을 쓰지 못해 설치를 멈춥니다"

"Could not write the plugin's hook settings (node and key paths), so the installation stops." The installer could not write the Node.js and key paths into the plugin's hooks, and stopped before registering the plugin, so Claude Code is unchanged; if an earlier plugin is installed, it keeps running. Extract the archive again into a new folder and run the installer from there. If it stops again, send a diagnostics file (it includes the install log shown on the 자세한 기록: line).

The PLAN bar is empty

The PLAN bar shows the plan's remaining usage, which Claude Code passes only to a connected status line. What the empty bar says tells you why:

  • -- statusline 연결이 꺼져 있음(다시 설치할 때 켤 수 있음) ("status line connection is off; can be turned on when reinstalling"): run the installer again with --statusline (macOS / Linux).
  • -- 요금제가 알려 주지 않음 ("the plan does not report it"): connected, but the value comes only on Pro / Max plans or behind a gateway with a spend limit. This account does not get it.
  • -- Windows에서는 statusline 연결을 지원하지 않음 ("the statusline connection is not supported on Windows"): on Windows the PLAN bar stays empty.

claude-office doctor shows the connection on its 요금제 한도(선택) (plan limits, optional) line: 연결됨(최근 1시간 안에 갱신됨) (connected, updated within the last hour), 연결됨(아직 받은 값 없음) (connected, no value received yet), 연결 안 됨 (not connected), ⚠️ … 다른 statusline이 설정되어 연결이 빠졌습니다 (another status line was set, so the connection was dropped: run the installer again with --statusline; the status line you use keeps showing), or Windows에서는 지원하지 않음 (not supported on Windows).

The installer finished with "no" without asking

입력을 받을 수 없어 '아니오'로 처리했습니다. 설치하려면 --yes를 붙여 다시 실행하세요.

"Could not read input, so treated as 'no'. Run again with --yes to install." It ran somewhere it could not ask you, such as ! inside Claude Code. Run it again in a normal terminal, or answer yes to the PATH and plugin questions with sh install.sh --yes (add --statusline to also connect the status line) (Windows: powershell -ExecutionPolicy Bypass -File .\install.ps1 -Yes).

Uninstall

claude-office uninstall

If the installer connected the status line, uninstall first puts statusLine back, but only if it is still the one the installer set (statusline 설정을 원래대로 되돌렸습니다., "Restored the statusline setting."); a status line you changed afterwards is left as it is (다른 statusline으로 바뀌어 있어 그대로 둡니다., "Changed to another statusline, so it is left as it is."). If it cannot, it prints statusline 설정을 되돌리지 못했습니다. Claude Code 설정의 statusLine을 확인해 주세요. ("Could not restore the statusline setting. Check statusLine in the Claude Code settings."). It asks two questions: whether to remove the Claude Code plugin, and whether to delete logs and diagnostics files (default: keep). Answer n to the second if you still need to send a diagnostics file. claude-office uninstall --yes answers yes to both.

4. Working with the lead (experimental)

Only on floors where "작업 지시" (sending instructions) is on, that is, floors with a channel connection. These features use the same experimental channels feature as sending instructions and starting a new floor. On a floor you opened yourself in a terminal the buttons are dimmed, with 작업 지시 켜기(옮겨 열기)로 연결하면 쓸 수 있습니다 ("Available after you connect it with 작업 지시 켜기 (reopen)") below them.

Every floor has one lead (리드, the team lead), the contact point between you and that floor's session. Reports, approvals, answers to chat questions, and sending a teammate off duty or letting one go all go through the lead. The dashboard sends the lead instructions in fixed templates; what you type (revision notes, answers) goes only into a fixed place in that template. Text the lead sends back (reports, questions) is never reused as an instruction. The buttons are in the 지시 (instructions) section at the top of the agent panel, which opens when you click a desk.

  • After sending, 리드에게 보냈습니다 ("Sent to the lead") shows below the button for a moment. On a paused floor it is not sent right away but kept (휴업 중이라 보관했다가, 재개할 때 확인하고 보냅니다., "Kept while paused; you confirm and send it when you resume"). Kept instructions appear in the check window before resuming and are sent only when you press 보내고 재개 (send and resume). If sending fails: 처리하지 못했습니다. 서버 연결을 확인하고 다시 시도해 주세요. ("Could not process it. Check the server connection and try again.")

Reports and approval (the folder)

  • 보고 요청 (request a report) in the lead's panel asks the lead to write a report and send it to the dashboard. When reports arrive, a small folder appears on the lead's desk, and if any wait for your decision, a count such as 결재 2 ("2 to approve") shows under the name tag.
  • 서류철 (folder; in the lead's panel as 서류철 · 대기 2, "2 waiting") lists received reports, newest first. Click one to open it on a sheet of paper. Report text is shown exactly as written, never formatted as Markdown or HTML (symbols such as ## and ** appear as they are).
  • A waiting report has 승인 (approve) and 수정 사항 적기 (write revisions). Write up to 4,000 characters and send them with 수정 요청 보내기 (send revision request). The stamps are 대기 (waiting), 승인됨 (approved) and 수정 요청 (revision requested).
  • If no report arrives more than 10 minutes after a request, the lead's panel shows 보고 요청 뒤 10분 넘게 답이 없습니다 ("No answer for more than 10 minutes after the request"). The lead may not have answered in the expected way; check the lead in its terminal.
  • If waiting reports pile up, 오래된 대기 보고서는 보관함으로 옮겨집니다 ("Old waiting reports are moved to the archive"). Open 보관함 (archive) at the bottom of the list to see them; you can approve them there too.
  • On a paused floor, an approval or a revision request is kept, one per report: the stamp shows 보관됨 ("kept") with 승인을 보관했습니다 — 재개할 때 확인하고 보냅니다 ("Approval kept — sent after you confirm when it resumes") or 수정 요청을 보관했습니다 — 재개할 때 확인하고 보냅니다. Pressing the other button replaces it. It is sent when you press 보내고 재개 (send and resume), and then the stamp changes to approved or revision requested.
  • On a floor without instructions turned on, you can still open and read the folder; only the approval buttons are dimmed.
  • Reports are kept only in reports.json in the install folder (readable only by your account). Nothing is written to ~/.claude.

Answering chat questions

  • 대화 질문 (chat question): when the lead or a teammate needs your decision and sends a question to the dashboard (ask_user), the character at that desk raises a hand with a yellow ?, and it counts in 결정 대기 (decisions waiting) in the top bar. Click it to see the question, 제안된 선택지 (suggested choices) and a 직접 답하기 (answer in your own words) box. Clicking a choice does not send it; pick one, then press 보내기 (send). Only the number you picked and the words you typed are sent (질문한 쪽이 쓴 선택지입니다. 고르면 번호만 보냅니다, "These choices were written by the one asking. Picking one sends only its number").
  • A teammate's question appears at that teammate's desk, and the answer goes to the teammate through the lead (developer의 질문입니다. 답은 리드를 거쳐 보냅니다, "A question from developer. The answer goes through the lead").
  • 답을 기다립니다 (waiting for your answer): if the lead asks in plain conversation text instead of the question tool and stops, the lead's desk shows a light-blue bubble (· · ·) and 답을 기다립니다. No hand is raised and it does not count as a decision. Click it to see the lead's last message and the choices taken from its numbered list, and answer the same way. A long message is shortened at the front and starts with …. This mark is a guess from the shape of the text: it can appear when nothing was asked, or miss a question.
  • If you answer in the terminal first, the mark disappears and an open answer window shows 이미 터미널에서 답했습니다 ("Already answered in the terminal"). A chat question (raised hand with ?) clears only when you answer from the dashboard or type something in the lead's terminal; the lead using other tools does not clear it. 답을 기다립니다 clears when the lead itself moves again. Teammates or subagents moving never clears either.
  • An answer given on a paused floor is kept (보관한 답이 있습니다. 재개할 때 확인하고 보냅니다, "An answer is kept. It is sent after you confirm when the floor resumes"). It is sent only when you press 보내고 재개 (send and resume) in the check window before resuming; then the mark disappears. If you delete that answer in the check window, the question can be answered again. 보관한 지시는 대시보드가 켜져 있는 동안만 남습니다. ("Kept instructions remain only while the dashboard is running.") If the dashboard restarts, kept answers and their question marks disappear too.
  • Questions that were showing, and report requests still waiting for a report, are gone after the dashboard restarts; ask again if you still need them.
  • On a floor without instructions turned on, you can only read the question (터미널에서 답하거나, 작업 지시 켜기(옮겨 열기)로 연결하세요, "Answer in the terminal, or connect it with 작업 지시 켜기 (reopen)").

Off duty, back on duty, long rest

  • 퇴근 (off duty) in a teammate's panel asks the lead to end that teammate. Until then, 퇴근 요청함 ("off duty requested") shows under the name tag. When the teammate ends, or shows no activity for 10 minutes after the request, an empty chair with a 퇴근 sign is left. Unlike a desk that simply went off (an empty chair without a sign), the sign is placed only where you sent someone off duty.
  • The off-duty mark is remembered only while the dashboard is running. After the dashboard restarts, the desk shows an empty chair without a sign.
  • 출근 (back on duty) in an off-duty teammate's panel asks the lead to put the teammate with the same name back to work. If the conversation history remains, it carries on.
  • A teammate whose last activity was more than an hour ago shows 오래 쉬는 중 ("resting for a long time"). This is only a mark; nobody is sent off duty automatically. Paused floors and teammates waiting on a decision are left out of this mark and of the off-duty check.
  • The lead has no off-duty or let-go buttons (it is the floor's contact point).

Letting a teammate go, and a new teammate

  1. 퇴사 (let go) in a teammate's panel opens a confirmation: designer의 기억은 새 팀원에게 이어지지 않고, 인수인계 메모만 넘어갑니다. 대화 기록은 지우지 않습니다. ("designer's memory does not carry over to the new teammate; only the handover note does. The conversation history is not deleted.") 퇴사 진행 (proceed) starts it.
  2. The leaving teammate writes a handover note and sends it. Meanwhile the desk shows 인수인계 쓰는 중 ("writing the handover"). If no note arrives within 5 minutes, the dashboard asks the lead once to write it instead. That request goes only while instructions are connected; on a paused floor it is kept and sent when you resume. If the dashboard restarts while a teammate is leaving, letting go continues when the floor connects again; until then 연결되면 이어 갑니다 ("Continues when connected") is shown under 퇴사 진행 중 (leaving) in the teammate's panel (and when you hover over the desk).
  3. When the note arrives in the folder as 인수인계 (handover, stamp 시작 전, "not started"), open it and press 새 팀원 시작 (start a new teammate). The lead ends the old teammate, then starts a new one with the same name and gives it the note as its first instruction. The new teammate has none of the old one's memory.
  4. The old teammate stays in the 전임자 (predecessors) drawer at the lower right of the floor (folded), with only its name and when it left (and when it started, if known). The conversation history is not deleted.

Building name and building info

The sign on the roof starts as User의 회사 ("User's company"). Click it to open 빌딩 정보 (building info).

  • 이름 (name): change it (1–40 characters) and press 저장 (save) to change the sign (for example, saving Acme shows Acme의 회사). This name is a dashboard setting, unrelated to your computer account name. It is saved in building.json in the install folder (readable only by your account).
  • Information: the same numbers as the top bar (today's tokens and cache reads, tokens in the last 5 hours and 7 days, 5H · WEEK · PLAN remaining), the number of floors and teammates, and the server and screen versions, in one place.
  • If PLAN remaining is empty, one line below it gives the reason. If the status line connection is off: PLAN 잔여는 Claude Code가 상태줄에 넘겨 주는 값입니다. 이 설치본은 상태줄 연결이 꺼져 있어 받지 못합니다. 켜려면 설치 스크립트를 --statusline을 붙여 다시 실행하세요. ("PLAN remaining is a value Claude Code passes to the status line. This install has the status line connection off, so it does not get it. To turn it on, run the installer again with --statusline."). If it is connected but no value comes: PLAN 잔여는 Claude Code가 상태줄에 넘겨 주는 값입니다. Pro·Max 요금제나 지출 한도가 있는 gateway에서만 오고, 이 계정에는 오지 않습니다. ("… It comes only on Pro / Max plans or behind a gateway with a spend limit, and not to this account."). On Windows: PLAN 잔여는 Claude Code가 상태줄에 넘겨 주는 값입니다. Windows에서는 상태줄 연결을 지원하지 않아 받지 못합니다. 5. Appendix: checking an installed copy (beta.14)

These checks confirm, in a real Claude Code session, what the tests could not. Install beta.14 from the archive, start the dashboard, and open a new Claude Code session.

  1. Permission policy deny. Block a tool with a permission policy in the dashboard, then ask Claude to use it. It is blocked.
  2. Allow and deny from the dashboard. When a permission request appears, allow it in the dashboard, then deny another. Claude Code follows each answer, including an edited input.
  3. Answering in the terminal first. While a raised hand is showing, answer in the terminal (or press Esc). The raised hand closes in the dashboard.
  4. Dashboard off. Stop the dashboard and use a tool. The terminal asks as usual, with no hook error.
  5. Other hooks. With another plugin's hooks also installed, a deny from the dashboard still wins, and a deny rule in your settings is not overridden by an allow from the dashboard. Note which answer applies to a permission request when another hook also answers.
  6. Working folder. Hooks still work when you start Claude Code from a project folder (the relay does not depend on the current folder or shell settings).
  7. No added text. Sending a prompt or starting a session adds nothing to the conversation from the plugin.
  8. Remote Linux over SSH. On a remote Linux machine, open the dashboard through the SSH tunnel. It opens, and is not refused with 같은 사용자 계정의 프로그램만 접속할 수 있습니다 (the same-account check passes for the tunnel).
  9. Cancelled hook. Start Claude Code with claude --debug, raise a permission request and answer it in the terminal first. The log shows the hook ended as cancelled, and the raised hand closes.

If any check fails, send the diagnostics file from claude-office diag to whoever supports you.

The status line connection looks for your original status line in the Claude Code settings folder in use when the status line is drawn (CLAUDE_CONFIG_DIR if you set it, otherwise ~/.claude). If you run Claude Code with a different settings folder than at install time, the original status line may show empty. If that happens, tell us as well.

6. Appendix: checking lead features in a real session

The lead features (chapter 4) depend on the lead following the expected steps, so they can be checked only in a real Claude Code session. Turn on the experimental features, start an agent-team floor from the dashboard, and go through these in order. If something differs, send a diagnostics file (claude-office diag) with what you saw.

  1. Reports arrive. Press 보고 요청. Within a few minutes a report arrives in the folder, and the folder appears on the lead's desk.
  2. Approvals reach the lead. Approve one report and send revisions for another. The lead receives the approval and the revisions and acts on them.
  3. The lead uses the question tool. Give the lead work that needs your decision. The lead's desk raises a hand with a yellow ?, and the lead continues as you answered on the dashboard.
  4. Asking in plain text. If the lead asks only in conversation text and stops, 답을 기다립니다 appears. Answering in the terminal clears it; teammates moving does not.
  5. A teammate's question. Have a teammate send a question. Its desk raises a hand, and the answer reaches the teammate through the lead.
  6. Answering on a paused floor. Pause a floor with a question showing and answer it. The answer is kept and reaches the lead when you press 보내고 재개.
  7. Off duty and back. Send a teammate off duty, then back on duty. Off duty leaves a 퇴근 sign; back on duty, the same teammate carries on.
  8. The new teammate does not remember. Let a teammate go and start a new one. A new teammate with the same name sits down and knows nothing of the old conversation beyond the handover note.
  9. Teammates do not connect to the channel themselves. While several teammates work, send the lead instructions and a report request. Instructions always reach the lead, and the lead's connection stays up ("작업 지시" stays on in the floor header).

    A teammate is recognized by three internal arguments Claude Code adds when it starts a teammate process (--agent-id, --agent-name, --team-name, not in the official documentation): all three must be present. This was checked with Claude Code 2.1.304. Check this item again after updating Claude Code. If the argument names change, this check turns off and only the rule that the dashboard refuses a second connection on the same floor remains. Then, after the dashboard restarts, the lead must connect first for instructions to reach it.
