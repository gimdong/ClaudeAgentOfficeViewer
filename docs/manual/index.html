1. 이 프로그램이 하는 일

Claude Code가 지금 무엇을 하고 있는지 작은 사무실 빌딩으로 보여 줍니다.

  • Claude Code 창 하나가 빌딩의 층 하나입니다.
  • Claude와 함께 일하는 도우미(팀원)는 층 안의 도트 캐릭터입니다.
  • 캐릭터 머리 위 말풍선에 지금 하는 일이 짧게 나옵니다.
  • Claude가 여러분의 확인을 기다리면 캐릭터가 손을 들고 머리 위에 노란 ?가 뜹니다.

이 프로그램은 여러분의 컴퓨터 안에서만 동작합니다. 대화 내용을 인터넷으로 보내지 않고, Claude Code의 설정 파일은 설치할 때 여러분이 동의한 상태줄(statusline) 연결 말고는 고치지 않습니다. 여러분이 대시보드에서 직접 누른 답(허용·거부 등)과, 미리 정해 둔 권한 정책(금지·항상 질문)만 Claude Code로 돌려보냅니다.

2. 준비물

설치하기 전에 두 가지가 있어야 합니다.

  1. Claude Code가 설치되어 있고, 한 번 이상 실행해 본 적이 있어야 합니다. 터미널에서 아래 명령으로 확인합니다. 
    claude --version
    숫자로 된 버전이 한 줄 나옵니다(예: 2.1.0 (Claude Code)). "명령을 찾을 수 없습니다"가 나오면 Claude Code를 먼저 설치해 주세요.
  2. Node.js 24 이상이 있어야 합니다. Node.js는 이 프로그램을 움직이는 기본 프로그램입니다. 터미널에서 확인합니다. 
    node --version
    v24 이상으로 시작하는 한 줄이 나옵니다(예: v24.1.0).

    없거나 24보다 낮으면 운영체제에 맞게 설치합니다.

    macOS

    nodejs.org에서 LTS라고 적힌 설치 파일(.pkg)을 받아 두 번 눌러 설치합니다. 설치 뒤에는 터미널을 닫았다가 다시 열어 주세요.

    Linux(Ubuntu)

    회사 IT 담당자에게 "Node.js 24 설치"를 부탁하는 것이 가장 안전합니다. 직접 설치한다면 nodejs.org의 안내(NodeSource 또는 nvm)를 따릅니다.

    Windows

    nodejs.org에서 LTS라고 적힌 설치 파일(.msi)을 받아 설치합니다. 설치 뒤에는 PowerShell을 닫았다가 다시 열어 주세요.

3. 설치

담당자에게 받은 파일 하나로 설치합니다. 인터넷 연결은 필요 없습니다. 프로그램 파일은 여러분의 사용자 폴더 안(~/.claude-office, Windows는 C:\Users\<사용자 이름>\.claude-office)에만 둡니다. 그 밖에는 여러분이 동의할 때만 셸 설정 파일 한 곳(PATH 추가), Claude Code의 플러그인 목록, Claude Code 설정의 상태줄(statusLine) 한 곳을 바꿉니다.

macOS

  1. 받은 파일 claude-office-2.0.0-beta.14.tar.gz를 다운로드 폴더에 둡니다.
  2. "터미널" 앱을 엽니다(⌘+Space를 누르고 "터미널"을 입력).
  3. 아래 명령으로 파일을 풉니다. 
    cd ~/Downloads && tar -xzf claude-office-2.0.0-beta.14.tar.gz

    다운로드 폴더에 claude-office-2.0.0-beta.14 폴더가 생깁니다.

  4. 설치 스크립트를 실행합니다. 
    cd ~/Downloads/claude-office-2.0.0-beta.14 && sh install.sh
  5. 질문 세 개에 답합니다(아래 "설치 중 질문").
드물게 "확인되지 않은 개발자" 경고가 나오면
베타 버전은 Apple의 서명을 받지 않아서 이 경고가 나올 수 있습니다. 담당자에게 받은 파일이 맞다면 시스템 설정 → 개인정보 보호 및 보안 아래쪽의 "그래도 열기"를 누른 뒤 같은 명령을 다시 실행합니다.

Linux(Ubuntu)

  1. 받은 파일 claude-office-2.0.0-beta.14.tar.gz를 다운로드 폴더에 둡니다.
  2. 터미널을 엽니다(Ctrl+Alt+T).
  3. 아래 명령으로 파일을 풀고 설치 스크립트를 실행합니다. 
    cd ~/Downloads && tar -xzf claude-office-2.0.0-beta.14.tar.gz && cd claude-office-2.0.0-beta.14 && sh install.sh
  4. 질문 세 개에 답합니다(아래 "설치 중 질문").

Windows

  1. 받은 파일 claude-office-2.0.0-beta.14.zip을 다운로드 폴더에 둡니다(압축은 아래 명령이 풉니다).
  2. 시작 메뉴에서 PowerShell을 엽니다. PowerShell ISE가 아니라 PowerShell 창(또는 Windows Terminal)에서 실행해 주세요.
  3. 아래 명령으로 파일을 풀고 설치 스크립트를 실행합니다. -ExecutionPolicy Bypass는 "이번 한 번만 이 스크립트 실행을 허용"한다는 뜻이고, 컴퓨터 설정은 바꾸지 않습니다. 
    cd $HOME\Downloads; Expand-Archive claude-office-2.0.0-beta.14.zip -DestinationPath . -Force; cd claude-office-2.0.0-beta.14; powershell -ExecutionPolicy Bypass -File .\install.ps1

    (Windows 화면은 베타에서 확인 전입니다)

설치가 막히면

"디지털 서명되지 않았습니다"처럼 내려받은 파일이 막혔다는 안내가 나오면, 아래 명령으로 압축 푼 폴더의 차단 표시를 푼 뒤 다시 시도합니다.

Get-ChildItem -Recurse $HOME\Downloads\claude-office-2.0.0-beta.14 | Unblock-File

실행 정책 때문에 막히면 압축 푼 폴더 안에서 아래처럼 실행합니다.

powershell -ExecutionPolicy Bypass -File install.ps1

그래도 막히면 회사 정책으로 막혀 있는 것입니다. 회사 IT 담당자(관리자)에게 문의해 주세요. (Windows 화면은 베타에서 확인 전입니다)

  1. 질문 두 개에 답합니다(아래 "설치 중 질문").

설치 중 질문

~/.zshrc에 claude-office 명령 경로를 추가할까요? [y/N]

y를 누르고 Enter를 누르면 어느 폴더에서나 claude-office라고만 쳐서 켤 수 있습니다. PATH는 "명령을 찾아보는 폴더 목록"입니다. 실제 화면에는 /Users/<사용자 이름>/.zshrc에 …처럼 전체 경로로 나옵니다. 파일 이름(~/.zshrc)은 쓰는 셸에 따라 ~/.bash_profile이나 ~/.bashrc로 보일 수 있습니다. Windows에서는 사용자 PATH에 claude-office 명령 경로를 추가할까요? [y/N]로 묻습니다(Windows 화면은 베타에서 확인 전입니다).

n을 누르면 설치가 끝날 때 다음부터는 이렇게 켜세요: ~/.claude-office/bin/claude-office처럼 켜는 명령을 알려 줍니다(4장).

Claude Code 플러그인(claude-office)을 설치할까요? 도구 사용 기록을 이 PC의 뷰어로 보내고, 대시보드에서 답한 허용·거부를 Claude Code에 돌려줍니다. [y/N]
y를 권장합니다. 플러그인은 Claude Code에 붙이는 작은 추가 기능이고, 말풍선과 손들기를 보여 주고, 대시보드에서 답하려면 필요합니다. 플러그인은 Claude Code의 소식을 대시보드로 보내고, 여러분이 대시보드에서 답하면 그 답을 Claude Code에 전합니다. 스스로 허용하거나 거부하지는 않고, 같은 열쇠 파일을 쓰는 이 컴퓨터의 대시보드가 보낸 답만 전합니다(대시보드가 꺼져 있을 때).
Claude Code 상태줄(statusline)에 연결할까요? PLAN 바(남은 사용량 %)를 채우려면 필요합니다. Claude Code 설정(~/.claude/settings.json)의 statusLine을 바꾸고, 원래 설정은 백업하며, 쓰던 상태줄은 그대로 보입니다. [y/N]

위쪽 막대의 PLAN 바(요금제 한도)를 쓰려면 y를 누릅니다. Claude Code가 상태줄에 넘겨 주는 사용 한도를 대시보드가 받도록, Claude Code 설정의 statusLine 한 곳을 바꿉니다. 원래 설정은 백업하고, 쓰던 상태줄은 그대로 보입니다. 실제 화면에는 설정 파일이 전체 경로로 나옵니다. 지울 때(7장) 되돌립니다.

이 질문은 --yes로는 켜지지 않습니다. 묻지 않고 켜려면 --statusline을 붙입니다. 묻지 않고 넘어가면 statusline 연결은 묻지 않고 건너뛰었습니다. 켜려면 설치 스크립트를 --statusline을 붙여 다시 실행하세요.가 나옵니다. Windows에서는 묻지 않습니다(지원하지 않음).

4. 켜기와 끄기

켜기

  1. 터미널(Windows는 PowerShell)을 새로 엽니다.
  2. 아래 명령을 실행합니다. 
    claude-office

    설치할 때 PATH 질문에 n을 눌렀다면, 설치 마지막 줄(다음부터는 이렇게 켜세요: …)에 나온 전체 경로로 켭니다.

    ~/.claude-office/bin/claude-office

    Windows는 $HOME\.claude-office\bin\claude-office.cmd입니다(Windows 화면은 베타에서 확인 전입니다).

  3. 웹 브라우저가 저절로 열리고 대시보드가 보입니다. 이때 브라우저 주소에는 접속 열쇠가 붙어 있다가, 열리고 나면 주소창에서 사라집니다. 열쇠는 이 브라우저에 1년 동안 기억됩니다. 그래서 그 뒤로는 http://127.0.0.1:4317을 북마크해 두고 열어도 됩니다. 127.0.0.1은 "이 컴퓨터 자신"이라는 뜻입니다.
  • 브라우저가 열리지 않고 터미널에 주소가 나오면 6장 "브라우저가 안 열리고 터미널에 주소가 나왔어요"를 봐 주세요.
  • 다른 브라우저로 보고 싶으면 터미널에서 claude-office open Safari처럼 브라우저 이름을 붙여 실행합니다. 이미 켜진 대시보드를 그 브라우저에서 열쇠와 함께 열어 줍니다(서버를 새로 켜지는 않습니다). 이름을 빼고 claude-office open만 실행하면 기본 브라우저로 엽니다. 대시보드가 열쇠 없이 열려 "열쇠 필요" 화면이 보일 때도 같은 방법입니다.
  • 대시보드가 이미 켜져 있을 때 claude-office를 다시 실행하면, 새로 켜지 않고 브라우저에서 대시보드를 다시 엽니다. 터미널에는 아래처럼 나오고 바로 끝납니다. 
    이 창을 닫으면 대시보드가 꺼집니다.
이미 켜져 있습니다. 브라우저에서 대시보드를 다시 열었습니다. 이 창은 닫아도 대시보드가 꺼지지 않습니다.

    첫 줄은 늘 먼저 나오는 안내입니다. 이 경우에는 둘째 줄이 맞습니다. 대시보드는 처음 켠 창에서 계속 돌아갑니다.

이 창을 닫으면 대시보드가 꺼집니다.
Claude Agent Office: http://127.0.0.1:4317  (data: /Users/<사용자 이름>/.claude)

브라우저에 빌딩과 층이 보이고, 위쪽 막대 오른쪽에 ● LIVE가 보입니다.

스크린샷 자리: 처음 켰을 때의 대시보드
터미널 창을 닫으면 대시보드도 꺼집니다. 대시보드를 보는 동안에는 창을 열어 두세요(작게 줄여 두어도 됩니다).

끄기

대시보드를 켠 터미널 창에서 Ctrl+C를 누르거나, 그 창을 닫습니다. Claude Code는 계속 쓸 수 있습니다.

Claude Code 안에서 !로 켜지 마세요. ! claude-office처럼 Claude Code의 명령 입력으로 켜면 대시보드는 돌아가지만 끌 창이 없습니다. 그 세션이 끝난 뒤에도 대시보드만 남고, 새 버전을 설치해도 옛 대시보드가 계속 돕니다. 꼭 일반 터미널 창에서 켜 주세요. 이미 그렇게 켰다면 6장 "끌 창이 없어요"를 봐 주세요.

대시보드를 끈 채 Claude Code를 쓰면 Claude Code는 아무 표시 없이 평소처럼 일하고, 권한이 필요하면 Claude Code 창에서 묻습니다. 이때는 권한 정책도 적용되지 않습니다. 옛 플러그인(beta.13 이하)이 남은 창에서는 PreToolUse:Bash hook error와 connect ECONNREFUSED 127.0.0.1:4317 같은 표시가 보일 수 있습니다. 대시보드에 닿지 못했다는 뜻일 뿐이고, Claude Code는 그대로 일합니다.

원격에서 보기(SSH 터널)

Claude Code를 다른 컴퓨터(예: 회사 Linux 서버)에서 쓸 때, 그 컴퓨터의 대시보드를 내 컴퓨터 브라우저로 볼 수 있습니다. 대시보드는 그 컴퓨터 안(127.0.0.1)에서만 들으므로, SSH 터널로 내 컴퓨터의 통로 번호를 그 컴퓨터의 4317에 잇습니다.

  1. 원격 컴퓨터에 이 프로그램을 설치하고(3장), 원격 컴퓨터의 터미널에서 claude-office로 대시보드를 켜 둡니다. 브라우저를 열지 못했다는 안내가 나와도 괜찮습니다. 그 창을 닫으면 대시보드가 꺼지므로, 대시보드는 따로 연 ssh 창이나 tmux 같은 프로그램 안에서 켜 두고, 아래 3번은 다른 창에서 합니다.
  2. 내 컴퓨터에서 새 터미널을 열고 터널을 엽니다. <원격 컴퓨터>는 평소 ssh로 접속할 때 쓰는 주소입니다. 대시보드를 보는 동안 이 창을 열어 둡니다. 
    ssh -L 4317:127.0.0.1:4317 <원격 컴퓨터>
  3. 그 ssh 창(원격 컴퓨터)에서 열쇠가 담긴 주소를 받습니다. 
    claude-office url

    아래처럼 주소 한 줄과 안내 한 줄이 나옵니다. 브라우저는 열지 않습니다. 원격 대시보드가 꺼져 있어도 주소는 나오지만, 그 주소는 대시보드를 켠 뒤에만 열립니다.

    http://127.0.0.1:4317/?k=…
이 주소는 열쇠입니다. 남에게 보내지 마세요.
  4. 그 한 줄 전체를 복사해 내 컴퓨터 브라우저 주소창에 붙여 넣습니다.
  • 내 컴퓨터에서도 이 대시보드를 쓴다면 앞 번호를 바꿉니다(예: ssh -L 14317:127.0.0.1:4317 <원격 컴퓨터>). 그리고 받은 주소의 번호만 바꿔 127.0.0.1:14317로 엽니다. 대시보드는 번호마다 열쇠를 따로 기억하므로, 내 컴퓨터의 대시보드와 함께 열어도 서로 방해하지 않습니다.
  • ssh로 접속하는 계정과 원격 컴퓨터에서 대시보드를 켠 계정이 같아야 합니다. Linux에서는 다른 계정의 접속을 거절합니다(6장).
  • 터널을 닫으면(ssh 창을 닫거나 exit) 브라우저 화면이 끊깁니다. 원격 컴퓨터의 대시보드와 Claude Code는 그대로 돕니다.
이 주소는 열쇠입니다. 남에게 보내지 마세요. claude-office url의 출력을 채팅이나 이슈에 붙여 넣지 마세요.

5. 화면 보는 법

  1. 층: Claude Code 창 하나입니다. 층 머리에 이름과 상태가 보입니다. Claude Code 창을 정상적으로 닫으면 그 층은 사라집니다. 불이 꺼진 채 흐리게 남은 층은 창이 갑자기 꺼진 경우입니다.
  2. 캐릭터: Claude(팀장)와, Claude가 함께 일하도록 부른 팀원들입니다.
  3. 임시 책상: Claude가 잠깐 부른 도우미(서브에이전트)는 일하는 동안 리드 책상 바로 옆에 점선 테두리의 작은 책상으로 보이고, 왼쪽 위에 임시 딱지가 붙습니다. 이름표는 그 도우미에게 맡긴 일이고, 아래 세 줄은 종류(예: Explore), 모델, 토큰입니다. 끝나면 빈 의자로 바뀌고 딱지 글자가 임시에서 끝남으로 바뀌었다가 30초 뒤 사라집니다. 한 층에 4개까지 보이고, 더 있으면 +2 같은 칩이 붙습니다(마우스를 올리면 서브에이전트 2명 더). 임시 책상은 누를 수 없습니다(마우스를 올리면 맡긴 일 전체가 보입니다). 하는 일은 리드 말풍선에 서브에이전트(종류)로 함께 보이고, 권한은 리드 패널의 서브에이전트 절에서 정합니다. 멈춘(휴업) 층에서는 다른 책상처럼 빈 의자입니다.
  4. 말풍선: 캐릭터가 지금 하는 일입니다(예: 저는 지금 「README.md」 파일을 읽고 있습니다).
  5. 손들기와 노란 ?: Claude가 여러분의 확인(권한 허락, 질문 답변, 계획 승인)을 기다립니다. 손 든 캐릭터를 누르면 결정 보고서가 열려 대시보드에서 바로 답할 수 있습니다(아래 "결정 보고서"). Claude Code 창에서 답해도 됩니다.
  6. 진단 칩: 위쪽 막대의 "진단" 단추입니다. 최근 1시간 안에 오류가 있었으면 빨간 점이 붙습니다. 누르면 오른쪽에 진단 패널이 열립니다.

진단 패널

진단 칩을 누르면 오른쪽에 패널이 열립니다. 위에서부터 이렇게 보입니다.

  • 판정 한 줄: 모두 정상입니다(초록), 확인할 항목이 2개 있습니다(노랑), 문제 1개를 찾았습니다(빨강) 가운데 하나입니다.
  • 최근 오류: 최근 1시간 오류 없음 또는 최근 1시간 오류 2건과, 로그가 저장되는 폴더입니다.
  • hook 수신: Claude Code가 보낸 소식을 얼마나 받았는지입니다(예: 최근 10분 5건, 마지막 수신 2분 전, 거부 0건).
  • 점검 결과: 6장의 환경 점검(doctor)과 같은 항목입니다. 문제(빨간 테두리)와 확인 필요(노란 점선 테두리)가 위에 오고, 아래에 고치는 법이 붙습니다. 정상 항목은 한 줄로 보입니다.
  • 진단 파일: 문제가 생겼을 때 담당자에게 보낼 파일을 만드는 단추입니다(6장).

오른쪽 위에 다시 확인 단추와 닫기 단추가 있습니다. Esc를 눌러도 닫힙니다.

결정 보고서

Claude가 여러분의 확인을 기다릴 때, Claude Code 창으로 가지 않고 대시보드에서 바로 답하는 창입니다.

  1. 여는 법: 손 든 캐릭터를 누릅니다. 또는 위쪽 막대의 결정 대기 N을 누르면 가장 오래 기다린 결정이 열립니다. 진단 패널과 같은 오른쪽 창으로 열립니다.
  2. 보이는 것: 어느 층의 누가, 무엇을 하려는지(명령이나 파일 경로를 가려서 요약한 것), 왜 묻는지 한 줄, 그리고 남은 시간입니다. 남은 시간은 9:50 남음 · 지나면 터미널에서 묻습니다처럼 거꾸로 셉니다.
  3. 답하기: 종류에 따라 다릅니다.
    • 권한 요청(예: 이 명령을 실행해도 될까요?): 허용 또는 거부를 누릅니다. 처음에는 실수로 허용하지 않도록 거부에 포커스가 있습니다. 거부할 때 거부 이유 (선택, Claude에게 전달됩니다) 칸에 짧게(200자까지) 이유를 적을 수 있습니다. 비워 두면 Claude에게 대시보드에서 사용자가 거부했습니다가 전해집니다.
    • 질문(질문에 답해 주세요): 질문마다 선택지를 고릅니다(여러 개를 고를 수 있는 질문도 있습니다). 맞는 것이 없으면 기타 (직접 입력)을 고르고 답을 씁니다. 모든 질문에 답한 뒤 이 답 보내기를 누릅니다.
    • 예산 도달: 아래 "예산"을 봐 주세요.
  4. 답한 뒤: 결과가 한 줄로 보이고, 3초 뒤 다음 결정으로 넘어가거나 창이 닫힙니다. 예: 대시보드에서 허용함, 터미널에서 이미 답함, 시간이 지나 터미널로 넘어감
  • 허용은 되돌릴 수 없습니다. 보고서의 요약(명령, 파일)을 꼭 읽고 눌러 주세요.
  • 같은 질문이 Claude Code 창에도 떠 있고, 먼저 답한 쪽이 적용됩니다.
  • Claude Code 창에서 먼저 답해도 대시보드에 그 요청이 잠깐 남아 있을 수 있습니다. 창에서 허용했다면 보통 그 작업이 끝날 때까지 남고, 드물게 더 오래 남습니다. 그 사이 대시보드에서 누른 답은 대시보드에서 허용함·대시보드에서 거부함으로 보여도 적용되지 않습니다. Claude Code 창의 답이 이미 적용되었습니다.
  • 대시보드에서 10분 안에(화면에서는 9:50부터 셉니다) 답하지 않으면 시간이 지나 터미널로 넘어감으로 닫히고, Claude Code 창에서 답하면 됩니다.
  • 대시보드가 꺼져 있으면 지금처럼 Claude Code 창에서만 묻습니다.

대시보드에서는 보기만 하고 답은 Claude Code 창에서 하는 것도 있습니다.

  • 계획 승인: 보고서에 계획 미리보기와 터미널에서 답해 주세요가 보입니다. 승인은 Claude Code 창에서 합니다.
  • 팀원 요청(팀원이 리드에게 보낸 [결정 필요] 메시지): 보고서에 메시지 요약과 터미널(리드 세션)에서 답해 주세요가 보입니다.

Claude Code의 권한 모드가 "auto"인 창은 Claude Code가 스스로 허용하는 일이 많아서, 일반 권한 요청이 대시보드에 드물게 뜹니다. 예산 도달은 모드와 관계없이 뜹니다.

예산

층(Claude Code 창)마다 쓸 토큰 양의 상한을 정할 수 있습니다. 세션을 시작한 때부터 셉니다. 돈이 아니라 토큰 수입니다.

  1. 정하기: 층 머리의 예산 막대 옆 설정 단추를 누릅니다. 이 층의 예산에 토큰 수를 적고 저장을 누릅니다. 비워 두면 예산 없음. 1,000 ~ 1,000,000,000입니다. 새 층의 기본값도 같은 창에서 정하며, 앞으로 새로 생기는 층에 적용됩니다. 지금 있는 층은 바뀌지 않습니다.
  2. 알림 허락: 예산을 처음 저장할 때 브라우저가 알림을 허용할지 묻습니다. 거절해도 층 경광등은 켜집니다.
  3. 막대: 층 머리에 남은 양이 %로 보입니다. 50% 이상 초록, 20% 이상 노랑, 그 아래는 분홍입니다.
  4. 예산에 닿으면: 그 층에 경광등이 켜지고, 브라우저 알림(예산에 도달했습니다)이 한 번 옵니다. 소리는 없습니다. 그 뒤 Claude가 다음 도구를 쓰려 할 때 Claude Code 창에 예산(500,000토큰)에 도달했습니다. 대시보드나 이 창에서 계속할지 정해 주세요 같은 권한 창이 뜨고, 대시보드에서는 그 층의 캐릭터가 손을 듭니다. 손 든 캐릭터(또는 위쪽 막대의 결정 대기 N)를 누르면 예산에 도달했습니다. 계속할까요? 보고서가 열립니다. 먼저 답한 쪽이 적용됩니다.
  5. 계속 / 중단: 계속을 누르면 하던 일을 이어 갑니다. 보고서에 적힌 대로(계속을 누르면 이 도구 실행도 함께 허용됩니다) 기다리던 그 도구도 함께 실행되고, 예산만큼 더 쓰면 다시 묻습니다. 중단을 누르면 Claude에게 예산에 도달해 사용자가 중단했습니다가 전해집니다. 중단하면 그 도구만 막히고, Claude가 다음 도구를 쓰려 하면 다시 묻습니다.

대시보드가 꺼져 있거나 답하지 않으면 Claude Code 창의 권한 창에서만 정합니다. Claude Code 창에서 허용해도 '계속'과 같습니다(예산만큼 더 쓰면 다시 묻습니다). 예산은 대화 기록으로 세므로 요금제의 실제 사용량과 다를 수 있습니다.

권한 정책

권한 정책은 대시보드가 켜져 있을 때만 적용됩니다. 대시보드를 끄거나 Claude Code가 대시보드에 닿지 못하면, Claude Code는 원래 규칙대로 일합니다. 그래서 이 기능은 남이 몰래 쓰는 것을 막는 보안 장치가 아니라, 맡긴 에이전트가 하지 않았으면 하는 일을 실수로 하지 않게 하는 실수 방지 장치입니다.

에이전트(리드, 팀원, 서브에이전트)마다 "이 도구는 쓰지 마"(금지), "이 도구는 쓸 때마다 물어봐"(항상 질문)를 미리 정해 둘 수 있습니다. 예를 들어 검토만 맡긴 팀원 reviewer는 명령 실행과 파일 고치기를 못 하게 하고, 리드의 명령 실행은 매번 묻게 할 수 있습니다. 허용을 늘리는 설정은 없습니다. 정책은 막거나 묻게만 합니다.

정하기

  2. 패널 위에 그 정책이 어디에 적용되는지 나옵니다. 팀원과 서브에이전트는 이 이름의 정책은 다른 세션의 같은 이름에도 적용됩니다, 리드는 리드의 정책은 모든 세션의 리드에 적용됩니다입니다. 정책은 창이 아니라 이름에 붙습니다.

Windows에서는 세션이 맞는지 확인할 방법이 없어 종료가 늘 이 세션의 프로세스를 확인하지 못해 끄지 않았습니다. 터미널에서 직접 끝내 주세요.가 됩니다. 그 층의 Claude Code 창에서 직접 끝내 주세요. (Windows 화면은 베타에서 확인 전입니다)

숨기기(목록에서만)

  • 끝난 층은 강제로 껐거나 Claude Code가 갑자기 꺼져 세션 기록이 남은 경우에 보입니다(정상적으로 끝난 층은 저절로 사라집니다).
  • 끝난 층의 숨기기를 누르면 그 층이 대시보드 목록에서 바로 사라집니다. 확인 창은 없습니다. 대화 기록은 지우지 않고 목록에서만 숨깁니다(단추에 마우스를 올리면 대시보드 목록에서만 숨깁니다. 대화 기록은 지우지 않습니다. 같은 세션을 다시 열면 다시 보입니다.).
  • 숨긴 층이 있으면 빌딩 맨 아래에 숨긴 층 3개 · 모두 보이기 단추가 보입니다. 누르면 숨긴 층이 모두 돌아옵니다(층마다 따로 되돌리기는 없습니다). 돌아오는 동안 잠깐 숨긴 층을 다시 불러오는 중…이 보입니다.
  • 층 번호는 남은 층으로 다시 매겨집니다(가장 오래된 층이 1F).
  • 숨긴 세션을 Claude Code에서 다시 열면(claude --resume) 저절로 다시 보입니다.

알아 둘 점

  • 멈춤과 숨김은 대시보드가 켜져 있는 동안만 유지됩니다. 대시보드를 끄면 멈춘 층도 바로 다시 도구를 쓰고, 다시 켜면 모든 층이 영업 중으로 돌아오고 숨긴 층도 다시 보입니다. 보안 장치가 아닙니다.
  • 멈춤: Claude가 다음에 도구를 쓰려 할 때부터 막습니다. 지금 쓰고 있는 답과, 터미널에서 직접 말을 걸었을 때의 대답은 이어집니다. 사용자에게 묻기와 팀원끼리 연락은 막지 않습니다.
  • 종료는 프로세스를 끄는 신호입니다. 하던 일을 정리하고 끝내게 하는 기능은 이번 버전에는 없습니다.
  • 리드·팀원·서브에이전트를 따로 멈출 수는 없습니다. 한 에이전트만 막으려면 권한 정책의 "모든 도구 금지"를 쓰세요.

작업 지시와 새 층(실험 기능)

실험 기능입니다. 작업 지시와 새 층은 Claude Code의 연구 프리뷰 기능(channel)을 씁니다. Claude Code가 바뀌면 동작이 바뀌거나 멈출 수 있습니다. 새 층을 띄울 때마다 Claude Code가 개발용 channel 경고를 띄웁니다. 회사 계정(Team·Enterprise)에서는 관리자가 허용하기 전까지 동작하지 않습니다.

  • 켜기: 위쪽 막대의 실험 기능을 누르고 설명에 동의한 뒤 켜기를 누릅니다. 대시보드를 다시 켜도 켠 상태가 남습니다. tmux 3.0 이상이 있어야 새 층을 띄울 수 있습니다(macOS·Linux). Windows에서는 쓸 수 없습니다.
  • 새 층 띄우기: 빈 층의 새 세션 시작을 누르고 폴더(전체 경로 또는 ~/로 시작), 이름, 모델, 첫 지시를 정한 뒤 띄우기를 누릅니다. 첫 지시와 이름은 -로 시작할 수 없습니다(Claude Code가 옵션으로 읽습니다). 대시보드가 그 폴더에서 tmux 안에 Claude Code를 띄웁니다. 터미널에서 아래 명령으로 붙어 확인 창 두 개(폴더 신뢰, 개발용 channel 경고)를 확인해 주세요. 확인하기 전에는 Claude가 시작하지 않습니다. 대시보드는 이 확인 창을 대신 누르지 않습니다. 확인하면 층이 빌딩에 나타나고 층 머리에 대시보드가 띄움 · 연결됨이 붙습니다.
  • 작업 지시: 층 머리의 작업 지시를 눌러 글을 보내면 그 세션에 사용자가 입력한 것처럼 들어갑니다. 작업 중이면 하던 일을 마친 뒤 읽습니다. 직접 터미널에서 띄운 층에는 보낼 수 없습니다(대시보드가 띄운 층에만 지시할 수 있습니다(Claude Code 제약)). 그런 층은 아래 작업 지시 켜기로 옮겨 열면 지시할 수 있습니다.
  • 작업 지시 켜기(옮겨 열기): 대시보드가 띄우지 않은 살아 있는 층에는 작업 지시 자리에 작업 지시 켜기 단추가 있습니다. 누르면 확인 창(제목 fake-shop 층을 tmux로 옮겨 열까요?)에 이 세션을 끄고, 같은 대화를 이어서 tmux에서 다시 엽니다. 다시 연 뒤에는 이 층에 작업을 지시할 수 있습니다. 지금 터미널 창의 Claude Code는 끝나고, 이후에는 tmux attach로 이어 봅니다.가 보입니다. 작업 중이면 ⚠ 지금 작업 중입니다. 끄면 하던 일(실행 중인 명령·파일 쓰기)이 중간에 끊길 수 있습니다. 끝날 때까지 기다리거나, 그래도 옮기려면 진행하세요.도 보입니다. 옮겨 열기를 누르면 그 세션을 끄고, 끝나기를 기다린 뒤(이 세션이 끝나기를 기다리고 있습니다(최대 15초). 창을 닫아도 계속됩니다.) 같은 폴더·같은 대화로 tmux에서 다시 엽니다. 다시 연 뒤에는 위 "다시 이어 보기"처럼 tmux attach로 붙어 확인 창을 확인해 주세요.
    • 위험: 하던 일이 중간에 끊길 수 있고, 원래 터미널 창의 Claude Code는 끝납니다. 끝나면서 원래 터미널에 Resume this session with: claude --resume …이 찍히지만, 옮겨 열기가 성공했다면 원래 터미널에서 다시 열지 마세요(tmux 쪽에 이미 열려 있어, 같은 대화를 두 프로세스가 쓰게 됩니다). 15초 안에 끝나지 않으면 강제로 끄지 않고 다시 열지도 않습니다(아직 끝나지 않았습니다. 곧 끝날 수 있으니 잠시 뒤 다시 눌러 보세요. 계속 켜져 있으면 터미널에서 직접 끝낸 뒤 아래 명령으로 이어 열 수 있습니다(이때는 작업 지시가 켜지지 않습니다).).
    • 누를 수 없는 층: 멈춘 층(멈춘 층은 스위치를 "영업 중"으로 돌린 뒤 옮겨 열 수 있습니다), Claude Code의 백그라운드 작업과 이어진 층(이 층은 Claude Code의 백그라운드 작업과 이어져 있어 옮겨 열 수 없습니다. 작업을 지시하려면 대시보드의 "새 세션 시작"으로 새 층을 띄워 주세요.), 이 대시보드를 켠 세션(이 대시보드를 켠 세션이라 옮겨 열 수 없습니다. 끄면 대시보드도 함께 꺼져 다시 열 수 없습니다. 작업 지시가 필요하면 대시보드를 다른 터미널 창에서 켜 주세요.). 마우스를 올리면 이유가 보입니다.
    • 끄기 전에 막히면(띄운 층이 너무 많거나 폴더가 없을 때) 세션은 끄지 않고 그대로 둡니다. 창에 대시보드가 띄운 층이 너무 많아(8개) 옮겨 열지 않았습니다. 세션은 끄지 않았습니다. 쓰지 않는 층을 끈 뒤 다시 해 주세요. 또는 이 층의 폴더를 찾을 수 없어 옮겨 열지 않았습니다. 세션은 끄지 않았습니다.가 보입니다.
    • 다시 열지 못했을 때(tmux 쪽이 열리지 않았을 때만): 세션은 껐지만 다시 열지 못했습니다. 대화 기록은 그대로 있어 터미널에서 아래 명령으로 이어 열 수 있습니다. 아래에 claude --resume … 명령이 나옵니다. 그 명령을 터미널에서 실행하면 같은 대화를 이어 쓸 수 있습니다(이때는 작업 지시가 켜지지 않습니다).
  • 휴업 중 지시: 멈춘 층에 보낸 지시는 바로 보내지 않고 보관합니다(층 머리 보관 N). 스위치를 영업 중으로 돌리면 재개 전 확인 창이 먼저 열려, 보관한 지시를 고치거나 지운 뒤 보내고 재개로 보낼 수 있습니다. 취소를 누르면 멈춘 채로 둡니다. 보관한 지시는 대시보드가 켜져 있는 동안만 남습니다.
  • 다시 이어 보기: 그 세션을 터미널에서 다시 보려면 tmux attach -t co-…(창에 나온 이름)로 붙습니다. 대시보드 기능 없이 이어 쓰려면 claude --resume을 씁니다.
  • 끝내기: 대시보드로 띄운 층은 위처럼 tmux attach로 붙어 그 창에서 /exit로 끝내기를 권합니다. 띄운 층은 대화가 따로 백그라운드 작업으로 이어질 수 있어, 층 머리의 종료로는 다 끝나지 않을 수 있습니다(확인 전입니다).
  • 참고: 이 플러그인은 모든 Claude Code 세션에 작은 channel 서버(office-channel)를 함께 띄웁니다. 대시보드가 띄운 층에서만 대시보드에 연결하고, 다른 세션에서는 아무것도 하지 않습니다. /mcp 목록에 보이는 것은 정상입니다.

리드와 일하기(실험 기능)

작업 지시가 켜진 층(channel이 연결된 층)에서만 쓸 수 있습니다. 위의 작업 지시와 새 층과 같은 실험 기능을 씁니다. 터미널에서 직접 연 층에서는 버튼이 흐리게 보이고, 그 아래에 작업 지시 켜기(옮겨 열기)로 연결하면 쓸 수 있습니다가 나옵니다(작업 지시 켜기).

층마다 리드(팀리더) 한 명이 여러분과 그 층의 세션을 잇는 창구입니다. 보고, 결재, 대화 질문의 답, 팀원의 퇴근과 퇴사는 모두 리드를 거쳐 전해집니다. 대시보드는 정해진 틀에 맞춰 리드에게 지시를 보내고, 여러분이 쓴 글(수정 사항, 답)은 그 틀의 정해진 자리에만 들어갑니다. 리드가 보내 온 글(보고서, 질문)은 대시보드에서 다시 지시로 쓰지 않습니다. 버튼은 책상을 눌러 여는 에이전트 패널 맨 위의 지시 절에 있습니다.

  • 보내면: 버튼 아래에 리드에게 보냈습니다가 잠깐 보입니다. 멈춘 층이면 바로 보내지 않고 보관합니다(휴업 중이라 보관했다가, 재개할 때 확인하고 보냅니다.). 보관한 지시는 재개 전 확인 창에 함께 보이고, 보내고 재개를 눌렀을 때만 보냅니다. 보내지 못하면 처리하지 못했습니다. 서버 연결을 확인하고 다시 시도해 주세요.가 나옵니다.

보고 요청과 결재(서류철)

  • 리드 패널의 보고 요청을 누르면 리드가 보고서를 써서 대시보드로 보냅니다. 보고서가 오면 리드 책상 위에 작은 서류철이 보이고, 결재할 것이 있으면 이름표 아래에 결재 2처럼 수가 보입니다.
  • 서류철(리드 패널의 서류철 · 대기 2)을 누르면 받은 보고서 목록이 최신 것부터 보입니다. 하나를 누르면 종이 모양 본문이 열립니다. 보고서 글은 글자 그대로 보여 주고, 마크다운이나 HTML로 꾸미지 않습니다(##·** 같은 기호도 그대로 보입니다).
  • 대기 중인 보고서에는 승인과 수정 사항 적기가 있습니다. 수정 사항은 4,000자까지 적어 수정 요청 보내기로 리드에게 보냅니다. 도장은 대기, 승인됨, 수정 요청 셋입니다.
  • 보고 요청 뒤 10분 넘게 보고서가 오지 않으면 리드 패널에 보고 요청 뒤 10분 넘게 답이 없습니다가 보입니다. 리드가 정해진 방법으로 답하지 않았을 수 있습니다. 터미널에서 리드의 화면을 확인해 주세요.
  • 대기 중인 보고서가 아주 많아지면 오래된 대기 보고서는 보관함으로 옮겨집니다. 목록 맨 아래의 보관함을 펼치면 보이고, 거기서도 결재할 수 있습니다.
  • 멈춘 층에서 결재하면 보고서마다 하나씩 보관되고, 같은 보고서에 승인과 수정 요청을 번갈아 누르면 나중 것만 남습니다. 이때 승인을 보관했습니다 — 재개할 때 확인하고 보냅니다(또는 수정 요청을 보관했습니다 — 재개할 때 확인하고 보냅니다)가 보이고, 도장은 보관됨이었다가 재개 전 확인 창에서 보내고 재개로 실제로 보내면 승인됨이나 수정 요청으로 바뀝니다.
  • 작업 지시가 켜지지 않은 층에서도 서류철은 열어 읽을 수 있습니다. 결재 버튼만 흐리게 보입니다.
  • 보고서는 설치 폴더의 reports.json(본인만 읽을 수 있는 파일)에만 둡니다. ~/.claude에는 쓰지 않습니다.

대화 질문에 답하기

  • 대화 질문: 리드나 팀원이 여러분의 결정이 필요할 때 대시보드로 질문을 보내면(ask_user), 그 책상의 캐릭터가 손을 들고 노란 ?가 뜹니다. 위쪽 막대의 결정 대기 수에도 들어갑니다. 누르면 질문과 제안된 선택지, 직접 답하기 칸이 열립니다. 선택지는 눌러도 바로 보내지 않고, 고른 뒤 보내기를 눌러야 보냅니다. 이때 보내는 것은 고른 번호와 여러분이 직접 쓴 글뿐입니다(질문한 쪽이 쓴 선택지입니다. 고르면 번호만 보냅니다).
  • 팀원이 보낸 질문은 그 팀원 책상에 뜨고, 답은 리드를 거쳐 그 팀원에게 갑니다(developer의 질문입니다. 답은 리드를 거쳐 보냅니다).
  • 답을 기다립니다: 리드가 질문 기능을 쓰지 않고 대화 글로 묻고 멈추면, 리드 책상에 하늘색 말머리(· · ·)와 답을 기다립니다가 보입니다. 손을 들지는 않고, 결정 대기 수에도 들어가지 않습니다. 누르면 리드의 마지막 글과 그 글의 번호 목록에서 뽑은 선택지가 보이고, 같은 방법으로 답할 수 있습니다. 글이 길면 앞부분을 줄이고 …로 시작합니다. 이 표시는 글 모양으로 짐작한 것이라, 묻지 않았는데 뜨거나 물었는데 뜨지 않을 수 있습니다.
  • 터미널에서 먼저 답하면 표시가 사라지고, 열어 둔 창에는 이미 터미널에서 답했습니다가 보입니다. 대화 질문(손들기)은 대시보드에서 답을 보내거나 여러분이 리드의 터미널에 직접 글을 쳤을 때만 사라집니다. 리드가 다른 도구를 써도 남아 있습니다. 답을 기다립니다는 리드 본인이 다음 일을 시작하면 사라집니다. 어느 쪽이든 팀원이나 서브에이전트가 움직여서는 사라지지 않습니다.
  • 멈춘 층에서 답하면 답은 보관됩니다(보관한 답이 있습니다. 재개할 때 확인하고 보냅니다). 재개 전 확인 창에서 보내고 재개를 누르면 보내지고 표시가 사라집니다. 확인 창에서 그 답을 지우면 질문은 다시 답할 수 있는 상태로 돌아갑니다. 보관한 지시는 대시보드가 켜져 있는 동안만 남습니다. 대시보드를 다시 켜면 보관한 답과 그 질문 표시도 함께 사라집니다. 다시 켜기 전에 떠 있던 질문과 아직 답이 오지 않은 보고 요청도 사라지니, 필요하면 다시 요청해 주세요.
  • 작업 지시가 켜지지 않은 층에서는 질문을 볼 수만 있습니다(터미널에서 답하거나, 작업 지시 켜기(옮겨 열기)로 연결하세요).

퇴근·출근·오래 쉼

  • 팀원 패널의 퇴근을 누르면 리드가 그 팀원을 끝냅니다. 그 동안 이름표 아래에 퇴근 요청함이 보이고, 팀원이 끝나거나 요청 뒤 10분 동안 활동이 없으면 빈 의자에 퇴근 팻말이 놓입니다. 그냥 꺼진 책상(팻말 없는 빈 의자)과 달리, 팻말은 여러분이 퇴근시킨 자리에만 놓입니다.
  • 퇴근 표시는 대시보드가 켜져 있는 동안만 기억합니다. 대시보드를 다시 켜면 팻말 없는 빈 의자로 보입니다.
  • 퇴근한 팀원 패널의 출근을 누르면 리드가 같은 이름의 팀원에게 다시 일을 시킵니다. 대화 기록이 남아 있으면 이어서 일합니다.
  • 마지막 활동이 1시간 넘은 팀원 책상에는 오래 쉬는 중이 보입니다. 표시만 하고 저절로 퇴근시키지는 않습니다. 멈춘 층이나 결정을 기다리는 팀원은 이 표시와 퇴근 판정에서 뺍니다.
  • 리드에게는 퇴근·퇴사 버튼이 없습니다(층의 창구라서).

퇴사와 새 팀원

  1. 팀원 패널의 퇴사를 누르면 확인 창이 열립니다: designer의 기억은 새 팀원에게 이어지지 않고, 인수인계 메모만 넘어갑니다. 대화 기록은 지우지 않습니다. 퇴사 진행을 누르면 시작합니다.
  2. 떠나는 팀원이 인수인계 메모를 써서 보냅니다. 그동안 책상에 인수인계 쓰는 중이 보입니다. 5분이 지나도 메모가 없으면 대시보드가 리드에게 대신 써 달라고 한 번 보냅니다. 이 부탁은 작업 지시가 연결되어 있을 때만 가고, 멈춘 층이면 보관했다가 재개할 때 보냅니다. 대시보드를 다시 켜도 퇴사는 이어 갑니다. 그 층이 다시 연결되면 하던 퇴사를 그대로 이어 가고, 연결이 없는 동안에는 그 팀원 패널의 퇴사 진행 중 아래에 연결되면 이어 갑니다가 보입니다(책상에 마우스를 올려도 보입니다).
  3. 메모가 서류철에 인수인계로 도착하면(도장 시작 전) 메모를 열어 새 팀원 시작을 누릅니다. 리드가 옛 팀원을 끝낸 뒤 같은 이름으로 새 팀원을 띄우고, 메모를 첫 지시로 줍니다. 새 팀원은 옛 팀원의 기억이 없습니다.
  4. 옛 팀원은 층 오른쪽 아래 전임자 서랍(접힘)에 이름과 퇴사 시각(알 수 있으면 시작 시각도)만 남습니다. 대화 기록은 지우지 않습니다.

빌딩 이름과 빌딩 정보

빌딩 지붕의 간판은 처음에 User의 회사입니다. 간판을 누르면 빌딩 정보 창이 열립니다.

  • 이름: 1~40자로 바꾸고 저장을 누르면 간판이 바뀝니다(예: Acme로 저장하면 Acme의 회사). 이 이름은 대시보드 설정이고, 컴퓨터 계정 이름과는 관계가 없습니다. 설치 폴더의 building.json(본인만 읽을 수 있는 파일)에 저장합니다.
  • 정보: 위쪽 막대와 같은 숫자(오늘 토큰과 캐시 읽기, 최근 5시간·최근 7일 토큰, 5H·WEEK·PLAN 잔여), 층과 팀원 수, 서버와 화면 버전을 한곳에 모아 보여 줍니다.
  • PLAN 잔여가 비어 있으면 그 아래에 이유가 한 줄 보입니다. 상태줄 연결을 켜지 않았으면 PLAN 잔여는 Claude Code가 상태줄에 넘겨 주는 값입니다. 이 설치본은 상태줄 연결이 꺼져 있어 받지 못합니다. 켜려면 설치 스크립트를 --statusline을 붙여 다시 실행하세요., 연결했지만 값이 오지 않으면 PLAN 잔여는 Claude Code가 상태줄에 넘겨 주는 값입니다. Pro·Max 요금제나 지출 한도가 있는 gateway에서만 오고, 이 계정에는 오지 않습니다.입니다.

위쪽 막대의 숫자

  • 토큰: Claude가 읽고 쓴 글자의 양입니다. 오늘·최근 5시간·최근 7일 합계가 보입니다.
  • 에이전트마다 모델과 토큰: 캐릭터 이름표 아래에 그 에이전트가 마지막으로 답한 모델(Opus 5.5)과 쓴 토큰 합계(1.20M)가 두 줄로 늘 보입니다. 캐릭터를 누르면 열리는 패널의 모델·토큰 절에서 입력·출력·캐시 쓰기·캐시 읽기로 나눈 값과, 세션 중에 모델을 바꿨다면 모델별 합계를 볼 수 있습니다. 합계에는 캐시 읽기를 넣지 않습니다.
  • 결정 대기 N: 대시보드에서 답을 기다리는 결정 수입니다. 누르면 가장 오래 기다린 결정의 보고서가 열립니다.
  • 권한 정책 N: 정해 둔 권한 정책의 대상 수입니다. 누르면 정책 목록이 열립니다(위 "권한 정책").
  • PLAN 바: 요금제 사용 한도 가운데 남은 %를 보여 줍니다. Claude Code가 상태줄에 넘겨 주는 값이라, 설치할 때 상태줄 연결을 켜야 채워집니다(3장). 연결을 켜지 않았으면 -- statusline 연결이 꺼져 있음(다시 설치할 때 켤 수 있음), 연결했지만 요금제가 값을 주지 않으면 -- 요금제가 알려 주지 않음으로 보입니다. 값은 Pro·Max 요금제나 지출 한도가 있는 gateway에서만 옵니다. Windows에서는 상태줄 연결을 지원하지 않습니다.

6. 문제가 생겼을 때

먼저 환경 점검(doctor)을 해 보세요

claude-office doctor

항목마다 ✅(정상), ⚠️(확인 필요), ❌(문제) 가운데 하나가 붙고, ⚠️·❌ 아래에는 → 고치는 법이 한 줄 나옵니다. 그대로 따라 해 보세요.

예: Claude Code를 한 번도 실행하지 않은 컴퓨터

❌ Claude 데이터 폴더: 없음 또는 읽을 수 없음
  → Claude Code를 한 번 실행한 뒤 다시 확인해 주세요.

진단 파일을 만들어 보내 주세요

고쳐지지 않으면 진단 파일을 만들어 담당자에게 보내 주세요. 진단 파일은 문제를 찾는 데 필요한 정보만 담은 파일 하나입니다. 대화 내용, 이름, 비밀값은 들어가지 않습니다. 폴더 이름도 <project-1>처럼 번호로 바뀝니다.

방법 1. 화면에서

  1. 위쪽 막대의 진단을 누릅니다.
  2. 패널 맨 아래 진단 파일 만들기를 누릅니다. 잠시 만드는 중…으로 바뀝니다.
  3. 받기를 눌러 파일을 내려받습니다.

진단 파일을 만들었습니다 아래에 파일 위치(예: ~/.claude-office/diagnostics/claude-office-diag-20261001-093000.json)와 받기 단추가 보입니다.

"진단 파일을 만들지 못했습니다. 잠시 뒤 다시 눌러 주세요. 계속 안 되면 터미널에서 claude-office diag를 실행해 주세요."가 나오면 아래 방법 2를 써 주세요.

방법 2. 터미널에서:

claude-office diag
진단 파일을 만들었습니다: /Users/<사용자 이름>/.claude-office/diagnostics/claude-office-diag-20261001-093000.json
이 파일을 담당자에게 보내 주세요. 대화 내용, 이름, 비밀값은 들어 있지 않습니다.

만들어진 파일(claude-office-diag-…json)을 메일이나 메신저로 담당자에게 보내면 됩니다.

결정 버튼을 눌렀는데 "이미 터미널에서 답했습니다"가 떠요

같은 질문이 Claude Code 창에도 떠 있고, 먼저 답한 쪽이 적용됩니다. 이 안내는 Claude Code 창에서 먼저 답한 뒤 대시보드에서 눌렀을 때 나옵니다. 대시보드에서 누른 답은 적용되지 않았고, 아무 문제도 생기지 않았습니다. 비슷한 안내로 다른 창에서 이미 답했습니다(대시보드를 연 다른 브라우저 창에서 먼저 답함)와 시간이 지나 터미널로 넘어감(10분이 지남)이 있습니다. Claude Code 창에 남은 질문이 있으면 그 창에서 답해 주세요.

Claude Code 창에서 허용한 경우에는 그 작업이 끝날 때까지(드물게 더 오래) 대시보드에 요청이 남아 있을 수 있습니다. 그 사이에 대시보드에서 누르면 이 안내 대신 대시보드에서 허용함·대시보드에서 거부함이 보일 수 있지만, 이때도 대시보드의 답은 적용되지 않습니다. 실제로 적용된 답은 Claude Code 창의 답입니다.

대시보드가 "터미널에서 claude-office로 열어 주세요"라고 해요

대시보드는 접속 열쇠를 가진 브라우저에서만 열립니다. 다른 웹페이지가 여러분 대신 허용을 누르지 못하게 하려는 것입니다. 다음 경우에 이 화면이 나옵니다.

  • 주소창에 http://127.0.0.1:4317을 직접 입력했는데, 그 브라우저로 한 번도 claude-office를 통해 연 적이 없을 때
  • 브라우저의 쿠키를 지웠거나, 개인정보 보호(시크릿) 창일 때
  • 다른 브라우저로 열었을 때

터미널에서 claude-office를 한 번 더 실행하면 열쇠가 담긴 주소로 다시 열립니다. 그 뒤로는 북마크로 열립니다.

claude-office

브라우저가 안 열리고 터미널에 주소가 나왔어요

claude-office가 브라우저를 열지 못하면 터미널에 열쇠가 담긴 주소를 보여 줍니다. 그 주소를 복사해 브라우저 주소창에 붙여 넣습니다.

브라우저를 열지 못했습니다. 이 주소를 브라우저에 붙여 넣어 주세요: http://127.0.0.1:4317/?k=…
이 주소는 열쇠입니다. 남에게 보내지 마세요.

실제 화면에서는 ?k= 뒤에 긴 영문·숫자가 이어집니다. 그 부분까지 한 줄 전체를 복사해야 합니다.

이 주소는 열쇠입니다. 남에게 보내지 마세요. 화면 공유나 화면 캡처, 터미널 내용을 붙여 넣을 때도 이 줄이 보이지 않게 해 주세요.

결정 보고서가 열리지 않거나, 바로 "시간이 지나 터미널로 넘어감"이 돼요

doctor의 결정 대기 시간 줄을 확인해 주세요. 플러그인이 대시보드의 답을 기다리는 시간입니다.

⚠️ 결정 대기 시간: 5초 — 대시보드에서 답하려면 플러그인을 업데이트해 주세요처럼 600초가 아니면, 그 아래 고치는 법대로 터미널에서 claude plugin update claude-office@claude-office를 실행한 뒤 Claude Code를 다시 엽니다. 이전 버전 위에 새 버전을 설치했는데 플러그인이 옛 버전으로 남았을 때 나옵니다(설치 스크립트가 이 명령을 대신 실행하지만, 실패했을 수 있습니다). 대시보드 열쇠 줄이 없음이면 claude-office를 다시 켜면 만들어집니다.

대시보드를 끄고 싶은데 끌 창이 없어요

Claude Code 안에서 !로 켰거나, 켠 터미널 창을 이미 닫은 경우입니다. 대시보드는 창 없이 계속 돌아갑니다. 새 터미널 창을 열고 아래 한 줄을 실행하면 4317 포트를 쓰는 대시보드가 꺼집니다(macOS·Linux).

lsof -ti :4317 | xargs kill

Windows(PowerShell)에서는 Get-NetTCPConnection -LocalPort 4317 | ForEach-Object { Stop-Process -Id $_.OwningProcess }를 실행합니다. 그다음 일반 터미널 창에서 claude-office를 켜 주세요.

새 버전을 설치했는데 화면이 그대로예요 / 결정 버튼이 없어요

예전에 켠 이전 버전(베타) 대시보드가 아직 돌아가고 있는 것입니다. 이때 claude-office를 실행하면 아래처럼 나오고 끝납니다.

이 창을 닫으면 대시보드가 꺼집니다.
이전 버전 대시보드가 켜져 있습니다. 그 대시보드를 켠 터미널 창에서 Ctrl+C를 누르거나 그 창을 닫은 뒤, claude-office를 다시 실행해 주세요. 창이 보이지 않으면(Claude Code 안에서 !로 켠 경우) 사용설명서 6장 "끌 창이 없어요"를 보세요.

새 버전을 설치한 직후라면 대시보드 화면 위쪽에 노란 띠로도 알려 줍니다: 새 버전이 설치됐습니다. 대시보드를 껐다 다시 켜 주세요(지금 화면은 새 버전, 서버는 이전 버전입니다). 이 띠가 보이는 동안은 정책 저장 같은 일이 "저장하지 못했습니다"로 실패할 수 있습니다. 대시보드를 껐다 켜면 사라집니다.

  1. 이전 버전 대시보드를 켜 둔 터미널 창을 찾아 Ctrl+C를 누르거나 그 창을 닫습니다. 창이 없으면 아래 "끌 창이 없어요"대로 합니다.
  2. 새 터미널에서 claude-office를 다시 실행합니다.
  3. 이때 브라우저에 옛 화면이 함께 열렸을 수 있습니다. 그 탭의 주소창에 ?k=로 시작하는 열쇠가 보였다면 그 탭을 닫아 주세요.

doctor에 hook 실행·hook 열쇠·hook 전달 경고가 나와요

beta.14부터 플러그인은 설치할 때 기록한 Node.js로 작은 중계 프로그램을 실행하고, 열쇠 파일(~/.claude-office/hook.key)로 암호화해 대시보드에 보냅니다. 이 길이 막히면 말풍선과 손들기가 보이지 않고, Claude Code는 평소처럼 Claude Code 창에서 묻습니다. doctor가 알려 주는 줄과 대처는 아래와 같습니다.

❌ hook 실행: hook을 실행할 node가 없습니다(nvm 등으로 바뀜) — 다시 설치하세요
  → 설치 스크립트로 다시 설치한 뒤, 열려 있는 Claude Code 창에서 /reload-plugins를 실행하거나 창을 다시 열어 주세요.

설치할 때 쓴 Node.js가 지워졌거나 옮겨졌습니다(예: nvm으로 버전을 바꿈). 지금 쓰는 Node.js로 설치 스크립트를 다시 실행합니다. hook 설정에 Node.js·열쇠 경로가 적혀 있지 않습니다가 나와도 같은 방법입니다.

⚠️ hook 실행: 옛 플러그인(http hook)입니다

옛 버전의 플러그인이 남아 있습니다. 같은 압축 파일로 다시 설치합니다(부록 A).

❌ hook 열쇠: 다른 계정의 파일입니다(hook을 받지 않음)
  → 설치 폴더의 hook.key를 지운 뒤 claude-office를 다시 켜 주세요. 지울 수 없으면 컴퓨터 관리자에게 문의해 주세요.

열쇠 파일이 내 계정의 것이 아니면 대시보드는 hook을 받지 않습니다. 내가 만들지 않은 파일이면 컴퓨터 관리자에게 알려 주세요.

⚠️ hook 전달: 최근 24시간 실패 3건

플러그인이 대시보드의 답을 확인하지 못한 횟수입니다. 다른 설치본의 대시보드가 켜져 있으면 늘어납니다. 그 대시보드를 끄고 이 설치본의 claude-office로 다시 켭니다. 그래도 늘어나면 같은 압축 파일로 다시 설치합니다. 이때 ⚠️ 실시간 이벤트: 다른 설치본의 대시보드가 켜져 있어 확인하지 못했습니다(열쇠가 다름)도 함께 나올 수 있습니다.

설치 스크립트가 플러그인 hook 설정(node·열쇠 경로)을 쓰지 못해 설치를 멈춥니다로 끝났다면, 압축 파일을 새 폴더에 다시 풀고 그 폴더에서 설치 스크립트를 다시 실행합니다. 그래도 같으면 진단 파일을 만들어 보내 주세요(바로 아래 줄 자세한 기록: …의 기록 파일이 함께 들어갑니다). 이 단계는 플러그인을 Claude Code에 등록하기 전이라 Claude Code 쪽은 바뀌지 않았습니다. 전에 설치한 플러그인이 있으면 그 플러그인이 그대로 돕니다.

"같은 사용자 계정의 프로그램만 접속할 수 있습니다"가 떠요(Linux)

Linux에서는 대시보드가 같은 사용자 계정의 프로그램이 보낸 접속만 받습니다. 여러 사람이 함께 쓰는 컴퓨터(서버)에서 다른 계정의 프로그램이 가짜 권한 요청을 띄우거나 여러분의 답을 받아 가지 못하게 하려는 것입니다. 다른 계정으로 접속하면 브라우저나 프로그램에 아래 글이 보이고 거절됩니다.

같은 사용자 계정의 프로그램만 접속할 수 있습니다
  • 다른 계정(예: sudo로 다른 사용자가 되어 연 브라우저나 Claude Code)에서 연 경우: 대시보드를 켠 계정으로 다시 열어 주세요.
  • 다른 컨테이너(Docker 등 네트워크가 따로 떨어진 곳)에서 접속한 경우: 같은 계정이어도 대시보드가 접속한 쪽을 확인할 수 없어 거절됩니다. 대시보드와 Claude Code를 같은 곳에서 실행해 주세요. 이 검사를 끄는 설정은 없습니다.
  • 막은 접속은 환경 점검(doctor)이 셉니다. 실시간 이벤트 줄의 원래 판정 뒤에 붙고, 여러 사람이 쓰는 컴퓨터라면 정상입니다. 
    ⚠️ 실시간 이벤트: 최근 10분 4건. 다른 계정의 접속 3건을 막았습니다. 여러 사람이 쓰는 컴퓨터라면 정상입니다.
  • macOS와 Windows에서는 이 검사를 하지 않습니다.

정책을 정했는데 안 막혀요

위에서부터 하나씩 확인해 주세요.

  1. 대시보드가 켜져 있나요? 정책은 대시보드가 켜져 있을 때만 적용됩니다. 위쪽 막대가 ● LIVE인지 보세요. 대시보드가 꺼져 있으면 Claude Code는 아무 표시 없이 평소처럼 일합니다(옛 플러그인이 남은 창에서는 connect ECONNREFUSED 127.0.0.1:4317이 보입니다). 대시보드를 끈 사이에 한 일은 막지 못합니다.
  2. [저장]을 눌렀나요? 패널에서 고르기만 하고 닫으면 적용되지 않습니다. 정책 목록에 그 이름과 요약이 보이면 저장된 것입니다. 저장할 때 이미 실행 중이던 도구는 막지 않습니다. 다음 도구부터입니다.
  3. 정책 목록이 통째로 비었나요? 정해 둔 정책 파일이 깨졌거나 읽을 권한이 없으면(파일을 손으로 고친 경우 등) 대시보드는 정책이 없는 상태로 켜집니다. 이때는 정책 목록 맨 위에 정책 파일을 읽지 못했다는 경고가 보이고, 위쪽 막대의 권한 정책 단추에도 표시가 붙습니다. 환경 점검(doctor)에서는 이렇게 나옵니다. 
    ⚠️ 프로그램 파일: 권한 정책 파일을 읽지 못함
  → 저장해 둔 권한 정책 파일을 읽지 못했습니다. 대시보드는 정책이 없는 상태로 켜집니다. 위쪽 막대의 "권한 정책"에서 다시 정해 주세요.
    정책을 다시 정해 [저장]하면 됩니다. 읽지 못한 파일은 처음 저장할 때 policy.json.broken이라는 이름으로 남으니, 진단 파일과 함께 담당자에게 보내 주세요.
  4. 이름이 같나요? 정책은 이름에 붙습니다. 미리 추가한 이름이 화면의 이름표와 대소문자까지 같은지 보세요. 서브에이전트는 종류 이름(예: Explore)입니다. 리드에는 "그 밖의 모든"이 적용되지 않습니다.
  5. 다른 묶음의 도구로 같은 일을 하지 않았나요? 명령 실행을 금지해도 파일 고치기나 외부 도구(MCP)로 파일을 바꿀 수 있습니다. 패널의 횟수(켠 뒤로 금지 …번)가 늘지 않았다면 정책에 걸린 도구를 쓰지 않은 것입니다. 막고 싶은 묶음을 모두 금지하거나 읽기 전용을 쓰세요.
  6. 환경 점검(doctor)을 해 보세요. 정책이 있는데 Claude Code의 소식이 대시보드에 닿지 않으면 아래처럼 고치는 법 맨 앞에 알려 줍니다. 그 줄대로 따라 하세요. 회사 PC라면 관리자 설정 때문일 수 있습니다(부록 A). 
    ⚠️ 실시간 이벤트: 받은 이벤트 0건
  → 권한 정책이 적용되지 않고 있습니다. Claude Code 세션에서 아무 작업이나 해 보세요. 그래도 0건이면 플러그인과 회사 관리자 설정 항목을 확인해 주세요. 그래도 안 되면 회사 관리자에게 사용설명서 부록 A를 전달해 주세요.

에이전트가 갑자기 아무것도 못 해요

에이전트가 일을 멈추거나 "할 수 없다"고 말하면 권한 정책 때문일 수 있습니다.

  1. 캐릭터를 보세요. 책상에 자물쇠가 있고 말풍선에 정책으로 막힘: …이 보였다면 정책이 막은 것입니다. 패널의 켠 뒤로 금지 …번도 늘어 있습니다.
  2. 정책 목록에서 그 이름을 찾으세요. 이름이 없으면 그 밖의 모든 팀원·서브에이전트 줄을 보세요. 패널에 정한 것이 없어 "그 밖의 모든"을 따릅니다가 보이면 그 줄의 정책이 적용된 것입니다. 다른 프로젝트에서 같은 이름에 정해 둔 정책일 수도 있습니다.
  3. 모든 도구가 금지인지 보세요. 그러면 파일 읽기까지 막혀 거의 아무것도 못 합니다(사용자에게 묻기와 팀원끼리 연락은 됩니다).
  4. 풀려면 그 이름의 패널(또는 목록의 고치기)에서 제한 없음을 누르고 [저장]을 누르세요. 목록에서 지우기를 해도 됩니다. 다음 도구부터 풀립니다. 다만 팀원·서브에이전트는 지우면 "그 밖의 모든"을 따르므로, 거기 정한 정책도 함께 확인하세요.
  5. Claude에게 다시 해 보라고 말해 주세요.

설치할 때 "이미 다른 파일이 있는 폴더입니다"가 나와요

이미 다른 파일이 있는 폴더입니다. 빈 폴더나 새 폴더 이름을 지정해 주세요.

설치할 폴더에 이 프로그램이 만들지 않은 파일이 이미 있어서, 그 파일을 지우지 않으려고 설치를 멈춘 것입니다. 다른 폴더를 쓰려면 설치 명령 끝에 --prefix와 새 폴더 이름을 붙입니다(예: sh install.sh --prefix ~/claude-office-beta). 판단이 어려우면 진단 파일 대신 이 화면을 담당자에게 보내 주세요.

설치(또는 제거)가 질문에 답할 틈 없이 '아니오'로 끝났어요

마지막에 아래 안내가 나왔다면, 질문에 답을 입력할 수 없는 곳에서 실행한 것입니다. 예를 들어 Claude Code 안에서 !로 명령을 실행하면 질문에 답할 수 없어서, 모든 질문을 "아니오"로 처리합니다.

입력을 받을 수 없어 '아니오'로 처리했습니다. 설치하려면 --yes를 붙여 다시 실행하세요.

Windows 설치와 제거에서는 이렇게 나옵니다.

  • Windows 설치: 입력을 받을 수 없어 '아니오'로 처리했습니다. 설치하려면 -Yes를 붙여 다시 실행하세요.
  • 제거(모든 운영체제, claude-office uninstall): 입력을 받을 수 없어 '아니오'로 처리했습니다. 제거하려면 --yes를 붙여 다시 실행하세요.

보통의 터미널 창에서 다시 실행하면 질문에 직접 답할 수 있습니다. 모든 질문에 "예"로 답하려면 아래처럼 실행합니다. 이 명령은 PATH 추가와 Claude Code 플러그인 설치에 모두 동의합니다.

macOS·Linux 설치(압축 푼 폴더 안에서):

sh install.sh --yes

Windows 설치(압축 푼 폴더 안에서, Windows 화면은 베타에서 확인 전입니다):

powershell -ExecutionPolicy Bypass -File .\install.ps1 -Yes

제거(모든 운영체제). 로그와 진단 파일까지 지워지니, 담당자에게 보낼 진단 파일이 있다면 먼저 보내 주세요:

claude-office uninstall --yes

멈춤으로 했는데 계속 답해요

멈춤은 도구만 막습니다. 아래는 고장이 아닙니다.

  1. 멈추기 직전에 쓰던 답이 끝까지 나옵니다.
  2. Claude Code 창(터미널)에 직접 말을 걸면 대답합니다. 다만 도구(명령 실행, 파일 고치기 등)를 쓰려 하면 대시보드 일시정지: … 문장을 받고 멈춥니다.
  3. 질문, 계획 승인 요청, 팀원끼리 메시지는 멈춘 층에서도 오갑니다.
  4. 칩 옆의 · 막힌 호출 N이 늘고 있으면 멈춤이 제대로 막고 있는 것입니다.
  5. 칩이 영업 중으로 돌아와 있고 도구가 계속 실행된다면, 대시보드를 껐다 켰는지 보세요. 다시 켜면 모든 층이 영업 중으로 돌아옵니다. 대시보드가 꺼져 있는 동안에는 멈춤이 적용되지 않습니다(4장 "끄기").

끄기를 눌렀는데 안 꺼져요

  1. 칩이 종료 중인가요? 끄기 신호는 보냈고 Claude Code가 끝나는 중입니다. 10초가 지나면 강제로 끌지 묻는 창이 뜹니다. 그 창을 닫았다면 종료를 다시 누르면 열립니다.

  3. 이미 끝난 층입니다.가 나왔나요? 이미 꺼졌습니다. 화면이 최대 3초 늦게 바뀝니다.
  4. 강제로 끈 층은 세션 기록이 남아 끝난 층(종료됨 HH:MM)으로 보이는 것이 정상입니다. 필요 없으면 숨기기로 목록에서 빼세요. 강제로 끈 뒤에도 칩이 종료 중으로 남아 있으면 진단 파일을 만들어 보내 주세요.

질문이 안 뜨고 설치가 안 돼요(Windows)

8. 부록 A: 회사 관리자에게 전달할 설정

이 절은 회사의 Claude Code 관리자에게 그대로 전달하는 내용입니다.

관리자님께

Claude Agent Office는 직원 PC 안에서만 동작하는 대시보드입니다. 플러그인 claude-office@claude-office는 Claude Code의 hook 이벤트를 같은 PC의 127.0.0.1:4317로 보냅니다. 외부로는 아무것도 보내지 않습니다. beta.14부터 hook은 command hook입니다. 설치할 때 기록한 Node.js 절대 경로로 플러그인 안의 작은 중계 프로그램(hooks/relay.cjs, Node.js 내장 기능만 씀)을 실행합니다. 이 프로그램은 이벤트를 직원 본인만 읽을 수 있는 열쇠 파일(~/.claude-office/hook.key)로 암호화해 보내고, 같은 열쇠로 암호화된 답만 받아들입니다. 대시보드에 닿지 못하거나 무엇이든 실패하면 아무것도 돌려주지 않고 끝나므로, Claude Code의 평범한 권한 창이 결정합니다. beta.13 이하의 플러그인은 HTTP hook으로 http://127.0.0.1:4317/hooks/event에 보냅니다.

결정을 돌려줍니다. 플러그인의 PermissionRequest hook은 최대 600초(10분) 동안 응답을 기다렸다가, 직원이 대시보드에서 누른 결정(권한 허용·거부, 질문 답, 예산 계속·중단)을 돌려줍니다. 직원이 누르지 않으면 아무것도 돌려주지 않고 Claude Code의 평범한 권한 창이 결정합니다. 자동 허용은 없습니다. 다른 hook의 timeout은 10초입니다. 대시보드가 5초 안에 답하지 않으면 플러그인이 먼저 결정 없이 끝냅니다.

예산에 닿은 층에서는 확인을 요청합니다. 그 층의 PreToolUse hook에 "ask"(확인 요청)를 돌려줘, Claude Code가 권한 창을 띄우게 합니다. 허용하는 것이 아니라 묻게 하는 것입니다. PermissionRequest 외에 결정을 돌려주는 hook은 이 PreToolUse 하나이고, 여기서 돌려주는 것은 이 예산 확인과 아래 에이전트별 권한 정책("deny"·"ask")뿐입니다.

관리자 설정(managed settings)에 다음이 필요합니다.

설정필요한 값언제
allowedHttpHookUrls"http://127.0.0.1:4317/*"를 목록에 추가이 목록을 쓰고 있을 때. 사용자가 이전 버전의 플러그인(http hook)을 쓰는 동안만 필요합니다. beta.14 플러그인은 command hook을 써서 필요 없습니다.
allowManagedHooksOnly켜 두려면 enabledPlugins에서 "claude-office@claude-office": true로 플러그인을 관리자가 활성화이 값이 true일 때
enabledPlugins"claude-office@claude-office": true위와 같음

예시(기존 설정에 합쳐 주세요):

{
  "allowedHttpHookUrls": ["http://127.0.0.1:4317/*"],
  "enabledPlugins": { "claude-office@claude-office": true }
}

관리자 설정 파일 위치:

  • macOS: /Library/Application Support/ClaudeCode/managed-settings.json
  • Linux: /etc/claude-code/managed-settings.json
  • Windows: C:\Program Files\ClaudeCode\managed-settings.json

MDM 등 다른 방식으로 정책을 배포한다면 같은 키를 그 방식으로 넣어 주세요. 플러그인 마켓플레이스는 각 직원 PC의 설치 폴더 ~/.claude-office/plugin(Windows는 %USERPROFILE%\.claude-office\plugin)에 있습니다.

이 설정은 베타에서 검증하지 못했습니다. 관리자는 IT 시험 PC에서 먼저 확인해 주세요. 특히 allowManagedHooksOnly가 켜진 경우 PermissionRequest hook도 막혀 대시보드에서 답할 수 없으며, 이 경우는 검증하지 못했습니다.

접속 열쇠 파일: ~/.claude-office/token(Windows는 %USERPROFILE%\.claude-office\token). 무작위 32바이트이고, macOS·Linux에서는 본인만 읽을 수 있게(0600) 둡니다. 대시보드의 쓰기 요청은 이 열쇠의 쿠키, 같은 출처, JSON 형식을 모두 요구합니다. 열쇠 값은 로그와 진단 파일에 남지 않습니다. 같은 PC의 명령줄 도구(claude-office doctor, claude-office diag)는 이 열쇠 파일을 읽어 Authorization 헤더로 보냅니다. 열쇠 없이 먼저 물어 이 프로그램(이전 버전 포함)의 서버로 확인된 경우에만 보냅니다. Windows에서 설치 폴더를 사용자 프로필(%USERPROFILE%) 밖으로 바꾸면, 열쇠 파일을 본인만 읽을 수 있는지 확인할 수 없습니다. 기본 위치를 권합니다.

에이전트별 권한 정책. 직원이 대시보드에서 에이전트 이름마다 도구 묶음을 금지하거나 항상 질문하게 정할 수 있습니다. 플러그인의 PreToolUse hook에 "deny"(막기) 또는 "ask"(확인 요청)를 돌려줍니다. 허용("allow")은 어떤 경로로도 돌려주지 않습니다. 정책 파일에 allow가 있어도 그 규칙은 무시합니다.

  • 대시보드가 켜져 있을 때만 적용됩니다. hook이 서버에 닿지 못하면 Claude Code는 원래 규칙대로 진행합니다(플러그인이 결정 없이 끝남). 보안 통제로 쓰지 마세요.
  • 같은 이름이면 다른 프로젝트·다른 세션에서도 같은 정책입니다.
  • 도구 이름으로만 가릅니다. 명령 내용·파일 경로는 보지 않습니다.
  • 이미 실행 중인 도구에는 적용되지 않습니다.
  • 가짜 hook은 정책을 느슨하게 만들 수 없습니다(정책은 막거나 묻게만 합니다). 위의 가짜 hook 위험은 그대로입니다.
  • 플러그인이 설치되지 않았거나 회사 관리자 설정이 hook을 막으면 적용되지 않습니다.

정책을 적용하지 않는 도구(사용자에게 묻기·팀 통신·서브에이전트 결과 돌려주기): AskUserQuestion, ExitPlanMode, SendMessage, TaskCreate, TaskUpdate, TaskList, TaskGet, SubagentHandback, TaskStop.

저장 위치는 ~/.claude-office/policy.json(Windows는 %USERPROFILE%\.claude-office\policy.json)이고, macOS·Linux에서는 본인만 읽을 수 있게(0600) 둡니다. 처음 저장할 때 생기고, 업그레이드해도 그대로 남습니다. 손으로 고친 파일이 깨져 있으면 다음 저장 전에 policy.json.broken으로 옮겨 보존합니다. 제거하면 둘 다 지웁니다. 대시보드가 켜져 있는 동안 이 파일을 손으로 고치면 반영되지 않고, 화면에서 정책을 저장할 때 덮어써집니다. 손으로 고치려면 대시보드를 끈 뒤에 고쳐 주세요. 파일을 읽지 못하면 빈 정책으로 시작하고, 로그에 src가 policy인 policy unreadable, starting empty 경고가 남습니다(같은 경고는 10분에 한 줄). 이때 화면의 정책 목록 맨 위와 doctor의 프로그램 파일 항목에 알림이 나옵니다.

로그에는 판정 한 건마다 결과(deny/ask), 묶음, 대상 종류(리드·팀원·서브에이전트·그 밖)만 남습니다. 에이전트 이름과 도구 입력은 남지 않습니다. 진단 파일에는 개수(대상 수, 종류별 규칙 수, 판정 수)만 들어갑니다.

팀원을 별도 터미널 창(tmux·iTerm 분할)으로 띄우는 방식에서는 확인 전입니다.

층 관리(멈춤·종료·숨기기). 직원이 대시보드에서 세션을 멈추거나 끄거나 목록에서 숨길 수 있습니다.

  • 멈춤: 그 세션의 PreToolUse hook에 "deny"를 돌려줍니다(권한 정책보다 먼저 판정). 권한 정책에서 빼는 도구와 같은 아홉 개는 통과합니다. 대시보드 서버 메모리에만 있어 서버를 다시 켜면 풀리고, 서버가 꺼져 있으면 적용되지 않습니다(플러그인이 결정 없이 끝남). 보안 통제로 쓰지 마세요.
  • 종료: 대시보드 서버가 그 세션의 Claude Code 프로세스에 SIGTERM을, 직원이 한 번 더 확인하면 SIGKILL을 보냅니다. 보내기 전에 세션 기록의 프로세스 번호와 시작 시각이 지금 프로세스와 같은지 확인하고, 확인할 수 없으면 보내지 않습니다(Windows는 늘 보내지 않습니다). 서버 자신에게는 보내지 않습니다.
  • 숨기기: 대시보드 목록에서만 숨깁니다. ~/.claude의 세션 기록 파일은 읽기만 하고 지우거나 고치지 않습니다. 숨김도 서버 메모리에만 있습니다.
  • 로그에는 floors 줄로 동작 이름(pause·resume·paused-deny·terminate·hide·unhide), 세션 순번(세션 id가 아니라 대시보드가 처음 본 순서), 도구 이름, 신호 이름만 남습니다. 실패하면 terminate failed(세션 순번·신호 이름·오류 코드), pause check failed·poke failed(오류 코드만) 줄이 남습니다. 명령·경로·도구 입력은 남지 않습니다. 진단 파일에는 지금 멈춘·숨긴·종료 중인 층의 수만 들어갑니다.

열쇠의 남은 위험: claude-office가 브라우저를 여는 순간, 열쇠가 붙은 주소가 잠깐 프로세스 목록에 보일 수 있습니다(같은 PC의 다른 사용자가 볼 수 있음). 또 브라우저가 열쇠가 붙은 첫 주소를 내부 방문 기록에 남길 수 있습니다. 열쇠를 새로 만들려면 대시보드를 끄고 열쇠 파일(~/.claude-office/token)을 지운 뒤 claude-office를 다시 실행합니다.

옛 hook 입구는 인증하지 않습니다(판정). beta.14부터 플러그인은 열쇠 파일로 암호화한 hook만 보내고, 대시보드는 그 열쇠가 없는 프로그램이 보낸 새 방식의 hook을 받지 않습니다. 다만 beta.14 대시보드는 옛 플러그인을 위해 암호화하지 않은 옛 입구도 함께 받습니다. hook은 결정을 "요청"할 뿐이고, 허용을 만들어 내는 길은 열쇠로 인증된 대시보드 하나입니다. 같은 PC의 다른 프로그램(이 PC에 로그인한 다른 사용자의 프로그램도 포함, 127.0.0.1에 닿을 수 있는 모든 프로그램)이 옛 입구로 가짜 hook을 보내면 다음 일이 생길 수 있습니다. 이것이 남은 위험입니다.

  • 화면에 가짜 요청이 뜰 수 있습니다. 그 요청에 답해도 실제 Claude Code에는 영향이 없습니다.
  • 가짜 요청을 많이 보내 대기 요청 상한(50건)을 채우면, 그동안 진짜 요청은 대시보드를 거치지 않고 Claude Code 창에서만 묻습니다.
  • 세션 id를 아는 프로그램은 "끝났다"는 가짜 소식으로 대시보드의 진짜 요청을 닫을 수 있습니다. 그 요청은 Claude Code 창에 그대로 남으므로 거기서 답하면 됩니다.
  • 도구 호출 id를 아는 프로그램은 예산 관문의 "계속"을 흉내 낼 수 있습니다. 그러면 예산 확인을 한 번 건너뜁니다.

대시보드가 켜져 있는 동안에는 어느 경우에도 도구 허용을 만들어 내지는 못하고, Claude Code 창의 권한 창은 그대로 뜹니다. 대시보드가 꺼져 있을 때는 아래와 다릅니다. 여러 사람이 함께 쓰는 PC나 서버에 설치할 때는 이 점을 고려해 주세요. Linux에서는 다른 계정의 접속을 대시보드가 모두 거절하므로(6장) 다른 계정은 옛 입구도 쓸 수 없습니다.

또 같은 PC에서 4317을 먼저 차지한 프로그램은 그 확인 표시를 흉내 낼 수 있습니다. 그러면 doctor·diag를 실행할 때 열쇠가 그 프로그램으로 갈 수 있습니다(그동안 진짜 대시보드는 켜지지 못합니다).

대시보드가 꺼져 있을 때 다른 계정이 대신 답할 수 있던 문제는 beta.14부터 고쳤습니다. beta.14 플러그인은 hook 이벤트를 내 계정만 읽을 수 있는 열쇠 파일(~/.claude-office/hook.key)로 암호화해 127.0.0.1:4317로 보내고, 같은 열쇠로 암호화된 답만 받아들입니다. 그래서 대시보드가 꺼진 동안 같은 컴퓨터의 다른 계정이 그 포트에 자기 프로그램을 먼저 띄워도, 입력한 지시나 도구 입력과 결과를 읽을 수 없습니다. 권한 요청에 대신 답하거나 Claude가 읽는 대화에 글을 끼워 넣을 수도 없습니다. 이때 Claude Code는 평소처럼 Claude Code 창에서 묻습니다.

beta.13 이하, 또는 옛 플러그인이 남아 있는 동안에는 위험이 그대로입니다. 옛 플러그인은 hook 이벤트를 암호화하지 않고 보냅니다. 대시보드가 꺼져 있는 동안 같은 컴퓨터의 다른 계정(다른 사람의 계정이나, 다른 계정으로 도는 서비스 프로그램)이 그 포트에 자기 프로그램을 먼저 띄우면, 그 프로그램이 입력한 지시, 도구 입력과 결과(예: 명령, 파일 내용)를 받습니다. 그리고 권한 요청에 대신 답하고(권한 창 없이 바로 허용하거나 입력을 바꾸는 것까지), Claude가 읽는 대화에 글을 끼워 넣을 수 있습니다. 같은 컴퓨터에서 내 계정이 아닌 계정으로 도는 프로그램(다른 사람, 따로 계정을 쓰는 서비스)이 없으면 해당하지 않습니다.

beta.14를 설치해도, 설치 전부터 열려 있던 Claude Code 창은 /reload-plugins를 실행하거나 다시 열 때까지 옛 플러그인으로 보냅니다. 그동안 대시보드 위쪽 막대에 옛 플러그인(http hook)이 남아 있습니다 — 같은 압축 파일로 다시 설치하세요가 보입니다. 열린 창을 모두 다시 열었는데도 이 표시가 남아 있으면 같은 압축 파일로 다시 설치해 주세요.

옛 버전이나 옛 플러그인을 쓰는 동안의 대처:

  • 대시보드를 쓰지 않을 때는 플러그인을 끕니다: claude plugin disable claude-office@claude-office --scope user (다시 켜기: claude plugin enable claude-office@claude-office --scope user). 이미 열린 Claude Code 창은 /reload-plugins를 실행하거나 다시 열어야 적용됩니다.
  • 그렇지 않으면 Claude Code를 쓰는 동안 대시보드를 늘 켜 둡니다. 예를 들어 서비스로 띄웁니다(Linux라면 systemd --user 서비스 등).

모르는 프로그램이 4317을 쓰고 있다면 다른 포트로 켜지 말고, 무엇인지 확인한 뒤 비워질 때까지 플러그인을 꺼 두세요. 다른 프로그램이 포트를 쓰면 claude-office doctor가 ❌ 포트: 다른 프로그램이 4317을 쓰고 있습니다로 알려 줍니다.

9. 부록 B: 베타에서 알려진 제한

  • Windows와 Linux는 충분히 검증하지 못했습니다. 베타는 macOS에서 확인했습니다. 다른 운영체제에서 문제가 생기면 진단 파일을 보내 주세요.
  • PLAN 바(요금제 한도)는 상태줄 연결을 켠 경우에만 채워집니다(회사 좌석은 대부분 해당 데이터가 오지 않음). 연결하지 않았으면 -- statusline 연결이 꺼져 있음(다시 설치할 때 켤 수 있음), 값이 오지 않으면 -- 요금제가 알려 주지 않음으로 보입니다. Windows에서는 지원하지 않습니다.
  • 코드 서명이 없습니다. 그래서 macOS에서는 드물게 "확인되지 않은 개발자" 경고가 나올 수 있고, Windows에서는 실행 정책에 막힐 수 있습니다. 대처법은 3장과 6장에 있습니다.
  • 회사 관리자 정책(allowManagedHooksOnly 등)이 켜져 있으면, 관리자가 부록 A대로 설정하기 전까지 말풍선과 손들기가 보이지 않고 대시보드에서 답할 수도 없습니다. 빌딩, 층, 토큰 숫자는 그대로 보입니다.
  • 대시보드에서 답하기의 한계: 대시보드가 꺼져 있으면 Claude Code 창에서만 묻습니다. 권한 모드가 auto인 창은 일반 권한 요청이 대시보드에 드물게 뜹니다(예산 도달은 모드와 관계없이 뜸). 계획 승인과 팀원의 [결정 필요]는 대시보드에서 보기만 하고 Claude Code 창에서 답합니다. 대시보드의 결정은 10분(화면은 9:50부터) 뒤 Claude Code 창으로 넘어갑니다. 허용은 되돌릴 수 없습니다. Claude Code 창에서 먼저 답해도 대시보드에 요청이 잠깐 남을 수 있고, 그때 대시보드에서 누른 답은 화면에 어떻게 보이든 적용되지 않습니다.
  • 권한 정책은 대시보드가 켜져 있을 때만 적용됩니다. 보안 장치가 아니라 실수 방지 장치입니다(5장 "권한 정책"). Windows에서는 확인 전입니다.
  • 층 관리의 멈춤과 숨김은 대시보드를 다시 켜면 풀립니다. Windows에서는 대시보드에서 층을 끌 수 없습니다(5장 "층 관리").
  • 대시보드는 4317번 포트에서만 말풍선과 손들기가 동작합니다. 다른 번호로 켜면 빌딩과 숫자만 보입니다.
  • 로그인할 때 저절로 켜지지 않습니다. 볼 때마다 claude-office로 켜 주세요.
  • 로그와 진단 파일은 자동으로 보내지 않습니다. 여러분이 직접 만든 진단 파일만 담당자에게 전달됩니다. 실행 로그는 7일이 지나면 저절로 지워집니다(설치 기록은 남습니다).

10. 부록 C: beta.14 설치본 확인

beta.14는 플러그인이 대시보드와 이야기하는 방식을 바꿨습니다. 아래 아홉 가지는 실제 Claude Code 창이나 원격 컴퓨터에서만 확인할 수 있습니다. beta.14를 설치하고 Claude Code 창을 모두 새로 연 뒤, 대시보드를 켜고 차례로 해 봅니다. 기대와 다르면 진단 파일(6장)과 함께 알려 주세요.

  1. 정책이 막는지: 권한 정책에서 한 도구를 막음으로 정하고 Claude에게 그 도구를 쓰게 합니다. 기대: 도구가 실행되지 않고, Claude Code 창에 정책이 막았다는 문장이 보입니다.
  2. 대시보드의 허용·거부가 그대로 적용되는지: 권한 요청이 손들기로 뜨면 대시보드에서 허용해 보고, 다른 요청은 거부해 봅니다. 기대: 허용한 도구는 실행되고, 거부한 도구는 실행되지 않습니다. 대시보드에서 입력을 바꿔 허용하는 요청(예: 질문에 답하기)은 바꾼 입력으로 실행됩니다.
  3. Claude Code 창에서 먼저 답하면 손들기가 닫히는지: 손들기가 떠 있는 동안 Claude Code 창에서 먼저 답하거나 Esc를 누릅니다. 기대: 대시보드의 손들기가 사라집니다.
  4. 대시보드를 끄면 평소처럼 묻는지: 대시보드를 끈 채 권한이 필요한 도구를 쓰게 합니다. 기대: 아무 오류 표시 없이 Claude Code 창에서 평소처럼 묻습니다.
  5. 다른 hook과 함께 쓸 때: 다른 플러그인이나 설정 파일의 hook이 같은 도구에 함께 걸려 있을 때, 대시보드의 정책 거부가 그대로 막는지, 권한 요청의 답이 어느 쪽으로 정해지는지 봅니다. 설정 파일의 거부 규칙은 대시보드의 허용으로도 풀리지 않는 것이 맞습니다.
  6. 작업 폴더와 프로젝트: 여러 프로젝트 폴더에서 Claude Code를 켭니다. 기대: 대시보드의 층 이름과 말풍선이 각 프로젝트에 맞게 보입니다.
  7. 대화에 글이 끼어들지 않는지: 새 대화를 시작하고 프롬프트를 보냅니다. 기대: Claude가 대시보드나 플러그인에서 온 글을 받은 것처럼 말하지 않습니다.
  8. 원격 Linux에서 터널로 열기: 4장 "원격에서 보기"대로 원격 Linux 컴퓨터의 대시보드를 터널로 엽니다. 기대: 같은 사용자 계정의 프로그램만 접속할 수 있습니다 없이 대시보드가 열립니다.
  9. 먼저 답했을 때의 기록: claude --debug로 Claude Code를 켜고 3번을 다시 해 봅니다. 기대: 기록의 Hooks: 줄에 그 hook이 cancelled로 끝났다고 나오고, 대시보드의 손들기가 사라집니다.

정책이 막을 때 Claude Code 창에 붙는 앞말(PreToolUse:Bash hook error: 등, 5장)은 beta.14에서 다르게 보일 수 있습니다. 1번을 할 때 실제로 보인 글을 함께 알려 주세요.

11. 부록 D: 리드 기능 실제 세션 확인

리드와 일하는 기능(5장)은 리드가 정해진 방법을 따르는지에 달려 있어, 실제 Claude Code 세션에서만 확인할 수 있습니다. 실험 기능을 켜고 대시보드로 agent team 층을 하나 띄운 뒤 차례로 해 봅니다. 기대와 다르면 진단 파일(6장)과 함께 알려 주세요.

  1. 보고서가 오는지: 보고 요청을 누릅니다. 기대: 몇 분 안에 서류철에 보고서가 도착하고, 리드 책상에 서류철이 보입니다.
  2. 결재가 전해지는지: 한 보고서는 승인하고, 다른 보고서는 수정 사항을 적어 보냅니다. 기대: 리드가 승인과 수정 사항을 받아 그에 맞게 움직입니다.
  3. 리드가 질문 기능을 쓰는지: 리드가 여러분의 결정이 필요한 일을 하게 합니다. 기대: 리드 책상에 손들기와 노란 ?가 뜨고, 대시보드에서 고른 답대로 리드가 이어 갑니다.
  4. 대화 글로 물을 때: 리드가 대화 글로만 묻고 멈추면 기대: 답을 기다립니다가 보입니다. 터미널에서 답하면 사라집니다. 팀원이 움직여도 사라지지 않습니다.
  5. 팀원의 질문: 팀원이 질문을 보내게 합니다. 기대: 그 팀원 책상에 손들기가 뜨고, 답이 리드를 거쳐 그 팀원에게 갑니다.
  6. 멈춘 층에서 답하기: 질문이 떠 있는 층을 멈추고 답합니다. 기대: 답이 보관되고, 보내고 재개를 누르면 리드에게 전해집니다.
  7. 퇴근과 출근: 팀원 하나를 퇴근시킨 뒤 출근시킵니다. 기대: 퇴근하면 퇴근 팻말이 놓이고, 출근하면 같은 팀원이 이어서 일합니다.
  8. 새 팀원이 옛 기억을 모르는지: 팀원 하나를 퇴사시키고 새 팀원을 시작합니다. 기대: 같은 이름의 새 팀원이 앉고, 인수인계 메모 밖의 옛 대화 내용을 모릅니다.
  9. 팀원이 channel에 따로 연결하지 않는지: 팀원이 여럿 일하는 동안 리드에게 작업 지시와 보고 요청을 보냅니다. 기대: 지시가 늘 리드에게 가고, 리드의 연결이 끊기지 않습니다(층 머리의 작업 지시가 계속 켜져 있음).

    팀원인지는 Claude Code가 팀원 프로세스를 띄울 때 붙이는 내부 인자 세 개(--agent-id, --agent-name, --team-name, 공식 문서에 없음)가 모두 있는지로 가립니다. Claude Code 2.1.304에서 확인했습니다. Claude Code를 업데이트한 뒤에는 이 항목을 다시 확인해 주세요. 인자 이름이 바뀌면 이 판별은 꺼지고, 대시보드가 같은 층의 두 번째 연결을 받지 않는 규칙만 남습니다. 그때는 대시보드를 다시 켠 뒤 리드가 먼저 연결되어야 지시가 리드에게 갑니다.
