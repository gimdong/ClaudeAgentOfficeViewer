이 설명서에서 쓰는 말
터미널
글자로 컴퓨터에 명령을 내리는 창입니다. mac은 "터미널" 앱, Windows는 "PowerShell", Linux는 "터미널"을 씁니다.
명령
터미널에 붙여 넣고 Enter를 누르는 한 줄입니다. 이 설명서의 검은 상자가 명령이고, 오른쪽 복사 버튼으로 복사할 수 있습니다.
Claude Code
터미널에서 쓰는 Claude입니다. 이 프로그램은 Claude Code가 일하는 모습을 보여 줍니다.
대시보드
이 프로그램의 화면입니다. 웹 브라우저(Chrome, Safari, Edge 등)에서 열립니다.

1. 이 프로그램이 하는 일

Claude Code가 지금 무엇을 하고 있는지 작은 사무실 빌딩으로 보여 줍니다.

  • Claude Code 창 하나가 빌딩의 층 하나입니다.
  • Claude와 함께 일하는 도우미(팀원)는 층 안의 도트 캐릭터입니다.
  • 캐릭터 머리 위 말풍선에 지금 하는 일이 짧게 나옵니다.
  • Claude가 여러분의 확인을 기다리면 캐릭터가 손을 들고 머리 위에 노란 ?가 뜹니다.

이 프로그램은 여러분의 컴퓨터 안에서만 동작합니다. 대화 내용을 인터넷으로 보내지 않고, Claude Code의 설정을 읽기만 합니다.

2. 준비물

설치하기 전에 두 가지가 있어야 합니다.

  1. Claude Code가 설치되어 있고, 한 번 이상 실행해 본 적이 있어야 합니다. 터미널에서 아래 명령으로 확인합니다. 
    claude --version
    숫자로 된 버전이 한 줄 나옵니다(예: 2.1.0 (Claude Code)). "명령을 찾을 수 없습니다"가 나오면 Claude Code를 먼저 설치해 주세요.
  2. Node.js 24 이상이 있어야 합니다. Node.js는 이 프로그램을 움직이는 기본 프로그램입니다. 터미널에서 확인합니다. 
    node --version
    v24 이상으로 시작하는 한 줄이 나옵니다(예: v24.1.0).

    없거나 24보다 낮으면 운영체제에 맞게 설치합니다.

    macOS

    nodejs.org에서 LTS라고 적힌 설치 파일(.pkg)을 받아 두 번 눌러 설치합니다. 설치 뒤에는 터미널을 닫았다가 다시 열어 주세요.

    Linux(Ubuntu)

    회사 IT 담당자에게 "Node.js 24 설치"를 부탁하는 것이 가장 안전합니다. 직접 설치한다면 nodejs.org의 안내(NodeSource 또는 nvm)를 따릅니다.

    Windows

    nodejs.org에서 LTS라고 적힌 설치 파일(.msi)을 받아 설치합니다. 설치 뒤에는 PowerShell을 닫았다가 다시 열어 주세요.

3. 설치

담당자에게 받은 파일 하나로 설치합니다. 인터넷 연결은 필요 없습니다. 프로그램 파일은 여러분의 사용자 폴더 안(~/.claude-office, Windows는 C:\Users\<사용자 이름>\.claude-office)에만 둡니다. 그 밖에는 여러분이 동의할 때만 셸 설정 파일 한 곳(PATH 추가)과 Claude Code의 플러그인 목록을 바꿉니다.

macOS

  1. 받은 파일 claude-office-2.1.0-dev.tar.gz를 다운로드 폴더에 둡니다.
  2. "터미널" 앱을 엽니다(⌘+Space를 누르고 "터미널"을 입력).
  3. 아래 명령으로 파일을 풉니다. 
    cd ~/Downloads && tar -xzf claude-office-2.1.0-dev.tar.gz

    다운로드 폴더에 claude-office-2.1.0-dev 폴더가 생깁니다.

  4. 설치 스크립트를 실행합니다. 
    cd ~/Downloads/claude-office-2.1.0-dev && sh install.sh
  5. 질문 두 개에 답합니다(아래 "설치 중 질문").
드물게 "확인되지 않은 개발자" 경고가 나오면
베타 버전은 Apple의 서명을 받지 않아서 이 경고가 나올 수 있습니다. 담당자에게 받은 파일이 맞다면 시스템 설정 → 개인정보 보호 및 보안 아래쪽의 "그래도 열기"를 누른 뒤 같은 명령을 다시 실행합니다.

Linux(Ubuntu)

  1. 받은 파일 claude-office-2.1.0-dev.tar.gz를 다운로드 폴더에 둡니다.
  2. 터미널을 엽니다(Ctrl+Alt+T).
  3. 아래 명령으로 파일을 풀고 설치 스크립트를 실행합니다. 
    cd ~/Downloads && tar -xzf claude-office-2.1.0-dev.tar.gz && cd claude-office-2.1.0-dev && sh install.sh
  4. 질문 두 개에 답합니다(아래 "설치 중 질문").

Windows

  1. 받은 파일 claude-office-2.1.0-dev.zip을 다운로드 폴더에 둡니다(압축은 아래 명령이 풉니다).
  2. 시작 메뉴에서 PowerShell을 엽니다.
  3. 아래 명령으로 파일을 풀고 설치 스크립트를 실행합니다. -ExecutionPolicy Bypass는 "이번 한 번만 이 스크립트 실행을 허용"한다는 뜻이고, 컴퓨터 설정은 바꾸지 않습니다. 
    cd $HOME\Downloads; Expand-Archive claude-office-2.1.0-dev.zip -DestinationPath . -Force; cd claude-office-2.1.0-dev; powershell -ExecutionPolicy Bypass -File .\install.ps1

    (Windows 화면은 베타에서 확인 전입니다)

설치가 막히면

"디지털 서명되지 않았습니다"처럼 내려받은 파일이 막혔다는 안내가 나오면, 아래 명령으로 압축 푼 폴더의 차단 표시를 푼 뒤 다시 시도합니다.

Get-ChildItem -Recurse $HOME\Downloads\claude-office-2.1.0-dev | Unblock-File

실행 정책 때문에 막히면 압축 푼 폴더 안에서 아래처럼 실행합니다.

powershell -ExecutionPolicy Bypass -File install.ps1

그래도 막히면 회사 정책으로 막혀 있는 것입니다. 회사 IT 담당자(관리자)에게 문의해 주세요. (Windows 화면은 베타에서 확인 전입니다)

  1. 질문 두 개에 답합니다(아래 "설치 중 질문").

설치 중 질문

~/.zshrc에 claude-office 명령 경로를 추가할까요? [y/N]

y를 누르고 Enter를 누르면 어느 폴더에서나 claude-office라고만 쳐서 켤 수 있습니다. PATH는 "명령을 찾아보는 폴더 목록"입니다. 실제 화면에는 /Users/<사용자 이름>/.zshrc에 …처럼 전체 경로로 나옵니다. 파일 이름(~/.zshrc)은 쓰는 셸에 따라 ~/.bash_profile이나 ~/.bashrc로 보일 수 있습니다. Windows에서는 사용자 PATH에 claude-office 명령 경로를 추가할까요? [y/N]로 묻습니다(Windows 화면은 베타에서 확인 전입니다).

n을 누르면 설치가 끝날 때 다음부터는 이렇게 켜세요: ~/.claude-office/bin/claude-office처럼 켜는 명령을 알려 줍니다(4장).

Claude Code 플러그인(claude-office)을 설치할까요? 도구 사용 기록을 이 PC의 뷰어로 보냅니다. [y/N]
y를 권장합니다. 플러그인은 Claude Code에 붙이는 작은 추가 기능이고, 말풍선과 손들기를 보여 주려면 필요합니다. 플러그인은 보기만 하고 Claude의 동작을 바꾸지 않습니다.

설치가 끝나면 환경 점검(doctor) 결과가 나옵니다.

✅ Node.js: 버전 24
✅ 프로그램 파일: 있음
⚠️ 포트: 서버가 꺼져 있습니다(4317)
  → claude-office 명령으로 대시보드를 켜 주세요.
✅ Claude 데이터 폴더: 세션 2개, 프로젝트 3개
✅ Claude Code: 있음
✅ 플러그인: 켜져 있음
✅ 회사 관리자 설정: 파일 없음(회사가 다른 방식으로 정책을 배포했을 수 있음)
✅ 프록시: 없음
⚠️ 실시간 이벤트: 서버가 꺼져 있어 확인하지 못했습니다
  → 대시보드를 켠 뒤 다시 확인해 주세요.
✅ 요금제 한도(선택): 없음
설치 완료. 새 터미널에서 claude-office 를 실행하세요.

마지막 줄에 "설치 완료"가 보이면 성공입니다.

설치 직후에는 위의 노란 줄 두 개(⚠️ 포트, ⚠️ 실시간 이벤트)가 함께 나오는 것이 정상입니다. 아직 대시보드를 켜지 않았기 때문이고, 4장대로 켜면 사라집니다.

4. 켜기와 끄기

켜기

  1. 터미널(Windows는 PowerShell)을 새로 엽니다.
  2. 아래 명령을 실행합니다. 
    claude-office

    설치할 때 PATH 질문에 n을 눌렀다면, 설치 마지막 줄(다음부터는 이렇게 켜세요: …)에 나온 전체 경로로 켭니다.

    ~/.claude-office/bin/claude-office

    Windows는 $HOME\.claude-office\bin\claude-office.cmd입니다(Windows 화면은 베타에서 확인 전입니다).

  3. 웹 브라우저가 저절로 열리고 대시보드가 보입니다. 열리지 않으면 브라우저 주소 창에 http://127.0.0.1:4317을 입력합니다. 127.0.0.1은 "이 컴퓨터 자신"이라는 뜻입니다.
이 창을 닫으면 대시보드가 꺼집니다.
Claude Agent Office: http://127.0.0.1:4317  (data: /Users/<사용자 이름>/.claude)

브라우저에 빌딩과 층이 보이고, 위쪽 막대 오른쪽에 ● LIVE가 보입니다.

스크린샷 자리: 처음 켰을 때의 대시보드
터미널 창을 닫으면 대시보드도 꺼집니다. 대시보드를 보는 동안에는 창을 열어 두세요(작게 줄여 두어도 됩니다).

끄기

대시보드를 켠 터미널 창에서 Ctrl+C를 누르거나, 그 창을 닫습니다. Claude Code는 계속 쓸 수 있습니다.

5. 화면 보는 법

  1. 층: Claude Code 창 하나입니다. 층 머리에 이름과 상태가 보입니다. Claude Code 창을 정상적으로 닫으면 그 층은 사라집니다. 불이 꺼진 채 흐리게 남은 층은 창이 갑자기 꺼진 경우입니다.
  2. 캐릭터: Claude(팀장)와, Claude가 함께 일하도록 부른 팀원들입니다.
  3. 말풍선: 캐릭터가 지금 하는 일입니다(예: 저는 지금 「README.md」 파일을 읽고 있습니다).
  4. 손들기와 노란 ?: Claude가 여러분의 확인(권한 허락, 질문 답변, 계획 승인)을 기다립니다. Claude Code 창으로 가서 답해 주세요.
  5. 진단 칩: 위쪽 막대의 "진단" 단추입니다. 최근 1시간 안에 오류가 있었으면 빨간 점이 붙습니다. 누르면 오른쪽에 진단 패널이 열립니다.

진단 패널

진단 칩을 누르면 오른쪽에 패널이 열립니다. 위에서부터 이렇게 보입니다.

  • 판정 한 줄: 모두 정상입니다(초록), 확인할 항목이 2개 있습니다(노랑), 문제 1개를 찾았습니다(빨강) 가운데 하나입니다.
  • 최근 오류: 최근 1시간 오류 없음 또는 최근 1시간 오류 2건과, 로그가 저장되는 폴더입니다.
  • hook 수신: Claude Code가 보낸 소식을 얼마나 받았는지입니다(예: 최근 10분 5건, 마지막 수신 2분 전, 거부 0건).
  • 점검 결과: 6장의 환경 점검(doctor)과 같은 항목입니다. 문제(빨간 테두리)와 확인 필요(노란 점선 테두리)가 위에 오고, 아래에 고치는 법이 붙습니다. 정상 항목은 한 줄로 보입니다.
  • 진단 파일: 문제가 생겼을 때 담당자에게 보낼 파일을 만드는 단추입니다(6장).

오른쪽 위에 다시 확인 단추와 닫기 단추가 있습니다. Esc를 눌러도 닫힙니다.

위쪽 막대의 숫자

  • 토큰: Claude가 읽고 쓴 글자의 양입니다. 오늘·최근 5시간·최근 7일 합계가 보입니다.
  • PLAN 바: 요금제 사용 한도를 보여 주는 자리입니다. 베타에서는 지원하지 않아서 "데이터 없음"으로 보입니다. 고장이 아니니 신경 쓰지 않아도 됩니다.

6. 문제가 생겼을 때

먼저 환경 점검(doctor)을 해 보세요

claude-office doctor

항목마다 ✅(정상), ⚠️(확인 필요), ❌(문제) 가운데 하나가 붙고, ⚠️·❌ 아래에는 → 고치는 법이 한 줄 나옵니다. 그대로 따라 해 보세요.

예: Claude Code를 한 번도 실행하지 않은 컴퓨터

❌ Claude 데이터 폴더: 없음 또는 읽을 수 없음
  → Claude Code를 한 번 실행한 뒤 다시 확인해 주세요.

진단 파일을 만들어 보내 주세요

고쳐지지 않으면 진단 파일을 만들어 담당자에게 보내 주세요. 진단 파일은 문제를 찾는 데 필요한 정보만 담은 파일 하나입니다. 대화 내용, 이름, 비밀값은 들어가지 않습니다. 폴더 이름도 <project-1>처럼 번호로 바뀝니다.

방법 1. 화면에서

  1. 위쪽 막대의 진단을 누릅니다.
  2. 패널 맨 아래 진단 파일 만들기를 누릅니다. 잠시 만드는 중…으로 바뀝니다.
  3. 받기를 눌러 파일을 내려받습니다.

진단 파일을 만들었습니다 아래에 파일 위치(예: ~/.claude-office/diagnostics/claude-office-diag-20261001-093000.json)와 받기 단추가 보입니다.

"진단 파일을 만들지 못했습니다. 잠시 뒤 다시 눌러 주세요. 계속 안 되면 터미널에서 claude-office diag를 실행해 주세요."가 나오면 아래 방법 2를 써 주세요.

방법 2. 터미널에서:

claude-office diag
진단 파일을 만들었습니다: /Users/<사용자 이름>/.claude-office/diagnostics/claude-office-diag-20261001-093000.json
이 파일을 담당자에게 보내 주세요. 대화 내용, 이름, 비밀값은 들어 있지 않습니다.

만들어진 파일(claude-office-diag-…json)을 메일이나 메신저로 담당자에게 보내면 됩니다.

설치할 때 "이미 다른 파일이 있는 폴더입니다"가 나와요

이미 다른 파일이 있는 폴더입니다. 빈 폴더나 새 폴더 이름을 지정해 주세요.

설치할 폴더에 이 프로그램이 만들지 않은 파일이 이미 있어서, 그 파일을 지우지 않으려고 설치를 멈춘 것입니다. 다른 폴더를 쓰려면 설치 명령 끝에 --prefix와 새 폴더 이름을 붙입니다(예: sh install.sh --prefix ~/claude-office-beta). 판단이 어려우면 진단 파일 대신 이 화면을 담당자에게 보내 주세요.

설치(또는 제거)가 질문에 답할 틈 없이 '아니오'로 끝났어요

마지막에 아래 안내가 나왔다면, 질문에 답을 입력할 수 없는 곳에서 실행한 것입니다. 예를 들어 Claude Code 안에서 !로 명령을 실행하면 질문에 답할 수 없어서, 모든 질문을 "아니오"로 처리합니다.

입력을 받을 수 없어 '아니오'로 처리했습니다. 설치하려면 --yes를 붙여 다시 실행하세요.

Windows 설치와 제거에서는 이렇게 나옵니다.

  • Windows 설치: 입력을 받을 수 없어 '아니오'로 처리했습니다. 설치하려면 -Yes를 붙여 다시 실행하세요.
  • 제거(모든 운영체제, claude-office uninstall): 입력을 받을 수 없어 '아니오'로 처리했습니다. 제거하려면 --yes를 붙여 다시 실행하세요.

보통의 터미널 창에서 다시 실행하면 질문에 직접 답할 수 있습니다. 모든 질문에 "예"로 답하려면 아래처럼 실행합니다. 이 명령은 PATH 추가와 Claude Code 플러그인 설치에 모두 동의합니다.

macOS·Linux 설치(압축 푼 폴더 안에서):

sh install.sh --yes

Windows 설치(압축 푼 폴더 안에서, Windows 화면은 베타에서 확인 전입니다):

powershell -ExecutionPolicy Bypass -File .\install.ps1 -Yes

제거(모든 운영체제). 로그와 진단 파일까지 지워지니, 담당자에게 보낼 진단 파일이 있다면 먼저 보내 주세요:

claude-office uninstall --yes

Windows에서 설치가 "디지털 서명되지 않았습니다"로 막혀요

베타 버전은 코드 서명을 하지 않아서, 내려받은 파일이나 회사의 실행 정책 때문에 막힐 수 있습니다. PowerShell에서 아래 명령을 실행한 뒤 다시 설치합니다.

Get-ChildItem -Recurse $HOME\Downloads\claude-office-2.1.0-dev | Unblock-File

그래도 막히면 powershell -ExecutionPolicy Bypass -File install.ps1로 실행해 보고, 그래도 안 되면 회사 IT 담당자에게 문의합니다. (Windows 화면은 베타에서 확인 전입니다)

자주 묻는 증상

① 위쪽 막대에 "○ 재연결 중"이 보여요

대시보드 프로그램이 꺼졌거나 다시 켜지는 중입니다. 대시보드를 켠 터미널 창이 열려 있는지 확인하고, 닫혔다면 4장대로 다시 켜 주세요. 다시 켜지면 저절로 ● LIVE로 돌아옵니다.

② 캐릭터는 보이는데 말풍선과 손들기가 안 나와요

Claude Code가 대시보드에 소식을 보내지 못하고 있습니다. doctor에서 이렇게 보입니다.

⚠️ 실시간 이벤트: 받은 이벤트 0건
  → Claude Code 세션에서 아무 작업이나 해 보세요. 그래도 0건이면 플러그인과 회사 관리자 설정 항목을 확인해 주세요. 그래도 안 되면 회사 관리자에게 사용설명서 부록 A를 전달해 주세요.
  1. Claude Code에서 아무 질문이나 한 번 해 봅니다.
  2. doctor의 플러그인 항목이 ⚠️이면 그 고치는 법대로 플러그인을 설치합니다. 설치 뒤에는 Claude Code를 닫았다가 다시 엽니다.
  3. doctor가 모두 정상인데도 말풍선이 안 보이면, 회사 정책 때문일 수 있습니다. 회사가 관리 도구로 정책을 배포하면 이 컴퓨터에서는 설정 파일이 보이지 않을 수 있습니다. 회사 관리자에게 부록 A를 전달해 주세요.

③ doctor에 "회사 관리자 설정"이 ❌로 나와요

❌ 회사 관리자 설정: 있음: 관리자 hook만 허용
  → 사용설명서 부록 A를 회사 관리자에게 전달해 설정을 부탁해 주세요.

회사가 Claude Code에 추가 기능을 막아 두었습니다. 여러분이 직접 바꿀 수 없습니다. 부록 A를 회사 관리자에게 전달해 주세요. 그 전까지도 빌딩, 층, 토큰 숫자는 그대로 볼 수 있고, 말풍선과 손들기만 보이지 않습니다.

④ 켤 때 "포트 4317번이 이미 사용 중입니다"가 나와요

포트 4317번이 이미 사용 중입니다. --port 로 다른 포트를 지정하세요.

포트는 프로그램이 쓰는 "통로 번호"입니다. 대시보드가 이미 다른 창에서 켜져 있을 가능성이 가장 큽니다. 브라우저에서 http://127.0.0.1:4317을 열어 보세요. 대시보드가 보이면 그대로 쓰면 됩니다.

다른 프로그램이 4317을 쓰고 있다면 doctor에 이렇게 나옵니다.

❌ 포트: 다른 프로그램이 4317을 쓰고 있습니다

그 프로그램을 끄는 것이 가장 좋습니다. 다른 번호로 켤 수도 있지만(--port), 그러면 말풍선과 손들기가 보이지 않습니다.

예전에 받은 이전 버전(v1) 뷰어가 4317을 쓰고 있다면 doctor에 이렇게 나옵니다. 브라우저에서 화면은 보이지만 진단 칩이 없는 것이 이전 버전입니다.

⚠️ 포트: 이전 버전(v1) 서버가 4317을 쓰고 있습니다 — 끄고 다시 실행해 주세요
  → 이전 버전 뷰어를 켠 터미널 창에서 Ctrl+C를 누르거나 그 창을 닫은 뒤, claude-office 명령으로 다시 켜 주세요.

이때 실시간 이벤트 항목은 확인하지 못했습니다(이전 버전 서버)로 나옵니다. 이전 버전을 끄고 다시 켜면 둘 다 정상으로 돌아옵니다.

스크린샷 자리: 포트 사용 중 안내

⑤ "Node.js 24 이상이 필요합니다"가 나와요

Node.js 24 이상이 필요합니다(지금 v20.11.0).

설치하는 중이었다면 아래 줄이 함께 나옵니다. 이 기록 파일은 진단 파일을 만들 때 함께 들어갑니다.

자세한 기록: /Users/<사용자 이름>/.claude-office/logs/install-20261001-093000.log

2장대로 Node.js를 새로 설치한 뒤, 터미널을 닫았다가 다시 열고 켜 주세요.

7. 지우기

  1. 대시보드가 켜져 있으면 먼저 끕니다(4장).
  2. 아래 명령을 실행합니다. 
    claude-office uninstall
  3. Claude Code에서 claude-office 플러그인도 지울까요? [y/N]라고 묻습니다. y를 누르면 Claude Code에서도 빠집니다. n을 누르면 플러그인은 남겨 두었습니다. 지우려면: claude plugin uninstall claude-office@claude-office --scope user라고 나중에 지우는 명령을 알려 줍니다.
  4. 로그와 진단 파일도 지울까요? [y/N]라고 묻습니다. 담당자에게 보낼 진단 파일이 남아 있다면 n을 누르세요.

프로그램 파일과 PATH에 넣었던 줄은 질문과 관계없이 항상 지워집니다. 마지막에 무엇을 지우고 남겼는지 알려 줍니다.

두 질문에 모두 y를 누른 경우:

제거를 마쳤습니다.
지움: 프로그램 파일, PATH 설정, 플러그인, logs, diagnostics
남김: 없음

두 질문에 모두 n을 누른 경우:

제거를 마쳤습니다.
지움: 프로그램 파일, PATH 설정
남김: 플러그인, logs, diagnostics

새 터미널에서 claude-office를 입력하면 "명령을 찾을 수 없습니다"가 나옵니다.

8. 부록 A: 회사 관리자에게 전달할 설정

이 절은 회사의 Claude Code 관리자에게 그대로 전달하는 내용입니다.

관리자님께

Claude Agent Office는 직원 PC 안에서만 동작하는 읽기 전용 대시보드입니다. 플러그인 claude-office@claude-office는 Claude Code의 hook 이벤트를 같은 PC의 http://127.0.0.1:4317/hooks/event로 보냅니다. 외부로는 아무것도 보내지 않고, hook에 어떤 결정도 돌려주지 않습니다(도구 실행을 막거나 허용하지 않음).

관리자 설정(managed settings)에 다음이 필요합니다.

설정필요한 값언제
allowedHttpHookUrls"http://127.0.0.1:4317/*"를 목록에 추가이 목록을 쓰고 있을 때
allowManagedHooksOnly켜 두려면 enabledPlugins에서 "claude-office@claude-office": true로 플러그인을 관리자가 활성화이 값이 true일 때
enabledPlugins"claude-office@claude-office": true위와 같음

예시(기존 설정에 합쳐 주세요):

{
  "allowedHttpHookUrls": ["http://127.0.0.1:4317/*"],
  "enabledPlugins": { "claude-office@claude-office": true }
}

관리자 설정 파일 위치:

  • macOS: /Library/Application Support/ClaudeCode/managed-settings.json
  • Linux: /etc/claude-code/managed-settings.json
  • Windows: C:\Program Files\ClaudeCode\managed-settings.json

MDM 등 다른 방식으로 정책을 배포한다면 같은 키를 그 방식으로 넣어 주세요. 플러그인 마켓플레이스는 각 직원 PC의 설치 폴더 ~/.claude-office/plugin(Windows는 %USERPROFILE%\.claude-office\plugin)에 있습니다.

이 설정은 베타에서 검증하지 못했습니다. 관리자는 IT 시험 PC에서 먼저 확인해 주세요.

9. 부록 B: 베타에서 알려진 제한

  • Windows와 Linux는 충분히 검증하지 못했습니다. 베타는 macOS에서 확인했습니다. 다른 운영체제에서 문제가 생기면 진단 파일을 보내 주세요.
  • PLAN 바(요금제 한도)는 베타에서 지원하지 않습니다(회사 좌석은 대부분 해당 데이터가 오지 않음). 화면에는 "데이터 없음"으로 보입니다.
  • 코드 서명이 없습니다. 그래서 macOS에서는 드물게 "확인되지 않은 개발자" 경고가 나올 수 있고, Windows에서는 실행 정책에 막힐 수 있습니다. 대처법은 3장과 6장에 있습니다.
  • 회사 관리자 정책(allowManagedHooksOnly 등)이 켜져 있으면, 관리자가 부록 A대로 설정하기 전까지 말풍선과 손들기가 보이지 않습니다. 빌딩, 층, 토큰 숫자는 그대로 보입니다.
  • 대시보드는 4317번 포트에서만 말풍선과 손들기가 동작합니다. 다른 번호로 켜면 빌딩과 숫자만 보입니다.
  • 로그인할 때 저절로 켜지지 않습니다. 볼 때마다 claude-office로 켜 주세요.
  • 로그와 진단 파일은 자동으로 보내지 않습니다. 여러분이 직접 만든 진단 파일만 담당자에게 전달됩니다. 실행 로그는 7일이 지나면 저절로 지워집니다(설치 기록은 남습니다).
