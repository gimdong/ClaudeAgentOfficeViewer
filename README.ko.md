# Claude Agent Office Viewer

Claude Code의 토큰 사용량·잔여량, 실행 중인 세션, agent team 팀원 상태를 네온 도트 사무실로 보여주는 로컬 대시보드입니다.
`~/.claude`는 읽기만 하며, 서버는 `127.0.0.1`에서만 열립니다. 플러그인을 설치하면 대시보드에서 권한 요청·질문에 답할 수 있습니다(답은 그 요청에만 돌아가고 설정 파일은 바꾸지 않습니다).

회사 관리자용 설정 안내는 [docs/admin.md](docs/admin.md)에 있습니다.

## 실행

```bash
npm install
npm run build
npm start            # http://127.0.0.1:4317
```

개발 모드: `npm run dev` (Vite + API 서버 동시 실행)

옵션: `npm start -- --port 5000 --claude-home /path/to/.claude --config ./my.config.json`

Claude 데이터 폴더는 `--claude-home` > `CLAUDE_HOME` 환경변수 > `CLAUDE_CONFIG_DIR` 환경변수 > 기본값 `~/.claude` 순으로 정해집니다(Claude Code 자체가 설정 폴더를 옮길 때 쓰는 `CLAUDE_CONFIG_DIR`도 인식합니다).

원격 컴퓨터의 대시보드 보기: 내 컴퓨터에서 `ssh -L 14317:127.0.0.1:4317 <원격 컴퓨터>`로 터널을 열고, 원격에서 `claude-office url`이 알려 준 주소의 번호만 `14317`로 바꿔 내 브라우저에서 엽니다([설명서](docs/manual/index.html#remote)).

## 예산과 컨텍스트 창 설정 (선택)

`claude-office.config.example.json`을 `claude-office.config.json`으로 복사해 값을 바꿉니다.
- `budget.fiveHour`, `budget.weekly`: HUD의 5H·WEEK 잔여량 기준(토큰 수). 없으면 `-- 설정 필요`.
- `contextWindows`: 모델 이름 접두어별 컨텍스트 창 크기. 없으면 200k로 추정.

## 요금제 한도 표시 (선택)

`npm run setup:statusline`을 실행하면 statusline 입력을 `~/.claude/claude-office/limits.json`에 복사하도록 설정합니다(설정은 백업).
기존에 직접 만든 `command` 타입 statusline이 있었다면 그 모양이 그대로 유지됩니다. statusline을 따로 설정한 적이 없어 Claude Code 기본 상태줄을 쓰고 있었다면, 설치 후에는 상태줄이 빈 줄로 보일 수 있습니다(한도 수집 자체에는 영향 없음) — 원래 statusline 설정이 없어 다시 실행할 명령이 없기 때문입니다.
되돌리기: `npm run remove:statusline`. Claude Code가 한도 정보를 넘겨주지 않는 버전에서는 PLAN 바가 `-- 데이터 없음`으로 표시됩니다.

## 실시간 활동 표시 (플러그인, 선택)

플러그인을 설치하면 Claude Code의 hook 이벤트가 이 컴퓨터의 서버(`127.0.0.1:4317`)로 암호화되어 갑니다. 대시보드는 에이전트가 지금 하는 일을 말풍선으로 보여주고, 권한 요청·질문·계획 승인을 기다리는 캐릭터는 손을 들고 머리 위에 노란 ?가 뜹니다. **대시보드에서 답한 결정만 돌려줍니다.** 손든 캐릭터를 눌러 결정 보고서에서 허용·거부·질문 답을 고르면 그 답이 Claude Code로 돌아갑니다. 같은 요청의 터미널 창도 함께 떠 있고 먼저 답한 쪽이 적용되며, 대시보드가 10분 안에 답하지 않거나 서버가 꺼져 있으면 터미널 창이 그대로 결정합니다. 계획 승인과 팀원 요청은 보고서만 보여 주고 답은 터미널에서 합니다.

**권한 정책(Phase 3).** 캐릭터를 누르거나 위쪽 막대의 "권한 정책"을 열어, 에이전트 이름(리드, 팀원, 서브에이전트 종류, "그 밖의 모든")마다 도구 묶음(명령 실행, 파일 고치기, 웹 접근, 팀원·서브에이전트 만들기, 외부 도구(MCP), 그 밖의 도구, 모든 도구)을 `금지` 또는 `항상 질문`으로 정해 둘 수 있습니다. 플러그인의 PreToolUse hook이 그 정책대로 막거나 권한 창을 띄웁니다. 정책은 막거나 묻게만 하고 허용을 늘리지는 않습니다. 사용자에게 묻기(질문·계획 승인)·팀원끼리 연락·서브에이전트 결과 돌려주기는 막지 않습니다. 정책은 `~/.claude-office/policy.json`(개발 모드는 `.logs/policy.json`)에 저장되고, 이름이 같으면 다른 세션에도 적용됩니다. **대시보드가 켜져 있을 때만 적용되는 실수 방지 장치이며 보안 장치가 아닙니다.** 서버가 꺼져 있거나 hook이 닿지 못하면 Claude Code는 원래 규칙대로 진행합니다. 자세한 한계는 사용설명서 5장 "권한 정책"과 부록 A에 있습니다.

**층 관리(Phase 4a).** 층 머리의 영업 스위치로 그 세션을 멈추고(`멈춤` — 리드·팀원·서브에이전트가 다음에 도구를 쓰려 할 때부터 PreToolUse hook이 막습니다. 사용자에게 묻기·팀원끼리 연락 등 권한 정책에서 빼는 도구는 통과합니다) 다시 돌릴 수 있습니다. "종료"는 확인 창 뒤 그 세션의 Claude Code 프로세스에 SIGTERM을 보내고, 10초 뒤에도 켜져 있으면 한 번 더 확인한 뒤 SIGKILL을 보냅니다. 신호는 세션 기록의 프로세스 번호와 시작 시각이 지금 프로세스와 맞을 때만 보내고, 확인할 수 없으면 보내지 않습니다(Windows는 확인 전). 끝난 층은 "삭제"로 대시보드 목록에서만 숨깁니다(세션 기록 파일은 건드리지 않음). 멈춤과 숨김은 서버 메모리에만 있어 대시보드를 다시 켜면 풀리고, **대시보드가 켜져 있을 때만 적용되며 보안 장치가 아닙니다.** 자세한 한계는 사용설명서 5장 "층 관리"에 있습니다.

요약 필드와 마지막 문장의 비밀값은 흔한 형식(Authorization/Bearer, 이름=토큰, ghp_·sk-·AKIA 등 접두어, URL 자격 증명, 긴 무작위 문자열)만 가리며 모든 형식을 막지는 못합니다.

설치는 릴리스 압축 파일의 설치 스크립트로 합니다(설치 스크립트가 hook 설정에 node·열쇠 경로를 적습니다). 저장소를 마켓플레이스로 직접 추가하면 hook이 동작하지 않습니다.

서버에는 요약된 값(명령·설명·파일 경로·검색어·도메인·받는 사람·할 일·질문, 각 200자)만 메모리에 남고, 파일로 쓰지 않습니다.

조직이 `allowedHttpHookUrls`를 설정했다면 `http://127.0.0.1:4317/*`은 사용자가 이전 버전의 플러그인(http hook)을 쓰는 동안만 넣으면 됩니다. beta.14 플러그인은 command hook을 써서 필요 없습니다. `allowManagedHooksOnly`가 켜져 있으면 관리자가 플러그인을 강제 활성화해야 합니다.

### 개발용 플러그인

사용자의 대시보드(4317)와 겹치지 않게 개발 서버는 다른 포트에서 띄우고, 포트만 바꾼 플러그인 복사본을 실험 세션에 로드합니다. 사용자 설정(`enabledPlugins`)은 바꾸지 않습니다.

```bash
npm run build && npm start -- --port 4318
node scripts/make-dev-plugin.mjs --port 4318 --out /tmp/claude-office-dev-plugin
claude --plugin-dir /tmp/claude-office-dev-plugin
```

### PLAN 바와 요금제

PLAN 바는 statusline이 넘겨 주는 `rate_limits`의 5시간·주간·지출 한도(`spend_limit`) 가운데 가장 많이 쓴 창을 보여줍니다. Pro/Max 구독이나 지출 한도가 있는 gateway 뒤에서만 값이 오고, 그 밖에는 `-- 데이터 없음`입니다.
PLAN 바 값은 `npm run setup:statusline`으로 statusline tap을 설치해야 들어옵니다(설치는 사용자가 직접 결정합니다).

## 보안

- **같은 계정 검사는 Linux에서만 합니다.** Linux에서는 같은 사용자 계정의 프로그램이 보낸 연결만 받고(`/proc/net/tcp`로 확인), 다른 연결에는 `같은 사용자 계정의 프로그램만 접속할 수 있습니다`로 거절합니다. 다른 네트워크를 쓰는 컨테이너는 같은 계정이어도 거절됩니다. macOS·Windows에서는 이 검사를 하지 않습니다. 암호화된 hook(beta.14)은 꾸밀 수 없지만, beta.14는 옛 http hook도 받으므로 같은 컴퓨터의 다른 계정이 가짜 hook(예: 가짜 권한 요청)을 보낼 수는 있습니다. 대시보드의 데이터와 답(`/api`)은 열쇠가 있어야 합니다. ([설명서 6장](docs/manual/index.html#same-user))
- **hook 이벤트는 암호화됩니다(beta.14부터).** 플러그인은 hook 이벤트를 작은 중계 프로그램에 넘기고, 중계 프로그램은 내 계정만 읽을 수 있는 열쇠 파일(`~/.claude-office/hook.key`)로 암호화해 보냅니다. 답도 같은 열쇠로 암호화된 것만 받습니다. 대시보드가 꺼진 동안 다른 계정이 4317을 차지해도 입력한 지시, 도구 입력과 결과를 읽을 수 없고 대신 답할 수도 없습니다. 그때 Claude Code는 평소처럼 터미널에서 묻습니다.

  이전 버전을 설치했다면 그 플러그인은 아직 암호화하지 않은 http hook을 보내고, 대시보드에 `옛 플러그인(http hook)이 남아 있습니다 — 같은 압축 파일로 다시 설치하세요`가 보입니다. 받은 압축 파일로 다시 설치하세요. 이미 열려 있던 Claude Code 창은 `/reload-plugins`를 실행하거나 다시 열기 전까지 옛 hook을 씁니다. 그 전까지는 예전 위험이 그대로 남습니다: 대시보드가 꺼진 동안 같은 컴퓨터의 다른 계정이 4317을 차지하면 입력한 지시, 도구 입력과 결과를 받고, 권한 요청에 대신 답하고, 대화에 글을 끼워 넣을 수 있습니다. beta.14는 이 옛 http hook도 받으므로, 다시 설치하지 않은 사람에게는 여전히 해당합니다.

  모르는 프로그램이 4317을 쓰고 있다면 다른 포트로 켜지 말고, 무엇인지 확인한 뒤 비워질 때까지 플러그인을 꺼 두세요. 다른 프로그램이 포트를 쓰면 `claude-office doctor`가 `❌ 포트: 다른 프로그램이 4317을 쓰고 있습니다`로 알려 줍니다.
- **대시보드는 `~/.claude`를 읽기만 합니다.** 설치는 동의한 경우에만 Claude Code의 `claude plugin` 명령으로 플러그인 설정을 기록하고, 셸 설정 파일에 PATH 한 줄을 더합니다.
- **층 제어는 고른 Claude Code 프로세스에 신호를 보냅니다.** 보내기 전에 세션 기록의 pid와 시작 시각을 확인하고, Windows에서는 보내지 않습니다.

## 알아두면 좋은 점

- **1M 컨텍스트 창을 쓰는 경우:** `claude-office.config.json`의 `contextWindows`에 실제 쓰는 모델의 창 크기를 설정하는 것을 권장합니다. 설정이 없으면 사용량이 200k를 넘을 때만 1M으로 추정하므로, 150k~200k 구간에서는 아직 200k 창으로 간주되어 경고색이 보일 수 있습니다. `contextWindows`의 키는 모델 ID의 접두어이며, `"[1m]"` 같은 접미사 없이 적습니다(예: `"claude-opus-5-5"`).
- **예시 설정의 1M 값:** `claude-office.config.example.json`의 `contextWindows` 값(1,000,000)은 1M 창을 실제로 쓰는 사용자를 기준으로 한 예시입니다. 200k 창으로 쓰고 있다면 이 값을 그대로 복사하지 말고 실제 창 크기(예: 200000)로 바꿔야 합니다 — 그렇지 않으면 CTX 사용률이 실제보다 낮게 표시됩니다.
- **"불 꺼진" 사무실(종료된 세션 표시):** Claude Code는 세션을 정상적으로 종료하면 `sessions/<pid>.json` 파일을 스스로 지웁니다. 따라서 화면에 반투명하게 계속 남아 있는 "불 꺼진" 사무실은 대부분 비정상 종료(강제 종료, 크래시 등)된 세션이며, 정상적으로 닫은 세션은 애초에 목록에서 사라집니다.
